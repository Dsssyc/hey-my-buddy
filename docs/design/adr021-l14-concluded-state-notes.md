# 微任务的终态与三处顺带

本说明记录开发者 2026-10-13 定下的行为改动。微任务与回合的名字不变，版本号与 schema 版本号不变，升级基点样板与生成脚本不变；待做升级继续归档旧看板并新建只带设置的看板，没有工作历史的换算。

`conclude` 在写结论、固定 Host 部分产物与记事件的同一个事务中，把 `workflow_runs.state` 与 `tasks.state` 改成 `concluded`。结论的 `execution_status` 保留此前的 `delivered`、`failed` 或 `cancelled`，执行尝试的真实结果不重写；没有另外增加执行结果副本。微任务的关闭状态为 `accepted` 或 `concluded`：继续、验收、取消与另一条结论均不能重开它，同一条结论仍按原请求回放，Host 的 `reclaim` 仍可使用。任务状态取值、约束、迁移表、终态读取、等待与 CLI 帮助已同步；`workflow_turns.state` 的同名回合状态保持原义，没有与微任务终态共用常量。

`workflow_host_conclusions` 的每个微任务只允许一条结论，唯一索引按 `run_id` 建立。`host_conclusions.current` 只在微任务状态为 `concluded` 时读取结论。`evidence_json` 仍是明确含 `references` 数组的对象，删除 `artifactSetSha256`；执行状态、尝试、继续事件与产物集合摘要不再用来决定新看板的结论是否当前。回收复核改为核对微任务的关闭状态与 Host 所有权代次，保留实际停止、物理检出、产物绑定与依赖的检查。`list` 的待验收筛选、宏任务计数与控制台待验收判断用 `delivered` 区分待验收微任务，保留普通执行任务原有的待验收规则及停止证据检查。新状态沿用“已结束”文字和原有布局，打包资产已重建。

回合的截断事实存入 `workflow_turns.outcome_truncated_json`，与 `outcome_json` 和 `provenance_json` 分开。SQL NULL 表示没有摘要数组截断事实；有截断时保存原回合记录的对象，其中 `remaining` 或 `decisions` 下的 `droppedItems` 和 `shortenedItems` 分别表示丢弃的条目数与被缩短的保留条目数。正常结果及取消后的迟到结果都保存这份事实，`get` 的当前回合、回合列表、审计回合和 CLI 简略当前回合均读同一列；它没有混入结果或来源对象，也没有与显示摘要的 `summaryTruncated` 合用。

打回的当前记录使用 `tasks.review_rejected_at` 和 `tasks.review_rejection_note` 两列，`workflow.review_rejected` 继续保留原产物、说明与 Host 意见的历史。下一次继续或验收归档当前打回时使用这两列；继续先归档旧打回，再写本次的新打回，连续打回不会由旧记录的清理覆盖新记录，验收成功清空它们；`accepted_at`、`acceptance_note`、`acceptance_verdict` 只表示验收，数据库约束使非空 `acceptance_verdict` 只能是 `accepted`。`get`、任务视图、CLI、宏任务时间线及控制台现有打回显示均读独立字段。普通执行确认与微任务共用任务表，所以普通执行的 `rejected` 输入也写独立字段，其重复请求、冲突、事件与重试归档保持原有规则。被打回后执行失败的微任务不再因为验收时间非空而被拒绝写结论。

控制台停止宏任务先在事务中固定并停止本次范围，再用同一结论路径结束确已停止的微任务；已交付或失败的执行来源不会被改成取消，正在执行的微任务及其协助微任务要等 Worker 确认停机。停止命令回执保存目标、原尝试、Host 所有权代次和根及目标的继续记录数，Worker 提交结果或释放尝试后继续处理固定目标。继续或接管使旧停止意图作废；响应返回当前状态及每个目标实际结束、待处理或已作废的原因。没有借此取得 Host 删除检出的凭据，控制台发起的回收受阻时仍明确返回原因，Host 可以用自己的 `reclaim` 收尾。

删除的判断包括新看板结论与执行状态、尝试、继续事件、产物集合摘要的有效性比对，记录另一条当前结论的重复查询，验收时通过查询结论判断已结束的分支，以及把打回解释成验收、继续时清空验收三列的分支。没有整份测试文件只为这些判断存在；删除了 `test_takeover_preserves_a_conclusion_until_the_new_host_continues` 中继续后使结论失效的断言，并把用例改为终态接管；删除了 `test_failure_conclusion_preserves_failure_and_never_becomes_an_acceptance` 中继续失败任务、以同一说明记录下一次结论的断言。其余所有权、部分产物、回放、回收与封存竞争检查保留。

新增或扩展的测试覆盖三种执行来源进入 `concluded`、继续与验收及不同结论的拒绝、同一结论的回放、待验收筛选和宏任务计数、取消归因的保留、现有真实检出的回收、打回后失败再写结论、验收三列不出现打回、普通执行拒绝的回放与归档、连续两次打回的当前说明与事件历史、正常和迟到回合的截断存储及 `get`/CLI 回读、结束后读取询问历史、CLI 等待识别终态、路由祖先关闭、控制台待验收判断与打回显示。宏任务停止另覆盖已停止结果、排队任务、未确认停机的协助微任务、固定范围回放、停止后继续与接管的失效。
