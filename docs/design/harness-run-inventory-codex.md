# Codex 单次运行现状清单

本文只记录指定十个 Python 文件的静态实现，不把声明的能力、请求的权限或结果中的布尔值当作本机原生验证。三种入口都有实现：Worker 的 `start`、快速路由的 `start_no_tool_structured`、审阅路由的 `start_read_only_structured`；后两者转入共用的 `read_only` 启动函数，三者都运行 `codex_runner`。源码位置：`src/buddy/adapters/codex.py:24`、`src/buddy/adapters/codex.py:33`、`src/buddy/adapters/codex.py:42`、`src/buddy/adapters/codex.py:96`、`src/buddy/adapters/read_only.py:146`、`src/buddy/adapters/read_only.py:198`。

用词遵循 `CONTEXT.md`：buddy 是参与者，Worker 运行时是执行进程的宿主，宏任务用于归组，微任务是 Host 拥有并验收的有界工作；原生 `thread` 和 `turn` 的标识与黑板的执行回合标识分别记述。ADR-023 说明统一事件词汇与黑板统一判定尚未实现，并要求复用已有执行载体；本文记录现状，不把这些原则写成已经实现的行为。依据：`CONTEXT.md:19`、`CONTEXT.md:23`、`CONTEXT.md:72`、`CONTEXT.md:78`、`CONTEXT.md:82`、`CONTEXT.md:91`、`docs/decisions/023-harness-integration-principles.md:5`、`docs/decisions/023-harness-integration-principles.md:38`、`docs/decisions/023-harness-integration-principles.md:42`。

## 5. 结束约定

- **三种模式都没有完成工具**：Worker 提示明确唯一接口是原生 outputSchema 下的 `{outcome: ...}`，没有 buddy_finish_turn；两种路由把请求 outputSchema 传给 turn/start，同样从原生 final_answer 取文本。Worker 的结果文件由控制进程写，不要求 buddy 自己写 turn-output.json；结构化路由没有 Worker 的 turn-output 文件协议。依据：`src/buddy/adapters/codex_runner.py:490`、`src/buddy/adapters/codex_runner.py:500`、`src/buddy/adapters/codex_runner.py:207`、`src/buddy/adapters/codex_no_tool.py:248`、`src/buddy/adapters/codex_runner.py:631`。

- **三层时间界限**：runner 总截止由 execution_deadline 计算，0 为无限；Worker 外层 handle 同样把 0 变 inf，快速请求限 60 秒且 handle.deadline 不加余量，审阅 handle.deadline 则是 budget.timeoutSeconds 加 10 秒；外层谁监测这个 handle 字段，在指定文件中未确认。共用版本诊断最长 5 秒，快速还受总剩余时间限制；Connection 的 RPC/读写共用总截止，额度快照、原生 interrupt 和停止另有有限等待，不能把 0 写成所有等待无限。依据：`src/buddy/adapters/codex_runner.py:122`、`src/buddy/adapters/codex_runner.py:317`、`src/buddy/adapters/codex_runner.py:349`、`src/buddy/adapters/codex.py:110`、`src/buddy/adapters/read_only.py:153`、`src/buddy/adapters/read_only.py:161`、`src/buddy/adapters/read_only.py:205`、`src/buddy/adapters/codex_protocol.py:70`。

- **内层收尾共用实现**：finally 关闭原生 stdin，在总时间剩余范围内等最多三秒；0.2 秒 settle 未确认停止就 terminate(grace=1)，再以 0.5 秒 settle 确认，写 processState.shutdownConfirmed/nativeExitCode，关闭 stdout。快速此前已通过 `_drain` 读到 EOF；Worker/审阅没有这一步。成功结果若原生非零退出或组未停止，改成 native-shutdown-failed 并撤销 Worker 记录；取消标记置位只把当时尚非 ok 的结果改为 cancelled。依据：`src/buddy/adapters/codex_runner.py:592`、`src/buddy/adapters/codex_runner.py:605`、`src/buddy/adapters/codex_no_tool.py:162`。
- **双层停止证据**：内层 ProcessHandle 拥有 App Server，外层 handle 拥有 Python 控制进程，两者各有自己的组/Job；collect 必须同时看到原生 processState.shutdownConfirmed=true 与外层 handle.shutdown_confirmed()。ProcessHandle 在启动时保存 pgid，不靠领导 PID 退出推断后代停止；group_alive 对权限错误、其他观察错误和未持有 Job 的 Windows 组保留 alive，shutdown_confirmed 还要求领导进程已退出。依据：`src/buddy/adapters/codex_runner.py:371`、`src/buddy/adapters/codex.py:110`、`src/buddy/adapters/codex.py:119`、`src/buddy/adapters/read_only.py:262`、`src/buddy/adapters/base.py:194`、`src/buddy/adapters/base.py:236`、`src/buddy/adapters/base.py:290`。

- **凭据收尾不同**：快速/审阅只有确认原生停止后才在 finally 移除私有 auth 符号链接；Worker 的 auth 清理由外层 collect 在双层停止且 codingHomePrepared=true 时调用 remove_coding_auth，结果记 credentialCleanup.complete/removed 或错误。后者逐级固定目录并允许移除普通文件或链接，拒绝不安全路径；未确认停止不执行这一清理。依据：`src/buddy/adapters/codex_runner.py:303`、`src/buddy/adapters/codex_runner.py:603`、`src/buddy/adapters/codex.py:120`、`src/buddy/adapters/codex_home.py:30`、`src/buddy/adapters/codex_home.py:119`。
- **结果收集界限**：Worker stdout 接受最多 512 KiB，使用严格 decode_json；路由 stdout 和逐次 JSON 证据接受最多 256 KiB，要求防链接检查与普通文件，用普通 json.loads。前者无有效汇总时记 invalid-result，后者记 invalid-native-result；都要求汇总成功、控制进程零退出与双层停止才返回 ok，确认停止且汇总 cancelled 则返回 cancelled。Worker 还由负 returncode 生成 signal 名；路由 collect 不设 signal/artifacts，取 AdapterOutcome 默认值。审阅可捕获 raw 与高层事件的分别上限合计大于其汇总读取上限，这些限制不是同一数值。依据：`src/buddy/adapters/codex.py:116`、`src/buddy/adapters/codex.py:128`、`src/buddy/adapters/codex.py:282`、`src/buddy/adapters/codex.py:292`、`src/buddy/adapters/read_only.py:212`、`src/buddy/adapters/read_only.py:248`、`src/buddy/adapters/base.py:99`、`src/buddy/adapters/base.py:102`、`src/buddy/adapters/codex_runner.py:228`、`src/buddy/adapters/codex_runner.py:240`。
- **快速持久证据**：确认双层停止后，collect 依据启动时冻结的 `_NoToolEvidence`，尝试从私有调用目录的 call-1/call-2 复制成对 request.json/result.json；若没有成对来源则保存原始请求和汇总结果为证据根下的 call-1。本 Codex run_call 没有逐次写这些文件或按 captureEvidence 保存事件的实现，控制中的 evidenceRoot 也不是它的写入接口；因此这里不能声称已有两次纠正调用的逐次原生轨迹。留存失败改变状态为 evidence-retention-failed，并在 handle 保留身份与目录诊断。依据：`src/buddy/adapters/read_only.py:183`、`src/buddy/adapters/read_only.py:186`、`src/buddy/adapters/read_only.py:224`、`src/buddy/adapters/read_only.py:267`、`src/buddy/adapters/codex_no_tool.py:189`、`src/buddy/adapters/codex_no_tool.py:275`。

- **Worker 续接保存位置**：原生 CODEX_HOME 在按微任务定位的 nativeRoot/codex-home；额外绑定位于同一 nativeRoot 下，以 thread id 的 SHA-256 命名 JSON，通过临时文件和替换发布。绑定记 taskId/threadId/cwd/完整配置/codexHome/credentialSource，以及最近 native turn、attempt 与输入哈希；只有 checkpoint 证明 started、completed 且原生零退出、确认停止才保存并置 bindingSaved=true，即使最终结构化 outcome 失败也可能保存这个已完成原生历史。依据：`src/buddy/adapters/codex.py:83`、`src/buddy/adapters/codex_runner.py:66`、`src/buddy/adapters/codex_runner.py:70`、`src/buddy/adapters/codex_runner.py:621`。

## 11. 抽取时的观察

1. **公共执行载体已经存在**：第 1 节的三种外层入口都调用同一 runner，第 2、6 节的 App Server 启动、初始化、目录读取、interrupt 和进程组收尾已经集中在 `_run` 与 Connection/ProcessHandle；可直接作为公共部分的依据是已有共用调用链，无须把它描述为尚需另建的通道。依据：`src/buddy/adapters/codex_runner.py:309`、`src/buddy/adapters/codex_runner.py:409`、`src/buddy/adapters/codex_runner.py:578`、`src/buddy/adapters/codex_runner.py:592`、`src/buddy/adapters/codex_protocol.py:43`。
