# 控制台前端重建：执行计划

依据 [ADR-029](../decisions/029-console-frontend-foundation.md)。只动 `apps/console`、随包提交的构建产物和相应的参考文档，不改服务逻辑与契约。工作在单独的分支上进行，由 Claude Code Host 主持：设计由 Host 定稿，有边界的实现交给微任务。每一步结束时给用户看截图并验收，Host 自己的核对记在[记录](../acceptance/console-frontend.md)里。合入集成分支只在界面整体一致的两个节点进行，即 F1 结束与 F2 结束，这样日常的源码安装不会带上半新半旧的界面。

## 设计

ADR-029 第 8 条：界面重新设计，不以复刻为目标。静态稿在 [console-frontend/](console-frontend/README.md)，每页一份，用户确认后实现；任务页的方向已于 2026-10-11 得到用户认可；Buddy 页的目录在模型、Harness 两项做出来之后于同日重新设计了一次（按 harness 分节，设置就地展开，见下），四份稿得到用户认可；微任务详情的稿于同日得到认可；Buddy 页的角色分区与设置页的稿待确认。还没有出稿的：任务页的记录一项、窄屏、空状态与出错状态。

稿里的规则，实现时照此做，要偏离先问 Host：

- **颜色各有一个含义，取自标志。** 绿是正在进行的、当前的与选中的。橙是标志里连接两根立柱的那一块，表示有事等人接手：等 Host 决定或验收、没有保存的改动、快到上限的额度。墨色是记录，已经结束的历史一律用墨色。红只表示失败。唯一的例外是代码改动：增加的行与行数用绿，删去的用红；它们总是带着加号、减号出现，只用在改动的行数与差异里，不用来表示状态，在主题变量里有自己的名字。新的语义色先加进主题变量的明暗两套，不直接写色值。
- **形状先于文字。** 状态用一组固定的记号：实心圆是进行中，橙色菱形是等人接手，对勾是已验收，叉是失败，空心圆是还没有开始或不在场。同一个状态在列表、时间轴与详情里是同一个记号；一行只把一件事说一遍。
- **文字是名称、状态与数值，不是句子。** 名称用名词；状态用固定的词：进行中、等待 Host、等待验收、已验收、已完成、已结束、失败、排队；数值是数字加单位，两个数的关系写成 `3 / 4`。界面上不出现像句子的短语，例如"由谁路由""4 次里选出 3 次"。完整的句子只出现在空状态、出错与确认里。buddy 写成四元组 `harness / provider / model / effort`，放不下的地方写 `model / effort`。第四部分叫推理强度，它的每一级也叫一个推理强度，不另起名字；“档位”只指权限档位。
- **Buddy 页的目录按 harness 分节。** 一节是一个 harness：节头是它的标志、名字与提供方，右边是账户的摘要，写额度最紧的那个窗口的百分比与重置时间，按量计费的写余额；harness 不能工作时在名字旁写它记录的状态，例如未登录、额度用完与重试的时刻，这样的 harness 排在最后。点这段摘要，节头向下展开位置（路径、来源、检测、指定路径）、账户与额度三块：它们留在节头自己的白底上，三块之间用竖线隔开，底下一条较重的线收住，看得出是节头的一部分。节头左端的箭头只管收起与展开这一节的模型；没有任何 buddy 启用的 harness 默认收起，收起时写有几个模型、启用了几个 buddy。额度只在节头出现。按钮只写“检测”与“全部检测”，不加“重新”。
- **节里一行是一个模型。** 这里的模型指一个 harness 经一个提供方给出的一个模型。行上只写已经启用的推理强度，连同它实际生效的偏好，写成字（优先、固定、排除），不用颜色区分；名字前的绿点表示这个模型有 buddy 在用，没有启用任何 buddy 的模型名字用浅色；行尾是并发的占用与上限。待确认、新发现、不可用写在模型的名字旁。一件事只说一遍：harness 已经写了状态，它的模型就不再各写一遍不可用；记录下来的原因是这个词的说明，悬停与读屏时给出。界面上不说“家族”：通常的说法里模型家族指同一系列的几个模型，与这里的意思不同。两个筛选沿用原来的：只看已启用、显示不可用。
- **点模型，设置就地展开，不设右栏。** 展开的是从这一行垂下来的抽屉：底色下沉一级，左边的绿线连着被选中的那一行，与节头的展开看得出不是一回事。左边“模型”一块放默认偏好、并发、备注，并发属于模型；右边“Buddy”一块里，这个模型的推理强度排成一条刻度带，一格是一个 buddy，顺序是这个 harness 自己的顺序，启用的格子是白底加绿色的上沿，格子里写它生效的偏好。点一格，下面的面板只列这一个 buddy：完整的四段名字、启用、偏好的覆盖与理由、计入评价的次数；启用与偏好属于 buddy。刻度带与面板左右对齐，备注一栏的底边与面板的底边齐平。抽屉的右半边留给以后的评价。
- **窄屏用同一个结构。** 模型的行变成两行，刻度带排成三列，面板里的控件竖排；没有另一套版式，也没有“回到表”的按钮。
- **harness 的标志用图标包里的彩色原样。** 以依赖的方式引入静态图标包，只引用用到的文件；只有单色画法的那一个随文字颜色着色。不改图形，不把别人的标志用作本项目自己的标识。标志的颜色属于标志本身，不算进上面的颜色词表。出处与取舍见整合分支 `docs/research/` 里 2026-10-11 的两份记录。
- **Buddy 页的分区是并列的几个方面。** 现在是目录（上面的分节列表，也就是术语表里的模型目录加上用户在每个 buddy 上的选择）与角色（谁担任 Router，连同这个角色的设置与记录）；以后是评价与画像。谁担任什么角色只写在角色分区，目录里不重复。
- **微任务的详情按回合组织。** 它占用时间轴所在的区域，宏任务的头部不动；自己的头部写名称、状态、开始、历时与回合数，左端是回到时间轴的按钮。左边一栏是这个微任务在时间轴上的那一行竖过来：委派、路由、每个回合、Host 的每次决定、验收各是一步，步与步之间的线就是等待，画法与时间轴相同（细线是已经结束的等待，橙色虚线是还在等人接手），线旁写等待的种类与时长。回合的记号是方块，与时间轴上的执行条同色：墨色是已结束，绿是进行中，红是失败；路由是空心的方块，因为它也是一次执行，只是执行的是 Router；Host 的决定是菱形。选中一步，右边列出这一步自己的内容，从时间轴上的哪一段打开就选中哪一步。回合的右栏是这个回合的过程，按时间从上到下，这样宏任务的时间轴、微任务的步骤、回合的过程是同一条时间线的三级：Router 与 Worker 各有自己的一步，不放在同一个界面里（用户 2026-10-11 要求分开；没有做成右栏里的页签，因为左栏本来就是在各步之间切换的地方，路由在时间轴上也是自己的一段）。两者的右栏是同一种样子，顶上是一条浅底的横带：角色的标签（Router、Worker）、这个 buddy 的四元组、右端的数值，第二行是用量（进行中时是模型回合与工具调用的计数）与会话的编号。路由一步的带下面是 Router 的过程，末尾的结果写它选中的 buddy 与理由；候选的名单不列（用户 2026-10-11：知道是谁选的、为什么就够了，名单没有新的信息；它仍在决策记录里）。没有经过 Router 时没有路由这一步，Worker 的带右端写 Host 指定或唯一候选。回合一步是会话的内容（[ADR-024](../decisions/024-console-session-view.md)，用 AI Elements 的组件渲染），画成一条过程线：线上的每个节点是一件事，输入是菱形加一段浅底的引文，推理与工具调用各是一个带图标的小方块加一行（类别、对象、数值，点开看输入与输出），消息是一个小圆点加正文，最后的结果是一个实心方块。产物是末尾的一条横带。进行中时底部固定一行，写当前的阶段与最近上报，正在执行的那一步用绿色。这样一眼分得出谁的内容、哪些是动作、哪些是话。会话内容的读取接口做完之前，Worker 一块里只有结果，中间不放占位。担任角色的 buddy 用角色的名字称呼：这里是 Worker 与 Router。Host 的决定：请求的内容与决定的内容。委派：任务的原文、来源与标识、协助任务。验收：产物、整合，以及失败或取消时 Host 的结论。正常的情况不写，只写例外：停止已确认、正常完成不出现，停止未确认与别的终止原因才出现。是谁做的写在左边那一步上，右边不重复；右边的标题写这一步的状态、精确的起止时刻与历时。
- **用线和留白分区。** 容器是直角，用细线与一级底色区分，不用带圆角的盒子套盒子。只有控件有 4px 的圆角。
- **版式只有几种。** 顶栏用标志的墨色，明暗主题下相同。页面的头部放标题、分区页签与一行状态。设置类的内容是"左边名称、右边控件"的分节，节与节之间一条细线。成组的记录是列表或表格。
- **舒适。** 信息都在，但不密集：字号只有四档，正文与控件 14px，次要信息 12px，面板标题 16px，页面标题 18px，没有小于 12px 的字；数字、时刻与编号用等宽数字。控件高 32px，小的 28px。静态稿的 `base.css` 里有几处 13px 与 11px，实现时一律归到这四档。
- **看得清。** 文字与它的底色的对比不低于 4.5 比 1。为此最浅的一档文字比最初的稿深了一些（浅色 `#626D66`，深色 `#89928C`）；这一条由一项测试守着，它从 `tokens.css` 里读出每一种文字色与每一种底色来算；顶栏上的数目用浅橙底配深色字，因为顶栏在明暗两种主题下都是深色的。
- **没有常驻的说明句。** 名称要自己说得清；确实需要解释的，用提示组件在悬停与键盘聚焦时给出，同时写进可访问的名称或说明，不用浏览器自带的 `title`，不放问号按钮。一个暂时不能用的控件不做成禁用，这样它仍能得到焦点、说出原因，只是点了不起作用。一种情况例外：一项设置的作用在页面上看不出来、用户又未必知道它是做什么的，就在名称下面写一两句说明，说它做什么、什么时候该开。现在只有设置页的访问一节是这样（用户 2026-10-11 要求）。
- **组件与文字。** 浮层、对话框、选择、页签与滚动区一律用 `components/ui` 里的组件，它们保持 shadcn 生成的样子，只为配色与圆角做必要的改动。文字全部走文案：每个页面一个命名空间，中文在 `src/i18n/zh/`，英文在 `src/i18n/en/` 并用 `satisfies` 对齐键，术语取 `CONTEXT.md` 里成对的写法；日期、时间与数字用 `src/i18n/format.ts`。测试读中文。
- **每个页面有浏览器检查。** 用 `browser/preview.ts` 里的断言：各项在框内、互不重叠、文字不被裁掉、页面不横向滚动、页面没有报错。中文与英文、宽与窄都跑。

## 已定而尚未实现的功能放在哪里

界面的骨架按所有已接受的 ADR 来定，这样它们实现时只是往已有的位置里添东西，不必再改结构；它们各自的界面等黑板一侧做完再做，现在不提前画。

| 已定的功能 | 出处 | 在界面里的位置 | 对现在的稿的要求 |
| --- | --- | --- | --- |
| Router 列表的增删与排序，每项的状态 | ADR-021 第 2、16 条 | Buddy 页的角色分区，Router 一块 | 位置已有 |
| 维护间隔、探索、立即维护，路由、维护、画像三层各自的记录与用量 | ADR-021 第 3、7、8 条 | 角色分区的 Router 一块：设置在上，三种记录在下 | "记录"届时分成三种 |
| 评价按领域与任务类型组织 | ADR-021 第 10 条 | 模型展开的抽屉里，Buddy 面板之下，显示选中的那个 buddy：行是领域，列是七种任务类型（用户 2026-10-11 的设想）；要不要另设整页的分区届时再定 | 抽屉的右半边留着 |
| 模型画像的状态、构建与内容 | ADR-021 第 12、13 条 | Buddy 页新增画像分区，整页宽 | 届时加分区，右边一栏不放 |
| 模型待确认 | ADR-027 | 表里模型名字旁的状态 | 位置已有 |
| 账户状态、credits、目录的读取时间 | ADR-027，ADR-021 第 22 条 | 目录里节头展开的“账户”与“额度”两块 | 位置已有 |
| Lead 列表 | ADR-026 第 3 条 | 角色分区里 Router 之后的一块，做法同 Router 列表 | 届时加一块 |
| Lead 的泳道 | ADR-026 第 10 条 | 时间轴的行可以成组：Lead 一行，它名下的微任务排在它下面 | 时间轴的行要能分组 |
| 换手 | `CONTEXT.md` | 时间轴上两个回合之间的记号；行名下写当前的 buddy；微任务详情的左栏里是两个回合之间的一步 | 记号词表加一个 |
| 预期时长、已超时、可能卡住、终止的原因 | ADR-022 | 执行条上的记号；微任务详情里回合的标题与底部的那一行 | 记号词表加两个 |
| 路由的依据：领域与类型、证据的层级、探索、唯一候选、Host 指定、由谁选的 | ADR-021 第 6、20 条 | 微任务详情左栏里"路由"一步的右栏；时间轴上路由是一种片段 | 稿里已有；领域与类型、证据的层级、探索届时写在带的第二行 |
| 结束之后的回收结果，没有结论的提示 | ADR-021 展示线 U5 | 微任务详情的左栏在验收之后加一步"回收" | 届时加一步 |
| 会话视图 | ADR-024 | 微任务详情里回合的右栏：过程的主体就是会话的内容 | 稿里已有；读取接口做完之前过程里只有路由、结果与产物 |
| 急停 | ADR-021 第 21 条 | 宏任务头部的"更多"菜单 | 头部已有菜单 |
| 删除宏任务 | ADR-028 | 同一个菜单，带确认 | 同上 |

由此得出、现在就要守住的四点：Buddy 页的分区是并列的几个方面，目录里的设置在所属的那一行下面就地展开，不设右栏；时间轴的行不与某一个 buddy 绑死，并且可以成组；宏任务的头部有一个菜单；微任务的详情是一个按回合组织的完整视图，不是一条摘要。

## 现有功能的去向

重新设计不等于减功能。每一页的稿定稿之前，先从这一页现有的组件与测试里列出全部功能与入口，逐项写明去向：留在哪里、并到哪里，或者删除及其原因。

Buddy 页（依据它的 14 个测试文件，约 150 项行为）：

| 现有的功能 | 去向 |
| --- | --- |
| 搜索；只看已启用；显示不可用（默认隐藏、分页读取、浏览器记住两个筛选） | 目录的工具条，与分页并在同一条带里 |
| 折叠没有启用 buddy 的 Harness，并显示启用数与总数 | 节头左端的箭头；收起的节头写有几个模型、启用了几个 buddy |
| 不可用的原因：Harness 一组上的一句、条目上的一句 | 一处说一遍：harness 不能工作时在节头它的名字旁写状态，否则在模型名字旁写不可用；记录的原因是这个词的说明，展开模型之后也写在“模型”一块的右端。黑板记下的几种固定原因写成话，别的照原样显示 |
| 发现模型，新发现的做标记 | 目录的工具条；标记在模型的名字旁 |
| 更新记录（已发布的版本） | 删除。它只列出版本号、来源、时间与条数，看不到改了什么（用户 2026-10-11 指出）。Router 维护的运行记录以后在角色分区的记录里；命令行的 `evaluation-history` 不受影响 |
| 模型待确认及起始时间 | 模型的名字旁；展开之后在“模型”一块的右端 |
| 启用开关；已退役的只能停用、不能再启用 | 展开模型之后，Buddy 面板里的开关；刻度带的格子与收起的行显示状态 |
| 偏好：模型的默认与单个推理强度的覆盖（跟随、无、优先、固定、排除），带理由；每种偏好有记号，不只靠颜色 | 展开模型之后：默认在“模型”一块，覆盖与理由在 Buddy 面板；刻度带的格子与收起的行上写这个 buddy 实际生效的偏好，写成字 |
| 各项设置旁的"未保存" | 改过而没有保存的设置名旁有一个橙色圆点，刻度带上对应的格子与收起的那一行也有 |
| 并发上限与当前占用 | 模型行的行尾；展开之后的“模型”一块 |
| 备注 | 展开之后的“模型”一块 |
| 评价（只读）：每个推理强度的评价卡片、证据、发布者，以及配置 ID、上下文、能力、目录来源、目录状态与可用性 | Buddy 面板里只写一个数，叫"计入评价"：Host 验收或打回过、并且记为证据的执行次数，取消的、没有结论的与环境故障不算。快照里每个 buddy 只有这一个数，稿里画的"执行 / 验收"两个数没有来源；它不是微任务的数目。卡片、证据与发布者以后进模型抽屉里的评价；上下文与能力以后进画像分区；目录状态与可用性就是模型一块右端的状态；配置 ID 与目录来源不再显示。在评价分区做出来之前，控制台里看不到评价卡片 |
| 设为 Router，连同不能设的原因 | 角色分区 Router 列表的"添加" |
| 当前担任 Router 的 buddy、默认模式、审阅预算、重试间隔、路由健康与失败明细 | 角色分区的 Router 一块 |
| Harness 的检测结果、试过的位置与处置办法、手动路径、本地资格、单个重新检测 | 节头展开的“位置”一块，按钮叫“检测” |

## 步骤

### F0 打底（已完成）

Tailwind 与 shadcn 接入，九个基础组件与标签组件就位；顶栏、连接提示与启动页换到新基础上；i18n 的骨架与外壳的两份文案；Playwright 的浏览器检查。做了什么、核对了什么、新增的包与许可、产物大小与没有核对的部分，见[记录](../acceptance/console-frontend.md)。

新旧并存期间只有一条规矩：迁过的页面不再引用旧样式表里的类，旧样式表只减不增。Tailwind 的基础样式会让还没有迁的页面出现细小的变化，这在分支之内可以接受，不为它给旧样式表打补丁。

### F1 按稿实现各页

先由 Host 把打底的成果改到新的设计上。主题变量、圆角、顶栏、标签与按钮已于 2026-10-11 改完（[记录](../acceptance/console-frontend.md)）：`tokens.css` 就是稿里的那一套颜色，名字也用稿里的；旧样式表还在读的名字收在 `legacy-tokens.css` 里指向同一套颜色，所以还没有迁的页面已经换了配色，这个文件随旧样式表在 F3 删除。状态记号与页面头部、分节这几种版式，随第一个用到它们的页面做。然后按设置、Buddy（目录、角色）、任务的列表与详情的顺序实现，不含时间轴。每一页做五件事：按稿实现；文字写进两份文案，并按 `CONTEXT.md` 完成改名；重写这一页的组件测试，行为与安全方面的断言一项不少；写这一页的浏览器检查；删掉这一页用过的旧代码、旧样式与它的稿。

打底时发现、要在这一步处理的：

- `tests/probes/` 里三个旧的浏览器脚本（`console_layout_check.mjs`、`console_interaction_check.mjs`、`console_routing_check.mjs`）靠旧的类名找元素。哪一页迁完，就把它们检查的那部分写成新的浏览器检查，并删掉脚本里对应的部分；三页都迁完时脚本删除。
- 数据层（`api.ts` 等）里的中文报错不属于某一个页面，随第一个用到它们的页面抽进公共的命名空间。
- 任务页的四个状态页签各写一个数目，而列表的接口一次只给当前筛选的总数。实现任务页时让列表的回复一并给出四个数，这是读取投影上的一处小改动，随那一页一起验收。
- 英文有单复数。第一次遇到带数量的句子时定下写法；倾向于写成"名称：数字"，免得复数的键让两份文案的键对不上。

时间轴滚动区的滚动条闪动在这一步随滚动区的替换一并解决。它的成因是滚动区两个方向都按需出现滚动条、定制的滚动条又占用布局空间，时间轴按可见宽度算自己的宽度，于是每次更新都互相挤占；这是从代码里读出来的，没有在浏览器里复现过，替换之后要在真实的浏览器里确认。

### Buddy 页的实现划分

这一页是 F1 里最大的一页：呈现的组件约 1,700 行（`BuddyConfig`、`FamilyDetail`、`HarnessStatus`、`HarnessAccount`、`RoutingStatusBar`、`EvaluationHistory`、`QuotaRecovery` 等），底下是约 2,200 行的数据与编辑层（`use-editor`、`draft`、`policy`、`use-profile-history`）。数据与编辑层管的是草稿、版本冲突、保存与权限，属于行为与安全，原样保留，连同它们的测试；重做的只是呈现。

新的代码放在 `src/buddies/` 之下，按 ADR-029 第 9 条是一个自成一体的视图：一个入口，数据经注入的客户端与编辑器取得，地址经回调交给外层，文字在 `buddies` 命名空间里。

| --- | --- | --- | --- |

B3 与 B4 于 2026-10-11 验收（[记录](../acceptance/console-frontend.md)）。两份产出原样各成一个提交，Host 的修正另成提交：窄窗口里动作的结果行、写在代码里的标点、Router 一行在窄窗口里的排法、各 Router 记录的宽度，以及共用的说明、对话框与时间格式。两个视图各有了自己的浏览器检查。
| B5 收口 | 删掉这一页的旧组件、旧样式与静态稿；浏览器检查；看像素；记录 | Host | B1 至 B4 |

B0 的第一部分于 2026-10-11 完成（[记录](../acceptance/console-frontend.md)）：页面自己的导航、三个视图的地址、提醒的记号，以及 `buddies` 命名空间。B0 余下的部分与 B1、B2 于同日一起完成：状态记号、未保存的记号、分段选择、开关与说明的包装成了共用组件，草稿的提示与保存条换到了新样式，模型一项照稿整页做了出来。Harness 一项与角色里面还是原来的内容。

模型一项（B1 与 B2）由 Host 自己做，B0 余下的共用版式随它一起落地：它是第一张照稿做出来的整页，表、小块与右栏的做法由它定下来，后面的微任务照着用。B3 与 B4 在它之后交给微任务，两者写的文件互不相同，可以并行。原先的安排是 B1 也交给微任务、与 B3、B4 并行；2026-10-11 用户看到"新导航套着旧内容"的截图，指出与方向稿完全不一致，Host 因此改了顺序，并且不再把新旧混搭的中间状态当作进展拿给用户看。每个微任务的任务书里列出它要接过来的旧测试文件，交付时给出旧断言到新断言的对照，行为与安全方面的断言一项不少；只跑受它影响的组件测试与类型检查，浏览器检查由 Host 在整合后跑。

### 长等待的画法（已定）

用户于 2026-10-11 在三份静态稿里选了方案 A，否决了没有时间刻度的方案 C（看不出并发），并要求 A 画得更整齐；同日确认了整理后的稿。它是 F2 的依据，实现之后写进 `console.md`。

- **活动时段与断口。** 时间分成两种时段。有片段开始或结束的是活动时段，所有活动时段按同一个比例画，每分钟的宽度相同。没有任何片段开始或结束的时段压成断口，断口一律等宽，不随缩放变化。只有按比例画出来比断口更宽的时段才压缩，所以没有"多少分钟以上才折叠"这样的阈值。时间范围不完整或时钟不可靠时不压缩，这一条沿用现在的规则。
- **时间轴。** 每个活动时段的起点写时刻，段内有刻度。断口处时间轴断开并画断裂记号，断口下方写被压掉的时长。最右是"现在"线，写当前时刻。
- **行。** 一个微任务一行，行与行之间有细线，左边的名称列固定不动。
- **片段只有三种画法。** 执行是实心条，条内写时长，必要时写状态；已经结束的等待是细线；还在等的是需要注意的颜色的虚线，旁边写在等什么与已经等了多久。等待的线穿过断口时不中断。失败的执行用失败色。
- **点状的事件**（验收、打回、取消等）是线上的记号，旁边写名称。
- **图例**只列这三种画法。

## 微任务的划分

- 一个微任务只做一件可以独立验收的事。写入范围按页面或模块划分，不并行修改同一个文件。
- 机械的工作（抽取文案、替换类名）与需要设计判断的工作（组件的形态、时间轴）分开。
- 主题变量、组件的形态与时间轴的设计由 Host 定稿之后再交给微任务实现。
- 不保留旧样式的兼容层，不留两套写法。被取代的代码与测试在同一次改动里删除。
- 要联网的事（装包、取 shadcn 的组件）由 Host 先做好，微任务不联网。
