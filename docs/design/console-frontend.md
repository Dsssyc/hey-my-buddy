# 控制台前端重建：执行计划

依据 [ADR-029](../decisions/029-console-frontend-foundation.md)。只动 `apps/console`、随包提交的构建产物和相应的参考文档，不改服务逻辑与契约。工作在单独的分支上进行，由 Claude Code Host 主持：设计由 Host 定稿，有边界的实现交给微任务。每一步结束时给用户看截图，验收之后合入集成分支。

## 步骤

### F0 打底

- 接入 Tailwind 与 shadcn。把 `tokens.css` 里的语义变量迁成主题变量，明暗两套。
- 外壳就位：顶栏与三个页面的框架。基础组件就位：按钮、输入、选择、复选、对话框、浮层、提示、页签、滚动区。
- i18n 的骨架：react-i18next，中文与英文两份文案，语言跟随浏览器。外壳的文字先迁进去。
- Playwright 就位：能在合成看板上启动私有预览，并跑通一条断言。
- 记录：新增的包与各自的许可，构建产物大小的前后对比，内容安全策略的核对。

新旧并存期间只有一条规矩：迁过的页面不再引用旧样式表里的类，旧样式表只减不增。

### F1 逐页迁移

顺序是设置、Buddy 配置（模型、Router、Harness）、委派记录的列表与详情，不含时间轴。每一页做四件事：换成新的组件；文字抽进两份文案，并按 `CONTEXT.md` 完成改名；更新这一页的组件测试；删掉这一页用过的旧样式。

时间轴滚动区的滚动条闪动在这一步随滚动区的替换一并解决。它的成因是滚动区两个方向都按需出现滚动条、定制的滚动条又占用布局空间，时间轴按可见宽度算自己的宽度，于是每次更新都互相挤占；这是从代码里读出来的，没有在浏览器里复现过，替换之后要在真实的浏览器里确认。

### 长等待的画法

与 F0、F1 并行。Host 出静态稿，用户选定，然后写进本计划与 `console.md`，作为 F2 的依据。

### F2 重画时间轴

按下面的顺序，每一项可以单独验收：

1. 比例尺：纯函数，输入是片段与空闲、等待的区间，输出是时间与像素的互换和刻度。
2. 绘制：片段、标记、现在线与读数线，用 SVG。
3. 文字：先测量，再决定显示哪一种写法。
4. 键盘与读屏：每个片段可以聚焦，有说明文字。
5. 接入：浮层、检查器、缩放与滚动。

旧的排布、比例换算和守几何的测试在这一步删除。新增比例尺的单元测试与浏览器里的断言。

### F3 收尾

删除旧样式表和不再使用的代码。更新 `console.md`、`objectives.md` 与两份 README 里涉及界面的部分。在 `AGENTS.md` 的验证一节写上浏览器检查的命令。

## 微任务的划分

- 一个微任务只做一件可以独立验收的事。写入范围按页面或模块划分，不并行修改同一个文件。
- 机械的工作（抽取文案、替换类名）与需要设计判断的工作（组件的形态、时间轴）分开。
- 主题变量、组件的形态与时间轴的设计由 Host 定稿之后再交给微任务实现。
- 不保留旧样式的兼容层，不留两套写法。被取代的代码与测试在同一次改动里删除。

## 验证

- 每个微任务跑受它影响的组件测试。
- 每一步整合之后：前端全量；重新构建，产物与提交的逐字节一致；浏览器里的断言；Host 在私有预览里看像素，明暗与宽窄都看；仓库卫生测试与读取产物的 Python 测试。
- 没有 Python 改动时不跑 Python 的完整检查。
