# 控制台前端重建：执行计划

依据 [ADR-029](../decisions/029-console-frontend-foundation.md)。只动 `apps/console`、随包提交的构建产物和相应的参考文档，不改服务逻辑与契约。工作在单独的分支上进行，由 Claude Code Host 主持：设计由 Host 定稿，有边界的实现交给微任务。每一步结束时给用户看截图并验收，Host 自己的核对记在[记录](../acceptance/console-frontend.md)里。合入集成分支只在界面整体一致的两个节点进行，即 F1 结束与 F2 结束，这样日常的源码安装不会带上半新半旧的界面。

## 设计基准

打底一步定下的写法。迁移页面的微任务照此做，要偏离时先问 Host。

- **字号只有四档。** 正文与控件 14px（`text-sm`），次要信息 12px（`text-xs`），面板标题 16px，页面标题 18px。不出现小于 12px 的字。数字、时刻与编号用等宽数字（`tabular-nums`）。
- **间距、高度与圆角。** 用 Tailwind 的刻度，不写任意像素值。控件高 36px，工具栏与密集处用小号 32px。控件与输入框的圆角 6px（`rounded-md`），面板 8px（`rounded-lg`），标签 4px（`rounded-sm`）。
- **颜色只用语义类**，例如 `bg-card`、`text-muted-foreground`、`border-border`、`text-destructive`、`bg-warning-wash`。不直接写色值，也不用 Tailwind 自带的调色板。要新的语义色时，先加进 `tokens.css` 的明暗两套，再在 `index.css` 里映射。
- **状态用标签组件的四种色调**：普通、良好、需要注意、失败。颜色不是唯一的信号。
- **解释放在提示里。** 一个标记或数字是什么意思，用提示组件在悬停与键盘聚焦时给出，同时写进可访问名称，不用浏览器自带的 `title`。浮层、对话框、选择、页签与滚动区一律用 `components/ui` 里的组件，不自己写定位与焦点管理。
- **`components/ui` 保持 shadcn 生成的样子**，只为配色做必要的改动，便于以后对照上游。
- **文字全部走文案。** 每个页面一个命名空间，中文在 `src/i18n/zh/`，英文在 `src/i18n/en/`，英文用 `satisfies` 与中文对齐键。术语取 `CONTEXT.md` 里成对的写法。日期、时间与数字用 `src/i18n/format.ts` 里的格式化，组件里不再写 `toLocaleString`。测试读中文。
- **每个页面有浏览器检查。** 用 `browser/preview.ts` 里的断言：各项在框内、互不重叠、文字不被裁掉、页面不横向滚动、页面没有报错。中文与英文、宽与窄都跑。

## 步骤

### F0 打底（已完成）

Tailwind 与 shadcn 接入，九个基础组件与标签组件就位；顶栏、连接提示与启动页换到新基础上；i18n 的骨架与外壳的两份文案；Playwright 的浏览器检查。做了什么、核对了什么、新增的包与许可、产物大小与没有核对的部分，见[记录](../acceptance/console-frontend.md)。

新旧并存期间只有一条规矩：迁过的页面不再引用旧样式表里的类，旧样式表只减不增。Tailwind 的基础样式会让还没有迁的页面出现细小的变化，这在分支之内可以接受，不为它给旧样式表打补丁。

### F1 逐页迁移

顺序是设置、Buddy 配置（模型、Router、Harness）、委派记录的列表与详情，不含时间轴。每一页做五件事：换成新的组件；文字抽进两份文案，并按 `CONTEXT.md` 完成改名；更新这一页的组件测试；写这一页的浏览器检查；删掉这一页用过的旧样式。

打底时发现、要在这一步处理的：

- 合成预览不提供 `/api/runtime-version`，设置页在预览里读不到版本，浏览器控制台有一条 404。设置页开始之前先给预览补上这个接口，否则它的浏览器检查会因为页面报错而失败。
- `tests/probes/` 里三个旧的浏览器脚本（`console_layout_check.mjs`、`console_interaction_check.mjs`、`console_routing_check.mjs`）靠旧的类名找元素。哪一页迁完，就把它们检查的那部分写成新的浏览器检查，并删掉脚本里对应的部分；三页都迁完时脚本删除。
- 数据层（`api.ts` 等）里的中文报错不属于某一个页面，随第一个用到它们的页面抽进公共的命名空间。
- 英文有单复数。第一次遇到带数量的句子时定下写法；倾向于写成"名称：数字"，免得复数的键让两份文案的键对不上。

时间轴滚动区的滚动条闪动在这一步随滚动区的替换一并解决。它的成因是滚动区两个方向都按需出现滚动条、定制的滚动条又占用布局空间，时间轴按可见宽度算自己的宽度，于是每次更新都互相挤占；这是从代码里读出来的，没有在浏览器里复现过，替换之后要在真实的浏览器里确认。

### 长等待的画法

与 F0、F1 并行。Host 出静态稿，用户选定，然后写进本计划与 `console.md`，作为 F2 的依据。2026-10-11 用户在三个方案里选了 A（把没有任何开始或结束的时间段压成等宽的断口），否决了 C（看不出并发），并要求 A 画得更整齐。Host 已给出整理后的稿，等用户确认。

### F2 重画时间轴

按下面的顺序，每一项可以单独验收：

1. 比例尺：纯函数，输入是片段与空闲、等待的区间，输出是时间与像素的互换和刻度。
2. 绘制：片段、标记、现在线与读数线，用 SVG。
3. 文字：先测量，再决定显示哪一种写法。
4. 键盘与读屏：每个片段可以聚焦，有说明文字。
5. 接入：浮层、检查器、缩放与滚动。

旧的排布、比例换算和守几何的测试在这一步删除。新增比例尺的单元测试与浏览器里的断言。

### F3 收尾

删除旧样式表和不再使用的代码。更新 `console.md`、`objectives.md` 与两份 README 里涉及界面的部分。

## 等用户决定

- **页签的名字。** 打底按 Host 的建议写成了 `任务`、`伙伴`、`设置`（`Tasks`、`Buddies`、`Settings`）。`伙伴` 取自术语表；`任务` 不是术语，这里用作宏任务与微任务的总称。
- **网址。** Host 建议让网址跟着名字走：`#buddy` 改为 `#buddies`，`#system` 改为 `#settings`，并删掉旧书签 `#models`、`#settings` 到 Buddy 配置的转向。保留转向是用户当初的决定，所以等用户发话；按 0.x 的规则它属于应当删除的兼容。

## 微任务的划分

- 一个微任务只做一件可以独立验收的事。写入范围按页面或模块划分，不并行修改同一个文件。
- 机械的工作（抽取文案、替换类名）与需要设计判断的工作（组件的形态、时间轴）分开。
- 主题变量、组件的形态与时间轴的设计由 Host 定稿之后再交给微任务实现。
- 不保留旧样式的兼容层，不留两套写法。被取代的代码与测试在同一次改动里删除。
- 要联网的事（装包、取 shadcn 的组件）由 Host 先做好，微任务不联网。

## 验证

- 每个微任务跑受它影响的组件测试。
- 每一步整合之后：前端全量；重新构建，产物与提交的逐字节一致；浏览器检查；Host 看像素，中英文、明暗与宽窄都看；仓库卫生测试。
- 没有 Python 改动时不跑 Python 的完整检查。
- 浏览器检查要绑定一个本机端口，并需要 Playwright 的无头 Chromium。Linux 上跑中文的几何检查之前要先装中文字体。
