# 控制台前端重建：执行计划

依据 [ADR-029](../decisions/029-console-frontend-foundation.md)。只动 `apps/console`、随包提交的构建产物和相应的参考文档，不改服务逻辑与契约。工作在单独的分支上进行，由 Claude Code Host 主持：设计由 Host 定稿，有边界的实现交给微任务。每一步结束时给用户看截图并验收，Host 自己的核对记在[记录](../acceptance/console-frontend.md)里。合入集成分支只在界面整体一致的两个节点进行，即 F1 结束与 F2 结束，这样日常的源码安装不会带上半新半旧的界面。

## 设计

ADR-029 第 8 条：界面重新设计，不以复刻为目标。静态稿在 [console-frontend/](console-frontend/README.md)，每页一份，用户确认后实现；任务页的方向已于 2026-10-11 得到用户认可；伙伴页的目录与角色两个分区、设置页的稿待确认。还没有出稿的：微任务的详情（按回合组织，见下面的对照）、窄屏、空状态与出错状态。

稿里的规则，实现时照此做，要偏离先问 Host：

- **颜色各有一个含义，取自标志。** 绿是正在进行的、当前的与选中的。橙是标志里连接两根立柱的那一块，表示有事等人接手：等 Host 决定或验收、没有保存的改动、快到上限的额度。墨色是记录，已经结束的历史一律用墨色。红只表示失败。新的语义色先加进主题变量的明暗两套，不直接写色值。
- **形状先于文字。** 状态用一组固定的记号：实心圆是进行中，橙色菱形是等人接手，对勾是已验收，叉是失败，空心圆是还没有开始或不在场。同一个状态在列表、时间轴与详情里是同一个记号；一行只把一件事说一遍。
- **文字是名称、状态与数值，不是句子。** 名称用名词；状态用固定的词：进行中、等待 Host、等待验收、已验收、已完成、已结束、失败、排队；数值是数字加单位，两个数的关系写成 `3 / 4`。界面上不出现像句子的短语，例如"由谁路由""4 次里选出 3 次"。完整的句子只出现在空状态、出错与确认里。伙伴写成四元组 `harness / provider / model / effort`，放不下的地方写 `model / effort`。
- **伙伴页的目录是一张表，一行是一个模型。** 这里的模型指一个 Harness 经一个提供方给出的一个模型，占前三列：Harness、提供方、模型；第四列是它的各个档位，每个档位是一个伙伴，画成一个小块，启用与否一眼可见。四列之间用斜线隔开，合起来就是伙伴的四个部分，这样看得出伙伴不等于模型。与上一行相同的 Harness 与提供方用浅色。界面上不说"家族"：通常的说法里模型家族指同一系列的几个模型，与这里的意思不同。一个事实只出现一次，并挂在它所属的那一层：额度与登录状态写在 Harness 的名字旁，并发属于模型，启用与偏好属于伙伴。表里不设偏好一列：一个伙伴实际生效的偏好写在它的小块上。右边一栏只列所选之物自己的设置：选中一行时是档位（各档位的开关、偏好与次数）与模型（默认偏好、并发、备注）；选中一个 Harness 时是这个 Harness 的事实与操作，所以"重新检测"只在那里出现。右边这一栏只放小的设置，放不下的内容各有自己的整页分区。两个筛选沿用原来的：只看已启用、显示不可用。Harness 可以折叠：一组第一行上的三角是把手，收起之后这一组变成一行，写有几个模型、几个档位；没有任何伙伴启用的 Harness 默认收起，这一条沿用原来的做法。不另设表头行，也不做按列的筛选。
- **伙伴页的分区是并列的几个方面。** 现在是目录（上面这张表，也就是术语表里的模型目录加上用户在每个伙伴上的选择）与角色（谁担任 Router，连同这个角色的设置与记录）；以后是评价与画像。谁担任什么角色只写在角色分区，目录里不重复。
- **用线和留白分区。** 容器是直角，用细线与一级底色区分，不用带圆角的盒子套盒子。只有控件有 4px 的圆角。
- **版式只有几种。** 顶栏用标志的墨色，明暗主题下相同。页面的头部放标题、分区页签与一行状态。设置类的内容是"左边名称、右边控件"的分节，节与节之间一条细线。成组的记录是列表或表格。
- **舒适。** 信息都在，但不密集：字号只有四档，正文与控件 14px，次要信息 12px，面板标题 16px，页面标题 18px，没有小于 12px 的字；数字、时刻与编号用等宽数字。
- **没有常驻的说明句。** 名称要自己说得清；确实需要解释的，用提示组件在悬停与键盘聚焦时给出，同时写进可访问名称，不用浏览器自带的 `title`，不放问号按钮。
- **组件与文字。** 浮层、对话框、选择、页签与滚动区一律用 `components/ui` 里的组件，它们保持 shadcn 生成的样子，只为配色与圆角做必要的改动。文字全部走文案：每个页面一个命名空间，中文在 `src/i18n/zh/`，英文在 `src/i18n/en/` 并用 `satisfies` 对齐键，术语取 `CONTEXT.md` 里成对的写法；日期、时间与数字用 `src/i18n/format.ts`。测试读中文。
- **每个页面有浏览器检查。** 用 `browser/preview.ts` 里的断言：各项在框内、互不重叠、文字不被裁掉、页面不横向滚动、页面没有报错。中文与英文、宽与窄都跑。

## 已定而尚未实现的功能放在哪里

界面的骨架按所有已接受的 ADR 来定，这样它们实现时只是往已有的位置里添东西，不必再改结构；它们各自的界面等黑板一侧做完再做，现在不提前画。

| 已定的功能 | 出处 | 在界面里的位置 | 对现在的稿的要求 |
| --- | --- | --- | --- |
| Router 列表的增删与排序，每项的状态 | ADR-021 第 2、16 条 | 伙伴页的角色分区，Router 一块 | 位置已有 |
| 维护间隔、探索、立即维护，路由、维护、画像三层各自的记录与用量 | ADR-021 第 3、7、8 条 | 角色分区的 Router 一块：设置在上，三种记录在下 | "记录"届时分成三种 |
| 评价按领域与任务类型组织 | ADR-021 第 10 条 | 伙伴页新增评价分区，整页宽：行是领域，列是七种任务类型 | 届时加分区，右边一栏不放 |
| 模型画像的状态、构建与内容 | ADR-021 第 12、13 条 | 伙伴页新增画像分区，整页宽 | 届时加分区，右边一栏不放 |
| 模型待确认 | ADR-027 | 表里模型名字旁的状态 | 位置已有 |
| 账户状态、credits、目录的读取时间 | ADR-027，ADR-021 第 22 条 | 选中 Harness 时的右栏 | 位置已有 |
| Lead 列表 | ADR-026 第 3 条 | 角色分区里 Router 之后的一块，做法同 Router 列表 | 届时加一块 |
| Lead 的泳道 | ADR-026 第 10 条 | 时间轴的行可以成组：Lead 一行，它名下的微任务排在它下面 | 时间轴的行要能分组 |
| 换手 | `CONTEXT.md` | 时间轴上两个回合之间的记号；行名下写当前的伙伴 | 记号词表加一个 |
| 预期时长、已超时、可能卡住、终止的原因 | ADR-022 | 执行条上的记号；微任务的详情 | 记号词表加两个 |

| 急停 | ADR-021 第 21 条 | 宏任务头部的"更多"菜单 | 头部已有菜单 |
| 删除宏任务 | ADR-028 | 同一个菜单，带确认 | 同上 |

由此得出、现在就要守住的四点：伙伴页的分区是并列的几个方面，右边一栏只放小的设置；时间轴的行不与某一个伙伴绑死，并且可以成组；宏任务的头部有一个菜单；微任务的详情是一个按回合组织的完整视图，不是一条摘要。

## 现有功能的去向

重新设计不等于减功能。每一页的稿定稿之前，先从这一页现有的组件与测试里列出全部功能与入口，逐项写明去向：留在哪里、并到哪里，或者删除及其原因。设置页与任务页的这张表在各自实现之前补上。

伙伴页（依据它的 14 个测试文件，约 150 项行为）：

| 现有的功能 | 去向 |
| --- | --- |
| 搜索；只看已启用；显示不可用（默认隐藏、分页读取、浏览器记住两个筛选） | 目录的工具栏 |
| 折叠没有启用伙伴的 Harness，并显示启用数与总数 | 表里：Harness 可以折叠，收起的一行写数目 |
| 发现模型，新发现的做标记 | 目录的工具栏；标记在表里模型的名字旁 |
| 更新记录（已发布的版本） | 删除。它只列出版本号、来源、时间与条数，看不到改了什么（用户 2026-10-11 指出）。Router 维护的运行记录以后在角色分区的记录里；命令行的 `evaluation-history` 不受影响 |
| 模型待确认及起始时间 | 表里模型的名字旁；选中这一行时右栏的模型一块 |
| 启用开关；已退役的只能停用、不能再启用 | 右栏的档位一块；表里的小块显示状态 |
| 偏好：模型的默认与单个档位的覆盖（跟随、无、优先、固定、排除），带理由；每种偏好有记号，不只靠颜色 | 右栏：默认在模型一块，覆盖与理由在档位一块；表里每个小块上写这个伙伴实际生效的偏好 |
| 并发上限与当前占用 | 表里的并发一列；右栏的模型一块 |
| 备注 | 右栏的模型一块 |
| 评价（只读） | 右栏的档位一块写执行与验收的次数，以后进评价分区 |
| 设为 Router，连同不能设的原因 | 角色分区 Router 列表的"添加" |
| 当前担任 Router 的伙伴、默认模式、审阅预算、重试间隔、路由健康与失败明细 | 角色分区的 Router 一块 |
| Harness 的检测结果、试过的位置与处置办法、手动路径、本地资格、单个重新检测 | 选中这个 Harness 时的右栏 |
| 全部重新检测 | 目录的工具栏 |
| Harness 的账户：换来源、独立密钥、OAuth 登录与取消、移除 | 选中这个 Harness 时右栏的"账户"，在对话框里操作 |
| 额度：接近上限的提醒、来源、窗口与重置时间，过期与未知的观测，额度恢复 | 百分比只在表里 Harness 的名字旁出现；其余在选中这个 Harness 时的右栏 |

| 直达某个伙伴、某个 Harness 与 Router 的地址 | 保留，地址随新的结构重新定 |
| 草稿、底部的保存条、版本冲突的处理 | 保留 |

## 步骤

### F0 打底（已完成）

Tailwind 与 shadcn 接入，九个基础组件与标签组件就位；顶栏、连接提示与启动页换到新基础上；i18n 的骨架与外壳的两份文案；Playwright 的浏览器检查。做了什么、核对了什么、新增的包与许可、产物大小与没有核对的部分，见[记录](../acceptance/console-frontend.md)。

新旧并存期间只有一条规矩：迁过的页面不再引用旧样式表里的类，旧样式表只减不增。Tailwind 的基础样式会让还没有迁的页面出现细小的变化，这在分支之内可以接受，不为它给旧样式表打补丁。

### F1 按稿实现各页

先由 Host 把打底的成果改到新的设计上：主题变量换成稿里的颜色与圆角，顶栏改成稿里的样子，补上状态记号与页面头部、分节这几种版式。然后按设置、伙伴（模型、Router、Harness）、任务的列表与详情的顺序实现，不含时间轴。每一页做五件事：按稿实现；文字写进两份文案，并按 `CONTEXT.md` 完成改名；重写这一页的组件测试，行为与安全方面的断言一项不少；写这一页的浏览器检查；删掉这一页用过的旧代码、旧样式与它的稿。

打底时发现、要在这一步处理的：

- 合成预览不提供 `/api/runtime-version`，设置页在预览里读不到版本，浏览器控制台有一条 404。设置页开始之前先给预览补上这个接口，否则它的浏览器检查会因为页面报错而失败。
- `tests/probes/` 里三个旧的浏览器脚本（`console_layout_check.mjs`、`console_interaction_check.mjs`、`console_routing_check.mjs`）靠旧的类名找元素。哪一页迁完，就把它们检查的那部分写成新的浏览器检查，并删掉脚本里对应的部分；三页都迁完时脚本删除。
- 数据层（`api.ts` 等）里的中文报错不属于某一个页面，随第一个用到它们的页面抽进公共的命名空间。
- 英文有单复数。第一次遇到带数量的句子时定下写法；倾向于写成"名称：数字"，免得复数的键让两份文案的键对不上。

时间轴滚动区的滚动条闪动在这一步随滚动区的替换一并解决。它的成因是滚动区两个方向都按需出现滚动条、定制的滚动条又占用布局空间，时间轴按可见宽度算自己的宽度，于是每次更新都互相挤占；这是从代码里读出来的，没有在浏览器里复现过，替换之后要在真实的浏览器里确认。

### 长等待的画法（已定）

用户于 2026-10-11 在三份静态稿里选了方案 A，否决了没有时间刻度的方案 C（看不出并发），并要求 A 画得更整齐；同日确认了整理后的稿。它是 F2 的依据，实现之后写进 `console.md`。

- **活动时段与断口。** 时间分成两种时段。有片段开始或结束的是活动时段，所有活动时段按同一个比例画，每分钟的宽度相同。没有任何片段开始或结束的时段压成断口，断口一律等宽，不随缩放变化。只有按比例画出来比断口更宽的时段才压缩，所以没有"多少分钟以上才折叠"这样的阈值。时间范围不完整或时钟不可靠时不压缩，这一条沿用现在的规则。
- **时间轴。** 每个活动时段的起点写时刻，段内有刻度。断口处时间轴断开并画断裂记号，断口下方写被压掉的时长。最右是"现在"线，写当前时刻。
- **行。** 一个微任务一行，行与行之间有细线，左边的名称列固定不动。
- **片段只有三种画法。** 执行是实心条，条内写时长，必要时写状态；已经结束的等待是细线；还在等的是需要注意的颜色的虚线，旁边写在等什么与已经等了多久。等待的线穿过断口时不中断。失败的执行用失败色。
- **点状的事件**（验收、打回、取消等）是线上的记号，旁边写名称。
- **图例**只列这三种画法。

### F2 重画时间轴

按下面的顺序，每一项可以单独验收：

1. 比例尺：纯函数，输入是片段与空闲、等待的区间，输出是时间与像素的互换和刻度。
2. 绘制：片段、标记、现在线与读数线，用 SVG。
3. 文字：先测量，再决定显示哪一种写法。
4. 键盘与读屏：每个片段可以聚焦，有说明文字。
5. 接入：浮层、检查器、缩放与滚动。

旧的排布、比例换算和守几何的测试在这一步删除。新增比例尺的单元测试与浏览器里的断言。

### F3 收尾

删除旧样式表和不再使用的代码。更新 `console.md`、`objectives.md` 与两份 README 里涉及界面的部分。

## 用户已定的

2026-10-11 用户确认：

- **界面重新设计**，不必复刻原样（ADR-029 第 8 条）；设计的约定只属于本项目。
- **界面由自成一体的视图组成**（ADR-029 第 9 条）。别的项目怎样使用这些视图现在不考虑。
- **页签的名字**是 `任务`、`伙伴`、`设置`（`Tasks`、`Buddies`、`Settings`）。`伙伴` 取自术语表；`任务` 不是术语，这里用作宏任务与微任务的总称。
- **网址跟着名字走**：`#tasks`、`#buddies`、`#settings`，其他的井号地址一律打开任务页。旧书签 `#models`、`#settings` 到 Buddy 配置的转向已删除，它属于 0.x 不保留的兼容。

## 微任务的划分

- 一个微任务只做一件可以独立验收的事。写入范围按页面或模块划分，不并行修改同一个文件。
- 机械的工作（抽取文案、替换类名）与需要设计判断的工作（组件的形态、时间轴）分开。
- 主题变量、组件的形态与时间轴的设计由 Host 定稿之后再交给微任务实现。
- 不保留旧样式的兼容层，不留两套写法。被取代的代码与测试在同一次改动里删除。
- 要联网的事（装包、取 shadcn 的组件）由 Host 先做好，微任务不联网。

## 验证

- 每个微任务跑受它影响的组件测试。
- 每一步整合之后：前端全量；重新构建，产物与提交的逐字节一致；浏览器检查；Host 看像素，中英文、明暗与宽窄都看；仓库卫生测试。
- 没有 Python 改动时不跑 Python 的完整检查。
- 浏览器检查要绑定一个本机端口，并需要 Playwright 的无头 Chromium。Linux 上跑中文的几何检查之前要先装中文字体。
