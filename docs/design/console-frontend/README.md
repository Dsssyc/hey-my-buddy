# 控制台的静态稿

[执行计划](../console-frontend.md)的设计依据：每个页面一份静态稿，用浏览器直接打开 HTML 文件即可。数据是编的，稿不联网，也不是实现。在 `<html>` 上加 `data-theme="dark"` 看深色。

| 文件 | 内容 | 状态 |
| --- | --- | --- |
| `tasks.html` | 任务页：宏任务的列表、一个宏任务及其时间轴、选中的微任务；已结束的执行用浅底，一个进行中的回合判为可能卡住，一次问询，一行修正另一行；下方的检查器已由 `timeline-detail.html` 的固定一行取代 | 已由开发者认可（2026-10-16，第二版） |
| `timeline-detail.html` | 任务页的交互，可以点：行名一栏常驻，单击一行或一段打开详情，各步挂在展开的那一行下面，行名后一格的记号，时间轴下方固定的一行；时间条按线性比例简画，画法以 `tasks.html` 为准 | 已由开发者认可（2026-10-17） |
| `tasks-narrow.html` | 任务页在 390px 宽时：宏任务的列表与一个宏任务，行名在轨道上方 | 已由开发者认可（2026-10-16） |
| `tasks-empty.html` | 第一次使用，还没有宏任务 | 已由开发者认可（2026-10-16） |
| `tasks-offline.html` | 连接中断，显示上一次读到的内容 | 已由开发者认可（2026-10-16） |
| `task-delete.html` | 删除宏任务的确认 | 已由开发者认可（2026-10-16） |
| `task-delete-blocked.html` | 还有没了结的微任务时的删除 | 已由开发者认可（2026-10-16） |
| `task.html` | 微任务的详情：等待验收的微任务，选中第二个回合；右栏是这个回合的过程：Worker 一块里是会话的内容，末尾是产物；左端的返回按钮与左栏已由 `timeline-detail.html` 取代 | 已由开发者认可 |
| `task-wide.html` | 微任务的详情：宏任务的列表收起之后的样子 | 已由开发者认可 |
| `task-live.html` | 微任务的详情：进行中的回合判为可能卡住，过程里有一次 Host 的问询，底部是当前的阶段 | 已由开发者认可（2026-10-16 改过） |
| `task-router.html` | 微任务的详情：选中路由一步，右栏是 Router 的过程与它的选择 | 已由开发者认可 |
| `task-accepted.html` | 微任务的详情：已验收的微任务，选中验收一步 | 已由开发者认可 |
| `buddies.html` | Buddy 页的目录：按 harness 分节，节头带标志与账户的摘要；这一份里 Codex 的账户与一个模型同时展开，看得出两种展开的区别 | 已由开发者认可（2026-10-11，第三版） |
| `buddies-edit.html` | 目录：有未保存的改动，以及一行可能带的记号（待确认、不可用、新发现） | 已由开发者认可 |
| `buddies-narrow.html` | 目录在 390px 宽时的样子，结构相同 | 已由开发者认可 |
| `buddies-en.html` | 目录的英文：最挤的展开区放得下，标签的列宽随文字加宽 | 已由开发者认可 |
| `roles.html` | Buddy 页的角色：Router 的列表、设置与记录 | 待确认 |

颜色、记号与版式的规则写在 `base.css` 里，含义见执行计划的"设计"一节。页面实现并验收之后，对应的稿删除。

各份稿共用一个 `base.css`，类名很短，后加的规则曾经三次撞上 `buddies.html` 里已有的类名（`.grp`、`.fold`、`.n`），把那份稿的表头与收起的一行画坏而没有被发现；2026-10-11 已改名修好，并把全部十份稿重新截图看过。改 `base.css` 之后要把每一份稿都重新打开看一遍，不只看正在改的那一份。稿里有几处 13px 与 11px 的字，实现时按执行计划归到四档字号。

目录的四份稿另有一份 `buddies.css`，类名都带前缀，不与 `base.css` 里的短类名相撞；它们仍然用 `base.css` 里的控件。这四份稿画得比别的高（1280×1000，窄的一份 390×1180）。harness 的标志从 `apps/console/node_modules` 里的静态图标包读取，所以要先在 `apps/console` 里装好依赖才显示得出来；稿里不带图形文件。
