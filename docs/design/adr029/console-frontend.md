# 控制台前端重建：执行计划

依据 [ADR-029](../../decisions/029-console-frontend-foundation.md)。只动 `apps/console`、随包提交的构建产物和相应的参考文档，不改服务逻辑与契约。工作在单独的分支上进行，由 Claude Code Host 主持：设计由 Host 定稿，有边界的实现交给微任务。每一步结束时给开发者看截图并验收，Host 自己的核对记在[记录](../../acceptance/adr029/console-frontend.md)里。合入集成分支只在界面整体一致的两个节点进行，即 F1 结束与 F2 结束，这样日常的源码安装不会带上半新半旧的界面。

## 设计

ADR-029 第 8 条：界面重新设计，不以复刻为目标。静态稿在 [console-frontend/](../console-frontend/README.md)，每页一份，开发者确认后实现；任务页的方向已于 2026-10-11 得到开发者认可；Buddy 页的目录在模型、Harness 两项做出来之后于同日重新设计了一次（按 harness 分节，设置就地展开，见下），四份稿得到开发者认可；微任务详情的稿于同日得到认可；Buddy 页的角色分区与设置页的稿待确认。2026-10-16 Host 对现有页面与稿做了一次体验与审美的审查，开发者同日认可了由此改出的任务页、进行中的微任务详情与设置页，以及删除宏任务、第一次使用、连接中断与窄屏五份新稿（改了什么见下面带日期的几条规则）。任务页的记录一项于 2026-10-16 出稿并得到认可；开发者说只看图片看不出最终的效果，用上控制台之后可能还会提意见。

稿里的规则，实现时照此做，要偏离先问 Host：

- **颜色各有一个含义，取自标志。** 绿只用于“现在”的时间标尺（开发者 2026-10-19 改定：原来也表示进行中与选中；进行中改用亮度与动效，选中改用亮白或银色的框，键盘焦点也用银色）。橙是标志里连接两根立柱的那一块，表示有事等人接手：等 Host 决定或验收、没有保存的改动、快到上限的额度。墨色是记录，已经结束的历史一律用墨色。红只表示失败。唯一的例外是代码改动：增加的行与行数用绿，删去的用红；它们总是带着加号、减号出现，只用在改动的行数与差异里，不用来表示状态，在主题变量里有自己的名字。新的语义色先加进主题变量的明暗两套，不直接写色值。
- **形状先于文字。** 状态用一组固定的记号：实心圆是进行中，橙色菱形是等人接手，对勾是已验收，叉是失败，空心圆是还没有开始或不在场。同一个状态在时间轴、详情与各处的数目里是同一个记号；一行只把一件事说一遍。宏任务的列表是例外（开发者 2026-10-17 定）：条目前面不画记号，还有事的宏任务在左缘画一道色边，橙色是等人接手，绿色是进行中；已结束的不画，包括 Host 给了结论的失败；失败只在第二行的数目里用叉写出。状态词写进这一行的可访问名称。选中的条目只用浅绿的底色，不画左缘的线，免得与进行中的色边混淆。真实数据里大多是已结束的宏任务，一列同样的记号又多又乱，色边让还有事的那几行浮出来。时间轴的行名一栏也是例外（开发者 2026-10-17 定）：名称后面一格放记号，只给还有事的微任务：进行中是实心绿点，外圈慢慢扩散，2.4 秒一次，系统要求减少动态效果时不动；等人接手是橙色菱形，排队是空心圆，都不动；已结束的不放。鼠标指着或键盘聚焦时，记号换成展开的尖角，展开之后尖角转向下。第二行照旧写状态词，因为等待 Host、等待 Lead 与等待验收要靠它分开；这一行的状态说了两遍是有意的，记号兼作这一行能展开的提示。
- **已结束的执行用浅底，要处理的浮在上面。**（2026-10-16）时间轴上已经结束的执行是墨色的一级浅色（主题变量 `--past-wash`）加细边，条内的字用墨色；进行中的沿用它的 buddy 颜色、亮一档，右端缓慢呼吸（2026-10-19 改定，原来是实心绿：换色会让人以为换了 buddy），失败的是实心红。一屏里先看到的是等人接手、进行中与可能卡住的，历史退到后面。小的记号仍是实心的墨色，例如微任务详情左栏里回合的方块与列表里的记号：浅色在小面积上看不清，也会与表示路由的空心方块混淆。
- **提醒画在执行条上。**（2026-10-16）进行中的条一直填到现在。判为可能卡住时，从最后一次进展起的那一段画成橙色空心的尾巴，尾巴里写“可能卡住 · 静默 19 分”；没有判为可能卡住时不画尾巴。越过预期时长之后，条上在预期的位置画一道橙色的刻线；没有越过时只在读数里写预期（2026-10-17）：刻线不画到现在之后，时间轴不为它延伸到未来，因为预期常是几个小时，未来的空白会把时间条拉长。两种提醒的字也写在微任务详情回合的标题里，用橙色，不用红。
- **问询是执行条上的空心菱形。**（2026-10-16）回合的过程里，Host 的问题是一个输入节点：空心菱形加一段浅底的引文，写谁问的、几点问的，右端是送达的状态；答复是它后面的一条消息。
- **修正写在行名旁。**（2026-10-16）修正别的微任务的那一行，名字后面写“↪ 被修正的标题”；被修正的那一行写“↩ 次数”。悬停给出完整的标题，详情的委派一步可以跳过去。
- **宏任务、微任务和其中的一步各有地址。**（2026-10-16）`#tasks/<宏任务>`、`#tasks/<宏任务>/<微任务>`，再加上步的序号；后退与前进可用，Host 交付时可以把链接交给用户。
- **文字是名称、状态与数值，不是句子。** 名称用名词；状态用固定的词：进行中、等待 Host、等待 Lead、等待验收、已验收、已完成、已结束、失败、排队；数值是数字加单位，两个数的关系写成 `3 / 4`。界面上不出现像句子的短语，例如"由谁路由""4 次里选出 3 次"。完整的句子只出现在空状态、出错与确认里。buddy 写成四元组 `harness / provider / model / effort`，放不下的地方写 `model / effort`。第四部分叫推理强度，它的每一级也叫一个推理强度，不另起名字；“档位”只指权限档位。
- **Buddy 页的目录按 harness 分节。** 一节是一个 harness：节头是它的标志、名字与提供方，右边是账户的摘要，写额度最紧的那个窗口的百分比与重置时间，按量计费的写余额；harness 不能工作时在名字旁写它记录的状态，例如未登录、额度用完与重试的时刻，这样的 harness 排在最后。点这段摘要，节头向下展开位置（路径、来源、检测、指定路径）、账户与额度三块：它们留在节头自己的白底上，三块之间用竖线隔开，底下一条较重的线收住，看得出是节头的一部分。节头左端的箭头只管收起与展开这一节的模型；没有任何 buddy 启用的 harness 默认收起，收起时写有几个模型、启用了几个 buddy。额度只在节头出现。按钮只写“检测”与“全部检测”，不加“重新”。
- **节里一行是一个模型。** 这里的模型指一个 harness 经一个提供方给出的一个模型。行上只写已经启用的推理强度，连同它实际生效的偏好，写成字（优先、固定、排除），不用颜色区分；名字前的绿点表示这个模型有 buddy 在用，没有启用任何 buddy 的模型名字用浅色；行尾是并发的占用与上限。待确认、新发现、不可用写在模型的名字旁。一件事只说一遍：harness 已经写了状态，它的模型就不再各写一遍不可用；记录下来的原因是这个词的说明，悬停与读屏时给出。界面上不说“家族”：通常的说法里模型家族指同一系列的几个模型，与这里的意思不同。两个筛选沿用原来的：只看已启用、显示不可用。
- **点模型，设置就地展开，不设右栏。** 展开的是从这一行垂下来的抽屉：底色下沉一级，左边的绿线连着被选中的那一行，与节头的展开看得出不是一回事。左边“模型”一块放默认偏好、并发、备注，并发属于模型；右边“Buddy”一块里，这个模型的推理强度排成一条刻度带，一格是一个 buddy，顺序是这个 harness 自己的顺序，启用的格子是白底加绿色的上沿，格子里写它生效的偏好。点一格，下面的面板只列这一个 buddy：完整的四段名字、启用、偏好的覆盖与理由、计入评价的次数；启用与偏好属于 buddy。刻度带与面板左右对齐，备注一栏的底边与面板的底边齐平。抽屉的右半边留给以后的评价。
- **窄屏用同一个结构。** 模型的行变成两行，刻度带排成三列，面板里的控件竖排；没有另一套版式，也没有“回到表”的按钮。
- **harness 的标志用图标包里的彩色原样。** 以依赖的方式引入静态图标包，只引用用到的文件；只有单色画法的那一个随文字颜色着色。不改图形，不把别人的标志用作本项目自己的标识。标志的颜色属于标志本身，不算进上面的颜色词表。出处与取舍见整合分支 `docs/research/` 里 2026-10-11 的两份记录。
- **Buddy 页的分区是并列的几个方面。** 现在是目录（上面的分节列表，也就是术语表里的模型目录加上用户在每个 buddy 上的选择）与角色（谁担任 Router，连同这个角色的设置与记录）；以后是评价与画像。谁担任什么角色只写在角色分区，目录里不重复。
- **微任务的详情按回合组织。** （开发者 2026-10-18 改定：各步改为详情顶部常驻的一行，就是这个微任务在时间轴上的那一行，左栏不再展开，见[第 4 步余项](step4-remaining-plan.md)的批次三；下面的画法在新稿认可之前仍是现状。）它占用时间条所在的区域，宏任务的头部与左边的行名一栏都不动（开发者 2026-10-17 定，稿是 `timeline-detail.html`）；自己的头部写名称、状态、开始、历时与回合数，用头部左端的 ← 或 Esc 收起，焦点回到这一行（开发者 2026-10-17 试用之后改定，见文末一节）。各步挂在行名一栏里展开的那一行下面，画法是 Buddy 页的抽屉：底色下沉一级，不画绿线（文末一节）。各步是这个微任务在时间轴上的那一行竖过来：委派、路由、每个回合、Host 的每次决定、验收各是一步，步与步之间的线就是等待，画法与时间轴相同（细线是已经结束的等待，橙色虚线是还在等人接手），线旁写等待的种类与时长。回合的记号是方块，与时间轴上的执行条同色：墨色是已结束，绿是进行中，红是失败；路由是空心的方块，因为它也是一次执行，只是执行的是 Router；Host 的决定是菱形。选中一步，右边列出这一步自己的内容，从时间轴上的哪一段打开就选中哪一步。回合的右栏是这个回合的过程，按时间从上到下，这样宏任务的时间轴、微任务的步骤、回合的过程是同一条时间线的三级：Router 与 Worker 各有自己的一步，不放在同一个界面里（开发者 2026-10-11 要求分开；没有做成右栏里的页签，因为左栏本来就是在各步之间切换的地方，路由在时间轴上也是自己的一段）。两者的右栏是同一种样子，顶上是一条浅底的横带：角色的标签（Router、Worker）、这个 buddy 的四元组、右端的数值，第二行是用量（进行中时是模型回合与工具调用的计数）与会话的编号。路由一步的带下面是 Router 的过程，末尾的结果写它选中的 buddy 与理由；候选的名单不列（开发者 2026-10-11：知道是谁选的、为什么就够了，名单没有新的信息；它仍在决策记录里）。没有经过 Router 时没有路由这一步，Worker 的带右端写 Host 指定或唯一候选。回合一步是会话的内容（[ADR-024](../../decisions/024-console-session-view.md)，用 AI Elements 的组件渲染），画成一条过程线：线上的每个节点是一件事，输入是菱形加一段浅底的引文，推理与工具调用各是一个带图标的小方块加一行（类别、对象、数值，点开看输入与输出），消息是一个小圆点加正文，最后的结果是一个实心方块。产物是末尾的一条横带。进行中时底部固定一行，写当前的阶段与最近上报，正在执行的那一步用绿色。这样一眼分得出谁的内容、哪些是动作、哪些是话。会话内容的读取接口做完之前，Worker 一块里只有结果，中间不放占位。担任角色的 buddy 用角色的名字称呼：这里是 Worker 与 Router。Host 的决定：请求的内容与决定的内容。委派：任务的原文、来源与标识、协助任务。验收：产物、整合，以及失败或取消时 Host 的结论。正常的情况不写，只写例外：停止已确认、正常完成不出现，停止未确认与别的终止原因才出现。是谁做的写在左边那一步上，右边不重复；右边的标题写这一步的状态、精确的起止时刻与历时。
- **用线和留白分区。** 容器是直角，用细线与一级底色区分，不用带圆角的盒子套盒子。只有控件有 4px 的圆角。
- **版式只有几种。** 顶栏用标志的墨色，明暗主题下相同。页面的头部放标题、分区页签与一行状态。设置类的内容是"左边名称、右边控件"的分节，节与节之间一条细线。成组的记录是列表或表格。
- **舒适。** 信息都在，但不密集：字号只有四档，正文与控件 14px，次要信息 12px，面板标题 16px，页面标题 18px，没有小于 12px 的字；数字、时刻与编号用等宽数字。控件高 32px，小的 28px。静态稿的 `base.css` 里有几处 13px 与 11px，实现时一律归到这四档。
- **看得清。** 文字与它的底色的对比不低于 4.5 比 1。为此最浅的一档文字比最初的稿深了一些（浅色 `#626D66`，深色 `#89928C`）；2026-10-17 选中的底色加深之后，它与橙色的字又各调了一次，好让落在选中底色上的字仍过 4.5 比 1：浅色的最浅一档 `#606B64`、橙字 `#B2461E`，深色的最浅一档与已结束的墨色都是 `#98A29B`；这一条由一项测试守着，它从 `tokens.css` 里读出每一种文字色与每一种底色来算；顶栏上的数目用浅橙底配深色字，因为顶栏在明暗两种主题下都是深色的。选中的底色 2026-10-17 加深为浅色 `#DCEDE2`、深色 `#243B2E`：原来的深色 `#1E2B25` 与面板的底色几乎分不出，开发者在原型里找不到展开的那一行。2026-10-18 批次三的修整给微任务条目的第二行（模型与强度）加了更浅的一档 `ink4`（浅色 `#657068`、深色 `#8B9196`），在它实际所处的几种底色上仍过 4.5 比 1；落在选中的底色上过不了，所以选中行的这一行仍用 `ink3`。
- **没有常驻的说明句。** 名称要自己说得清；确实需要解释的，用提示组件在悬停与键盘聚焦时给出，同时写进可访问的名称或说明，不用浏览器自带的 `title`，不放问号按钮。一个暂时不能用的控件不做成禁用，这样它仍能得到焦点、说出原因，只是点了不起作用。一种情况例外：一项设置的作用在页面上看不出来、用户又未必知道它是做什么的，就在名称下面写一两句说明，说它做什么、什么时候该开。现在是设置页的访问一节（开发者 2026-10-11 要求）与提醒一节（2026-10-16 认可的稿）。语言的选项用各自语言的名字：中文写“中文”，英文写“English”，界面是哪种语言都不翻译。
- **组件与文字。** 浮层、对话框、选择、页签与滚动区一律用 `components/ui` 里的组件，它们保持 shadcn 生成的样子，只为配色与圆角做必要的改动。文字全部走文案：每个页面一个命名空间，中文在 `src/i18n/zh/`，英文在 `src/i18n/en/` 并用 `satisfies` 对齐键，术语取 `CONTEXT.md` 里成对的写法；日期、时间与数字用 `src/i18n/format.ts`。测试读中文。
- **每个页面有浏览器检查。** 用 `browser/preview.ts` 里的断言：各项在框内、互不重叠、文字不被裁掉、页面不横向滚动、页面没有报错。中文与英文、宽与窄都跑。

| 换手 | `CONTEXT.md` | 时间轴上两个回合之间的记号；行名下写当前的 buddy；微任务详情的左栏里是两个回合之间的一步 | 记号词表加一个 |
| 预期时长、已超时、可能卡住、终止的原因 | ADR-022 | 执行条上的静默尾巴与预期刻线；微任务详情里回合的标题与底部的那一行 | 稿已出（2026-10-16）；已超过预期与可能卡住在旧页面里已有，见“现有功能的去向” |
| 路由的依据：领域与类型、证据的层级、探索、唯一候选、Host 指定、由谁选的 | ADR-021 第 6、20 条 | 微任务详情左栏里"路由"一步的右栏；时间轴上路由是一种片段 | 稿里已有；领域与类型、证据的层级、探索届时写在带的第二行 |
| 结束之后的回收结果，没有结论的提示 | ADR-021 展示线 U5 | 微任务详情的左栏在验收之后加一步"回收" | 届时加一步 |
| 会话视图 | ADR-024 | 微任务详情里回合的右栏：过程的主体就是会话的内容 | 稿里已有；读取接口做完之前过程里只有路由、结果与产物 |
| 急停 | ADR-021 第 21 条 | 宏任务头部的"更多"菜单 | 头部已有菜单 |
| 删除宏任务 | ADR-028 | 同一个菜单，总是可点；还有没了结的微任务时列出各自怎样了结，否则列出要删掉的数目，默认焦点在取消 | 稿已出（2026-10-16）；黑板一侧的删除与删除前的清单随第 4 步做 |
| 回合内问询 | ADR-031 执行计划的问询一项（0.42.1） | 执行条上的空心菱形；回合过程里的输入节点与答复 | 稿已出（2026-10-16）；读取接口要带上问询，随微任务详情一起做 |

由此得出、现在就要守住的四点：Buddy 页的分区是并列的几个方面，目录里的设置在所属的那一行下面就地展开，不设右栏；时间轴的行不与某一个 buddy 绑死，并且可以成组；宏任务的头部有一个菜单；微任务的详情是一个按回合组织的完整视图，不是一条摘要。

## 现有功能的去向

重新设计不等于减功能。每一页的稿定稿之前，先从这一页现有的组件与测试里列出全部功能与入口，逐项写明去向：留在哪里、并到哪里，或者删除及其原因。

打底时发现、要在这一步处理的：

- 数据层（`api.ts` 等）里的中文报错不属于某一个页面，随第一个用到它们的页面抽进公共的命名空间。
- 任务页的四个状态页签各写一个数目，而列表的接口一次只给当前筛选的总数。实现任务页时让列表的回复一并给出四个数，这是读取投影上的一处小改动，随那一页一起验收。
- 英文有单复数。第一次遇到带数量的句子时定下写法；倾向于写成"名称：数字"，免得复数的键让两份文案的键对不上。

时间轴滚动区的滚动条闪动在这一步随滚动区的替换一并解决。它的成因是滚动区两个方向都按需出现滚动条、定制的滚动条又占用布局空间，时间轴按可见宽度算自己的宽度，于是每次更新都互相挤占；这是从代码里读出来的，没有在浏览器里复现过，替换之后要在真实的浏览器里确认。

### 长等待的画法（已定）

开发者于 2026-10-11 在三份静态稿里选了方案 A，否决了没有时间刻度的方案 C（看不出并发），并要求 A 画得更整齐；同日确认了整理后的稿。它是 F2 的依据，实现之后写进 `console.md`。

- **活动时段与断口。** 时间分成两种时段。有片段开始或结束的是活动时段，所有活动时段按同一个比例画，每分钟的宽度相同。没有任何片段开始或结束的时段压成断口，断口一律等宽，不随缩放变化。只有按比例画出来比断口更宽的时段才压缩，所以没有"多少分钟以上才折叠"这样的阈值。时间范围不完整或时钟不可靠时不压缩，这一条沿用现在的规则。
- **时间轴。** 每个活动时段的起点写时刻，段内有刻度。断口处时间轴断开并画断裂记号，断口下方写被压掉的时长。最右是"现在"线，写当前时刻。
- **行。** 一个微任务一行，行与行之间有细线，左边的名称列固定不动。
- **片段只有三种画法。** 执行是条，条内写时长，必要时写状态：已结束的浅底，进行中沿用 buddy 颜色、亮一档、右端缓慢呼吸，失败实心红，可能卡住时进行中的条带一段橙色空心的尾巴（2026-10-16）；已经结束的等待是细线；还在等的是需要注意的颜色的虚线，旁边写在等什么与已经等了多久。等待的线穿过断口时不中断。失败的执行用失败色。
- **点状的事件**（验收、打回、取消等）是线上的记号，旁边写名称。整合不另画，验收的对勾已经包含它；几个记号挤在一起时只画记号，名称留给读数（2026-10-17）。
- **图例**只列这三种画法，加上静默的尾巴（2026-10-16）。

### F2 重画时间轴

**已完成（2026-10-17）。** 六项都已合入控制台分支，验收记录在 `docs/acceptance/adr029/console-frontend.md`。


按下面的顺序，每一项可以单独验收。开发者 2026-10-17 在可点的原型 `timeline-detail.html` 上改定了任务页的交互，结构因此排在绘制之前：

1. 比例尺：纯函数，输入是片段与空闲、等待的区间，输出是时间与像素的互换和刻度。
2. 结构：行名一栏常驻，右边是时间条或详情；单击一行或一段打开详情，再点展开的那一行或按 Esc 收起；各步挂在展开的那一行下面；行名后一格的记号；时间轴下方固定一行，取代检查器；选中的底色加深。时间条在这一步先用新的比例尺画执行条、等待线、断口的底色、刻度与现在线。窄屏照 `tasks-narrow.html`：行名在各自轨道的上方；打开详情时，展开的那一行留在详情的顶上，点它或按 Esc 收起。旧的时间轴、检查器与按时间排列的清单在这一步删除。
3. 绘制：补全片段的画法（断口、静默的尾巴、预期刻线、问询与点状的事件）与读数线，用 SVG。
4. 文字：先测量，再决定显示哪一种写法。
5. 键盘与读屏：每个片段可以聚焦，有说明文字。
6. 接入：浮层、缩放与滚动；按时间排列的清单照新的比例尺重做。

## 开发者试用 0.45.2 之后改定的（2026-10-17 晚）

0.45.2 装上之后，开发者在日常控制台上又看出几处，Host 在合成预览里用“第 4 步”宏任务的真实时间轴画了几种画法，开发者选定下面这些。它们优先于下一节与上面各节里与之冲突的写法。

- **选中一个微任务与选中其中一项分开画。** 点行名选中一个微任务：时间轴上这一行铺一层很淡的中性灰底，不用绿色；它横贯整行，盖过空闲的断口，左右铺满到时间轴的两缘；这一行的执行条都不描框。点一段执行、一段等待或一个记号：这一行照样铺灰底，只有点中的那一项描一圈浅色的单线框，底部那一行只写这一项。左栏选中的行名用亮一档的中性底色（2026-10-19 改定，原来是绿色）。这取代下一节“这一行变底色，它的片段描边”的写法：原来整行描框，与选中一项分不开。

- **记号的文字只紧挨着记号。** 事件记号的名字放在记号的右边，右边放不下就放左边，两边都放不下就不画；指着、聚焦或选中时，底部那一行照样写出名字。连线（等待的线、通往验收的线）与执行条、断口、别的记号一样是障碍，文字不压在线上。原来文字会被推到很远，读起来像别的时刻发生的事。

## 开发者试用合成预览之后改定的（2026-10-19 至 2026-10-20）

控制台可读性这一批，开发者在合成预览上试了十几轮，另请了一次外部审查，由 Host 逐条复现核实。定下的这些优先于上面各节里与之冲突的写法。

- **单击即打开，悬停即聚焦。** 这推翻了 2026-10-17 的“单击选中、双击打开”：双击不容易被发现，选中又多一步（开发者 2026-10-20 定）。
  - 单击行名、时间片、记号，或成簇记号列表里的一项，打开那一步；回车同。
  - 单击时间轴行内的空白，只选中这一行。
  - 指着或聚焦一项时，给它画框，给它那一行铺淡底，底部读数写它，离开就收；打开过的那一项回来后保留框与淡底。
- **配色按色相排除，逐个取最远的颜色**（2026-10-20）。
  - 色相角（CIE LCh）落在 320°–80° 与 100°–200° 的不用，这两段包住两种主题下的失败红、等待橙与“现在”的绿。
  - 在亮度 54–66、彩度 24–48 的固定网格上，每个新颜色取与之前所有颜色最近距离最大的那个（Glasbey 的逐个取最远法），iwanthue 只用来换算颜色。
  - 改的原因：按色差排除时，色相相同、亮度不同的颜色照样过关，出现过与“现在”同色相的绿和暗红；iwanthue 的增量扩展在受限的色域里，6 种时最近色差只有 6.9，40 种以内出现完全相同的颜色。
- **执行条里只写 harness 标志、模型名与时长，状态靠形状与颜色。**
  - 失败的条保留 buddy 颜色，加红色描边与红叉；
  - 进行中的条亮一档，右端在自己的色相里发光、呼吸。
  - 这取代上一节“失败仍用实心红”的写法。
- **图例是一个按钮。** 读数行右端的“图例”打开一张卡片（2026-10-19：图例与读数一起放在下方太占地方）。打开详情时，读数行只留这个按钮，不重复头部已有的状态。
- **缩放不用按钮**（2026-10-19）。
  - 刻度带上：滚轮缩放，Shift 加滚轮平移，双击适应宽度；键盘照旧 + − 0。
  - 放大之后，刻度右端才出现“适应宽度”。
  - 刻度带加亮，提示它能缩放。指针停住时，提示跟着指针，到边上时留在视口里。
  - 详情的步骤条整条都能滚轮缩放，不加亮。
- **悬停提示等 0.6 秒**（开发者定），提示文字居中，提示本身不接收指针。
- **微任务详情的顶部分三组：** 头部、步骤条、标签与内容。
  - 步骤条是一条通栏的带子：铺页面底色，上下各一条细线。
  - 只靠间距分组的做法试过（2026-10-19），组内与组间的间距相差不大，分不出组。
- **刻度在空闲处连续。** 横线穿过折叠处，那里只画一个折断记号并写出时长；斜纹只在时间片区域。
- **会话是详情里的标签页**，见 ADR-024 第 7 条的补记；状态栏不设会话入口。
- **中文里的名字列表用顿号。**

## 开发者在日常控制台上试用之后改定的（2026-10-17）

0.45.0 装上之后，开发者在日常控制台上用真实数据试了任务页，定下这些。它们优先于上面各节里与之冲突的写法：

- **深色主题去掉绿调。** 底色改成中性的近黑：`--paper #0E0F10`、`--surface #16171A`、`--sunk #121315`、`--line #26282C`、`--line2 #363940`、顶栏 `--bar #0B0C0D`；次要文字 `--ink2 #A9AEB4`、`--ink3 #9AA0A6`，已结束的墨色 `--past #9AA0A6`、浅底 `--past-wash #2B2E33`，选中 `--live-wash #1D3B2B`。绿色只留给进行中与选中，才显得出来。浅色主题不变。
- **执行条按 buddy 着色，颜色不设数量上限。** （开发者 2026-10-19 改定：原来是六种自定的低饱和色，超过六个就重复；六种是照当时 buddy 的个数定的，而一个宏任务里可以有任意多个 buddy。）颜色由成熟的配色库（iwanthue）按约束生成：暗色下不刺眼，避开绿、橙、红三个已有含义的颜色；在一个宏任务里按 buddy 第一次执行的先后分配，后出现的不改变已有的颜色，不预设数量。颜色只是辅助：人眼能分清的颜色有限，十几种之后再好的配色也会彼此相近，所以每一段执行条都带着它的 buddy 记号（harness 的标志，条够宽时加模型的简称），悬停显示完整的四段身份。进行中的条沿用同一个颜色、亮一档（在同一个颜色空间里提高亮度，由程序算出），失败仍用实心红。（2026-10-20 改定：配色的生成与失败的条，见上一节。）
- **单击是选中，双击或回车才打开。** （2026-10-20 推翻：单击即打开，悬停即聚焦，见上一节。） 单击一行或一段：这一行变底色，它的片段描边，底部那一行写它，缩放以它为中心。打开之后，单击别的行就换成那一行的详情。收起用详情头部左端的 ←（取代原来那里的状态记号）或 Esc；详情还在读取或读取失败时，← 也在同一个位置。单击一个记号（事件或问询）同样是选中，底部那一行写这个记号。这推翻了同日在原型上定的“单击打开”。
- **行名用状态色边。** 每一行的左缘画状态：进行中用正文颜色（2026-10-19 改定，原来是绿）、等待接手橙、失败红、已验收与已结束墨色，排队不画；还在进行由行名后的呼吸点表示。展开的那一行只靠底色与抽屉的底色，不再画连着各步的绿线，免得左缘有两种意思。行名后那一格只留进行中的呼吸点与指着时的尖角。宏任务列表不变。
- **图例与记号。** 虚线写“等待接手”，不用“换手”（术语表里换手是换了执行的 buddy）；静默的尾巴写“可能卡住”。图例列出问询、事件、成簇的记号与空闲。验收是圆圈里的 ✓，失败的结论是圆圈里的 ✕，与线分开。同一行上不同东西的标签至少隔开 12px，否则会读成一句：开发者看到的“问询 36 分”，是问询的标签挨着后面那段等待的时长。隔不开的省掉，留给读数，与挤在一起的事件名称同一条规则。点问询打开那一回合时，滚到那条问询并标出它。
- **空闲。** 断口画斜线纹，与时间轴的底色分得开；指着它时，读数写“空闲 起–止 · 时长”。
- **读数线。** 指针处的时刻标在刻度那一行、竖线的顶端；放大到足够细时带秒。指针在断口里时不标时刻：断口里的时间不是线性的，读数写空闲的起止与时长。

## 开发者看过真实页面之后改定的（2026-10-11）

开发者在合成预览里看了重做之后的 Buddy 页，结论是大体可以，下面几条要改；它们同时是以后每一页的规则。

- **展开、收起、选中与悬停都要有过渡，不许跳变。** 展开与收起用高度与透明度的过渡，150 到 200 毫秒；颜色的变化 100 到 150 毫秒。用 Radix 自带的可折叠组件来做，不自己写测量高度的代码。系统设置了“减少动态效果”时不做过渡。

- **展开的记号用细线的尖角，不用实心三角。** 开发者看过第二版之后说实心的三角“长得真丑”。记号用图标库 `lucide-react` 里现成的 `ChevronRight`：16px，线宽 1.5，次要颜色，悬停时变成正文颜色；展开时旋转 90 度，旋转带过渡。所有能展开的行都用这一个记号：节头、模型行、任务页里以后的折叠处。记号本身小，按钮的可点范围不小于 28px 见方。时间轴的行名一栏里，它只在这一行被指着、聚焦或已经展开时出现，平时那一格放状态记号（开发者 2026-10-17）：一列同样的尖角里，看不出哪一个转了向。
- **选中的样子不能被悬停盖掉。** 已经展开的模型行，鼠标移上去仍然是选中的底色；悬停只能让它更明显，不能让它看起来像没选中。别的可选中的行与格子同理。

- **不采信实现方的“已完成”。** 每一页交回之后，按本文“现有功能的去向”那张表与被取代的旧测试逐项核对有没有遗漏，由 Host 或另一个模型来做，结果写进验收记录。

## 微任务的划分

- 一个微任务只做一件可以独立验收的事。写入范围按页面或模块划分，不并行修改同一个文件。
- 机械的工作（抽取文案、替换类名）与需要设计判断的工作（组件的形态、时间轴）分开。
- 主题变量、组件的形态与时间轴的设计由 Host 定稿之后再交给微任务实现。
- 不保留旧样式的兼容层，不留两套写法。被取代的代码与测试在同一次改动里删除。
- 要联网的事（装包、取 shadcn 的组件）由 Host 先做好，微任务不联网。

## 验证

- 每个微任务跑受它影响的组件测试。
- 每一步整合之后：前端全量；重新构建，产物与提交的逐字节一致；浏览器检查；Host 看像素，中英文、明暗与宽窄都看；仓库卫生测试。
- 没有 Python 改动时不跑 Python 的完整检查。
