# 微任务详情：步骤条与概述联动（执行计划）

2026-10-27，开发者报告问题，同日确认方向。依据 [ADR-029](../../decisions/029-console-frontend-foundation.md)（第 5、10、11、13 条）与[控制台前端执行计划](console-frontend.md)。

## 现状（读源码与日常控制台得到的）

- **步骤条只能选整个步骤。** `task-detail/StepStrip.tsx` 只把步骤做成可点的目标（`sliceButton`）。问询、等待、结算这些标记由共用的 Track 画在色块上，本身不是单独的目标，点它们等于点它们所在的步骤。
  - 在日常控制台上点“CI 偶发失败与分片”的问询标记：页面切到第 11 步（第 5 回合），地址只记 `/11`；概述里的那个问询框既没有滚动过去，也没有高亮。
- **“聚焦的一项”已经有一套机制，但只有问询在用。**
  - 状态是 `MacroTasks.tsx` 里的 `origin`：从宏任务时间轴点某一项进入详情时带上，例如 `inquiry:<id>`；`onStep` 换步骤时保留它。
  - `TaskDetail.tsx` 把它变成 `highlightedInquiry`，`ask.tsx` 据此把问询框滚到中间并高亮。
- **步骤内部的项怎样对应到步骤**，由 `steps.ts` 的 `stepForItem` 判定，前缀有 `inquiry:`、`span:`（等待）、`settle:` 与 `event:` 四种。
- **概述没有交互**，只有“展开更多”。

## 要做的

1. **步骤条 → 概述。**
   - 步骤条上代表步骤内部某一项的标记，都做成单独的目标：问询、等待、结算与验收事件，以 `stepForItem` 认得的为准。
   - 点击、回车或空格：选中它所在的步骤，并把它设为聚焦的一项；概述把对应的框滚进视野并高亮。
   - 滚动与高亮沿用问询现在的做法，推广到每一种在步骤条上有标记的项。
2. **概述 → 步骤条。**
   - 鼠标停在概述里某个在步骤条上有标记的框上，或键盘聚焦到它时，步骤条上它的标记亮起来。
   - 点这个框上的时间，把它设为聚焦的一项。步骤条照现在露出选中步骤的办法，以最小的横向滚动露出它的标记。
3. **只有一套机制。** 聚焦的一项只有一个状态，就是现在的 `origin`；步骤条与概述都读它，不另设第二个高亮状态。地址的形式不变。
4. **动效与颜色。**
   - 平滑滚动；系统要求减少动态效果时直接跳过去。不引起布局跳动。
   - 高亮只用现有的“选中”底色与焦点框，不加新颜色：颜色只用来区分 buddy，状态靠形状表达（第 13 条）。
   - 先在暗色下核对清晰度（第 10 条）。
5. **可访问。**
   - 新的目标都有可访问的名称；悬停与键盘聚焦时的说明照第 11 条。
   - Tab 能走到；回车与空格选中；左右方向键在步骤之间移动，行为不变。
6. **删掉被取代的。** 问询专用的 `highlightedInquiry` 等写法换成通用的聚焦项，旧的一并删除。

## 检查

- **前端单元测试**（`npm --prefix apps/console test`）覆盖三件事：点标记会设聚焦项并选中步骤；停在概述的框上，它的标记会亮；点时间会设聚焦项。
- **浏览器检查**（`npm --prefix apps/console run test:browser`，跑在合成预览上），断言几何：
  - 在一个很长的回合里，点靠后那条问询的标记，它的框会滚进视野并高亮；
  - 标记与框的联动在 390、1280、1440 三种宽度和中英文下都成立；
  - 要求减少动态效果时不做平滑滚动；
  - 布局不跳动。
- 改了 `apps/console/`，就按 AGENTS.md 重建并一起提交 `src/hey_my_buddy/console/assets`。
