# Buddy 页与 Router 的重做：计划

2026-11-08，Host 起草。依据 [ADR-029](../../decisions/029-console-frontend-foundation.md) 与[控制台的设计规矩](console-frontend.md#设计)，以及[待办](../backlog.md)里“Buddy 页与 Router 的重做”与并进来的几条。做法照宏任务界面那次：先出静态稿、看真实像素，开发者确认之后按稿实现。

## 开发者的决定

- 2026-10-29：两页都做得不好，要像重做宏任务的列表与详情那样大改一次。
- 2026-11-08：先不顾窄屏。静态稿只出宽屏，实现时不为窄屏另做版式，这两页窄屏的样子照实写成没有核对。这是眼下的安排，不改 ADR-029 的规矩。
- 2026-11-08，Host 提出、开发者确认：Buddy 区分成目录、模型、Router 三个并列的分区，加上模型分区；Router 的三个面并列，左边选面、右边一个面，不竖排成一页；删除不在目录里的 buddy 先不做；两页一起出稿。
- 2026-11-08，开发者看过第一轮静态稿：方向可以；目录没有沿用已有的设计，例如 harness 的标志与展开的三角；模型分区里的评价没有分清哪些是 buddy 的。Host 核对，两处都出在计划：计划把评价搬进了模型分区，与 ADR-021 第 1 条的归属（评价属于同型 buddy）和第 16 条 2026-10-20 开发者定的位置（评价放在这个 buddy 设置的展开里）相违，计划却没有说明；给实现方的任务书只要求照现有的字段与说法，没有要求照现有的样子。第二轮照下面改过的计划画。
- 2026-11-08，开发者看过第二轮静态稿：提供方单独一行是冗余，写在 harness 的节头上；目录里不放评价；第三个分区叫评价，排在 Router 后面，因为目录与 Router 是设置，评价是参考，它的动作要等 Router 配好；额度早已定下不显示（ADR-021 第 22 条 2026-10-18 的修改），第二轮是照 Host 任务书里一条过时的写法画上去的；模型的对应关系平时用不到，主要给维护划代用，不该单列一块、排在最前，每行三个按钮也看不出作用与副作用；画像运行的用量与错误不是用户在这里要看的，短暂提示就够，要留存就放到 Router。ADR-021 第 16 条里评价的位置（2026-10-20）、模型分区的名字、批量构建与立即维护的位置随之改变，开发者看过第三轮稿之后写进第 16 条。
- 2026-11-08，开发者补充两条：评价按 buddy 组织是否更合适（Host 答按同型 buddy，见“评价”一节）；Router 的三个面在界面上不说“面”，只写 Router 的三种工作，“面”是设计里的说法，用户不必知道。
- 2026-11-08，开发者看过第三轮静态稿：评价里要分清三样，模型画像、领域评价、用户备注；用户备注可有可无，待定，开发者觉得它对 Router 的选择影响太大。页签照术语表叫“模型画像”，不叫 Host 问过的“共识画像”（开发者：“共识”太抽象）。
- 2026-11-08，开发者看过第四轮静态稿：用户备注去掉（ADR-021 第 12 条同日的修改）；每个画面基本是一大片文字，设计不好。Host 按 ADR-029 的规矩补了“画法”一节。
- 2026-11-09，开发者看过第五轮静态稿：看着还行，领域树太僵硬。Host 画了三种画法的草图，开发者选了从左往右分叉的枝条，并要颜色不全灰、用时间轴的配色表；定为每个顶层领域取那张表的一个色系，画线用中间亮度（ADR-029 第 13 条同日的修改）。第八轮之后，开发者要 Router 左边去掉 buddy 的名字，其余等装上之后亲手检验。
- 2026-11-09，0.67.0 装上之后开发者试用：日常黑板上的领域树有 41 个顶层领域，从一根散开成放射状，名字都在画面外，Host 用真实数据画了草图，开发者选了按数量排序的大纲加计数条；“每种颜色只有一个含义”只管时间轴与任务界面，Buddy 页用 logo 的色调，暗色下不全用白与灰（ADR-029 第 13 条同日的改定）；样本条与 Router 记录里的数平时收起，点开才显示；分区页签要垂直居中，选中的下划线压在下面的分隔线上。领域树的配色在纯绿与两条色带的草图里选了从青经绿到黄的那条。Host 用日常黑板的真实读取在新构建里出图之后定（开发者同意由 Host 定）：子领域的段不再压暗一档，改为按自己的数取色，因为压暗之后黄的一端发橄榄色，展开的子领域行也与父条里的段对不上。

## 现状

2026-11-08 的盘点（只读，带无头截图）：Buddy 区有“目录”与“角色”两个分区。目录按 harness 分节，一行是一个模型服务，点开是抽屉：左边模型服务的并发、右边各推理强度的 buddy 设置，下面依次是模型画像、最近一次画像运行、模型备注、模型的对应关系与同型 buddy 的评价。角色分区是一长列：Router 列表、默认模式、等待模型开始作答、重试间隔、探索名额，然后是维护面（buddy、间隔、立即维护、记录、领域树）、画像面（buddy）与 Router 的记录。

盘点看到的问题，这次都要解决：

1. 同一个 harness 下同名的模型分不出提供方；提供方的冷却在节头与每一行各写一遍。
2. “目录 / 角色”的切换栏有两份。
3. “待确认”读起来像要用户做事，也没有悬停的说明（[ADR-027](../../decisions/027-model-catalog-trust.md) 第 2 条）。
4. 只联网那一句对每个 harness 都说“可供画像面使用”，与它前一行“未声明强制限制”矛盾。
5. 抽屉左右失衡：画像、画像运行、用户写给模型的备注与对应关系都属于模型（ADR-021 第 1 条），却挂在一个模型服务的抽屉里，而一个模型会出现在好几个服务下；抽屉的右半边原本留给评价，评价却收在抽屉的最底下。
6. 刻度带的格子被选中格的内容撑得不等宽。
7. 角色分区没有层次：设置、运行的记录与领域树排成一列，各块宽度上限不一，右半屏空着。
8. Router 记录里是协议代码不是话；最近失败的微任务只写编号，不能点过去；列表首行的“上移”与末行的“下移”不可用时看不出来。
9. 单位的写法不一：有的写进标签，有的在输入框旁；“每 N 个给 1 个”的 N 与旁边的输入框看不出关系。
10. 时间一会儿短格式一会儿长格式；维护记录一行两个时刻没有列头。
11. 画像运行：被打回的原因没有显示；“画像已在运行”是那次点击的回复，运行结束后还挂着，与“失败”同时出现。
12. 深色下层级几乎只靠字号，次要信息一片同档的灰。

## 新的结构

Buddy 区的分区页签只有一份，放在页头，顺序是目录、Router、评价：前两个是设置；评价是参考，它的两个动作（构建画像、立即维护）要等 Router 配好（开发者 2026-11-08）。

已经定下的照旧，这一次只改下面明说的地方。知识的归属照 ADR-021 第 1 条：画像属于模型，评价属于同型 buddy，冷却与计费方式属于 harness 与提供方，并发属于模型服务，启用与偏好属于 buddy。目录的样子照[控制台的设计](console-frontend.md#设计)里 Buddy 页的几条、它们后来的修改与现在的控制台：harness 的标志、节头左端收起本节的箭头、节头整行展开位置、账户与冷却；模型一行，行首展开抽屉的箭头，名字前的圆点表示有 buddy 在用，没有 buddy 在用的名字用浅色，已启用的推理强度连同生效的偏好写成字，行尾是并发；状态只写例外。控制台不显示额度窗口的百分比、重置时间与余额（ADR-021 第 22 条 2026-10-18 的修改）。

### 目录

只管有什么、启用哪些、怎样用。

- 工具条照旧：搜索、只看已启用、显示不可用、全部检测、发现模型；“启用 x / y”只写在页头（见“实现”一节第 6 条）。
- 一节是一个 harness。节头写标志、名字与提供方；一个提供方冷却时，冷却、大约何时再试与开放重试紧跟在它的名字后面，只说这一遍，它的模型行不再写。计费方式（订阅、按量）在展开后的账户一块。
- 一行是一个模型服务，样子照旧（见上）。一个 harness 有两个以上提供方时，名字后用浅色写提供方，同名的模型才分得出；只有一个提供方的不写。启用了却还没有画像的，用空心圆记号提示（ADR-021 第 16 条“首次启用时提示尚未构建画像”）。
- “待确认”改成“这次没读到”，悬停给出完整的意思与起始时间（ADR-027 第 6 条）：从何时起最近的读取没看到，此前照常可用，满一小时再读一次，仍没有才记为不可用，用户不用做什么。术语表“模型目录”一条用同一个说法。
- 抽屉只放这个模型服务与它的 buddy：左边可用状态、并发与并发的提醒；右边推理强度的刻度带（等宽）与选中 buddy 的面板：四元组、启用、偏好与理由、计入评价的次数、基础设施失败的次数。计入评价的次数可以点，到评价分区里这个 buddy 所属的同型 buddy。抽屉里没有评价（开发者 2026-11-08）。
- harness 展开三块：位置（版本写两个：装着的版本与核实时的版本，[ADR-023](../../decisions/023-harness-integration-principles.md) 第 10 条，不按版本封锁；各档位的说明按这个 harness 的声明写，没有声明强制只联网的，不说它能担任画像面）、账户（含按提供方的计费方式）、冷却（每个冷却中的提供方一行与开放重试）。

### Router

三个面并列。界面上不说“面”，只写 Router 的三种工作：路由、维护、画像（Routing、Maintenance、Profiles）；“面”是设计里的说法，用户不必知道（开发者 2026-11-08）。左边是三项工作的列表，每项只有名字与一行状态，写最近一次的结果：路由的最近一次选择、维护的最近一轮、画像的最近一次运行，没有指定 buddy 时写“未设置”；buddy 的名字只在右边的“谁担任”里（开发者 2026-11-09：名字长会换行，又与右边重复）。每项的高度随内容。右边是选中的那个面，每个面都是同样三块：谁担任、设置、记录，块头写一句这个面做什么（ADR-021 第 16 条的“三个面的简短说明”）。一个面没有指定 buddy 时，写明这个面不运行，请用户设置（第 2 条）。

- 路由面：担任是有序的 Router 列表（添加、上移、下移、移除；到头的按钮看得出不可用）；设置是默认模式、等待模型开始作答、重试间隔、探索名额，单位一律写在输入框后，探索写成“每 [5] 个里给 1 个”，旁附一句说明（第 16 条）；记录是各 Router 的应答情况与最近的失败，原因写成话，微任务可以点过去。
- 维护面：担任是维护 buddy；设置是维护间隔；记录是每一轮维护，带列头，这一轮没有答案时保留上一版，写出原因（第 2 条）；领域树也在这里，改名与合并都是维护面的事。“立即维护”在评价分区。
- 画像面：担任是画像 buddy，点“选择 buddy”才列出候选，候选按声明只列能强制只联网的；记录是各模型的画像运行：状态、打回几轮与打回的原因、用量、按工具的成败，全部失败的一项醒目。批量构建在评价分区。

### 评价

参考，以同型 buddy 为单位组织（开发者 2026-11-08 问按 buddy 是否更合适，Host 答按同型 buddy：只差提供方的几个 buddy 共用一份评价，按 buddy 列会把同一份列几遍；ADR-021 第 1 条）。左边是列表，右边是选中项的详情，与宏任务页同一种做法。

- 列表按 harness 分组，与目录同一个顺序，组头是 harness 的标志与名字；一行一个同型 buddy，写模型与推理强度、样本数，它的模型还没有画像时带空心圆。默认只列有 buddy 在用的，可以切到全部。界面不说“同型”：详情的标题写 harness、模型与推理强度三段，旁边写共用这一份的是哪几个提供方的 buddy。
- 列表头两组：“已建画像 x / y”与“批量构建”（为选中的或全部没有画像的模型各跑一次，先确认会用哪个画像 buddy 的额度、跑几次，ADR-021 第 13、16 条）；“n 个微任务待维护”与“立即维护”。Router 没有指定相应的面时，按钮不可用，悬停写明先在 Router 里设置。
- 详情的标题写三段名字与共用它的提供方，下面两个页签：领域评价与模型画像（开发者 2026-11-08 要分清；用户备注同日去掉）。领域评价属于这个同型 buddy，默认打开；模型画像属于它的模型，页签里写明是哪个模型的，同一个模型的几个同型 buddy 看到的是同一份。
- 领域评价：计数与维护面的归纳（只有文字，不列它引用的微任务，见“实现”第 3 条）；领域乘任务类型的表，行是领域树，可以收起，没有样本的格子留空；一行“名字：gpt-6.1-sol、sol-latest”，是这一组样本记在哪些名字下（第 24 条），不带样本数，行尾一个“…”菜单收着对应关系的三个动作；之前的样本排在后面，作次一级的证据（第 24 条）。
- 模型画像：定位、擅长、不擅长，每条的来源与日期，以及构建或重建的按钮，按钮跟着运行的状态走。画像运行的用量、打回与错误不在这里，在 Router 的画像。
- 构建结束或失败时弹出一条短提示：结果与用量，失败写原因并链到画像的那条记录，几秒后消失（ADR-021 第 13 条“完成后显示实际用量”）。
- 对应关系的三个动作：标出换代、归到另一个模型、撤回（只有画像面或用户改过的名字才可以撤回）。换代是一个名字的事（第 24 条），所以每个动作先让人选是哪个名字，只有一个名字时直接选好；再弹出说明，写清会做什么、不会做什么，例如标出换代：“从现在起，sol-latest 的新结果算新的一代，它之前的样本留作旧一代，作次一级的证据；不改名字的显示，也不动目录”。
- 批量构建点了之后弹出确认框：会用哪个画像 buddy、为哪些模型各跑一次、共几次。

### 画法

层次、留白与形状先于文字（ADR-029）。要比较的数、一个整体的几部分，画成图形，确切的数写在旁边或放在悬停里；颜色按这一页自己的语义用（ADR-029 第 13 条 2026-11-09 的改定）：图形带 logo 的色调，不全用白与灰；失败用粉红并带叉；同一个图形里相邻的颜色在两种主题下都算过，分得开。带一排数的图形平时只画图形，图形本身是按钮：指着时出现贴边的框、光标变成手形，键盘聚焦时同样显示；点开在下面列出确切的数，再点收起，开合照控制台别处的折叠记住。

- 评价的计数：样本分成一次通过、返工后成功与失败三段，画成一条细的分段条，绿、琥珀黄与粉红；平时只有样本数与这条条，点开列出各段的数、返工轮数与中位数。
- 中位数（交付时长与输入、缓存、输出的用量）：一行小数字，一个“中位数”的标签管一行，不每项重复，随计数收在点开的部分里。
- 领域乘任务类型的表：每格一条短的条表示一次通过率，旁边小字写样本数，返工轮数放在悬停里；没有样本的格子留空。
- 名字一行只列名字，不画分段条；之前的样本是另一组，计数照同样的分段条画，更淡。
- 模型画像：定位一句；擅长与不擅长分成两列，各用加号与减号的记号；来源缩成条目后的小标号，来源与日期在最后列一次。
- 并发：占用与上限画成一个小的计量条，上限可以改；并发的那段提醒只在把上限调高时出现，平时不常驻。
- Router 的记录：每个 Router 的应答与没有应答画成一条分段条，应答用绿，没有应答用粉红；最近的错误写成话；维护与画像的记录每行以对勾或叉开头，用量画成小的分段条；画像运行里按工具的成败也画成分段条。这些条旁边的数平时收起，点开才显示。
- 领域树画成按数量排序的大纲加计数条：没有“全部”这一根，顶层领域按微任务数从多到少排；名字、数、条三列对齐，行不画分隔线，子节点的数也算进父节点；条按领域自身与各子领域分段，段间留缝。配色是一条按微任务数的色带，从青经绿到黄，越多越暖：按对数刻度取色，最大的领域在黄的一端；每一段按它代表的微任务数在色带上取色：领域自身那段按直接归入它的数，子领域那段按子领域连同它下面的数；展开后子领域那一行与它在父条里那一段同色，不另设压暗的一档；浅色主题另算一组更深的；每档对底色至少 3:1，自身与子领域两段的色差照 ADR-029 第 13 条。树的上方一行写顶层领域数、节点数与微任务数，旁边一个“全部展开 / 全部收起”。有子领域的行带展开的箭头，展开后子领域缩进并带一条细引线，指着子领域时父条里的那一段跟着亮。定义、合并来源与改名、合并在指着或聚焦那一行时出现在旁边的浮层里，不盖住名字。节点与层数不设上限：领域多时纵向变长。

## 实现

静态稿 2026-11-09 定下，照着它实现完的那几张随各批删掉了。四批都在 2026-11-09 验收并合入整合分支，同日随 0.67.0 装上（[安装记录](../../acceptance/installs/0.67.0.md)）。Host 先让一个 Worker 只读地把稿里每样东西对到现有的数据（对照报告在被忽略的 `tmp/redo/mapping/`，Host 抽查过其中关键的几处），下面是据此定下的做法与批次。整个重做随一次安装上线（存储形式变，0.67.0），不分阶段装半个重做。

### 对照之后定下的

1. 等待模型开始作答只存了一项，路由与画像共用：只在路由的设置里写一次，旁边一句说画像构建也按它；画像没有“设置”一块。稿里画了两处，以这里为准。
2. 维护的记录里，运行中的一轮排在最上面，实心圆，写开始时刻与“…”，行尾一个“停止”（现有的停止，ADR-021 第 8 条）；下一轮的时刻写在维护间隔旁边。失败的一行不放“立即重试”，立即维护在评价分区。稿里没有画这一行，现有界面有，不能丢。
3. 名字一行只列名字与菜单，不画按名字的分段条与样本数，换代对话框里的名字也不带样本数（开发者 2026-11-09 同意）：统计只按同型 buddy 累积（ADR-021 第 9 条），按名字的数要给统计加一维，或另存一份与样本数重复的计数。这一行原来叫“证据来自”，改叫“名字”，免得读成证据的出处。归纳只显示文字，不列它引用的微任务（开发者 2026-11-09：那是对宏任务与微任务的引用，任务删掉之后追溯不到，前后对不上）；引用仍留在内部，维护的输出靠它通过校验（ADR-021 第 11 条），删除宏任务时随之删去。控制台的读取不再给出引用。
4. 之前的样本：读取给出每个同型 buddy 的旧组：现在指向这个模型的每个名字，它更早的、还在的对应关系指向别的模型的，那个模型同一 harness 与推理强度下有样本的就是一个旧组；一个旧组只列一次，带上连着它的那几个名字与各自现在这一行的时刻；仍是某个模型服务现在的对应的模型不算旧组，它自己就是一个在用的同型 buddy。由已存的对应关系推出，不新存。评价只写“之前的样本”，不分换代还是归并：两者存成同一种对应关系，撤回又删掉整行，事后分不出（服务端那一批的 Worker 核对后指出）。
5. 管理账户去掉：账户与登录是用户的（ADR-030），账户一块只读。
6. “启用 x / y”只在页头写一次，目录的工具条不再写。
7. 没有并发记录的模型写“—”，不写 0。
8. 地址：模型用 modelId，同型 buddy 用 harness、modelId 与推理强度；旧的 `#buddies/roles/...` 换成新地址，先查清谁在引用。
9. 批量构建：确认一次之后，控制台为每个模型各发一次 `profile_start`，短提示按模型给出结果；不加批量的操作。
10. 最近的失败带微任务的标题，由服务的读取一并给出。
11. 核实时的版本：读 harness 声明里写的版本（ADR-023 第 10 条），没有写的写“未核对”。Codex、Claude Code 与 ZCode 的核对仍是待办里那一条，不随这次做。
12. 画像运行没有逐轮的事实：一次运行的用量按 attempt 汇总，早先几轮的核对意见在运行结束时随文件清掉，只留最后一次的。记录写打回的轮数与失败的原因（作答不合格时，原因带着最后一次核对的意见），不画每轮的用量与意见，也不为此新存（服务端那一批的 Worker 核对后指出）。

### 批次

按顺序做；前一批的封存输出 Host 读完差异之后，下一批可以在它上面开工；控制台的批次不同时跑。

1. **服务端（存储 38 → 39）。** 去掉模型备注，从存储、写入、快照、Router 的输入与说明，到控制台的解析、草稿与输入框，一次删干净，升级删除现有的备注（ADR-021 第 12 条 11-08 的修改）；顺带改 `model_correspondences_no_update` 触发器还写着 append-only 的报错。补上新画面要的读取：最近失败的标题、同型 buddy 之前的样本、harness 声明的核实版本；控制台只跟上解析与预览数据，不改样子。Host 面对的契约不变，控制台快照的形状变。
2. **外壳与目录。** 一份分区页签、页头的汇总、新地址；目录的行、抽屉与 harness 展开照稿与上面第 5–8、11 条。
3. **Router。** 左边三项工作与右边三块；路由的记录画成分段条，最近的失败带标题；维护的记录（含第 2 条的运行中一行）与枝条的领域树；画像的记录与展开的失败运行（第 12 条）。抽屉里的“最近一次画像运行”在这一批删掉。
4. **评价。** 列表与列表头（已建画像、批量构建、待维护、立即维护），领域评价与模型画像两个页签，名字一行与它的菜单、对话框，之前的样本，构建的短提示；控制台的读取去掉归纳的引用。抽屉里剩下的画像、对应关系与评价在这一批删掉。

每个控制台的批次做 `console-frontend.md` 说的五件事：照稿实现；文字进两份文案；重写这一块的组件测试，行为与安全方面的断言一项不少；写浏览器检查；删掉被取代的代码、样式、测试与它照着做的稿。Host 每批验收时看真实像素；装之前跑完整检查与浏览器全量，存储这一步照惯例演练升级并注入几处故障。

2. **配色**：Buddy 页的图形改用 logo 的色调；样本条是绿、琥珀黄与粉红，Router 记录与维护、画像的条照“画法”；每组相邻的颜色在两种主题下算过色差再定。
3. **点开才显示的数**：评价的样本条（连同中位数）、Router 的路由记录、维护与画像的记录。
4. **分区页签**：目录、Router、评价这一行垂直居中，选中的下划线压在下面的分隔线上，与顶栏的做法一致。
5. **设置的说明放进问号圈**：Router 设置里每一项为什么需要、到时会怎样，收进标签旁的问号圈，指着或聚焦时浮出；告诉用户哪些内容会发给提供方的那一句（默认模式）仍留在明处。“等待模型开始作答”的说明是：这段时间里模型没开始作答，路由就换列表里的下一个 Router，维护这一轮算失败、下一轮再来，画像构建算失败、可以再点；开始作答之后不限时。有它，卡住的提供方才不会一直挡住委派。
6. **顺带**（待办里的三条，加开发者 2026-11-09 提的一条）：任务页排队时写出原因，维护失败的原因不露出校验的标识，会话视图那项在负载下失败的单元测试；时间轴上停止的发起者写成“由 Host 停止”这类说法，不写“Host 停止”，免得读成 Host 自己停了或崩了，其余发起者同样改，英文的 “Service stopped” 同理。

### 0.67.2 之后

开发者 2026-11-10 在 0.67.2 上看过之后定的；Host 用日常黑板的只读快照在真实浏览器里出过原型图（深浅两色），开发者看过。依次由三个微任务做：布局、浮层的展开、文字。

1. **Router 三项工作移到上方。** 改掉“左边是三项工作的列表”与“0.67.1 之后”第 3 条：三项工作放在“目录 / Router / 评价”下面的一条工具带里，与目录页的筛选带同一层级；每项是带图标的小块（路由用路线，维护用扳手，画像用证件），选中的一项填底色，不用下划线，所以与上面的分区标签分得开；小块上不带状态。小块的底边贴着工具带下面的横线，只有上面两个角是圆的（开发者 2026-11-10 在 0.67.4 上看过后定）。指着或键盘聚焦一项时，在它下方浮出这项工作做什么（原来块头的那句，ADR-021 第 16 条的“三个面的简短说明”）。路由需要处理时（未指定 Router、Router 不可用、路由连续失败），“路由”上加一个与 Router 分区标签上同样的橙点；维护与画像不加。
2. **块头删去。** 右侧每项工作的块头（名称与说明）删去。没有指定 buddy 时，“此项工作不运行，请指定 buddy。”写在维护与画像各自的 buddy 区里，只出现一次，画像原有的同义一句删去；维护与画像说明哪些内容会发给提供方的那行小字，收进 buddy 区标题旁的问号圈。区标题不再写“谁担任”（开发者：这种口语之前说过很多次）：路由写“Router 列表”，维护写“维护 buddy”，画像写“画像 buddy”。
3. **领域树的详情改由 i 圈打开。** 改掉“画法”里“定义在指着或聚焦那一行时出现在旁边的浮层里，不盖住名字”：指着一行、键盘移到这一行或它的详情开着时，名字右侧出现 i 圈；点 i 圈在它下方打开详情（定义、合并来源、重命名与合并），按 Esc 或点别处关上；点行本身仍是展开与收起；指着子领域时，父领域条里对应的一段照旧高亮。详情是点开的，开着时可以盖住下面几行的名字。自写的放置与避让代码删去，放置交给 Radix 的 Popover。
4. **下划线标签收紧。** 开发者觉得带下划线的标签行太高、字离下划线太远。字到下划线一律约 6 像素：顶栏从 44 像素降到 36 像素，Buddy 的分区栏从 48 像素降到 36 像素，评价详情两个标签的底边距从 12 像素改为 8 像素；任务列表那种标签本来就是 6 像素，不动。
5. **锚在控件上的卡片都用目标卡片的展开。** 开发者认为类似的浮层都用目标卡片那种展开会更好。点一个控件打开、锚在它旁边的卡片，即目标卡片、时间统计、会话覆盖、时间轴的图例、合并的记号、设置的问号圈与领域树的详情，都从打开它的控件处展开，方向随卡片开在控件的哪一侧；展开的前沿线只在目标卡片上用目标的颜色，其余用中性的墨色，免得一种颜色在任务页上有两种意思（ADR-029 第 8 条）。悬停提示、下拉菜单与模态对话框不变：提示随指针频繁出现，展开显得慢；菜单是一列动作，不是卡片。放置一律交给 Radix 的 Popover，目标卡片也改过去，删掉自己的放置代码，外观与展开不变。点开的卡片开着时可以盖住下面的内容，直到用户关上它：去掉左边的列表之后，设置的问号圈会压住下面几行的输入，Host 在布局微任务里定为开在问号圈下方、左缘与这一项的标签对齐、离窗口边缘至少 16 像素，与领域树的详情同一条规矩。
6. **文字润色。** 界面文字按“标签写名词或固定状态词，不用问句与口语；完整句子只用于说明、空状态、错误与确认”逐条润色，两种语言共改 151 个键。例如“还没有”改“暂无”，“只看”改“仅显示”，“知道了”改“关闭”，“改名”改“重命名”，“擅长 / 不擅长”改“优势 / 不足”，“这次没读到”改 ADR-027 定的“待确认”，“可能卡住”改“疑似停滞”，“等待模型开始作答”改“开始作答时限”，探索名额写成“每 [5] 个微任务中 1 个”；harness 在中文里一律小写，helper 写“协助任务”，审阅模式的路由写“审阅”。核对时发现三处原文与代码不符，一并改正：探索名额的说明写成累计满 N 次之后的下一次，代码给的是第 N 次；“额度被拒，已改派”在满载时同样发生，改为“提供方拒绝，已改派”；“停止请求未提交”实际是服务拒绝了请求，改为“停止请求被拒绝”。
7. **手写定位的排查。** 开发者问能否把手写的避让都换掉。领域树与目标卡片按上面两条换成 Radix 的放置；时间轴的缩放尺本来就是 Radix 的提示；刻度标签让开“适配”按钮、文字溢出的检测属于画图与量文字，没有库可替代，留着。会话面板自己写的“跟到底部”记进待办。

### 0.67.3 之后

开发者 2026-11-10 看过 0.67.3 之后定的；Host 用日常黑板的只读快照出过三版原型图，开发者逐版改过。由一个微任务做。

1. **模型抽屉重排。** 改掉“目录”一节里抽屉的“左边可用状态、并发与并发的提醒；右边推理强度的刻度带（等宽）与选中 buddy 的面板”：开发者说抽屉非常不均衡，左边只有两行，右边的刻度带每格都是只写一个词的宽框，理由的输入框拉满整行。现在：
   - 顶上一行是模型服务：状态、首次缺席的时间（待确认时）与并发；并发的范围错误与提醒在这一行下面。
   - 下面分两栏。左栏是 buddy：标题照旧写数目与启用数；每个推理强度一行，按从低到高排列，行首是启用开关（开发者：启用是最常用的快捷设置，属于推理强度这一层，免得每次挪鼠标），点这一行的其余地方是选中它，有偏好的在后面写偏好；选中的一行有底色，一直铺到两栏之间的分隔线。左栏的高度跟着右栏走，强度多、放不下时在左栏里滚动，打开抽屉或换了选中时，选中的一行滚到看得见的地方（开发者否掉了排两列：要做对齐，以后有更多、更细的强度就放不下）。左栏的宽度按内容定，只放得下开关、强度名与偏好词，其余宽度给右栏（开发者 2026-11-10：左栏只剩几个按钮了）。

   - 去掉“基础设施失败”：它数的是因提供方拒绝或 harness 不可用而结束的回合，机制已经把它们排除在评价之外，对用户是无用的信息（开发者）。Router 的路由依据里照旧有这个数，只是界面不显示。
2. **harness 的信息放进右侧栏。** 改掉“harness 展开三块”：模型行与 harness 节头都是点了在下面展开，开发者的师弟因此一直没找到模型的抽屉。现在目录页的右边是一栏 harness：按节的顺序依次列出每个 harness 的位置一块（状态、装着的版本与核实时的版本、路径、来源、检测时间、只读与只联网档位及说明、检测与指定路径）与账户一块（状态与各提供方的计费方式），不用点开就能看到，这一栏自己滚动。harness 节头不再点开什么；整个节头点了就收起或展开这一节，左端的箭头只是随之转动的记号（开发者 2026-11-10：判定更宽松，也更友好）；冷却与开放重试照旧写在节头，原来展开里那块冷却明细与节头重复，删去。窄屏放不下侧栏时，它排到列表下面。指向一个 harness 的地址把侧栏滚到它那一块并聚焦它。

1. **三项工作改为大标题。** 改掉“0.67.2 之后”第 1 条的工具带与小块：开发者觉得顶栏、分区栏再加一条工具带，标签栏叠得太多。三项工作是 Router 分区顶上的三个大标题（18 像素），没有图标；当前一项加粗、用正文色，其余淡色，指着时变正文色，键盘聚焦有焦点框；每项仍是一个链接，地址不变。指着或聚焦一项时，在它下方浮出这项工作做什么（原来小块上的那句，ADR-029 第 11 条）；路由需要处理时“路由”旁加橙点，条件不变。内容往下滚之后，标题下面出现一条细线。悬停提示的宽度上限加到 min(28rem, 屏宽减 2rem)，路由的说明不再折成两行。
