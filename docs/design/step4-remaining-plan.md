# 第 4 步（控制台）余下的事：执行计划

2026-10-17，整合 Host。控制台的重做与试用之后的修改已随 0.45.1 装上。本文把“顺序”一节第 4 步里余下的各项逐条核对过，写明哪些已经不用做、哪些挪到别处、剩下的怎样分批。

## 核对过、已经不用做的

- **执行期间租约为什么会过期。** [ADR-031](../decisions/031-one-process-per-execution.md) 之后，执行由服务直接起进程，没有租约，只剩资源占用的认领。
- **控制台把控制台的停止也画成 Host 的事件。** 重做之后，详情按执行记录里的 `stopInitiator` 写停止的发起者。
- **时间轴跨好几天时，刻度挤成一团。** F2 的比例尺让带字的刻度至少隔开 72px。跨天的刻度不写日期，要不要在零点处写，留给试用来定。
- **“等验收”的那一处前端判断。** 有了终态 `concluded` 之后，前端里的 `delivered` 只指等验收。
- **改名收尾时留下的三处小事。** 少空格的那句话与把回合说成 concluded 的几处已随重做消失；目录页对比度断言的偶发失败近来没有再见到。
- **控制台前端的重做停在 Buddy 页。** 重做已于 0.45.0 做完。前端源码里写死的中文只剩注释；服务写进回复的中文归到下面的批次二。
- **刷新控制台时，任务页的内容经常长时间加载不出来。** 在 0.45.1 上没有复现：日常看板上读宏任务列表要 0.2 到 0.3 秒。

## 挪到别处的

- **Buddy 页删除 buddy。** 这一条自己定了时机：等 Router buddy 的功能做完。Router 的几个面已于 2026-10-15 挪到首次发版之后，它随之挪后。
- **环境变量白名单的核对。** 原定随 ADR-030 的批次 5（代理的设置）一起看；批次 5 已于 2026-10-15 取消。它成了单独的一项核对，放进“没有排进去的，碰到了再做”。
- **设置页检查和安装更新。** 要先有发布渠道，随第 5 步。

## 分批

### 批次一：控制台的小批次（2026-10-17 开工）

两条上一批留下的顺带项，以及合成预览里由 Lead 发起的停止。只动前端与合成预览，不改契约，装的时候只动末位。

### 批次二：黑板一侧，一次升级（0.46.0）

1. **有结构的原因。** 服务写进回复与记录的文字改成原因的代码与参数，文字由读的一侧按语言给出：控制台走文案，给 Host 的回复带代码与参数。涉及的地方：
   - 路由不可用的原因；
   - harness 检测的处置办法；
   - 路由边界与等待原因；
   - 黑板替 Lead 写的关注请求与结论说明；
   - 存储的分类名；
   - 宏任务的事件名与“未命名微任务”；
   - 控制台入口失效时的页面。

   Worker、Host 与 Lead 自己写的文字是内容，不在此列。记录里黑板写的句子在升级里换成代码。
2. **推理强度的顺序由 harness 声明。** 随模型目录带到控制台，控制台照此排列，删掉写死的总表。2026-10-17 核对：各 harness 的原生目录本来就按自己的顺序列出推理强度，看板存着原始回复，只是 `buddies` 表按行存、顺序丢了；Host 定为从当前那次目录读，不改存储；2026-10-17 做完，在批次二的分支上（[验收记录](../acceptance/console-frontend.md)）。
3. **删除宏任务（[ADR-028](../decisions/028-macro-task-deletion.md)），黑板一侧。** 先由实现方照 ADR 与现在的代码起草一份执行计划：
   - 删除的依赖顺序；
   - 文件与 Git 引用的处置；
   - 各 harness 的会话怎样删；
   - 结果事实怎样不再指回已删除的微任务；
   - 删除记录的表；
   - 升级。

   这份计划由 Host 审，并请另一个模型独立审一次，看有没有层层设防。计划定了再实现。

   2026-10-17：计划第 1 版经 Host 与 Opus 分别审过、打回，第 2 版于同日接受，见[执行计划](macro-task-deletion-plan.md)：先打删除标记，再删物理内容，最后一个事务删记录；Codex CLI 的会话经它的 app-server 的 `thread/delete` 删除（Host 实测）。开发者同日定：L7 之前的删除不保留结果事实（[ADR-028](../decisions/028-macro-task-deletion.md) 的补充）。实施分五个微任务：升级与存储形式、Router 归属的根因修复、删除引擎、harness 会话、控制台后端与契约。

批次二改了契约与存储的形式，安装要求看板空闲并做校验过的备份。它改了控制台读的回复（例如请求的 summary 与结论的 note 可以为空），控制台跟上要等批次三，所以 0.46.0 与批次三一起装（2026-10-18）。删除要在日常规模的私有副本上演练并量出耗时（ADR-028 的验证边界）。

### 批次三：控制台

- **删除：** 宏任务上的删除入口与确认框，照 `docs/design/console-frontend/` 里剩下的两份稿。
- **原因：** 有结构的原因按语言显示。第 4 项之后问询消息的 `reason` 是原因对象，任务详情仍按字符串读它（`task-detail/parse.ts`），不改的话带原因的消息会让详情页解析失败（日常看板上有 3 个微任务）。
- **推理强度：** 排序已随批次二做完，这里只剩两处顺带项（类型必有、合成预览补上位置）。
- **时间轴的滚动条：** 开发者 2026-10-18 提出。宏任务页的微任务名字列与时间轴轨道共用一个竖向位置，却各有一条原生滚动条，靠 `onScroll` 互相同步；ADR-029 第 1 条要滚动区用共用的基础，宏任务列表已经在用。改成共用的滚动区：竖向只在轨道右缘留一条，名字列照常能滚、不显示自己的；横向与竖向都和列表一样只在悬停或滚动时出现，不占宽度。缩放保持锚点，定时更新时滚动条不闪（ADR-029 并入的待办）。
- **微任务条目单击打开：** 开发者 2026-10-18 定：时间轴左栏的微任务条目单击就打开详情；时间轴上的时间片、记号与事件照旧单击选中、双击打开。
- **详情顶部的时间片行：** 开发者 2026-10-18 定：微任务详情的各步不再挂在左栏展开的那一行下面，改为详情顶部常驻的一行，就是这个微任务在时间轴上的那一行，沿用时间片的画法；能横向滚动，第一次打开时聚焦到打开的那一段，之后不跟随；点其中一段切换下面的内容。左栏只用来切换微任务，不再展开。先出静态稿，开发者认可后实现。
- **Lead 的泳道：** [ADR-026](../decisions/026-delegation-authority.md) 第 10 条，开发者 2026-10-18 定随批次三做；归属早已完整存下，不需要新的存储。先出静态稿，开发者认可后实现。
- **并行设置处的风险提示：** 开发者 2026-10-13 定下要加。措辞只陈述官方的说法与出处，见[调研](../research/2026-10-13-harness-terms-and-orchestration.md)。Host 起草之后先给开发者看。

## 顺带

- **从控制台停止的宏任务，里面的微任务停在“已取消”。** 删除宏任务做完之后，用户可以删掉整个宏任务来了结它们（ADR-028 第 4 条）。这一条随批次三关闭。
