# ADR-031 M1：执行进程

本说明记录 M1 的实现与受影响范围验证，最终验收由 Host 完成；M2 及后续阶段尚未实现。

## 入口与材料

Worker 认领后经 `owned_popen` 以新会话启动 `python -m hey_my_buddy.buddy.runtime.execution --startup <私有启动文件>`，每次执行一个进程。命令行只有文件路径，任务、执行、回合、Router 冻结输入、凭据、`workerId` 与 nonce 均由私有启动文件传入。入口在导入运行模块及读取文件前保存 SIGTERM、SIGINT 等停止信号，建立执行对象后重放。

证据目录为 `attempts/<runId>/<attemptId>/`，只保存 `protocol/attempt_evidence.py` 声明的不涉密证据，包括 `spawn.intent`、`spawn.marker` 和执行进程的两份日志。私有目录由 `private_dirs.attempt_root(state, actual_adapter, task_id, attempt_id)` 计算，即 `harnesses/<adapter>/micro-tasks/<…>/attempts/<attemptId>/`；Router 使用实际 CLI harness 的适配器名。`execution-start.json`、`execution-live.json`、`execution-stop.json`、`execution-budget.json`、`result-receipt.json`、`result-delivery.json` 与原生进程日志都放在私有目录，目录和文件分别使用私有权限，备份不复制这些材料。启动文件中的凭据和端点令牌通过现有 `cleanup_attempt_credentials` 的精确文件名集合，在确认原生停止后删除；清理失败只记日志，不改变回合的结果。

## 合并后的结构

执行进程负责预检、准备回合、原生调用、Router 预算、Host 总结宽限、收集与归类、部分产出补充、回执持久化与交付。Worker 回合及 Router 的 fast、review 直接在进程内调用 `run_harness`，通过对象返回结果；命令继续启动独立会话的子进程。模型启动前失败的重试创建新的原生调用，执行进程身份不变，每个原生身份仍写入同一执行进程的日志。

每次原生调用及总结回合仍注册自己的 `HarnessRunLive` 端点。执行进程通过当前端点对象读取活动；Worker 的在线转发读取私有 `execution-live.json`，在跨进程边界核对身份、令牌和端点凭据。已核实的端点描述保存在持有的执行句柄中，凭据清理之后仍可清理这个执行进程留下的端点。服务仍经 Worker 转发，服务直接连接执行端点留给 M2。

## 停止与证据

Worker 每 2 秒读取服务的停止意图，写入绑定任务、执行与代次的私有停止请求，再向执行进程发送 SIGTERM。Host 或 Lead 的 wrap-up 保留服务给定的绝对宽限，重复请求不延长它，第二次停止与强停会取消当前原生调用。执行进程的本地控制线程将停止传给进程内运行，等待它真正结束后才收集；取消后的等待没有额外的 10 秒截断。

Worker 提供外部时限：强停及 Host 宽限到期后，执行进程在 8 秒内仍未退出，就强杀其持有的进程组或 Job。Router 的单调时钟期限在输入准备完成、原生启动之前写入私有预算文件，Worker 按同一期限执行外部升级，不把预检等待算进预算。已有确认原生停止的待交回执时，Worker 允许执行进程继续等待服务恢复交付，不再因停止宽限杀死交付者。

`shutdownConfirmed` 表示本次执行为运行创建的进程全部已停：CLI harness 依靠原生停止证据，命令依靠其实际进程组。执行进程交出回执后才退出，它的存活与原生停止是两个事实；执行进程主 PID 消失也不单独证明其进程组、Job 或原生会话已停。

Worker 回收执行进程时先确认其完整进程组或 Job 已结束；持有句柄仍观察到组内存活者时先清理该组。没有确认原生停止的待交回执，就读取该执行进程的原生日志，以现有 `read_native_process_journal` 和 `stop_orphan_process` 核实并停止记录在案的存活者。未决创建不妨碍清理已知身份，但只有日志完整、没有未决创建、全部原生身份均已不在时才确认整个执行停止；缺失、无法核实或未决的证据保持未知。启动、`spawn.marker` 写入或监督失败及外部强杀都经过同一接力边界。

## 回执与交付

执行进程先 fsync 写入私有 `result-receipt.json`，再调用 `worker_result`，传输失败按退避一直重试，直到服务确认或明确拒绝。活动与等待原因在内存里各保留最新值，每次交结果前先尝试交提示，提示失败不挡回执。服务离线期间原生工作照常结束；执行进程继续保留待交回执并等待。

回执不包含 nonce，执行进程从内存取 nonce，Worker 接力时从其启动或孤儿意图取 nonce。服务确认或拒绝后先 fsync 私有交付确认，再删除待交回执；相同 `commandId` 保持丢失回复后的幂等重放。一个回执同时只有一个交付者：Worker 的重新附着、主循环与退休入口，均先按 `spawn.marker` 的完整身份确认执行进程已不在，存活或未知时不接手。回收时没有回执，Worker 写失败回执并按日志事实填写停止确认，再调用同一交付代码。

## Worker 剩余职责

Worker 保留注册、认领、启动意图、执行进程创建与身份发布、续租、读取停止意图、在线转发、外部停止升级、回收与孤儿处理。Worker 的启动意图记录实际私有适配器，便于重启与退休时定位同一私有目录；Worker 池也用这份意图计算未交付证据。Worker 目录不再有结果回执队列，私有执行回执和交付确认不进备份。

## 删除与后续

运行控制入口只保留模型发现；Worker 回合、fast、review 的运行控制进程及控制、请求帧、stdout 结果帧、verdict 文件交接都已替换为进程内对象。删除了退休的请求和结果帧编解码及大小常量、只测试这些帧和伪造进程内结果降级的测试、执行进程读取自己端点的 RPC、未设置的状态、单元素循环，以及 `_Renewal` 的适配器字段和预检唤醒等待。进程内结果遵守断言，不再按外来帧重复校验；模型产出、磁盘原生证据和真正跨进程的材料仍在各自边界校验。

Host 授权的服务配套修改限于统一读取原生进程日志，以及 Worker 池和备份的回执读取调整：命令也记日志，`blackboard/tasks/interruption.py` 不再按适配器排除，服务恢复与 Worker 孤儿处理使用相同的日志路径与候选。服务的调度、认领、`workers` 表、租约列、`attempt_process_identities` 及 `previousProcessStopped` 链、schema 22 均未改变。服务的 Worker 池、supervisor、Worker 身份、续租、实时转发及服务恢复主体保留到后续阶段；没有实现 M2 至 M4，也没有改 `docs/reference`。

## 验证

所有 Python 测试均经 Host 指定解释器的 `python -m hey_my_buddy.cli.checks <受影响文件或目录>` 运行，使用默认进程数；没有运行完整检查、安装产品、操作日常服务、运行真实 CLI harness 探针或调用付费模型。CLI harness 测试均使用离线夹具。Windows 创建继续使用现有 `owned_popen`，本机未验证 Windows 和 Linux 的实际进程行为。

本轮聚焦验证已覆盖：私有文件的位置与权限、无 nonce 的回执与备份排除、清理失败保留原结果、两个服务失联完成场景、提示先于回执、明确拒绝后退出、真实执行进程被杀及被冻结后的命令接管、真实 `spawn.marker` 写入失败、完整进程组的交付门槛、活着的执行进程独占交付、超过 10 秒的原生清理、读取启动材料前后 SIGTERM、Router 冻结输入全文相等，以及 DSH CLI、Codex CLI、ZCode CLI 夹具经真实执行入口写出的服务可定位原生日志。较早并行修改期间的检查失败已用于修正遗留断言，最终受影响批次结果在最终核对时记录；本说明不是 Host 验收。

本轮受影响批次覆盖 187 个测试文件：Buddy 全部目录、服务、路由、派发与工作流、所改存储恢复、协议、安装，以及 Host 指出的评价与私有目录文件；首次组合运行有 179 个文件通过，8 个文件暴露旧句柄、目录或夹具断言，随后全部在修正后复查通过。没有将这次选择运行称为完整检查，也没有把不同批次重复的用例数相加。

最终复查包括：运行时全目录、工作流 Worker 和 C-Two 集成的 17 个通过文件（150 个用例）；六个角色、ZCode CLI 夹具、工作流与活动文件（146 个用例）；Router 决策、预算和冻结输入三个文件（139 个用例）；并行派发与真实接管两个文件（32 个用例）；备份、Windows 备份模拟、评价与私有目录五个文件（69 个用例）。运行时复查同批的决策文件随后在三个 Router 文件的复查中通过；其他上述聚焦批次均退出 0，检查运行器均报告私有根已清理。

最后一次执行入口、真实接管与 C-Two 集成复查共 3 个文件、21 个用例通过，退出 0，私有根已清理；`git diff --check` 通过。
