## A. 停止证据与“不知道不等于已停”

A1（高）：执行进程在写回执前崩溃，而原 Worker 仍活着时，独立原生进程组没有接管路径。`src/hey_my_buddy/buddy/runtime/worker.py:629-644` 保存并监督的是执行进程身份；`src/hey_my_buddy/buddy/runtime/command.py:54-68` 在执行进程内再用 `start_new_session=True` 创建命令的独立进程组。只杀执行进程可以留下命令；Worker 在 `worker.py:661-679` 写入并提交 `shutdownConfirmed=False`，随后 `worker.py:591-592` 清掉启动意图，既未读取原生日志也未停止命令。服务虽然在 `src/hey_my_buddy/blackboard/store/store.py:2504-2508,2557-2572` 保留未确认尝试及资源，但 `src/hey_my_buddy/blackboard/tasks/interruption.py:108-114,138-140` 对“原 Worker 身份仍在”的记录跳过恢复与候选生成，因此空闲 Worker 的 `recover_orphans()` 同样拿不到它。这没有把未知误报为已停，却使仍能写工作区的命令失去实际监督；该 Worker 即使继续做别的微任务，也会继续挡住这份记录的恢复。命令原先直接由 Worker 持有，新增执行进程使这一中间进程崩溃窗口进入命令路径；修复可以在当前 Worker 的退出接力边界完成，无须提前实现 M3 的整个恢复方案。

A1 的复现或证伪做法：在私有服务上让真实 Worker 执行一个等待释放标记的命令，等 `spawn.marker` 和原生日志完整写出后，只杀 `spawn.marker` 中的执行进程，保持 Worker 存活；确认失败回执为 false、原生日志中的命令身份仍为 alive，再经过恢复调用和服务 sweep，要求命令被按完整身份接管停止且资源只在确证后释放。当前 `tests/python/buddy/runtime/test_execution_process.py:404-439` 已构造前半段，但最后由测试主动写释放标记让命令退出，没有验证接管；这正好不能证伪本问题。若执行进程退出前已经留下合法回执，正常监督路径 `worker.py:641-644,668-679` 会重放原回执，是否停止仍取回执的事实，不从执行进程退出推导。

A2（中）：Router 超时后可以在线程尚未收完原生停止证据时固化 false 回执，之后的确定证据没有收集入口。`src/hey_my_buddy/buddy/roles/run_execution.py:95-107` 的 `InlineRunHandle.terminate()` 只设置取消事件；`src/hey_my_buddy/buddy/runtime/execution.py:368-385` 在 Router 预算到期后仅再等 10 秒，无论线程是否结束都调用 collect，随后在 `execution.py:423-433` 写回执。DSH CLI 的正常清理路径就能超过这一窗口：`src/hey_my_buddy/buddy/harnesses/dsh/native_run.py:1478-1487` 调用 shutdown，`dsh/acp/connection.py:838-877` 依次等待写线程、stdin 锁、stdout drain 和 stderr，`dsh/acp/client.py:178-186` 还可等待 leader 5 秒，必要时才由 native_run 终止进程组。在线程返回前，`run_execution.py:500-507` 尚未把最终 result 和 done 写回，collect 因而得到 false；`src/hey_my_buddy/buddy/roles/router.py:112-116` 还缓存该 outcome。false 在当时是诚实的未知，但原生组稍后证实 gone 后没有重新收集，服务会继续保留资源，并可落入 A1 所述的“Worker 仍活，恢复跳过”状态。非 daemon 的运行线程还会使执行进程在交完回执后等待线程结束；不能据此声称普通 DSH CLI 流程必然无限挂起。

## D. 过度防御、重复与遗留

D1（中）：执行进程和重启 Worker 可以同时成为同一回执的发送者，接力没有始终受“执行进程已退出”约束。`src/hey_my_buddy/buddy/runtime/worker.py:362-373,595-610` 在 reattach/run_once 重放前只检查磁盘回执，退休路径第 342-353 行也如此；没有核对旧执行身份是否已经消失。服务停机时执行进程写好回执并等待重试，旧 Worker 崩溃，新 Worker 可以先恢复并提交该回执，旧执行进程仍活着且持有最新提示。服务幂等判断通常避免重复完成事件，但两者会并发写 DELIVERY、删 RECEIPT，新 Worker 也没有执行进程内存中的提示；结果先提交后，提示会被终态拒绝。这不是删除 Worker 调度的 M2 问题，而是 M1 已迁移的发送所有权仍被旧重放入口越过。应在私有夹具中保留活执行、重启同 ID Worker，记录各发送者和事件次序，要求只在确认执行退出后才接力。现有 `_Renewal._recover()` 第 832-837 行已经遵循这个原则，其他重放入口没有。

D2（中）：旧跨进程 request/result/verdict 的防错逻辑改读内存后，仍按不可信外部帧层层容错。`src/hey_my_buddy/buddy/roles/run_execution.py:517-555` 再核对同一调用返回对象的 harness/identity、request identity、verdict 精确键集与 elapsedMs 类型；第 709-721 行再检查本进程生成 verdict 的布尔字段、错误键集及字符串长度。这些对象由 `roles/inline_run.py:159-169,192-211` 和 `_launch()` 第 500-507 行直接传回，已没有原 stdout 或请求/判定文件的进程边界。可保留明确的内部不变量断言并让编程错误暴露，继续整套“无效外部结果”降级会掩盖本模块的错误。磁盘 evidence 的大小/哈希、服务输入、模型产出与真实跨进程 live 材料校验有独立边界，不属于本条。

D3（低）：运行控制帧的生产读写已删除，专用编解码及若干搬迁残留未一起清理。`src/hey_my_buddy/buddy/harnesses/run_contract.py:645-670,695-704` 的四个 encode/decode_run_request/result 函数与帧尺寸常量在 `src/` 已没有调用者，只剩导出和测试/夹具使用；继续保留并以 round-trip 测试证明自己，不能说明执行仍需要这套文件传输协议。应保留实际使用的 RunRequest、RunResult 和它们的领域约束，重新裁定已失去生产边界的帧辅助代码及其专属测试。另 `runtime/execution.py:349` 的 `live_release_attempted` 已无设置者，`runtime/worker.py:405-418` 的单元素 records 循环来自旧两次控制进程身份重放，`_Renewal` 第 694-705、750-760 行的 implementation 字段和 wait/_wake 预检接口已不再承担迁入执行进程的预检职责；这些是具体可删的搬迁残留，不要求提前删掉整个续租线程。

D4（低）：执行进程通过磁盘和 C-Two 读取自己进程内的原生活动，保留了内部绕行。`src/hey_my_buddy/buddy/roles/inline_run.py:34-43` 在执行进程中创建端点，`runtime/execution.py:523-531` 的本地控制线程仍经 `roles/live.py:40-76,79-103` 读 `execution-live.json`、校验自己的 PID/IPC 域，再对自己发 observe。Worker 为服务转发读取该文件确有跨进程边界，M1 需要保留；执行进程自身可从持有的端点或进程内活动发布对象取得同一事实，不必再次绕过文件与 RPC。顺带，`roles/live.py:58` 将刚从 descriptor 解析出来的 instance_id 与同一载荷字段比较，`roles/live.py:123` 将 `handle.process.pid` 与直接返回同一 PID 的属性比较，均没有增加独立证据。此条是精简建议，未据此宣称出现错误停止结论。

成立的保留项：Worker 认领、身份发布、续租、每 2 秒读取停止意图、私有停止文件加 SIGTERM、服务经 Worker 的转发，以及当前孤儿记录均为 M1 明确保留；执行的本地控制线程不调用 renew，不算第二份续租机制。`src/hey_my_buddy/buddy/roles/run_controller.py` 仍用于模型发现，`roles/run_execution.py:832-875` 仍真正起发现子进程并读取其结果，因此 `buddy/harnesses/controller.py` 的创建边界、发现结果读取和内外停止合取有现存用途，不能整模块按遗留删除。`roles/live.py` 给 Worker 使用的普通文件、大小、尝试身份、PID、端点凭据及 IPC 域检查，`run_execution.py:110-121` 对磁盘原生证据引用的核对，以及 Router 冻结输入校验都处在真实边界，保留有依据。源码没有新增执行侧 SQLite 写入，也没有修改 schema、存储升级、认领或租约契约；不能因为这些后续项仍在而否定 M1。
