# 工作目标浏览（0.15.1）：精简交互设计稿

状态：设计稿，供实现与审查使用；不是实现、验收或安装记录，未经浏览器验证。Host 已修订本稿的数据与停止边界，以 docs/reference/console.md 与 objectives.md 的 0.15.1 契约为准；schema 仍为 12。未提到的部分沿用 [0.15 设计稿](objective-browser-0.15.md)（下称“0.15 稿”）与当前实现；本稿与 0.15 稿冲突时以本稿为准。第 9 节记录 Host 对契约和技能边界的定稿。

## 0. 层级用词

界面统一使用四级用词，并在工作目标头部用一行小字说明（第 3 节）：

| 层级 | 含义（界面上的一句话说明） | 数据来源 |
| --- | --- | --- |
| 工作目标 | 用户的一项议程，只用于归档与浏览，本身不执行、不验收 | `ObjectiveSummary` |
| 委派 | Host 为该议程提交给 Worker 的一项工作（根委派），单独验收 | `TimelineRow.depth = 0` |
| 协助任务 | 委派执行中经批准派生的子工作，由所属委派整合，不单独验收 | `TimelineRow.kind = "helper"` |
| 回合 | 委派或协助任务的一次执行；接续会增加回合 | 执行片段（按 `turnId` 去重，缺失时每段算一个） |

现有文案中的“根委派”改为“委派”，“N 轮”改为“N 个回合”，只在工作目标层提供“停止目标”。

## 1. 布局与断点（按视口）

断点只按**视口宽度**判断（`matchMedia`），不再按右栏容器宽度切换模式；实测右栏宽度只用于夹紧数值。删除 0.15 的上下停靠（`right-dock.stack`）与 1000px 容器阈值。

| 视口 | 未打开详情 | 打开详情 |
| --- | --- | --- |
| ≤760px | 分层：列表 → 工作目标 | 分层：列表 → 工作目标 → 详情（第 6 节） |
| ≥761px | 列表列（沿用 SplitView：默认 330，260–480，≤50%）｜时间轴 | 窄侧栏 48px ｜ 时间轴列 ｜ 分隔线 ｜ 详情列 |

**窄侧栏（rail）**：打开详情时列表列自动收成 48px 竖条（右侧 1px `--line`），列表列宽度记忆保留，关闭详情后恢复。竖条自上而下：展开按钮（竖排“工作目标 ›”，`aria-expanded`）、当前工作目标的状态图标。展开后列表以**浮层抽屉**覆盖在右栏左侧（宽 320px，不超过视口 − 48 − 200，阴影 + `--surface` 底），右栏几何不变；点击外部、Esc 或再次点击竖条关闭，焦点回到竖条按钮。抽屉里选中**同一**工作目标只关闭抽屉；选中**另一个**工作目标会关闭详情、恢复完整列表列，不需要确认（记录只读，无草稿可丢）。

**右栏几何**（R = 实测右栏宽度 = 视口 − 48）：

| 量 | 规则 |
| --- | --- |
| 分隔线 | 命中区 10px，视觉 2px（沿用 `dock-divider`） |
| 详情列 D | 默认 `clamp(360, round(0.4 × R), 600)`；最小 360；最大 `min(720, R − 10 − 320)` |
| 时间轴列 T | `R − 10 − D`；硬下限 320（由 D 最大值保证） |
| 时间轴内容最小宽 | 560 = 标签列 + 轨道 ≥380；T < 560 时时间轴在自身列内横向滚动，标签列吸左（沿用 sticky） |
| 标签列 | T ≥ 760 用 240px，否则 180px（按时间轴列容器查询） |

按上式估算（未计外边距与滚动条，实现以实测 R 为准）：

| 视口 | R | D 默认 | T | 时间轴 |
| --- | --- | --- | --- | --- |
| 900 | 852 | 360 | 482 | 横滚（内容 560），标签 180，D 最大 522 |
| 1024 | 976 | 390 | 576 | 不横滚，标签 180，D 最大 646 |
| 1280 | 1232 | 493 | 729 | 标签 180，D 最大 720 |
| 1440 | 1392 | 557 | 825 | 标签 240，D 最大 720 |

实现注意：时间轴当前以 `滚动区宽 − 标签宽` 计算轨道视口（下限 120），需改为下限 380，使内容不小于 560 并出现横滚。检查器、弹层、委派卡条随时间轴列宽度收缩，卡条本来就横向滚动。

## 2. 分隔线：拖动与键盘

- 结构：`role="separator"`、`aria-orientation="vertical"`、`aria-controls` 指向详情列、`aria-valuemin/max/now` 为 D，`aria-valuetext` 写“详情 480 像素，时间轴 729 像素”。DOM 顺序为时间轴 → 分隔线 → 详情，Tab 可达，有可见焦点环。
- 指针：pointer capture 拖动，拖动中禁用文本选择、`cursor: col-resize`，实时夹紧到 [360, D 最大]；无过渡动画。双击复位为当前视口默认值。
- 键盘：← 详情加宽 20px，→ 变窄 20px；Shift+←/→ 每次 80px；Home 为详情最小（时间轴最宽），End 为详情最大；Enter 复位默认值。
- 记忆：用户拖过后 D 以像素存在页面内存（不写 localStorage）；视口变化时只重新夹紧，不重置。未拖过时始终跟随默认公式。

## 3. 工作目标头部

头部自上而下，除时间统计外默认全部可见，目标总高 ≤ 约 120px：

1. **标题**（做什么）：一行，超出省略；标题规则见第 5 节。
2. **可选描述**：1–2 句，`muted`，最多两行截断，没有就不占位。使用新增 nullable description，不从任务或 Worker 结论拼凑。
3. **事实行，仅三项**：状态徽标 · “x/y 个委派已验收” · “最近活动 16:02（12 分钟前）”。y 为 `counts.roots`，x 为服务端对完整分组返回的 `counts.accepted`（已验收根委派数），不从筛选后的行计算。协助任务不单独计入进度。
4. **层级说明**：一行小字“工作目标 › 委派 › 协助任务 › 回合”，旁边“?”展开第 0 节的四句说明。
5. **时间统计（默认折叠）**：`<details>` 摘要写“时间统计”。展开后用通俗句子，数值仍由 `objective-metrics.ts` 计算，含义不变：“从开始到最近一次活动：5 小时 12 分”；“其间至少有一项在运行的时间：2 小时 3 分”；两者不同时再写“各回合运行时间相加：3 小时 40 分（有回合同时运行，所以更长）”；进行中写“还有 1 个回合在运行，时间算到 16:11”；结束未确认写“有 1 个回合没确认何时结束，没有计入”；不完整写“只统计了已读取到的记录：原因…”。项目、来源 Host、当前 Host 移到同一折叠区末尾的“记录来源”。

从头部移除：项目标签行、来源/当前 Host 行、计数行与“共 N 个委派”、底部 `tl-note`。委派卡条（≥2 个委派）与单委派卡保留，按第 4 节调整。

## 4. 委派概览：固定三行

凡是展示“一个委派的概览”的位置，都用同一个三行块，行始终渲染，缺失时写占位，不上下跳动：

| 行 | 内容 | 缺失时 |
| --- | --- | --- |
| 做什么 | 委派标题（第 5 节规则） | “未命名委派” |
| 目标摘要 | 任务原文开头：空白归一后取前 120 字，单行截断，前缀小字“任务开头” | “未记录任务原文” |
| 结果摘要 | Worker 最近一次结论（`summary` / `workflow.resultSummary`），单行截断，后缀小字“Worker 自述，非验收” | “尚无 Worker 结论” |

- **详情“概览”页签**：三行块置顶，其下是停止状态（第 7 节），原“目标与回合”的事实表收进“记录细节”折叠区。完整任务原文只在此页签的“展开完整任务”和“执行记录”页签中出现。
- **单委派卡、多委派卡与检查器**：统一固定三行；目标摘要直接使用新 DTO 的 `taskSummary`，结果使用 `summary`，均单行截断。无需逐卡额外读取 API。状态可用紧凑徽标，不能代替三行内容。

## 5. 标题规则

- **新标题**：每个新委派和新工作目标都必须带标题，≤30 字（按字符计），意图在前，例如“修复时间轴窄屏焦点恢复”。这是技能规则，契约上限仍为 200 字，控制台不拒绝旧数据；技能文本的修改不在本稿的写入范围（第 9 节 D2）。
- **显示**：`titleSource = objective / title` 原样显示，单行省略；超过 30 字的旧标题同样单行省略，`title` 属性给出全文。
- **历史回退**（`titleSource = task`）：取任务首行约 40 字，单行，末尾中性小标“取自任务首行”；`title` 属性只放这 40 字加“完整任务见详情”，不放原文。完整原文只在详情中显示（第 4 节）。
- `titleSource = none` 显示“未命名委派”。Worker 结论永远不进标题位。

## 6. 窄屏（≤760px）

- 三层切换：列表 → 工作目标 → 详情，每层顶部一个返回按钮（“‹ 工作目标列表”“‹ 返回时间轴”）；返回时恢复上一层滚动、选中与焦点。没有窄侧栏和分隔线。
- 工作目标层：头部同第 3 节（事实行可换行）；时间轴用 `ObjectiveChronology` 列表；检查器为底部抽屉（最高 45vh），点按只选中，“打开详情”为主按钮，不依赖双击。多委派卡改为纵向列表，默认显示前 3 张。
- 停止确认对话框宽度 `calc(100vw − 32px)`，按钮纵向排列、安全按钮在上。

## 7. 记录只读；唯一写操作：停止目标

**删除**（“工作目标”与“全部执行记录”两个视图的详情都适用）：协助请求的决定表单与 `HelperForm`、手工接续、`RoutingPanel` 中补齐配置的提交、移交控制权、最终验收（`workflow_acknowledge`）与普通记录的 `task_acknowledge` / `task_retry`、“重试同一操作”通用按钮、`RecordDrafts` 与 `useRecordDraft`、导航锁（`locked`、`onLockChange`、`navigationLocked`、`LOCK_TITLE`、`LOCK_NOTE`、列表条目的锁定禁用）。请求、路由依据、产物与整合证明、验收记录仍只读显示；原“处理请求”按钮改为“查看请求”，旁注“由 Host 处理”。详情栏目选择改为工作区内存里按 `runId` 记住的普通状态，不再借用草稿。

**保留**：仅工作目标头部的“停止目标”，二次确认明确目标名称及“全部未验收委派和协助任务”。使用新增 `objective_stop`，Host 已实现整组单事务取消；不要提供单委派停止或直接调用 `workflow_cancel`。已验收根保留；停止范围由服务端解析完整组，不能从当前筛选/截断列表拼装。

停止请求按 `objectiveId` 在工作区保存 commandId 和结果未知状态，不阻止导航。丢回复后只能用同一身份重试；旧会话禁用重试。取消意图已记录但任何相关执行未确认时写“正在停止”或“停止未确认”，仅全部相关根及协助任务都有证据时可显示“已停止”。时间轴只读结果需尊重 scopeComplete，不能用部分行声称整组停止。保留设置的单写权限。

**设置编辑**：模型、路由、评价等设置页签的编辑模式不变，仍受单写会话与写入闸门约束；本稿不改变它们。

## 8. 精简验收标准

1. 视口 ≥761px 打开详情时，列表收成 48px 竖条，展开为 320px 浮层且右栏几何不变；关闭详情后列表恢复原宽度。
2. 900 / 1024 / 1280 / 1440 下默认 D 与 T 与第 1 节表格一致（误差来自外边距与滚动条）；900 时时间轴在列内横滚且内容不少于 560px；任何宽度时间轴列不小于 320px。
3. 分隔线可拖动，键盘 ←/→（20px）、Shift（80px）、Home/End、Enter 复位均生效，`aria-valuenow` 同步；视口变化只夹紧不重置。
4. ≤760px 为三层切换，返回恢复滚动、选中与焦点；无竖条、无分隔线。
5. 头部默认只见标题、（有则）描述、状态 · x/y 已验收 · 最近活动、层级说明；用时统计折叠且为通俗句子，数值与 0.15 定义一致。
6. 详情概览、单委派卡的三行块始终渲染，缺失时显示占位；完整任务原文只在详情里出现。
7. `titleSource = task` 的标题为约 40 字单行并带“取自任务首行”；Worker 结论不出现在标题位。
8. 两个视图的详情里除“停止目标”外没有任何写控件，也没有草稿、锁定提示或锁定禁用。
9. 停止需二次确认；对话框写清停止整个工作目标下所有未验收委派及其协助任务；不确定回复可按同一 `commandId` 重试，离开详情后状态不丢；停止状态按第 7 节区分“停止中”“已停止”“未记录”。
10. 设置页签的编辑模式与单写会话行为不变；浅色/深色主题、`prefers-reduced-motion`、非颜色的状态提示均满足。

## 9. Host 定稿

目标描述由 Host 在首次提交时写入创建事件，≤300 字，无 schema 变更。短标题是 skill 规则（API 仍兼容可选 200 字），整组停止由新增浏览器专属 objective_stop 原子实现。以上取代 Opus 原稿关于描述隐藏、逐卡补读及单委派停止的建议。Host 对这些修订负责；本稿不证明实现或浏览器验收。
