# 工作目标成员与人工归档：待用户决定

本页只列出本轮未获实施授权的 A2、A3。0.15 修缮保留当前同项目、原提交 Host 的加入限制，也不添加人工归档写入口。

## A2：显式跨 Host 加入

可选方案一是保留当前限制，通过原 Host 委派或接续；实现边界简单，但 Codex 起头、Claude 接手后新开的委派无法归入同一目标。方案二是同一来源项目下允许调用方显式提交已有 `obj-` 标识，不根据标题或会话猜测；推荐此方案用于后续迭代。新委派保留自己的来源 Host，目标保留原始创建者，组成员身份不授予接管、取消、验收或读取私有控制文件的权限。

若选择方案二，需确认跨 Host 加入是否对所有已认证 Host 开放，还是需要用户为某一目标批准加入；后者需要独立的授权记录。项目身份仍由实际工作区解析，不能由客户端自报字符串冒充。重放同一请求必须保持相同目标绑定。

## A3：用户整理历史委派

建议后续提供“归入已有目标 / 新建目标并归入 / 移出目标”，仅由当前可写控制台会话发起，接受预期版本以处理并发编辑。操作目标应是根委派及其完整协助树；不要把协助单独移动到另一个目标，或把同一棵树拆成多个归档归属。只修改浏览归属、派生活动索引和追加事件，不修改任务说明、执行输入、产物、验收或 Host 控制权。

需要用户选择是否允许整理尚在执行的根委派。允许时须在一个事务中更新完整树并使后续协助继承新归属；不允许时只展示已停止的可选条目。两种方案都应保留变更前后目标 ID、用户会话和事件时间，以便解释历史并提供显式反向整理。旧目录和既有产物不随归档移动。空目标保留还是由用户显式移除，也应在实现前确定。
