## 控制台

- **"展开完整依据"另起一段重复显示全文。** 用户于 2026-10-01 指出：路由依据较长时（`apps/console/src/DecisionDetails.tsx` 约 81 行，超过 360 字），页面先显示截断的依据，再用 `<details>`"展开完整依据"在下方另渲染一整段完整文字，同一段话出现两次，按钮文字也冗长。建议改为在原位展开：默认显示截断文字，点击"展开"后同一段落替换为全文，按钮变为"收起"；其他同类的截断展开处一并检查。（2026-10-01）
- **时间轴的图标与文字会被后面的时间片挡住。** 用户于 2026-10-01 发现执行失败的"✕"被紧随其后的"等待 Host"片段盖住。原因：`apps/console/src/ObjectiveTimeline.tsx` 把结束标记（✕、⊘）、路由失败叉号和片段文字画在各自片段的元素内部，相邻片段按页面顺序叠放，后面的片段盖住前面片段的图标；`styles.css` 中 `.sp.routing` 带 `z-index: 1`，会形成独立的层叠上下文，内部图标即使提高层级也越不过相邻片段。建议给时间轴渲染定义明确的图层，由低到高依次为：时间片底色与边框（执行、排队、路由、等待 Host）、结束与状态标记（✕、⊘、降级标记、运行中脉冲）、文字标签、焦点与悬停等交互高亮。图标与文字所在的图层始终高于任何时间片；实现上可以把标记与文字放进时间片之上的独立定位层，或者去掉时间片自身的层叠上下文、按图层类统一设定层级。在真实浏览器中用"失败片段紧接等待 Host""多个片段贴边相邻"等夹具核对标记可见、可点击。（2026-10-01）

## ADR-021 待起草：路由输入与证据偏差

用户于 2026-09-30 指出快速路由过分依赖 Host 维护的评价卡片，最近几次都只选 GPT-6.1-Sol，容易形成信息茧房。本节收集相关问题，待起草 ADR-021（排在 B 批之后）；用户可能继续补充。

- **现象与证据。** decision `dec-5db666b9`、`dec-51725a3f`（Codex Host 为第 11 条发起的只读审查）的合法候选共 7 个，Router 都选了 `codex:openai:gpt-6.1-sol:high`。
  - Host 给了软偏好"优先 Codex"，Router 在理由中写"规格内的候选只有 codex 系四档"，把软偏好当成了硬约束，还凭空推测"task 的 timeout=60s"。
  - DeepSeek Flash（48 个样本）、GLM-5.3（40）、GLM-5.3-Flash（29）的卡片局限都写着"接受结果包含 Host 的修正"，这是所有委派的常态，却只出现在有历史的模型上，经验反而成了减分项。
  - 6.1-Sol 没有卡片，只凭用户备注"适合审查和复杂推理"入选；Luna 只有 1 次冒烟样本，被判为"缺乏证据"，缺少证据与负面证据被混为一谈。
  - Router 输入只有卡片、备注与偏好等文字，没有程序统计的成功率、耗时、token 用量与额度状态。
  - Host 按自己的习惯表达偏好（Claude Code Host 曾偏向 gpt-6-sol，Codex Host 偏向 Codex），把路由拉向熟悉的模型。
- **新例证（2026-10-01）。** 测试提速任务（decision `dec-15ab0cfd`，7 个合法候选）是多进程隔离与并发稳定性方面的复杂重构，快速 Router 选了 GLM-5.3 max，理由是 GPT-6.1-Sol"仅有单条只读审查样本"、GPT-6-Luna"仅有四项只读 smoke"、"均无编码质量证据"。用户评价 6.1-Sol 客观上强于 GLM-5.3，并已在备注中写明它适合复杂推理与代码逻辑实现，但样本数仍压过了备注。
- **客观参考数据。** 用户提议引入公开的基准分数作为客观参考。候选来源包括面向编码智能体的 SWE-bench、Terminal-Bench、Aider 的多语言排行榜，综合性的 LMArena（含 WebDev）、Artificial Analysis（同时给出速度与价格）、LiveBench 与 Epoch AI；对新模型的覆盖、更新频率与许可需先核实。注意：分数可能由厂商自报、存在数据污染、更新滞后于新模型，而且常在厂商自己的 agent 框架下测得，与本系统的 harness 和推理强度不一定一致。建议作为带来源与日期的"外部先验"数据，由用户或 Host 定期导入，不在路由时联网抓取；Router 在本机样本少时主要参考先验，样本积累后以本机证据为主；卡片与配置页显示先验的来源和日期。
- **改进方向。**
  - 引入带来源与日期的外部先验（公开基准分数、价格与速度档），与本机统计按样本量加权。
  - 程序从看板统计每个配置的委派次数、交付与验收比例、中位耗时、token 用量与近期额度状态，附样本量，与卡片一起作为 Router 输入。
  - 卡片的局限只记模型特有、有证据支撑的问题，不记"需要 Host 修正"这类普遍情况。
  - Router 原则写明：在能胜任的候选中选最便宜、最快的；软偏好只影响排序，不排除候选；没有证据不等于负面证据。
  - 低风险任务适度探索样本少但能胜任的配置，并在路由记录中标明。
  - Host 的任务偏好只表达任务需要（如"需要强推理""需要快"），不写厂商或 harness 名称。
