## 路由

- **Codex 0.159.0 的审阅验证失败，且证据没有保留。** 0.23.0 安装后用户在 Buddy 配置中重新验证 Codex 0.159.0（run `ecff1550`，约 41 秒），9 项检查中 nativePolicy、forbiddenTools、boundaryDenials、internalRead 四项失败，原因 `NATIVE_POLICY_UNVERIFIED`。这是 B 批第一阶段新检查器第一次在真实 Codex 上运行（第一阶段只用模拟事件测试过），无法判断是 Codex 0.159.0 的原生行为或事件格式变了，还是检查器没有正确读取真实事件；而结果中引用的 runner 日志并不存在，attempt 目录只剩启动标记，无法据此诊断。审阅 Router 因此保持不可用，按设计降级为快速路由。建议：先让检查保留足以诊断的脱敏证据（原生策略读回与相关事件摘要），再经用户批准重跑一次并据此修正检查器或确认 0.159.0 不满足只读要求。（2026-09-30）
- **没有重置时间的额度耗尽可能一直排除。** B 批第一阶段按原生观测把额度或余额耗尽的配置暂时移出自动路由，有重置时间的到点恢复；但没有重置时间的耗尽（例如 DeepSeek 余额为零）只能等更新的"可用"观测才恢复。DSH 没有主动的余额查询，被排除的配置也不会再被路由选中产生新观测，用户充值后仍可能一直被排除，界面也没有恢复入口。建议在 B 批第二阶段补上：Buddy 配置中为被排除的配置提供"重新检测 / 恢复"，或让没有重置时间的耗尽在一段时间（例如 1 小时）后允许重试一次。（2026-09-30）

## ADR-021 待起草：路由输入与证据偏差

用户于 2026-09-30 指出快速路由过分依赖 Host 维护的评价卡片，最近几次都只选 GPT-6.1-Sol，容易形成信息茧房。本节收集相关问题，待起草 ADR-021（排在 B 批之后）；用户可能继续补充。

- **现象与证据。** decision `dec-5db666b9`、`dec-51725a3f`（Codex Host 为第 11 条发起的只读审查）的合法候选共 7 个，Router 都选了 `codex:openai:gpt-6.1-sol:high`。
  - Host 给了软偏好"优先 Codex"，Router 在理由中写"规格内的候选只有 codex 系四档"，把软偏好当成了硬约束，还凭空推测"task 的 timeout=60s"。
  - DeepSeek Flash（48 个样本）、GLM-5.3（40）、GLM-5.3-Flash（29）的卡片局限都写着"接受结果包含 Host 的修正"，这是所有委派的常态，却只出现在有历史的模型上，经验反而成了减分项。
  - 6.1-Sol 没有卡片，只凭用户备注"适合审查和复杂推理"入选；Luna 只有 1 次冒烟样本，被判为"缺乏证据"，缺少证据与负面证据被混为一谈。
  - Router 输入只有卡片、备注与偏好等文字，没有程序统计的成功率、耗时、token 用量与额度状态。
  - Host 按自己的习惯表达偏好（Claude Code Host 曾偏向 gpt-6-sol，Codex Host 偏向 Codex），把路由拉向熟悉的模型。
- **改进方向。**
  - 程序从看板统计每个配置的委派次数、交付与验收比例、中位耗时、token 用量与近期额度状态，附样本量，与卡片一起作为 Router 输入。
  - 卡片的局限只记模型特有、有证据支撑的问题，不记"需要 Host 修正"这类普遍情况。
  - Router 原则写明：在能胜任的候选中选最便宜、最快的；软偏好只影响排序，不排除候选；没有证据不等于负面证据。
  - 低风险任务适度探索样本少但能胜任的配置，并在路由记录中标明。
  - Host 的任务偏好只表达任务需要（如"需要强推理""需要快"），不写厂商或 harness 名称。
