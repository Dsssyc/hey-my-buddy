# 待处理问题

用户在使用中发现、尚未进入实现的问题。每条写明现象、原因（已查明时）与建议；进入实现时移到对应的 ADR 或规格，完成后从这里删除并在验收记录中注明。



## 控制台

- **"展开完整依据"另起一段重复显示全文。** 用户于 2026-10-01 指出：路由依据较长时（`apps/console/src/DecisionDetails.tsx` 约 81 行，超过 360 字），页面先显示截断的依据，再用 `<details>`"展开完整依据"在下方另渲染一整段完整文字，同一段话出现两次，按钮文字也冗长。建议改为在原位展开：默认显示截断文字，点击"展开"后同一段落替换为全文，按钮变为"收起"；其他同类的截断展开处一并检查。（2026-10-01）
- **时间轴的图标与文字会被后面的时间片挡住。** 用户于 2026-10-01 发现执行失败的"✕"被紧随其后的"等待 Host"片段盖住。原因：`apps/console/src/ObjectiveTimeline.tsx` 把结束标记（✕、⊘）、路由失败叉号和片段文字画在各自片段的元素内部，相邻片段按页面顺序叠放，后面的片段盖住前面片段的图标；`styles.css` 中 `.sp.routing` 带 `z-index: 1`，会形成独立的层叠上下文，内部图标即使提高层级也越不过相邻片段。建议给时间轴渲染定义明确的图层，由低到高依次为：时间片底色与边框（执行、排队、路由、等待 Host）、结束与状态标记（✕、⊘、降级标记、运行中脉冲）、文字标签、焦点与悬停等交互高亮。图标与文字所在的图层始终高于任何时间片；实现上可以把标记与文字放进时间片之上的独立定位层，或者去掉时间片自身的层叠上下文、按图层类统一设定层级。在真实浏览器中用"失败片段紧接等待 Host""多个片段贴边相邻"等夹具核对标记可见、可点击。（2026-10-01）
- **"时间统计"浮层被面板左边缘裁掉，且只能再点一次按钮关闭。** 用户于 2026-10-02 在工作目标页发现：点开"时间统计"后，浮层左侧的文字被裁掉，每行缺开头一两个字；点击页面其他位置不会关闭，只能再点一次"时间统计"。原因：`apps/console/src/styles.css` 中 `.tl-head .time-stats-body` 以 `right: 0` 贴着按钮的右边缘向左展开，宽度可达 34em，而按钮位于标题栏靠左的位置，浮层越过了面板的左边缘，被 `.timeline-view { overflow: hidden; }` 裁掉；`apps/console/src/ObjectiveOverview.tsx` 用的是原生 `<details>`，只有点击 `<summary>` 才会开合，没有处理点击外部、Esc 与焦点移出。建议：浮层改为从按钮的左边缘向右展开，并把位置与宽度限制在面板可见范围内，不被面板裁切；点击浮层以外、按 Esc 或焦点移出时关闭，关闭后焦点回到按钮。在真实浏览器中核对宽窄两种窗口、状态行折行后按钮位于不同位置、以及高度不超过 800px 的紧凑形式；其他用 `<details>` 做浮层的地方一并检查。（2026-10-02）
- **模型列表的两个筛选不记住上次的选择。** 用户于 2026-10-02 指出：Buddy 配置的模型分区里，"只看已启用"与"显示不可用配置"每次进入都回到未勾选，要重新点。原因：`apps/console/src/BuddyConfig.tsx` 把两者存为组件内的状态，初始值固定为未勾选，页面重新加载或离开该分区再回来就丢失。建议：两个选择都保存在浏览器本地并在进入时恢复，做法与显示主题相同（`apps/console/src/theme.ts`），本地存储不可用时退回未勾选；它们是这个浏览器的查看习惯，不写入黑板。"显示不可用配置"目前靠勾选动作触发一次有界读取，恢复为已勾选时要在进入时自动发起这次读取；没有不可用配置、复选框不显示时，保留已存的选择而不报错。（2026-10-02）
- **文字与它所在的图形框不对齐，这类情况有很多处。** 用户于 2026-10-02 在任务详情界面指出："等待 Host"的文字底板与外面的边框错开，文字一侧多出一条底色；并指出当前控制台里同类的不对齐有很多，必须全部找出来修好。这一处的具体原因尚未查明：静态阅读代码无法确定截图对应的是时间轴上的等待片段（`apps/console/src/ObjectiveTimeline.tsx` 的 `.sp.wait`，带 1.5px 虚线边框、6px 内边距，悬停时另加偏移 2px 的外框）还是状态徽标（`ui.tsx` 的 `Status`），需要在真实浏览器里定位。建议按一次排查来做，而不是只修这一处：在真实浏览器中逐页检查带边框或底色的小元素（徽标、时间片及其文字、标记与旗标、分段按钮、筛选项、卡片标题行、浮层），覆盖默认、悬停、选中、键盘焦点、运行中与失败等状态，以及明暗两种主题、常见缩放比例与窄窗口；列出每一处不对齐及其原因后统一修正，并把时间片、徽标这类元素的盒模型规则（边框是否计入尺寸、文字的行高与内边距、外框的偏移）定成共用的写法，避免逐处微调。修好后留下对照截图作为验收依据。与上面"时间轴的图标与文字会被后面的时间片挡住"一条相关，宜一并处理。（2026-10-02）
- **设置里看不到版本，也不能检查和安装更新。** 用户于 2026-10-02 提出：控制台的设置页要显示当前版本，能检查更新，有更新时给出更新按钮，更新后自动重启。现状：设置页不显示产品版本，版本、契约、schema 与运行时标识只能通过 `buddy health` 与 `buddy runtime` 查看；更新只能由 Host 运行 `install` 或 `upgrade`；发布渠道与包名尚未决定，也没有发布过版本（见 [operations](../reference/operations.md) 的安装一节），所以"检查更新"目前没有可以比对的来源。建议分三步，前一步不依赖后一步：
    1. 显示版本。设置页显示已安装的版本、契约版本、schema、来源提交与安装时间，数据服务端已有。
    2. 检查更新。前提是用户先定下发布渠道并发布版本。检查由用户点击触发，只向发布渠道读取版本信息，不发送本机数据；设置中的数据流向说明补一句。有新版本时显示版本号与更新说明。
    3. 更新按钮与自动重启。用户点击即是对这一次安装的授权。更新沿用现有 `upgrade` 的全部保护：有委派在排队或运行时不更新，并列出是哪些委派；先备份并校验；失败时回滚并显示原因；涉及 schema 升级时在确认框中写明。控制台由被更新的服务自己提供，所以更新要由服务之外的引导程序执行，控制台只负责发起和显示进度；完成后服务自动重启，页面自动重连并显示新版本，同时提示已打开的 Host 会话仍在使用旧的 skill，需要新开会话。Worker 凭据不能触发更新。Windows 未验证。
  （2026-10-02）

## 安装与存储

**运行时目录的残留不会被清理。** Host 在安装 0.27.0 时发现：运行时清理把 37 个 `.install.lock` 文件、2026-09-23 与 2026-09-25 两次未完成安装留下的两个运行时目录和 9 个 `.build-*` 目录（合计不到 3 MB）判为无法证明是完整运行时而跳过，它们会一直留在 `runtime/` 下并逐次增加。建议：安装成功后删除本次用过的锁文件；清理时对超过保留期、没有被任何锁持有的未完成目录与孤立锁文件做受保护的删除。
