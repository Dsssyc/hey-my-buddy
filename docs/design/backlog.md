# 待处理问题

用户在使用中发现、尚未进入实现的问题。每条写明现象、原因（已查明时）与建议；进入实现时移到对应的 ADR 或规格，完成后从这里删除并在验收记录中注明。



## 控制台

- **"展开完整依据"另起一段重复显示全文。** 用户于 2026-10-01 指出：路由依据较长时（`apps/console/src/DecisionDetails.tsx` 约 81 行，超过 360 字），页面先显示截断的依据，再用 `<details>`"展开完整依据"在下方另渲染一整段完整文字，同一段话出现两次，按钮文字也冗长。建议改为在原位展开：默认显示截断文字，点击"展开"后同一段落替换为全文，按钮变为"收起"；其他同类的截断展开处一并检查。（2026-10-01）
- **时间轴的图标与文字会被后面的时间片挡住。** 用户于 2026-10-01 发现执行失败的"✕"被紧随其后的"等待 Host"片段盖住。原因：`apps/console/src/ObjectiveTimeline.tsx` 把结束标记（✕、⊘）、路由失败叉号和片段文字画在各自片段的元素内部，相邻片段按页面顺序叠放，后面的片段盖住前面片段的图标；`styles.css` 中 `.sp.routing` 带 `z-index: 1`，会形成独立的层叠上下文，内部图标即使提高层级也越不过相邻片段。建议给时间轴渲染定义明确的图层，由低到高依次为：时间片底色与边框（执行、排队、路由、等待 Host）、结束与状态标记（✕、⊘、降级标记、运行中脉冲）、文字标签、焦点与悬停等交互高亮。图标与文字所在的图层始终高于任何时间片；实现上可以把标记与文字放进时间片之上的独立定位层，或者去掉时间片自身的层叠上下文、按图层类统一设定层级。在真实浏览器中用"失败片段紧接等待 Host""多个片段贴边相邻"等夹具核对标记可见、可点击。（2026-10-01）

## 安装与存储

**运行时目录的残留不会被清理。** Host 在安装 0.27.0 时发现：运行时清理把 37 个 `.install.lock` 文件、2026-09-23 与 2026-09-25 两次未完成安装留下的两个运行时目录和 9 个 `.build-*` 目录（合计不到 3 MB）判为无法证明是完整运行时而跳过，它们会一直留在 `runtime/` 下并逐次增加。建议：安装成功后删除本次用过的锁文件；清理时对超过保留期、没有被任何锁持有的未完成目录与孤立锁文件做受保护的删除。
