# 工作目标时间轴：视觉与交互设计稿

状态：设计稿，供实现与视觉审查使用；不是实现、验收或安装记录。范围来自 [ADR-012 第十节](../decisions/012-claude-code-distribution-and-evidence-routing.md#十宏任务与委派时间轴) 的用户授权：界面名称“工作目标”，默认按最近活动排序，超过 30 分钟的真正空闲区间折叠且可展开。静态示意稿见 [`apps/console/design/work-objective-timeline.html`](../../apps/console/design/work-objective-timeline.html)，其中所有数据都是设计示例。

## 1. 不变量

- 工作目标只用于归档与浏览：不调度、不建依赖图、不作为路由输入、不增加验收条件，也没有“完成”操作。页面上不出现任何作用于工作目标本身的写操作。
- 时间轴只读，全部来自已记录的事实（ADR 第十节推导表）。读取不获取租约、不调用模型。
- 唯一的写入入口仍是现有委派详情（`TaskDetails` / `WorkflowPanel`）中的控件；时间轴、列表与标记不复制任何取消、决定、续接或验收按钮。
- 执行片段表示 attempt 的记录时间，不代表模型调用次数、token 或费用；页面不声明节省了多少成本或 token。
- 结束未确认一律显示为“结束未确认”，不显示为“已停止”。
- 顶部三个页签（委派记录 / 模型卡片 / 路由配置）、品牌区、编辑开关与其他页面保持不变；本设计只替换“委派记录”页签的内容。

## 2. 桌面布局（≥ 1100px）

沿用现有 `SplitView`：左侧列表栏（默认 330px，可拖动 260–480px），右侧详情栏。右侧详情栏有两层：工作目标时间轴，以及从时间轴打开的委派详情。

### 2.1 左栏：工作目标列表

- 工具条：标题“工作目标”，右侧“刷新记录”。筛选区保留现有的分段按钮（全部 / 进行中 / 待决定 / 待验收）、搜索、项目与委派方下拉。分段筛选作用于工作目标下的委派：只要有一项委派匹配，该工作目标就显示，计数不因筛选而改变。原“显示协助任务与内部执行”复选框移除：协助任务总是嵌套在时间轴中，内部路由计算作为“路由”片段出现并可打开。
- 分组：沿用 `group-heading`（▾ 项目名 · 已加载 N 个工作目标），项目路径放在 `title`。
- 条目（沿用 `task-row` 的尺寸、选中底色与左侧 3px 选中条）：
  - 第一行：汇总状态徽标 + 最近活动时间（相对时间，`title` 与 `dateTime` 给出绝对时间）。汇总状态按优先级取一项：待决定 > 进行中 > 待验收 > 已结束。
  - 第二行：工作目标标题，最多两行，超出省略。
  - 第三行：计数条，按“进行中 / 待决定 / 待验收 / 已结束”固定顺序，每项带图标与文字（● 进行中 2、◆ 待决定 1、✓ 待验收 1、■ 已结束 4），为 0 的项省略；末尾“共 N 个委派”。
  - 第四行：`来源 Host：<recorded source host>`，单行截断。
- 没有工作目标的旧根记录：各自作为一个条目，标题用该委派的标题回退，附中性标签“独立委派”。不做任何历史合并或按时间/文本猜测分组。
- 排序：最近活动时间倒序；同一项目内同样倒序，项目组按组内最新活动排序。

### 2.2 右栏：时间轴

自上而下：

1. **头部**（`detail-header` 样式）：项目名 · 汇总状态；工作目标标题（最多两行，完整标题在 `title`）；事实行“来源 Host：… · 共 6 个委派（含 1 个协助任务）· 最近活动 16:12”；同一计数条。一行小字：“工作目标只用于归档与浏览，不调度任务，也不作为验收条件。”
2. **工具条**：配置图例（色块 + `adapter / model`，按首次出现顺序）、状态图例（排队、路由、等待 Host、失败 ✕、已取消 ⊘、结束未确认 ?、执行中 ▸）、“展开全部空闲 / 折叠空闲”切换、刷新状态“每 3 秒只读刷新 · 截至 16:12:05”。
3. **截断提示**（有截断时常驻，见第 5 节）。
4. **时间轴画布**：单一滚动容器，时间刻度行吸顶，左侧标签列吸左（桌面 240px，中等宽度 180px）。
   - 刻度行：按可用宽度每 15 或 30 分钟一个刻度，跨日时刻度显示“09-27 00:00”；右端“现在”线（2px accent，标签“现在 16:12”）。
   - Host 标记轨：刻度行下方第一行，标签列写“Host 事件”。
   - 委派行：每个委派一行（40px），根委派按创建时间排序；协助任务紧跟在父委派之后，标签列缩进 16px 并以“↳”和细连接线表示层级，可多层。
5. **选中项信息栏**（固定 1–2 行高，位于画布下方）：显示当前聚焦或悬停项的完整事实：类型、委派标题、配置、开始–结束、时长、回合、结果；无聚焦时提示“悬停或聚焦片段查看记录；Enter 打开委派详情”。它代替浮动提示框，键盘与读屏同样可用。

标签列内容：状态图标 + 委派标题（单行截断，完整文本在 `title` 与信息栏）+ 第二行小字（执行配置，或“协助任务 · 执行配置”）。标题按现有回退：Host 提供的简短标题 > 该委派最近一轮已结束结果的摘要 > 原始任务首行 > “未命名委派”。信息栏可附“标题来源”，仅当契约能区分来源时显示。

### 2.3 打开委派详情与返回时间轴

- 单击或 Enter 片段、行标签、行上的结算旗标或 Host 标记，都在右栏打开该委派的**现有**详情（同一个 `TaskDetails` 组件，不另建控件集），并预选栏目：执行片段 → 执行记录（传入该片段的回合/attempt 标识，用于在已有记录中高亮；现有读取没有该回合时，只在定位条中显示时间轴已给出的回合事实）；等待 Host 片段与“决定”标记 → 协作与待办；验收标记与结算旗标 → 产物与验收；路由片段 → 路由依据（现有栏目，其中可进入内部路由计算记录）；排队片段与行标签 → 概览。
- 详情上方加一条定位条：“‹ 返回时间轴 · 工作目标标题 › 委派标题”，以及“来自时间轴：第 2 轮 · 执行片段 10:55–11:05 · codex / gpt-5-codex”。定位条在所有宽度下都是返回入口，此上下文中隐藏 `TaskDetails` 自带的 `mobile-back`，避免两个返回按钮。
- 时间轴在打开详情时保持挂载（`hidden`），返回后恢复滚动位置、展开的空闲区间与聚焦项，焦点回到打开详情的那个片段，并保留其选中描边。
- Esc 在详情中返回时间轴（焦点在输入框、文本域或下拉框中时不响应）。
- 详情里现有的协助任务跳转（`selectTask(childId)`）照常工作，定位条更新为子委派；“返回时间轴”回到同一个工作目标。

## 3. 视觉编码

| 元素 | 形状 | 颜色 | 非颜色标识 |
| --- | --- | --- | --- |
| 排队 | 6px 高细条，浅斜纹 | `--line-strong` 斜纹 | 信息栏“排队” |
| 路由 | 12px 高细条，密斜纹；宽度足够时内嵌“路由” | `--muted` 斜纹 | 文字“路由”，窄时见信息栏与 `aria-label` |
| 执行片段 | 22px 高实心条，圆角 3px；续接为同一行的新片段 | 按记录的执行配置（adapter + provider + model）分配 `--cfg-1…6` | 宽度足够时内嵌“第 N 轮 · model”；图例 |
| 等待 Host | 22px 高虚线框 | `--warning` 虚线，`--warning-wash` 底 | 文字“等待 Host” |
| 执行中 | 执行条右端开口渐隐 + 端点脉冲，延伸到“现在”线 | 配置色 | ▸ 与“执行中” |
| 失败 | 执行条加 `--danger` 描边 | 配置色 | 条尾 ✕ 圆标 + “失败” |
| 已取消 | 执行条叠加斜线 | 配置色 | 条尾 ⊘ 圆标 + “已取消” |
| 结束未确认 | 实心条至最后记录时间，之后点状描边尾段延伸到现在 | 配置色（淡） | “?” 圆标 + “结束未确认” |
| 结算 | 行上的小旗 | 验收 `--accent`，验收问题 `--danger` | ✓ 已验收 / ! 验收问题 |
| Host 标记 | 16px 圆角方标 | `--surface` 底、`--line-strong` 描边 | 派发 ▶、决定 ◆、续接 ↻、整合 ⊕、验收 ✓、验收问题 !、取消 ✕ |
| 空闲折叠 | 64px 宽锯齿断带贯穿各行 | `--subtle` | 刻度行“空闲 2 时 36 分 · 展开” |
| 现在 | 2px 竖线 | `--accent` | “现在 16:12” |

- 配置色在一个工作目标内按首次出现顺序分配，刷新时已有配置的颜色不变；超过 6 种时循环并叠加细条纹，图例同步显示条纹。颜色只表示实际执行配置，不表示好坏。
- 相距小于 14px 的 Host 标记合并为一个带数字的标记，聚焦后信息栏逐条列出，Enter 打开第一条对应的记录，信息栏中每条可单独打开。
- 聚焦或悬停 Host 标记时，在各行上画一条 1px `--focus` 参考线。
- 选中（从该片段打开过详情）的片段有 2px `--focus` 外描边，键盘焦点使用现有 `:focus-visible` 样式；两者可同时出现。

## 4. 空闲折叠

- 占用区间 = 所有片段（排队、路由、执行、等待 Host；执行中与结束未确认的片段一直占用到“现在”）与所有 Host 事件（前后各 1 分钟）的并集。
- 两个相邻占用区间之间超过 30 分钟时，这段空白折叠为 64px 的断带；时间轴只在断带两侧连续计时。正在执行的长工具调用、等待 Host、结束未确认的尾段都在占用区间内，永远不会被折叠。
- 断带的按钮位于刻度行，是画布之前的普通 Tab 停靠点，不参与画布内的方向键移动：Enter/单击展开，展开后区间以 `--subtle` 底色标出，刻度行出现“收起空闲 2 时 36 分”。工具条可一次展开或折叠全部。展开状态按工作目标保存在页面内存中，刷新不重置。
- 第一段占用之前与最后一段之后不画空白：时间轴从第一个委派创建开始，到“现在”（仍有占用）或最后一个事件结束。

## 5. 刷新、排序与截断

- 右栏沿用现有 3 秒轮询读取所选工作目标的时间轴。刷新只允许：延长正在执行/等待中的片段、追加新片段与事件、更新状态与计数。行按创建时间排序，已有行的相对顺序不变；新委派追加在末尾，标签列显示 3 秒淡出的“新”标记，不自动滚动，不移动焦点和选中项。
- 左栏的最近活动排序不在轮询中重排：计数与时间就地更新；若顺序应变化，列表顶部出现现有样式的提示条“有 N 个工作目标有新活动 · 按最近活动重新排序”，点击后才重排；已选中的工作目标无论排到哪里都保持选中。
- “现在”取最近一次成功读取的时间；读取失败时画布保留最后一次成功的数据，工具条显示“显示的是 16:11:42 的数据”并出现“重试读取”，执行中的片段停止延伸，不外推。
- 截断由接口显式报告，界面逐项展示，刷新不得隐藏：
  - 委派行：画布上方提示“显示 40 / 52 个委派”，画布末行“加载更多委派”（按接口游标）。
  - 片段：该行截断一侧出现“⋯ 片段已截断”标签，信息栏写明“显示 50 / 73 段”。
  - Host 事件：标记轨截断一侧出现“‹ 3 条事件未返回”，并计入提示条。
  - 提示条样式为 `warning-wash`，不是错误；没有“关闭”按钮，只在后续读取不再报告截断时消失。

## 6. 会话只读与草稿

- 只读会话（写权限已交给新窗口）下，列表、时间轴、打开详情全部照常可用；详情里现有控件按现有规则停用并显示现有文案，时间轴不增加任何提示。
- `RecordDrafts` 提供者放在列表、时间轴与详情之上，切换工作目标、返回时间轴或打开别的委派都不会卸载草稿存储；回到原委派时草稿仍在。
- 详情报告锁定（`onLockChange(true)`，即操作进行中或结果未确认）时：“返回时间轴”、切换工作目标、打开其他委派都停用（沿用 `aria-disabled` 与 `title`），定位条显示“有结果未确认的操作：核对前不切换，以免丢失操作标识。”。浏览当前委派的其他栏目不受影响。不为切换上下文丢弃未确认的命令或草稿。

## 7. 键盘与可访问性

- 列表：条目是按钮（`aria-pressed` 表示选中），Tab 顺序与现有委派列表一致。
- 画布：`role="group"`，`aria-label="工作目标时间轴"`，使用 roving tabindex，Tab 进入时落在上次聚焦项（默认第一行第一个片段）。←/→ 在同一行内按时间移动（行标签、片段、结算旗标），↑/↓ 移到相邻行中时间最近的项（Host 标记轨算第一行），Home/End 到行标签/行尾，Enter/空格打开详情，Esc 离开画布回到工具条。
- 每项有完整 `aria-label`，例如“执行片段，补充 schema 升级离线副本的验证测试，第 1 轮，zcode / glm-5，09:40 至 10:02，22 分钟，执行失败”。行标签按钮描述“委派，层级 2，协助任务，已结束”。
- 画布下方有“以列表查看”切换，列表视图与窄屏视图相同，读屏用户可以选择线性阅读。
- 状态从不只靠颜色；动画遵守 `prefers-reduced-motion`；所有颜色来自 token，浅色/深色两套完整。

## 8. 中等宽度与窄屏

- 760–1100px：标签列 180px，画布横向滚动，最小比例每分钟 1.6px；工具条图例换行。
- ≤ 760px：沿用现有单栏切换，三层：工作目标列表 → 工作目标（按时间排序的列表）→ 委派详情。每层顶部有返回按钮：“返回工作目标”“返回时间轴”。
- 窄屏的时间列表：头部与计数条同桌面；Host 事件与片段按开始时间合并成一列，每项显示时间、类型图标、委派标题（协助任务带“↳ 协助”前缀）、配置色块与名称、时长和结果文字。超过 30 分钟的空闲显示为分隔行“空闲 2 时 36 分”，因列表不压缩时间，无需展开。截断提示同桌面。
- 点按条目打开详情，返回后恢复列表滚动位置。

## 9. 空、加载与错误状态

| 情形 | 表现 |
| --- | --- |
| 没有任何工作目标 | 左栏 `Empty`：“还没有工作目标”“Host 提交委派后，这里按项目列出工作目标；旧记录各自显示为独立委派。” |
| 筛选无结果 | “没有匹配的工作目标”“调整筛选或搜索项目名称。” |
| 未选择 | 右栏 `detail-placeholder`：“选择一个工作目标”“查看各委派的排队、执行、等待 Host 与验收时间。只读，不调用模型。” |
| 首次读取中 | 头部照常显示列表中已有的信息，画布显示 3 行骨架与“正在读取时间轴…”（`role="status"`）。 |
| 读取失败且无旧数据 | 画布位置显示错误文本与“重试读取”（`role="alert"`），列表可继续选择其他工作目标。 |
| 读取失败有旧数据 | 见第 5 节，保留旧数据并标注时间。 |
| 委派尚未开始执行 | 行上只有排队/路由片段延伸到现在。 |
| 独立委派 | 头部标签“独立委派”，时间轴只有该委派及其协助任务。 |

## 10. 长文本

- 列表标题最多两行，时间轴标签单行，详情头部最多两行；完整文本在 `title`、信息栏与详情中。
- 项目路径、Host id、模型名使用 `overflow-wrap: anywhere` 或单行截断，不撑开栏宽。
- 执行片段内的文字只在片段宽度足够时显示，否则只在 `aria-label` 与信息栏中出现；图例文字可换行。

## 12. 建议的 React 拆分

字段为界面消费的逻辑名，最终命名以 Codex 的 `objective_list` / `objective_timeline` 契约为准；它们都对应 ADR 第十节推导表中已记录的事实，本设计不提出新的后端字段。

| 组件 / 模块 | 职责 | 需要的数据 |
| --- | --- | --- |
| `Objectives`（替换 `Tasks` 的页签内容） | 筛选状态、选中的工作目标键、右栏层级（时间轴/详情）、`locked`；包裹 `RecordDrafts` 与 `SplitView` | `snapshot`、`api`、`refresh`、`active`、`authority`、`writesAvailable`（与现 `Tasks` 相同） |
| `useObjectiveList` | 键集分页读取、就地更新、延迟重排提示 | 每项：`objectiveId`（或独立委派的根 `runId`）、项目 `id/label/path`、标题、`sourceHostId`、四项计数、委派总数、`lastActivityAt`；`nextCursor`、`total` |
| `ObjectiveList` | 分组渲染与选择 | 上述列表项、选中键、`locked`、加载/错误状态 |
| `useObjectiveTimeline` | 随 3 秒轮询读取、按 id 合并、保持行序、记录最后成功时间 | 选中键；返回时间轴数据与 `observedAt`（本地读取时间）、错误 |
| `ObjectiveTimeline` | 头部、工具条、截断提示、画布或列表视图、信息栏；持有聚焦项与展开集合 | 工作目标头部字段；`runs`、`events`、截断与分页信息 |
| `timeline-layout.ts`（纯函数） | 占用区间、空闲折叠、时间到像素映射、刻度、配置色分配、标记合并 | 片段与事件时间、展开集合、可用宽度、现在 |
| `TimelineAxis` | 刻度、断带按钮、现在线 | 布局结果 |
| `HostMarkerTrack` | Host 标记与合并 | 每条事件：`kind`、时间、`runId`、关联的请求/验收标识；事件截断信息 |
| `TimelineRow` | 行标签与该行片段、结算旗标 | 每个委派：`runId`、`parentRunId`、标题（已回退）、状态、执行配置摘要、`createdAt`、结算时间与结论、片段截断信息 |
| `TimelineSpan` | 单个片段按钮 | `kind`（queue/routing/execution/waiting-host）、开始、结束或空、配置键（adapter/provider/model）、回合序号与 `turnId`/`attemptId`、结果（完成/失败/取消/执行中）、`shutdownConfirmed`、路由计算的 `runId` 或求助请求 id |
| `TimelineList` | 窄屏与“以列表查看” | 与画布相同的数据，按时间展平，加折叠区间 |
| `RunDetailPane` | 定位条、返回、锁定提示；内部渲染现有 `TaskDetails` | 目标 `runId`、预选栏目、片段定位事实；`locked` 回调；其余沿用现有 `Tasks` 传给 `TaskDetails` 的参数 |

`TaskDetails` 只需两处小改：返回按钮文案与回调可由调用方传入；可接收预选栏目（写入现有的 `section` 记录草稿）与可选的回合定位信息。

## 13. 不在本设计内

结果账、路由改造、Host 自有工作登记、分发与第十二节其余待决事项；工作目标的创建、改名或关闭；时间轴上的任何写操作；接口、schema 与分页上限的具体取值（由 Codex 决定）。

## 14. 限制

示意稿是手写的静态 HTML，用容器查询模拟窄屏，并非生产 CSS；未在浏览器中截图或验证，交互脚本只覆盖布局所需的最少行为（选择、展开断带、打开/返回详情、主题与宽度切换）。实现后仍需按 ADR 第十三节在真实浏览器中按多种宽度检查。
