# 执行提醒

本实现落实 ADR-022 第 2、3 条，适用于微任务的一次执行与命令执行；Router 调用仍由它自己的预算控制。提醒只记录观察事实，不请求停止、不改执行状态，也不把停止未知当成已经停止。本文记录本微任务的实现与检查，安装和 Host 验收另行进行。

## 记录与等待

`attempt_reminders` 逐条保存提醒，绑定 `task_id` 与 `attempt_id`，记录种类、已用秒数、最近一次原生事件时间、当时是否处于工具调用阶段和记录时间。`expected-duration` 的 `expected_multiple` 表示第几个预期时长；到达一倍、两倍等时各写一条，调度恢复后也逐条补记已经越过的倍数。`native-silence` 的 `silence_started_at` 标识这一段沉默，同一执行的同一段沉默只有一条；没有原生事件时从执行开始计时，最近一次原生事件时间明确返回 `null`。提醒与 `attempt.reminder` 事件在同一事务中写入，同时推进执行记录的修订号。

原生事件事实来自当前执行的 `attempt_activity`，以 `lastNativeActivityAt` 为准；只有原生事件序号大于零而没有该时间的记录，才采用它的观察时间，序号单独出现时采用服务收到该记录的时间。发送提示等只有阶段观察、没有原生事件的记录不推迟沉默截止。续租、心跳、提醒本身和普通进度消息均不算原生事件；`phase=tool-running` 是提醒中工具调用正在进行的事实来源。新原生事件清除当前“可能卡住”的显示，随后再次沉默才生成新提醒。

`await` 经现有 `task_wait` 等待，携带 `consumeReminders=true` 和本次调用唯一的 `reminderWaitId`；服务在阻塞之前领取一条当前执行的待读提醒。`delivered_at` 与 `delivery_id` 保存这次领取，同一次 `await` 断线重试使用同一个标识，服务重放同一条领取记录，不会跳过提醒或领取下一条；下一次 `await` 使用新标识，继续等候或领取下一条。提前返回的 `outcome` 是 `expected-duration` 或 `native-silence`，`reminder` 包含 `reminderId`、`attemptId`、`runId`、`expectedMultiple`、`elapsedSeconds`、`lastNativeEventAt`、`toolInProgress` 和 `createdAt`，`ok=false`。普通查看不领取提醒；已经结束的执行优先交付结果，旧执行的未读提醒不遮住结果。

运行中的微任务等待自身执行时使用 `task_wait`，因此新提醒能立即结束等待；自身已经停止、仍在等待所属微任务停止证据的路径继续使用事件游标。`task_wait` 先取事件头再检查记录，再订阅并复查，避免检查与订阅之间丢失变化；它按本次剩余等待时间阻塞，去掉了原有的一秒重查。切换安装期间，已在围栏建立前返回的 Host 决策边界保持 `waiting-host`，若读取完整结果被围栏拒绝，则同时返回 `UPGRADE_IN_PROGRESS`，保留请求及后续命令，不声称交付了结果。

## 设置与升级

静默阈值存在自己的单行表 `reminder_settings`，只有 `id=1` 一行，字段为 `silence_seconds`、`updated_at` 与 `revision`，默认 900 秒。控制台通过要求已认证控制台会话的 `reminder_settings_set` 修改它，边界接受 1 至 86400 的整数秒，拒绝布尔值及未知字段；值未变化时不写新修订或事件。实际修改与 `reminder.settings_changed` 事件同事务提交，再通知调度器重算截止时间。修改阈值不会撤回已经记录的沉默提醒，同一段沉默仍只提醒一次，当前警告在下一次原生事件到来时解除。

schema 从 21 升至 22；`blackboard/store/upgrade.py` 是这一次待安装的显式升级，添加两个表和索引、写入默认阈值，再修改 schema 标记。安装协调器在旧服务停止、独占锁取得、备份验证完成后执行它；升级在单一事务内完成，拒绝不支持的 schema 或已有的提醒表，不猜测已有值。旧表行数、内容指纹、事件头，以及除 schema 标记外的 `meta` 全部保留；启动新运行时再核对迁移后的快照，失败沿备份恢复路径回退。普通服务启动只接受 schema 22。固定 schema 21 样板经完整升级流程后与新建 schema 22 的结构一致，原有数据和默认阈值均已核对。

## 调度与控制台

服务只启动一个提醒调度线程，取全部在跑且未交付结果的当前执行，计算下一倍预期时长与尚未提醒的沉默截止，选择最早时刻作为条件变量的等待时长。原生活动、领取、结束和设置变化经已有事件通知让它提前重算；没有执行时返回空截止，条件变量无限等待，提醒不产生周期唤醒。存在执行时按实际截止唤醒，不采用固定的一秒轮询；停止未知的执行仍保留提醒资格。服务关闭时唤醒并收回这个线程。

控制台设置页增加“执行提醒”，可查看、修改阈值，读写权限和连接状态沿用控制台机制；微任务当前执行的“已超过预期”和“可能卡住”紧邻已有状态显示，结束或切换执行后不沿用旧执行的警告。新增文字均有中英文 i18n，状态组可换行，320 像素宽度下检查文字可见且没有横向溢出；打包控制台资源已经重建。

## 检查

Python 只使用 `PYTHONPATH=src <Host 提供的 Python> -m hey_my_buddy.cli.checks <文件或目录>`，默认进程数，所有服务及命令均在检查运行器的私有根中运行，没有模型调用。覆盖 `tests/python/install/`、`tests/python/blackboard/store/`，提醒、`await`、`task_wait`、原生活动、停止证据、控制台及协议的相关测试；最后两批分别为 27 个文件 280 项、19 个文件 329 项，均通过且私有根收回，两批有重叠，不相加计数。完整 Python 检查按本微任务要求留给 Host 合并之后、安装之前执行。

私有服务中的命令执行验证一倍、两倍预期时长各有提醒、两次 `await` 各返回一次且命令继续运行；另用短阈值验证沉默提醒只返回一次，再等只到等待窗口结束。私有服务的手动 Worker 原生事件验证正在调用工具的事实。确定性检查还覆盖新事件后再次沉默、续租不推迟沉默、零原生事件、停止未知、跨调用领取及回复丢失后的领取重放。安装切换等待测试随实际返回路径更新后通过；旧断言失败留下的两个私有服务经各自的维护入口退出，检查运行器清扫确认删除 2 项、保留 0 项。
