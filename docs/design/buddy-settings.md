# Buddy 配置页设计（讨论稿）

状态：讨论稿，2026-09-28。尚未确认，未实现。确认后再决定是否需要 ADR 与实现授权。

## 要解决的问题

控制台现在有"模型卡片"和"路由配置"两个页面，用户反馈的问题：

- 两个页面讲的其实是同一件事：哪些配置可以当 buddy 干活，其中哪一个担任 Router。路由模型本质上是某个配置身上的一个角色，却单独占了一个页面，和模型设置重复。
- 常驻说明文字多、缺少层次，重要的状态和操作淹没在解释里。
- 启用一个配置要进入"评价与意见"区域操作，而不是一个直观的开关。
- 每个思考档位各自一张卡片、各自写意见和偏好，配置一个新模型要反复点击。但档位确实有区别（能力、成本、评价证据各不相同），不能简单合并。
- 右上角全局"编辑设置"开关让所有控件先处于不可用状态，操作路径长。

## 设计原则

1. 一个页面：顶部导航的"模型卡片"和"路由配置"合并为"Buddy 配置"。Host 是正在使用的会话，不在这里配置；这里只管可以担任 Worker 或 Router 的配置。
2. 按模型家族组织，档位作为家族内部的开关：常用操作在家族层面一次完成，档位差异在需要时展开。
3. 角色是配置上的属性：Router 是某个具体档位上的标记，通过"设为 Router"指定。
4. 状态用标记，解释进提示：常驻文字只保留名称、状态和数值；解释放进 `?` 悬浮提示；警告只在需要用户处理时出现，并直接给出处理办法。
5. 直接编辑：取消全局编辑开关，控件直接可用；有未保存修改时底部出现保存栏，保留现有的版本冲突和单写者保护。

## 页面结构

```
┌ Buddy 配置 ─────────────────────────────────────────────────────┐
│ Router：Claude Sonnet 5 · 中 ｜ 预算：标准 ｜ 状态：正常   [详情]  │  ← 一行全局状态
├──────────────────────┬──────────────────────────────────────────┤
│ 搜索                 │ Claude Sonnet 5            可用 ● 已启用 2/3│
│ ▾ Claude Code        │ 档位   [低 ○] [中 ● Router] [高 ●]         │
│   Sonnet 5   2/3 ★R  │ 偏好   无 / 优先 / 固定 / 排除    ?        │
│   Opus 5.5   1/2     │ 并发   2                          ?        │
│ ▾ Codex              │ 备注   ___________________________         │
│   GPT-6 Sol  0/2     │ 评价   摘要（自动，只读）  ▸ 按档位展开     │
│ ▾ DSH                │ ─ Router（仅当前 Router 所在家族显示）─    │
│   Flash      1/2     │ 路由预算  快速 / 标准 / 深入      ?        │
│ ▸ ZCode（不可用）     │                                          │
└──────────────────────┴──────────────────────────────────────────┘
                                   [有 2 项未保存修改   放弃   保存]
```

- 左侧：按 harness 分组的模型家族列表。每行显示名称、启用档位数（如 2/3）和 Router 标记。不可用的 harness 折叠并注明原因。新发现的模型带"新"标记，默认不启用。
- 右侧：选中家族的详情。
  - 档位：每个档位一个带开关的标签，点一下即可启用或停用；标签上显示可用性，Router 所在档位带标记。"设为 Router"放在档位标签的菜单里，只对具备已验证只读能力的档位可用，不可用时菜单里写明原因。已有 Router 时弹出确认："将替换当前 Router X"。
  - 偏好、并发、备注：默认在家族层面设置一次，作用于该家族的所有档位。各档位设置不一致时显示"各档位不同"，点开可按档位查看和修改。
  - 评价：自动评价只读，默认显示家族摘要，按档位展开查看各自证据。
  - Router 设置：只在当前 Router 所在家族显示路由预算。
- 顶部全局状态：显示 Router、预算和路由健康。正常时只有一行；异常时变成警告并给出处理动作，例如"当前 Router 未验证，请选择其他配置或批准验证"。失败明细放在"详情"里。

## 与现有数据的对应

现有数据按档位（profile）存储：启用状态、偏好、人工备注都以 profileId 为键；并发上限本来就是家族级。

- 方案 A（建议先做）：不改 schema。家族层面的修改由界面展开为对该家族每个档位的同值写入；读取时若各档位值相同则显示为家族值，否则显示"各档位不同"。一次保存仍是一次发布，沿用现有的草稿、版本和冲突处理。
- 方案 B：新增家族级偏好与备注的存储，档位级作为覆盖。语义更清楚，但需要 schema 变更和数据迁移，按现有规则需先停下来说明并取得用户同意。
