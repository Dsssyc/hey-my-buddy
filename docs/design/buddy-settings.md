# Buddy 配置页设计（讨论稿）

状态：已按方案 B 在源码实现（schema 13），未安装。2026-09-28 用户已确认页面名称、数据方案、路由入口、筛选、不做推荐和新增设置页（见"已确认的决定"）；实现尚未安装到日常运行时，安装需要单独授权。

## 要解决的问题

控制台原来有"模型卡片"和"路由配置"两个页面，用户反馈的问题：

- 两个页面讲的其实是同一件事：哪些配置可以当 buddy 干活，其中哪一个担任 Router。路由模型本质上是某个配置身上的一个角色，却单独占了一个页面，和模型设置重复。
- 常驻说明文字多、缺少层次，重要的状态和操作淹没在解释里。
- 启用一个配置要进入"评价与意见"区域操作，而不是一个直观的开关。
- 每个思考档位各自一张卡片、各自写意见和偏好，配置一个新模型要反复点击。但档位确实有区别（能力、成本、评价证据各不相同），不能简单合并。
- 右上角全局"编辑设置"开关让所有控件先处于不可用状态，操作路径长。

## 设计原则

1. 两个页面：顶部导航的"模型卡片"和"路由配置"合并为"Buddy 配置"；系统级内容（主题、存储，以后的语言）移到新的"设置"页。Host 是正在使用的会话，不在这里配置；这里只管可以担任 Worker 或 Router 的配置。
2. 按模型家族组织，档位作为家族内部的开关：常用操作在家族层面一次完成，档位差异在需要时展开。
3. 角色是配置上的属性：Router 是某个具体档位上的标记，通过"设为 Router"指定。
4. 状态用标记，解释进提示：常驻文字只保留名称、状态和数值；解释放进 `?` 悬浮提示；警告只在需要用户处理时出现，并直接给出处理办法。
5. 直接编辑：取消全局编辑开关，控件直接可用；有未保存修改时底部出现保存栏，保留现有的版本冲突和单写者保护。

## 页面结构

```
┌ Buddy 配置 ─────────────────────────────────────────────────────┐
│ Router：Claude Sonnet 5 · 中 ｜ 预算：标准 ｜ 状态：正常   [详情]  │  ← 一行全局状态
├──────────────────────┬──────────────────────────────────────────┤
│ 搜索                 │ Claude Sonnet 5            可用 ● 已启用 2/3│
│ ▾ Claude Code        │ 档位   [低 ○] [中 ● Router] [高 ●]         │
│   Sonnet 5   2/3 ★R  │ 偏好   无 / 优先 / 固定 / 排除    ?        │
│   Opus 5.5   1/2     │ 并发   2                          ?        │
│ ▾ Codex              │ 备注   ___________________________         │
│   GPT-6 Sol  0/2     │ 评价   摘要（自动，只读）  ▸ 按档位展开     │
│ ▾ DSH                │                                          │
│   Flash      1/2     │                                          │
│ ▸ ZCode（不可用）     │                                          │
└──────────────────────┴──────────────────────────────────────────┘
                                   [有 2 项未保存修改   放弃   保存]
```

- 左侧：按 harness 分组的模型家族列表。每行显示名称、启用档位数（如 2/3）和 Router 标记。不可用的 harness 折叠并注明原因。新发现的模型带"新"标记，默认不启用。
- 右侧：选中家族的详情。
  - 档位：每个档位一个带开关的标签，点一下即可启用或停用；标签上显示可用性，Router 所在档位带标记。"设为 Router"放在档位标签的菜单里，只对具备已验证只读能力的档位可用，不可用时菜单里写明原因。已有 Router 时弹出确认："将替换当前 Router X"。
  - 偏好、并发、备注：默认在家族层面设置一次，作用于该家族的所有档位。各档位设置不一致时显示"各档位不同"，点开可按档位查看和修改。
  - 评价：自动评价只读，默认显示家族摘要，按档位展开查看各自证据。
- 顶部全局状态：显示 Router、预算和路由健康。正常时只有一行；异常时变成警告并给出处理动作，例如"当前 Router 未验证，请选择其他配置或批准验证"。"详情"里集中放路由相关的一切：当前 Router、路由预算（快速 / 标准 / 深入）、路由健康与失败明细。Router 的指定仍在档位标签上完成，详情里显示是哪一个并可跳转过去。
- 筛选：列表提供"只看已启用"，与现有行为一致。
- 不提供推荐：页面不根据任何规则推荐档位或配置；选择依据是 Host 持续维护的评价，评价随证据积累而变得更准确。

## 设置页

新的"设置"页只放系统级内容，与 buddy 无关：

- 显示：浅色 / 深色 / 跟随系统。
- 存储：现在位于路由配置下方的存储占用与回收（检查占用、生成计划、确认回收），原样迁入。
- 以后的语言（i18n）也放在这里。

## 评价与用户设置的粒度

社区评测普遍把每个思考档位当作独立的被评测对象：[Aider 排行榜](https://aider.chat/docs/leaderboards/)把 `gpt-5 (high)`、`gpt-5 (medium)`、`gpt-5 (low)` 分行列出；[Artificial Analysis](https://artificialanalysis.ai/models) 为同一模型的不同 effort 各给独立的智能指数、价格和速度；[LMArena](https://arena.ai/company/leaderboard-changelog) 把思考版和非思考版分别上榜、各自积累评分。原因是档位之间的能力、成本和速度差异足以影响选择。

据此划分：

| 内容 | 粒度 | 维护者 |
| --- | --- | --- |
| 评价卡片、证据、样本计数 | 档位 | Host 维护（评价维护流程） |
| 启用状态 | 档位 | 用户，通过档位开关 |
| 偏好（优先 / 固定 / 排除） | 家族，可按档位覆盖 | 用户 |
| 备注 | 家族 | 用户 |
| 并发上限 | 家族（现状） | 用户 |

家族视图显示评价摘要，按档位展开看各自的证据。偏好允许按档位覆盖，例如整个家族"优先"，但成本过高的最高档位"排除"。

## 与现有数据的对应

现有数据按档位（profile）存储：启用状态、偏好、人工备注都以 profileId 为键；并发上限本来就是家族级。

- 方案 A（建议先做）：不改 schema。家族层面的修改由界面展开为对该家族每个档位的同值写入；读取时若各档位值相同则显示为家族值，否则显示"各档位不同"。一次保存仍是一次发布，沿用现有的草稿、版本和冲突处理。
- 方案 B：新增家族级偏好与备注的存储，档位级作为覆盖。语义更清楚，但需要 schema 变更和数据迁移，按现有规则需先停下来说明并取得用户同意。

## 数据契约（schema 13，实现依据）

存储：

- `family_preferences(adapter, provider, model, mode, reason, updated_revision)`：家族默认偏好，`mode` 为 `prefer`、`pin` 或 `exclude`。
- `evaluation_preferences(profile_id, mode, reason, updated_revision)`：改为档位覆盖，`mode` 增加 `none`（该档位明确不带偏好，即使家族有默认值）。
- `family_annotations(adapter, provider, model, text, revision, updated_at)`：家族备注。`evaluation_annotations` 删除。
- 视图 `effective_preferences(profile_id, mode, reason, source)`：档位有覆盖时取覆盖（`none` 视为无偏好，不出现在视图里），否则取家族默认；`source` 为 `override` 或 `family`。候选筛选、Router 输入、维护输入和控制台都读这个视图。
- 家族以 `(adapter, provider, model)` 标识，与并发上限一致。

控制台快照（`console_snapshot`）：

- `familyPreferences: [{adapter, provider, model, mode, reason}]`
- `preferenceOverrides: [{profileId, mode, reason}]`，`mode` 可为 `none`
- `preferences: [{profileId, mode, reason, source}]`：生效偏好（来自视图），只读
- `familyAnnotations: [{adapter, provider, model, text, revision, updatedAt}]`
- 删除原来的 `annotations`；`profiles`、`cards`、`modelConcurrency`、`configuration`（含 `decisionProfileId` 与 `routingBudget`）不变。

发布（`user_policy_publish`，字段补丁，未给出的字段不变）：

- `familyPreferenceChanges: [{adapter, provider, model, mode, reason}]`：`mode` 为 `prefer`、`pin`、`exclude`，或 `null` 表示清除家族默认。
- `preferenceChanges: [{profileId, mode, reason}]`：档位覆盖；`mode` 为 `prefer`、`pin`、`exclude`、`none`，或 `null` 表示删除覆盖、回到家族默认。
- `familyAnnotationChanges: [{adapter, provider, model, text}]`：空文本表示清除。
- 删除 `annotationChanges`；`profileSettings`（启用）、`configuration`、`modelConcurrency` 不变。
- 固定（`pin`）的规则不变：只要有任何生效的固定，候选就只限于生效为固定的档位。

迁移（12 → 13，在 `upgrade` 内、备份校验之后、独占锁下单事务完成）：

- 偏好：一个家族的全部档位都有相同的 `mode` 和 `reason` 时，合并为家族默认并删除这些档位行；否则原样保留为档位覆盖。
- 备注：同一家族只有一条或多条相同时直接作为家族备注；不同时按档位拼接为一条，每段标注来源档位，例如"（来自 high 档位）"，不截断。
- 迁移后，除上述三张表和 `meta` 的版本号外，其余表的指纹必须与迁移前一致；任何一步失败都用迁移前的备份和旧运行时恢复。

## 已确认的决定（2026-09-28）

1. 页面名称：Buddy 配置。
2. 数据方案：方案 B。用户偏好与备注在家族层面保存，偏好可按档位覆盖；Host 维护的评价留在各档位。实现需要 schema 变更，该变更已按上面的数据契约在源码实现，尚未安装。
3. 路由相关设置（Router、预算、健康）集中在顶部全局状态的"详情"里。
4. 提供"只看已启用"筛选。
5. 不做推荐。
6. 新增"设置"页，放主题、存储，以后放语言。

7. 偏好的档位覆盖直接标在档位标签上：优先、固定、排除各用一种颜色，外加一个小图标或描边样式，不只靠颜色区分（与时间轴的无障碍规则一致）。家族层面的偏好作为默认，没有覆盖的档位不额外标记；不再显示"N 个档位不同"之类的文字。
