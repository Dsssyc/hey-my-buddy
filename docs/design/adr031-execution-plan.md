# ADR-031 的执行计划

2026-10-15，整合 Host。依据 [ADR-031](../decisions/031-one-process-per-execution.md)，开发者当日同意。在第 3 步的 C 组装上之后开工：那次安装消费掉从 schema 21 到 22 的升级，本计划的存储变化开始下一次升级，从 22 到 23。

## 现状（2026-10-15 读源码所得）

- **三层进程。** 服务经 C-Two 连到常驻的 Worker；Worker 再经 C-Two 连到每次运行临时起的运行控制进程；运行控制进程驱动 harness。
- **Worker 的活。** 认领、每 120 秒续一次租、回执队列、启动意图与孤儿记录、崩溃后的恢复；服务发给运行中执行的请求，也由它转给运行控制。
- **代码量。** 相关代码约 5,100 行，其中 Worker 1,430 行、运行控制 841 行、守护进程 866 行、C-Two 实时通道 1,135 行。

## 做法

1. **合成一个执行进程。** 把 Worker 为一次执行做的事并进现在的运行控制进程。服务直接起它，起的时候就把这次执行交给它，不经 supervisor，也不再认领。
2. **服务直连执行。** 运行控制本来就注册了一个 C-Two 端点，服务直接连它，去掉 Worker 转发这一层，并对每个执行保持一个长调用。
3. **执行也连服务。** 执行进程对服务保持一个长调用。服务没了，它把要交的事件与回执记在这次执行自己的目录里，按退避重连，连上后按序交出。
4. **恢复只在服务一侧。** 服务启动时，按记录的进程身份逐个核对，并连回各执行的端点：
   - 连不上、身份也证明进程已不在：读回执结算，或记为被中断；
   - 身份还在却连不上：记为“不知道”；
   - 孤儿进程只由服务按身份停止。
5. **删掉的东西。** Worker 池、supervisor、`workers` 表与命令、`worker-start` 与 `worker-stop`、`HMB_WORKER_ID`、续租（租约列与续租调用）、Worker 目录（回执队列、启动意图、孤儿记录），以及服务经 Worker 的转发。Router 的调用同样走执行进程。

## 微任务

在整合分支上一个接一个做，中间不安装。前一个封存、Host 读完差异之后，后一个在它上面开工。

| 编号 | 内容 | 验收时 Host 另做的 |
| --- | --- | --- |
| 开工前 | C 组装上之后，升级基点挪到装着的那个提交，从它重新生成样板看板，删掉从 21 到 22 的转换 | 读差异，跑安装与存储的测试 |
| M1 | **执行进程。** 一个能独立跑完一次执行的进程入口：带着这次执行的身份起来，注册端点，连服务，驱动 harness，交回执，退出；服务不在时把要交的记在执行目录里，连上后按序交出。调度不动，测试直接起它 | 私有服务上跑命令执行与夹具 harness；执行途中杀掉服务再起，回执照常交到 |

## 每个微任务的提示词都写明

- 版本是 0.x：不写防御性的冗余，不留兼容，没有两套读法；被取代的代码与测试在同一个改动里删掉。
- 只用检查运行器给的私有服务；不启动、停止或重启日常的服务与 Worker，不读写日常看板。
- 实现方除了被替换掉的代码不删除任何东西，不用 `git stash`，不动分支与标签。
- 每一批顺带做掉同一块的小待办。
