# 工作目标浏览修缮（0.15）：交互设计稿

状态：设计稿，供实现与审查使用；不是实现、验收或安装记录。范围是用户批准的 0.15 修缮项 C1–C6、A4、A5，以及路由设置里的简单状态区。本稿在 [工作目标时间轴设计稿](work-objective-timeline.md)（下称“0.14 稿”）与 [objectives 契约](../reference/objectives.md) 的基础上改动，未提到的部分保持 0.14 稿与现有实现不变。

## 0. 边界

- 技术栈、页签、品牌区与新 logo（`brand-icon`）、浅色/深色 token 都不变。本稿**不新增颜色 token**：选中用 `--focus`，停靠详情的标记用 `--accent`，底色用 `--subtle`，不完整提示用 `--warning-wash`。
- 只读取现有有界响应：`GET /api/objectives` 与 `.../timeline`（最多 200 行、800 段、800 个 Host 标记）。界面上的派生值（委派卡、跨度、执行时长、相关事件）都只按响应里的记录计算，**不推断**历史关系、因果或缺失的时间。
- 以下读取契约由 Host 负责，本稿只写界面怎么消费；字段名是逻辑名，最终以 Host 的契约为准：
  - **titleSource / 意图标题**（A5）：需要把“意图”（显式标题、工作目标标题、任务首行）和“最近结果摘要”分成两个有界字段，例如 `intentTitle` + `intentSource`、`summaryLine`。
  - **路由摘要**（第 8 节）：包括最近 N 次路由失败和最后一次成功时间。
  - 契约到位前的回退写在各节里；回退不能冒充契约已到位。
- **不获授权、不能设计成已实现**：A2 跨 Host 加入工作目标，A3 用户手动归档。界面上不出现“加入”“归档到…”“移出”之类的按钮、菜单或拖放。`currentHostIds` 只作为只读事实显示。
- 工作目标仍然只用于归档与浏览（0.14 稿第 1 节）。检查器、弹层、委派卡里都不放任何写操作；写操作仍只在 `TaskDetails` 里。

## 1. 总体布局

```
┌ 左栏：工作目标列表（SplitView，260–480px，可收成 48px 窄条）┐┌ 右栏 ─────────────────────────────────────────────────────────┐
│ 工具条 / 筛选                                                  ││ A 概览头部：标题（意图）· 摘要次行 · 事实行                         │
│ ▾ 项目 A                                                      ││   跨度/执行时长行（不完整时标明原因）                              │
│   [工作目标条目 …]                                             ││   委派卡条：#1 #2 #3 …（单委派时换成一张展开的卡，C6）              │
│ ▾ 项目 B …                                                    ││ B 工具条（图例 / 空闲 / 以列表查看 / 刷新状态）+ 截断提示            │
│ ─────────────                                                 ││ C 时间轴画布（标签列吸左，刻度吸顶）  │ E 停靠详情（仅宽屏，C4）   │
│ ▸ 未归档委派（已加载 N）  ← 默认折叠（A4）                      ││ D 检查器（固定，C1/C2）            │   定位条 + TaskDetails     │
└───────────────────────────────────────────────────────────────┘└──────────────────────────────────────────────────────────────┘
```

- A 区可以收起（“收起概览”，收起后只剩标题行与跨度行）。每个工作目标的收起状态存在页面内存里。
- D 区替换原来的单行 `.inspector`：默认高 176px，可以在 120–320px 之间拖动；只有一个“收起为一行”的开关，收起后退回原来的单行样式。内容在区内滚动，不撑开画布。
- E 区只在右栏容器宽度 ≥ 1000px 时出现（第 6 节）。窄一些时详情仍然是“替换时间轴”的一层。

## 2. 左栏：列表（A4、A5）

**A4 默认视图**
- 主列表只显示 `kind = "objective"` 的条目，分组、排序与条目样式沿用现有 `ObjectiveList`。
- `kind = "standalone"` 的条目放到列表末尾的折叠区 `▸ 未归档委派（已加载 N）`，用现有 `group-heading` 样式。展开后区内仍按项目分组。条目徽标从“独立委派”改为“未归档委派”，其余信息不变。
- 列表按最近活动分页，一页里可能两种条目都有，所以 N 只统计**已加载**的条目。还有下一页（`nextCursor`）时写作“已加载 N · 可能还有更多”，不当作总数。只有 Host 另外提供 `kind` 筛选或分类计数，才能显示总数。
- 如果已加载的页里全是未归档委派，主区显示 `Empty`：“已加载的记录中暂无工作目标”，附“加载更早记录”。
- 筛选：在 `filter-pair` 里加一个下拉“显示：工作目标（默认）/ 未归档委派 / 全部”。选“未归档委派”时，主区只显示未归档条目，折叠区隐藏；选“全部”时恢复 0.14 的混排。分段筛选、搜索、项目与委派方筛选照常叠加。
- 未归档委派的说明文字：“这条委派提交时没有指定工作目标，按记录单独显示。”不提供归档入口（A3 未授权）。

**A5 标题**
- 条目、画布标签列、委派卡、概览头部都用两行：第一行是**意图**（加粗，最多两行，画布标签列只显示一行），第二行是摘要（`muted`，一行截断，前缀“结果：”）。完整文本放在 `title` 和检查器里。
- 契约到位前的回退：`titleSource` 为 `objective / title / task / none` 时，`title` 就是意图，摘要行留空。为 `summary` 时，该文本只能当作摘要，第一行显示 `title`，前面加一个中性小标“摘要”，说明当前没有可用的意图文本。不自行查找任务首行来替换。

## 3. 选中、检查器与详情（C1、C2、C3）

### 3.1 三种状态分开

| 状态 | 作用 | 存放位置 |
| --- | --- | --- |
| 焦点 `focusKey` | 画布内的 roving tabindex | `ObjectiveTimeline`（沿用） |
| 选中 `selection` | 固定检查器内容。取值为 `{type:"item", key}` 或 `{type:"run", runId}` | `ObjectivesWorkspace`，按 objectiveId 存在 Map 里，切换工作目标再回来时恢复 |
| 已打开 `detail` | 当前在详情里显示的委派 | `ObjectivesWorkspace`（沿用 `DetailTarget`） |

单击只改变选中，**不再**直接打开详情。原 `onOpenItem` 拆成 `onSelect(item)` 和 `onOpen(item)`。打开详情时，选中也会同步到被打开的项。

### 3.2 检查器内容

检查器顶部是“预览行”：没有选中时，显示悬停或焦点项的一行事实（即原来的信息栏）；已有选中而焦点或悬停在别的项时，显示“指向：…”。预览行下面是固定卡片，只随选中变化，刷新、悬停、方向键都不会替换它。卡片右上角有“打开详情”（主按钮）和“取消固定 ×”。

| 选中对象 | 卡片内容（全部来自响应，没有的字段显示“未记录”） |
| --- | --- |
| 执行 / 路由片段 | **时间**：开始–结束、时长；没有结束时写“至今（截至 observedAt）”；`clockSkew` 或时间颠倒时写“时间异常，未计算时长”。**配置**：该轮冻结的 adapter / provider / model / effort。**结果**：`resultStatus` 加执行状态；结束未确认优先显示为“结束未确认”。**摘要**：`disposition`、`error`；路由片段另附“内部路由计算 `decisionTaskId`”。**相关 Host 事件**：见下文。 |
| 等待 Host 片段 | 请求类型（`requestKind`）、请求状态、时间、`summary`、相关 Host 事件 |
| 排队片段 | 开始–认领时间，状态（仍在排队 / 已认领） |
| 单条 Host 事件 | 类型、时间、`actor`、`summary`、事件里带的记录标识（attempt / request / artifact / integration / continuation），所属委派（点击后选中该委派） |
| 结算旗标 | 验收结论、`acceptedAt`、所属委派 |
| **整项委派（C2）** | **任务**：意图标题、摘要行、层级（根委派 / 第 n 层协助）、父委派链接（点击选中父委派）、协助任务数。**轮次**：本委派每个执行片段一行，写“第 N 轮 · 时间 · 配置 · 结果”，按开始时间排序。**结果**：最近一个执行片段的结果，加上 `status` / `state`。**验收**：`acceptanceVerdict`、`acceptedAt`；`category = review` 时显示“待验收”。**待决**：未结束的等待 Host 片段（类型、摘要、开始于），没有则写“无”。 |

**相关 Host 事件**只按记录标识匹配：`event.attemptId === span.attemptId`，或 `event.requestId === span.requestId`。整项委派则用 `event.runId === row.runId`。**不按时间邻近推断关联。**列表里每条事件都是按钮，单击后改为选中该事件，旁边的“打开”进入详情。`truncated.events` 为真时，列表末尾写“Host 事件已截断，此列表可能不完整”。

如果选中的项在刷新后不在响应里了（被截断、筛选或行数变化），卡片保留上次的事实，加一行 `warning-wash` 提示：“该记录不在当前读取范围内（可能已截断或被筛选）”，同时停用“打开详情”，直到它重新出现或用户取消固定。不会静默清空。

### 3.3 行标签选中整项委派（C2）

- 单击行标签，选中 `{type:"run"}`：行标签加 `selected-run` 样式，本行所有片段和结算旗标加 1px `--focus` 描边（比单项选中的 2px 细一档），同时对应的委派卡进入选中态。协助任务的行不跟着高亮，只在检查器里列出。
- 画布上单击委派卡，效果与单击行标签相同，并把该行滚动到可见位置（`scrollIntoView` 用 `nearest`，不移动横向时间位置）。

### 3.4 聚合标记与弹层（C3）

- 相距小于 14px 的 Host 标记仍然合并成带数字的标记。单击、Enter 或空格都只会**打开弹层**，不选中任何事件，也不打开详情。
- 弹层是一个锚定在标记下方的非模态浮层（标记设 `aria-expanded` 和 `aria-controls`），宽 280–340px，最多显示 8 行，超出在层内滚动。每行显示图标、时间、标签、委派意图标题（协助任务加“↳”）和 actor；行尾是“打开”按钮。
- 单击某一行，选中该事件（固定检查器），弹层保持打开，方便逐条查看。双击某一行，或行上按 Enter，直接打开详情。
- 下列情况关闭弹层：Esc（焦点回到聚合标记）、点击弹层外部、滚动画布、下一次刷新导致这组标记的成员变化（关闭时写一行提示“事件分组已随刷新更新”）。
- 选中的事件在某个聚合里时，这个聚合标记带选中描边。

### 3.5 打开与停靠详情（C4）

- 打开详情的入口：检查器里的“打开详情”、焦点项上按 Enter、双击片段/标签/标记/旗标/委派卡，以及弹层行上的“打开”或 Enter。预选栏目与定位信息沿用现有 `TimelineItem.section/locator`。
- **分层模式**（右栏宽度 < 1000px）：保持现状，详情替换时间轴，时间轴隐藏但不卸载；返回后恢复滚动、展开的空闲区间、焦点，以及**选中**。
- **停靠模式**（右栏宽度 ≥ 1000px）：右栏分成“时间轴列（最小 520px）| 分隔条 | 详情列（440–640px，默认 520px）”。分隔条复用 `SplitView` 的 `pane-divider` 行为（拖动、←/→ 每次 20px）。时间轴列在停靠时标签列收窄为 180px，并且仍然可以选中、悬停、滚动。定位条的返回按钮改成“× 关闭详情”。已打开的委派在其行标签上有 3px `--accent` 左条和“详情”小标，和选中描边可以同时出现。
- 停靠时，在时间轴里单击别的项只改变检查器，详情不变。要换详情，必须显式打开另一项。
- 右栏宽度跨过 1000px 阈值（比如拖动左栏或缩放窗口）时，两种模式之间切换，但保持 `detail`、`selection` 和滚动位置。
- 右栏头部提供“收起列表”（宽度 ≥ 1100px 时出现），把左栏收成 48px 窄条（竖排“工作目标 ›”按钮），让 1280 左右的宽度也能进入停靠模式。收起状态存在页面内存里。

### 3.6 锁定与草稿保护（沿用并放宽只读浏览）

- `locked`（详情报告有未确认的操作）时，下列操作停用，并沿用 `aria-disabled` 和 `LOCK_TITLE`：打开另一委派的详情、关闭或返回、切换工作目标、双击或 Enter 打开别的委派。打开**同一个**委派的其他栏目仍然允许。
- 锁定时，选中、悬停、弹层、检查器、滚动、展开空闲区间照常可用，因为它们都是只读的，不会卸载详情。停靠模式因此能在锁定期间继续查看时间轴；分层模式下时间轴被遮住，行为和现在一样。
- `RecordDrafts` 仍然放在最外层。切换详情目标、切换停靠/分层、收起列表都不会卸载草稿存储，也不会丢弃草稿或未确认的命令。

## 4. 概览头部（C5、C6）

**事实行**（沿用）：项目 · 汇总状态 · 来源 Host · `currentHostIds`（只读，写“当前 Host：…”）· 共 N 个委派 · 最近活动。

**跨度与执行时长行**：新增纯函数模块 `objective-metrics.ts`，只使用响应里的片段。

| 值 | 定义 | 显示 |
| --- | --- | --- |
| 总跨度（墙钟） | 最早片段开始（没有时用 `objective.createdAt`）到最晚记录时刻（片段结束、事件时间；有进行中或结束未确认的片段时取 `observedAt`） | “总跨度 5 时 12 分” |
| 执行占用（墙钟） | 所有执行片段区间的**并集**长度，即至少有一个执行在进行的时间 | “执行占用 2 时 03 分” |
| 累计执行 | 所有执行片段时长的**和**（N 段） | “累计 3 时 40 分（14 段，含并发）”。只有并集与和相等时才省略这一项 |

- 路由、排队、等待 Host 都不算进执行时长。进行中的片段算到 `observedAt` 并标注“至今”。结束未确认的片段只算到最后一次记录时间，并写“含 k 段结束未确认，尾段未计”。
- **不完整标记**：出现下列任一情况，数值前加“≥”，旁边放 `warning-wash` 小标“不完整”，悬停或聚焦时列出原因：`!scopeComplete`（筛选或截断）、`truncated.rows/spans/events`、有片段缺少时间或时间颠倒、有 `clockSkew`、有结束未确认的尾段。**不做**修补、外推，也不做“空闲扣除”之类的推算。
- 当前的 `canFold` 条件不影响这些计算，折叠只是显示上的处理。

**委派卡条**（`counts.roots ≥ 2`）：
- 按根委派的 `createdAt` 顺序横向排列，可以横向滚动，卡片宽 200–260px，用 roving tabindex。协助任务不单独成卡，只在卡里写“含 2 个协助”。
- 卡片内容：`#序号` + 状态图标 + 意图标题（一行）+ 一行“结果 失败 · 验收 待验收 · 待决 1”。结果取该根委派最近一个执行片段的结果，没有则写“未执行”。验收取 `acceptanceVerdict`，缺失时按 category 写“待验收”或“—”。待决是未结束的等待 Host 片段数。最后是一行小字“执行 42 分 · 3 轮”，数据不完整时同样加“≥”。
- 卡片的单击、双击、Enter、空格与行标签语义一致（3.3）。行被截断时，卡条末尾写“显示 40 / 52 个委派 · 加载更多委派”，复用画布的分页入口。

**单委派模式（C6）**：`counts.roots === 1`（包括未归档委派）时不显示卡条，改为一张全宽展开的委派卡，内容就是 3.2 表里“整项委派”的全部字段（任务 / 轮次 / 结果 / 验收 / 待决），加上执行时长行。卡上有“打开详情”。下面的画布照常显示这个委派及其协助任务的轮次片段。检查器初始为空，因为卡片已经展示了整项委派的内容，不自动选中。

## 5. 状态表

### 5.1 指针

| 目标 | 悬停 | 单击 | 双击 |
| --- | --- | --- | --- |
| 片段 / 旗标 / 单条标记 | 1px `--line-strong` 描边，预览行，标记与旗标显示参考线 | 选中并固定检查器 | 选中并打开详情 |
| 行标签 / 委派卡 | 本行片段淡描边，预览行 | 选中整项委派（C2） | 打开详情，预选概览 |
| 聚合标记 | 预览行写“Host 事件（n 条）”，显示参考线 | 打开或关闭弹层，不选中 | 同单击 |
| 弹层中的行 | 行底色 `--subtle` | 选中该事件，弹层不关 | 打开详情 |
| 检查器里的链接（事件 / 父委派） | — | 改为选中该对象 | — |
| 空白轨道 | — | 不改变选中，不关闭固定 | — |

### 5.2 键盘（画布，roving tabindex 沿用）

| 按键 | 行为 |
| --- | --- |
| ←/→、↑/↓、Home/End | 只移动焦点（沿用现有规则），不改变选中 |
| 空格 | 选中焦点项；在聚合标记上打开弹层 |
| Enter | 焦点项：选中并打开详情；聚合标记：打开弹层；锁定时对别的委派无效，并由 `aria-live` 读出锁定说明 |
| Esc | 弹层打开时关闭弹层，焦点回到标记；否则焦点移到工具条（沿用）。焦点在停靠详情里且不在输入框中时，关闭详情，焦点回到打开它的项；分层模式同理，返回时间轴。锁定时不响应 |
| 弹层内 ↑/↓、Home/End | 在行之间移动；Tab 在行与“打开”按钮之间切换 |
| 委派卡条 ←/→ | 在卡片之间移动；空格和 Enter 同 5.1 |

读屏：检查器卡片区设 `aria-live="polite"`，只在**选中**变化时播报；预览行不播报，避免方向键移动时反复朗读。聚合标记的 `aria-label` 写成“Host 事件 n 条，按 Enter 列出”。

### 5.3 选中、详情与锁定组合

| 选中 | 详情 | 锁定 | 表现 |
| --- | --- | --- | --- |
| 无 | 无 | — | 检查器只显示预览行与提示“单击选中查看记录；Enter 或双击打开详情” |
| 有 | 无 | — | 检查器固定；选中描边 |
| 有 | 有（分层） | 否 | 详情替换时间轴；返回后选中、滚动、焦点都恢复 |
| 有 | 有（停靠） | 否 | 两列并存；单击只换检查器 |
| 任意 | 有 | 是 | 可以选中和浏览；换详情、关闭详情、切换工作目标停用，定位条显示锁定说明 |

## 6. 响应式

| 视口 | 布局 |
| --- | --- |
| **320** | 沿用 ≤760px 三层：列表 → 工作目标 → 详情。概览：委派卡改为纵向列表，默认显示前 3 张，其余用“显示全部 N 个委派”展开；跨度与执行行换行。时间轴只用 `ObjectiveChronology`，点按条目只选中，检查器变成底部抽屉（最高 45vh，有拖动把手和“打开详情”主按钮），不依赖双击。没有聚合标记，事件逐条列出。从详情返回时恢复列表滚动和选中。未归档区与“显示”下拉放在筛选区内。 |
| **768** | 分栏：左栏 260–330px，右栏约 420px。标签列 180px，画布可以横向滚动。委派卡条横向滚动。检查器默认 144px。详情分层。建议使用“收起列表”腾出宽度（此宽度下不出现该按钮时，靠拖动左栏）。 |
| **1024** | 分栏：左栏约 300px，右栏约 700px。标签列 180px，检查器 176px。右栏仍低于 1000px，详情分层。 |
| **1440** | 左栏 330px，右栏约 1080px，达到阈值，进入**停靠**模式：时间轴列 ≥ 520px（标签列 180px），详情列默认 520px。收起列表后，时间轴列约 870px，标签列恢复 240px（按时间轴列的宽度用容器查询：< 760px 时用 180px）。 |

- 断点按**右栏容器宽度**判断（ResizeObserver 或容器查询），不按视口判断，这样拖动左栏、收起列表都能得到一致的结果。现有 760 与 1100 的视口断点保留，用于单栏与分栏的切换。
- 长文本规则沿用 0.14 稿第 10 节；弹层和检查器里的 id 和模型名用 `overflow-wrap:anywhere`。

## 7. 空、加载与截断的补充

- 截断提示条沿用；概览的“不完整”小标和检查器的截断说明使用同一份原因列表，文字保持一致。
- 首次读取期间，概览只显示列表条目里已有的字段，卡条显示 3 张骨架卡，跨度行写“读取中”。
- 读取失败但有旧数据时，跨度与执行时长冻结在旧的 `observedAt`，写“按 16:11:42 的数据”，进行中的片段不外推。

## 8. 路由设置：路由状态区（预留）

- 位置：“路由配置”页签的“固定决策模型”面板底部，新增只读小节“路由状态”。
- 内容：“最后一次成功：09-27 16:02”，加“最近 N 次中失败 k 次”。下面最多列 5 条失败记录（时间 · 失败类别 · 有界原因摘要 · 相关委派 id，点击跳到委派记录）。N 与字段都以 Host 的路由摘要读取契约为准。
- 契约没有提供或读取失败时，显示 `muted` 文字“路由摘要暂不可用”。不从任务历史里自行统计，也不调用模型探针。
- 这一小节没有任何写操作或“重试路由”按钮，编辑模式开关对它没有影响。

## 10. 验收要点

1. 单击任何片段、标记、旗标、标签或卡片，都不打开详情；检查器固定显示该项，之后的悬停、方向键、3 秒刷新都不会替换它。
2. Enter、双击、“打开详情”才打开详情；锁定时，打开别的委派、关闭详情、切换工作目标都停用，选中和检查器仍然可用；草稿与未确认命令不丢。
3. 行标签或委派卡选中后，该行所有片段带描边，检查器显示任务、轮次、结果、验收、待决，字段缺失时写“未记录”。
4. 聚合标记单击只弹出列表，不自动选中第一条；逐条选中时弹层保持打开；Esc 关闭后焦点回到标记。
5. 右栏 ≥ 1000px 时详情停靠，时间轴可以继续操作；< 1000px 时分层；两种情况下返回或关闭后，选中、滚动、焦点、展开的空闲区间都保持；跨过阈值时状态不丢。
6. 概览：多委派时卡片按创建顺序排列，每张一行结果/验收/待决；单委派时直接显示展开卡。总跨度、执行占用（并集）、累计执行（和）分开显示。构造两个并发片段时，占用小于累计。
7. 筛选、截断、时间缺失或颠倒、clockSkew、结束未确认任一出现时，数值前有“≥”和“不完整”原因；不补时间，也不按时间推断事件关联。
8. 默认列表只显示 `kind=objective`；未归档委派在折叠区，计数写“已加载 N”，有下一页时标明“可能还有更多”；页面上没有加入或归档类的写入口。
9. A5：`titleSource=summary` 的文本不当作意图显示在主标题位；契约提供意图字段后，主标题显示意图，摘要显示在次行。
10. 路由状态区在契约不可用时显示“暂不可用”，有数据时显示最后成功时间与最近 N 次失败；没有写操作。
11. 320 / 768 / 1024 / 1440 四档在浅色、深色主题下都要检查，logo 与页签不变；所有状态除颜色外还有文字或图标；遵守 `prefers-reduced-motion`；键盘可以完成第 5.2 节的全部路径。
12. 实现后在真实浏览器里按上述宽度核对（沿用 0.14 稿第 14 节的要求）；本设计稿本身没有经过浏览器验证。

## 11. 不在本设计内

A2 跨 Host 加入、A3 用户归档及其他任何写操作；工作目标的创建、改名或关闭；titleSource 与路由摘要读取契约的具体字段和上限（由 Host 决定）；列表的 `kind` 服务端筛选（如需精确的未归档总数，另行由 Host 决定）；成本或 token 统计。
