# 会话内容的覆盖：逐类有证据（执行计划）

2026-10-27，开发者同意。依据 [ADR-024](../../decisions/024-console-session-view.md) 与[接入要点](../../reference/harness-integration.md)的 Session content 一节；起因见[会话视图验收记录](../../acceptance/adr024/session-view.md)的补记。

## 现状

- 每个 harness 有一个 `session_omitted.py`，导出 `OMITTED`，是一组原因代码；`buddy/harnesses/registry.py` 把它们汇总，控制台按原因代码显示“这个 harness 不提供哪些内容”。
- 证据只写在各模块的说明文字里，没有结构，也没有检查。Claude Code、DSH 的模块都说覆盖没有核实，`OMITTED` 却是空的；ZCode 修好之后，计划这一类仍未核实，清单也是空的。只有 Codex 如实列出“内部推理不提供”。
- Host 2026-10-27 的只读比对：
  - Codex 的原生记录里推理不带可读文字；
  - Claude Code 运行时不保存原生会话，我们的记录里没有思考；
  - DSH 的原生会话都没留下，我们的记录里有思考，过程中几乎没有正文。

## 要做的

### C1：逐类声明与守住它的检查

1. **声明。** 每个 harness 对五类内容（消息、推理、工具输入、工具输出、计划），逐类给出三种之一：
   - **有证据**：写明 harness 的版本与来源（探针录下的原生事件、它自己存下的会话，或安装包里带的协议）；
   - **不提供**：带一个原因（例如 Codex 的内部推理）；
   - **未核实**。

   用它取代 `session_omitted.py` 里的说明文字与 `OMITTED`。结构放在 `protocol/` 里共用，不为某一家另做。
2. **检查。** 加一个测试：任何 harness 漏了某一类，或者“有证据”而没写版本与来源，就失败。证据靠现有的测试夹具与探针记录确定，找不到就是“未核实”。
3. **控制台。** 每个 harness 的那张表把“不提供”与“未核实”分开显示，文字走 i18n，中英文各一份；需要的原因代码在 `protocol/reason-codes.json` 注册。
4. **ZCode 顺带两件。** 计划声明为“未核实”。修好探针里两项 0.16.9 到 0.17.0 的既有漂移：目录为空时的警告断言；失败回合用 `*.json` 找会话绑定。

### C2：给 Claude Code、DSH 与 Codex 补证据（C1 之后）

照 ZCode 的做法，用探针让本机安装的 harness 连一个回环的假模型，不调用真实模型、不花钱：

- **Claude Code**：经 `ANTHROPIC_BASE_URL` 指向假模型，回复里带思考块、工具调用之间的正文与工具调用；
- **DSH**：提供方指向一个 OpenAI 兼容的假模型，回复里带 `reasoning_content` 与工具调用之间的正文；
- **Codex**（C1 验收时加入）：在探针私有的 Codex 配置里加一个指向假模型的提供方，回复里带正文、推理摘要、工具调用与计划。C1 只有工具输出有证据，消息、工具输入与计划仍是未核实；计划条目现在被写成一条标记正文，声明要照实际的样子定。

录下原始事件，逐类对照我们的投影。漏掉的就修，证据里没出现的保持“未核实”，然后更新声明。

顺带两件（C1 验收时记下，见[验收记录](../../acceptance/adr024/session-coverage.md)）：

- 声明的来源不写行号，只写文件，文档再加小节标题；检查核对文件与标题都在。
- 控制台在“有证据”旁边显示版本；`source` 不再发给控制台。

## 检查

- 改了控制台，就跑前端全量与浏览器检查，并重建、提交打包资源。
- 探针另行显式运行，原始事件留在检出的 `tmp/` 里。

- 在私有预览上亲眼看控制台那张表。
- 装上之后，在日常的真实回合上看一次。
