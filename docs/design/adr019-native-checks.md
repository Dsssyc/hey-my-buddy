# ADR-019 原生检查方案

2026-09-30。B 批第一阶段只在独立 worktree 实现源码和模拟验证；每次下表检查在执行前向用户展示本次命令、目录、数据流向、模型调用与取消办法，取得该次同意后才执行。登录由用户本人在浏览器完成。本文不是登录或能力验收证据。

所有检查使用新建的 `0700` 系统临时根、独立 `BUDDY_STATE_DIR` 与空的 `BUDDY_RUNTIME_ROOT`，不访问日常黑板。检查程序不打开任何凭据文件，不读取 shell 配置；原生 harness 自己使用其认证机制。只保留脱敏后的白名单事实、原生方法名、次数、退出码与持有进程的停止证据，不保存原始账户响应、授权 URL、设备码、密钥或 stderr。不要对本机共用登录执行登录、登出或密钥变更；不得把空目录中的未登录结果当成登录后隔离已成立。

| 编号 | 单次授权范围与操作 | 判据与取消办法 | 当前状态 |
| --- | --- | --- | --- |
| N1 | Codex 元数据：读取当前 CLI 版本，分别在全新 `CODEX_HOME` 和沿用本机登录的环境启动 App Server；只发送 `initialize`、`account/read`（不刷新登录）、`account/rateLimits/read`。 | 私有目录未登录；沿用环境只输出账户类型、计费标注、额度窗口与方法计数；零 `thread/start`、`turn/start`；关闭 stdin、等待并按持有进程组取消/回收。不执行 login/logout。 | 待用户单次授权及执行。 |
| N2 | Codex 私有登录：在新的 `CODEX_HOME` 运行 `account/login/start` 的浏览器或设备码变体；仅向当前用户显示链接/码。先测试取消，再另次授权完成登录。 | 捕获原生 `authUrl` 或 `verificationUrl`/`userCode`、`loginId`，`account/login/cancel` 有关联回执且进程停止；完成登录后只读查询私有与本机状态以核对隔离，不读取认证文件。未登录前后的同一账户类型不足以证明隔离。 | 待 N1 及分别授权取消/完成检查。 |
| N3 | Claude 私有状态与取消：新 `CLAUDE_CONFIG_DIR` 中运行 `auth status --json`，经静态协议确认后启动非 TTY `auth login`；不接触共用登录或钥匙串内容。 | 私有目录是否仍看到共用登录；是否从管道得到授权链接；中断后所持进程组是否退出。只记录公开 Keychain 服务/账户命名规则的原生证据，不查询凭据条目。不能证明隔离时拒绝开放 OAuth UI。 | 待用户单次授权；钥匙串隔离未验证。 |
| N4 | Claude 私有登录完成：仅当 N3 证明隔离与非 TTY 流程后，由用户完成浏览器授权。 | 私有状态可用且共用登录未变化；各进程实际停止。若任一前提未证实，仅提供原生工具指引。 | 待 N3；不预先实现登录入口。 |
| N5 | ZCode 私有 OAuth 与取消：新 `ZCODE_DATA_BASE_DIR` 下执行 `login --no-browser`，从管道捕获链接，由所持进程组取消。完成授权需另次同意。 | 不读 `credentials.json`；原生状态/服务商元数据证明私有目录无共用登录；链接可捕获，超时与取消均有停止证据。完成授权后通过原生元数据核对隔离。 | 待用户单次授权；适配器仍拒绝 OAuth。 |
| N6 | DSH 私有目录与密钥通路：新 `DSH_HOME` 下检查原生初始化/配置入口；仅在源码或原生协议确认后，经私有 stdin/管道调用原生 `ctx.credentials.set`，使用无效测试密钥先验证通路。 | 不读取 `.credentials.yaml`；测试密钥不出现于 argv、日志、事件、SQLite、成果及公开响应；只从原生脱敏状态确认是否设置；取消后进程停止。真实密钥由用户单独输入并逐次授权，不用环境继承绕过。 | 待原生入口核实及用户单次授权；不预设 CLI 写入可用。 |
| N7 | ZCode 密钥通路：在私有 `ZCODE_DATA_BASE_DIR` 经原生安全表单或 stdin 接口设置无效测试服务商密钥。 | 先证实原生接口存在；不使用带密钥参数、不直接编辑/读取服务商或凭据文件；脱敏原生元数据反映访问类型，公开持久记录无秘密。无安全接口时只给原生工具指引。 | 待接口核实及用户单次授权。 |
| N8 | 审阅能力重验：当前安装 harness、版本、平台，用现有只读探针的隔离随机输入、外部 sentinel 与可达无凭据本地网络端点执行一个标准预算模型调用。 | 原生身份与有效权限回执、关联越界读/内外写/网络拒绝、内部随机 marker 读取、输入和 sentinel 未变、预算与真实停止全部通过。模型自述、超时或文件未变单独不通过；失败不自动重试。CLI 显式执行或配置页点击是该次调用授权；Host 测试仍须先逐次请求同意。 | 源码入口实施中；本轮尚无调用授权。 |
| N9 | DeepSeek 余额：先核对官方只读 balance 接口与 DSH 原生安全凭据使用机制，再单独请求一次无模型查询授权。 | 不把凭据读入 Host 工具，不记录密钥或原始 HTTP 内容；只保留可用余额及来源；无法使用原生安全通路时不接通。 | 待核实与单次授权；第一阶段不接通。 |

登录完成、取消、登出、密钥写入和用量查询分别是独立检查，前一次同意不能用于后一项。对没有安全原生存储的路径，系统凭据库例外仅在第二阶段设计与核实时考虑，不回退到明文。Windows、Linux 的原生登录隔离与停止证据保持未验证，macOS 结果不外推。

原始检查报告存于本 worktree 的忽略目录 `tmp/worker-accounts/native/`；ADR-019 的“已核实／待核实”与第一阶段验收记录只引用脱敏结论。源码和模拟测试结果、每次用户批准的检查及其结果、未验证项分别记录。

## 2026-09-30 子批④结果

N1 已在 macOS Codex 0.159.0 完成：私有空 home 未登录、本机元数据及额度只读查询、零 thread/turn 和实际停止。N2 取消检查通过；本人浏览器完成第一次失败，观察到 605 秒的总体时长，推断与十分钟窗口有关，额外获得重试同意后第二次于 97.1 秒成功，私有 auth 文件 0600、本机状态未变化、原生停止确认。无效 Codex API key stdin 写入／account-read 和随后另次授权的私有登出通过。每项执行范围分别获用户同意，未读取认证文件内容或变更本机共用登录。

Claude 本轮只执行私有 auth status 元数据检查（含子进程无效 API key）及另次授权的专用 macOS Keychain 测试条目写入／读回／删除，零模型回合。N3 的 Claude OAuth 启动/取消及 N4 完整登录仍未做；N5–N9 没有由本轮补充证据。Windows/Linux 不外推。脱敏原生证据与完整源码验收见[记录](../acceptance/worker-accounts-batch4-0.26.0.md)；原始链接、码、密钥与响应不入持久检查报告。
