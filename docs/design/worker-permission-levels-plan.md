# Worker 权限档位：执行计划

2026-10-12，整合 Host 起草；用户同日确认了接口与顺带待办的安排。它落实 [ADR-023](../decisions/023-harness-integration-principles.md) 第 9 条与“Worker 的权限档位”一节，受 [ADR-030](../decisions/030-harness-layer-scope.md) 第 2 条约束：权限档位只经 harness 自己的参数表达，用户的 harness 配置不改。它在整体顺序里的位置见 [ADR-030 的执行计划](adr030-execution-plan.md)。这份计划不改变已经定下的事，只定怎样做、分几步、每步怎样验收。

## 要交付的

Host 在委派时为微任务选一个权限档位：只读、写检出、放开，不选就是写检出；同一个微任务进入后面的回合时可以换；选放开时带一句理由。档位只管文件能改到哪里。Worker 的回合不禁网，也不限制检出与临时目录之下的本机通信。各 harness 把每一档落到自己的原生机制上，落得下的强度分强制与约定两种，写进各自的参考文档。

不在这份计划里：用户一侧的上限（已定不设）、在界面上显示强度（已定不显示）、逐项的权限清单、Codex 与 Claude Code 接收问询、Windows 与 Linux 上的核对。

## 现状

角色层的工具范围有三个取值：不用工具、只读、可写。Worker 的回合取哪一个，由提交时的 `executionWorkspace.access` 决定，它现在只有 `read` 与 `write` 两个值，提交之后不能改。可写在各家落成的东西不同：

| harness | 今天的可写 |
| --- | --- |
| Codex | 只写检出与临时目录，禁网，不询问 |
| Claude Code | 自动接受检出内的编辑；Bash 必须在沙盒里，不许退到沙盒外；网络只放行包仓库 |
| DSH | 原生的默认预设，另有几行暂行的权限配置 |
| ZCode | `yolo`，不限制 |

Codex 的三种原生沙盒策略实际放开什么，2026-10-12 在 Codex 0.162.1、macOS 上量过，不调用模型：经它的应用服务器直接执行一个不依赖 harness 的小脚本。

| 这件事 | 今天的 Worker（写检出，禁网） | 写检出，放开网络 | 只读，放开网络 | 完全访问 |
| --- | --- | --- | --- | --- |
| 在检出里写 | 可以 | 可以 | 不行 | 可以 |
| 在检出外写 | 不行 | 不行 | 不行 | 可以 |
| 在临时目录写 | 可以 | 可以 | 不行 | 可以 |
| 绑定 Unix 套接字（检出里、临时目录里） | 不行 | 可以 | 不行 | 可以 |
| 绑定本机端口 | 不行 | 可以 | 可以 | 可以 |
| 访问网络 | 不行 | 可以 | 可以 | 可以 |
| 创建共享内存 | 不行 | 不行 | 不行 | 可以 |
| 列出进程（`ps`） | 不行 | 不行 | 不行 | 可以 |

所以只把网络放开，Codex 的 Worker 就能装依赖、起本机服务、跑要监听的测试；共享内存与列出进程仍然只有放开一档做得到，这与 ADR-023 记下的已知差别一致。

## 接口

只加一个取值、一个理由，不加别的开关。

- 提交：`executionWorkspace.access` 取 `read`、`write`、`full`，不给就是 `write`。取 `full` 时必须带 `executionWorkspace.accessReason`，一句话。
- 继续：`continue` 可以带 `access`（取 `full` 时带 `accessReason`），从下一个回合起生效；不带就沿用。
- 读取：`get` 给出现在的档位、每个回合用的档位、放开的理由。
- harness 给不出某一档时，沿用已有的能力声明与资格检查：指定了这个 buddy 的提交与继续被拒绝并说明原因，经路由时它不进候选。不为档位另做一套检查。

三个取值对应术语表里的只读、写检出、放开。术语表只讲概念，不写接口的取值；取值与术语的对应写在命令行的参考文档里。

## 存储与记录

- 每个回合用的是哪一档，记在这个回合自己的记录上，不从微任务“现在的档位”推出来；放开的理由随那一次选择记下；换档记一条事件。
- 存储的形式变了，就在同一个改动里扩展待做的那一次升级，并让检查套件升级样板看板后与新建的看板比对（`AGENTS.md` 的规定）。此前档位不能改，所以已有的回合换算成它所属微任务当时的 `access`，是准确的，不是猜的。
- 回合的证据里记下实际交给 harness 的原生设置，以及它是强制还是约定。

## 各 harness 的落法

取自 ADR-023 的对照表，加上这一批要改什么、还要量什么。量出来与表不一致时改声明与文档，不模拟。

| harness | 只读 | 写检出 | 放开 | 这一批要改的 | 还要量的 |
| --- | --- | --- | --- | --- | --- |
| Codex | 只读沙盒，放开网络 | 写检出沙盒，可写范围为检出与临时目录，放开网络；强制 | 完全访问 | 放开网络；新增放开；按回合给策略 | 续接的会话里换档是否生效 |
| Claude Code | 默认模式，不给 Bash 与写入工具；强制（不变） | 自动接受编辑；Bash 沙盒可写范围为检出与临时目录，域名全部放行，允许本机绑定与套接字；强制 | 跳过权限，不启用沙盒 | 沙盒的网络与本机通信设置；新增放开 | 沙盒能否在限制写入的同时放行全部域名；2026-10-11 遇到的 `npm` 与 `node` 被当作要批准的命令拒绝的原因；续接时换档；用户的受管设置禁止跳过权限时的表现 |
| DSH | `read-only` 预设；强制（不变） | `workspace-write` 预设；强制 | `danger-full-access` 预设 | 用原生预设取代暂行的权限配置行；新增放开 | 三个预设各自放开什么；续接的会话是否保留原来的权限，保留的话换档就要新开会话 |
| ZCode | 现在是冻结副本加事后核对；`plan` 模式待量 | `yolo`；约定 | `yolo` | 只有声明与文档 | `plan` 模式是否挡得住写入与命令 |

被拒绝的操作怎样到 Host 手里：harness 有原生的拒绝事件就用它（Claude Code 的权限请求、DSH 的提权请求），在请 Host 注意的事项里写明被拒绝的是什么；Codex 在不询问的策略下只是命令失败，由 Worker 在结果里报告。Worker 的角色说明加一句：被拒绝的操作照实报告，不绕过去。Host 据此决定是否换一档继续。

## 探针

同一个探针核对所有 harness：一个只用标准库的小脚本，在检出里运行，检查上表的八件事（ADR-023 列的七件，加上列出进程）。它放在 `tests/probes/`，由人有意运行，不进检查套件。Codex 可以不调用模型运行；Claude Code、DSH、ZCode 要借一个真实的回合，每一档一次，属于开发时的验证，逐次由用户批准。

## 分几步

1. **黑板与角色层。** 接口、存储与升级、`get`、能力声明与资格检查、回合请求带上档位。这一步之后还没有哪个 harness 给得出放开，选它会被如实拒绝。
2. **Codex。** 三档各自的原生策略，放开网络，续接时按回合换档，探针与它的 Codex 运行办法进 `tests/probes/`。
3. 验收前两步，安装一次。从这时起 Codex 的 Worker 默认能联网与监听，需要共享内存、列出进程或浏览器的微任务可以带理由选放开。
4. **Claude Code。** 先查清 2026-10-11 那次命令被拒的原因，再落三档。
5. **DSH。** 原生预设取代暂行的配置行；续接保留权限的话，写明换档时新开会话并作为事实报告。
6. **ZCode。** 量 `plan`；声明与文档；顺带把检查套件里还会启动真实 ZCode 的两组测试改成探针。
7. 验收后三步，再安装一次。
8. **Host 的文档。** skill 里怎样选档与放开要带理由、两份 Host 指南、各 harness 参考文档里的强度、ADR-023 里“尚未实现”的说明、待办里相应的条目。

可以提前的一小步：只把 Codex 写检出一档的网络放开，不动接口与存储。它就是第 2 步里写检出一档的终态，改动很小，可以随下一次安装先用起来；第 2 步再把它并进按档位取策略的写法里。 这一小步已于 2026-10-12 验收并合入（`3ad5f86a`，[记录](../acceptance/worker-permission-levels-host-review.md)），已于同日安装。

## 验收

- 第 1 步动存储与升级：在日常看板的一份副本上演练升级，核对已有回合换算出的档位；空主目录、不设状态目录、经启动器在私有服务上走一遍提交、继续换档与读取。
- 第 2、4、5、6 步动的是交给原生进程的参数：读完差异，跑受影响的测试，用探针在真实的 harness 上逐档核对，并各做一次真实的回合与一次续接换档。测试的假程序不校验真实接口，所以每一步都要有真实的核对。
- 完整检查每次整合之后跑一次；动到控制台时另跑前端全量并看像素。这份计划本身不要求改控制台：档位先在 `get` 里读得到，时间轴上怎样显示放进控制台其余页面的重做里。

## 与 ADR-021 的 L6 的关系

L6 要让 DSH 与 ZCode 的审阅运行复用 Worker 的执行载体。档位做完之后，审阅就是一次只读档位的 Worker 载体运行：DSH 用它强制的 `read-only` 预设；ZCode 若量出 `plan` 挡得住写入与命令就用它，否则沿用冻结副本加事后核对。L6 本身不在这份计划里实现，这里只定下它将来接在哪里。

## 顺带的待办

用户于 2026-10-10 同意随这一批处理的待办，这一批提前并收窄之后这样安排，用户于 2026-10-12 确认：

- 已经结束的执行在时间轴上仍显示“结束未确认”：原因在黑板一侧，随第 1 步修并补测试；界面上的部分留给控制台的重做。
- 准备检出失败时 Host 默认只看到一句话：随第 1 步，默认带上一行原因。
- “等 Host 处理的微任务”的数量：仍作为最后一步，与 Host 的文档一起。
- 清单里其余几项：DSH 用量边界的两处测试已随 ADR-030 批次 3d 补上；时间轴滚动条闪动属于控制台，随控制台的重做；读取命令执行失败、完整检查纳入前端测试、重量一次检查用时这三项与这一批不在同一块，留在待办里各自安排，Host 没有核对它们现在的状态。

## 这份计划之外仍然开着的

- 各 harness 在 Windows 与 Linux 上各档放开什么，没有量。
- 读取不在档位的范围内：写检出一档不保护检出之外的文件不被读到。数据流向说明里要写明。
