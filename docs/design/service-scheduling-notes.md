# ADR-031 M2：服务调度与执行端点

本说明记录 M2 的源码改动与选择检查，最终验收由 Host 完成；没有安装产品，没有操作日常看板，没有调用真实模型。M3 的重连、M4 的控制台与 M5 的安装生命周期仍按执行计划分开进行。

## 准入与启动

服务在看板提交新事件后唤醒调度，没有变化时也每 2 秒重看；一次唤醒持续准入到没有可运行的任务，停止或重启一经记录便不再准入。没有新事件的空准入不会反复唤醒自己。机器总上限、冻结模型服务的上限、工作目录与独占资源仍在原来的 SQLite 事务内判断，Router 的准备、模型选择、资源占用与 `begin_turn` 同事务提交。候选保留按到达顺序分批读取，并继续扫描受阻窗口后面的任务；共享 stash 仍在事务外观察，覆盖缺失时只针对选中的任务重试一次。

任务能力在准入边界检查一次，执行代码的能力与已声明的模型能力共同构成可承载集合；实际 harness、模型与 effort 的选择沿用工作流和路由规则。服务生成 nonce，看板只保存校验值。执行的 nonce 与回合凭据只写入权限受限的启动文件，先 fsync 文件及目录，再经现有 `owned_popen` 创建独立会话中的执行进程。没有创建进程的失败释放准入；已经创建的句柄由服务继续持有并核实停止，不因启动标记写入失败而丢弃。

执行进程自行构造并上报完整 OS 身份，服务用创建时持有的句柄核对后存储。Windows 的命名 Job 在启动前选定并写入私有材料，执行自身不依赖父进程的 `spawn.marker` 才能上报；首次身份确认之前不会启动原生工作。父侧身份捕获失败时，自报仍可与持有句柄中的创建事实核对并补齐监管；缺失身份始终保留占位，不据子进程退出就释放。身份只有开机会话、PID、启动时刻及进程组或命名 Job；一次执行只有一个不可变身份。进程号本身不构成停止证明。服务拥有的句柄负责回收子进程；执行的存亡由端点长调用与完整身份共同判断。

## 认证与端点

执行对看板的写操作只有 `execution_progress` 与 `execution_result`；进度携带提示、阶段及身份，结果保持原来的幂等提交与产出验证。两者以执行号、代次与 nonce 认证，并检查有效执行及封存中的中断栅栏。`harness_prepare` 也使用这组凭据。没有 Worker 登记、认领、续租或挂接操作；`worker_sessions` 仍表示 Worker buddy 的原生会话。

每个执行进程只注册一个 C-Two `ExecutionLive` 端点，问询、观察、停止与长调用都使用字符串请求及字符串回答，每个请求在端点边界核对身份、实例与令牌。原生回合和总结回合提供进程内的当前通道，执行端点将问询和观察交给它。服务的 `LiveRegistry` 只保存本服务实际连着的执行通道。

端点地址、C-Two 凭据、实例和令牌放在执行私有目录的 `execution-live.json`，不进看板或备份；执行等待结果交付时文件持续存在，真正退出才清理。服务按预定的私有目录读取并校验它，M3 可以使用同一材料接回。已经证明执行消失时，服务按该端点的凭据清理遗留端点；活着或未知的身份不能授权清理。

服务对自己启动的每个执行维持一条长调用，执行端每次最多等待 3 秒后回答，服务继续发起下一次。服务消失不会在 C-Two 0.7.4 的执行服务端积累无界等待。调用失败而身份仍在时按退避重连，执行继续占用名额；成功的长调用不触发另一套身份轮询。

## 停止与外部时限

Host、Lead、控制台及服务停止先留下持久停止意图，服务通过执行端点发送发起者和绝对宽限；每次重新连上端点都会补发。重复停止不会延长原来的宽限，强停会取消当前原生调用。私有停止文件已删除，操作系统信号仍按未知来源的停止处理。

服务执行 wrap-up 宽限和私有 `execution-budget.json` 中的 Router 时限，强停前写下 `execution.deadline` 的原因；强停约 8 秒后，仍活着的执行按核实过的身份结束其进程组或 Job。已经写出原生停止确认回执的执行可以继续等待交付。执行被强行结束后的结算保留停止原因，包含控制台、服务、宽限、强停和 Router 期限，不归类为 harness 错误。

## 唯一恢复路径

长调用失败或回收到子进程退出后，先按完整身份核对；只有身份消失或开机会话改变才接手。服务启动及每 15 秒的恢复也使用同一条路径。私有目录有回执时先验证执行绑定和回执边界，再进入 `execution_result` 的提交代码，保持相同的幂等、工作流、产出与资源结算。

没有回执时读取该执行的原生创建日志，核对并停止其中记录在案的存活进程；日志完整、没有未决创建且所有身份都已消失，才确认原生停止。未决创建不妨碍清理已经知道的身份，但不提供完整停止证明。确认不了就保留未确认及资源栅栏。已经提交过未确认停止的结果，恢复取得新的完整停止证据后仍进入同一结果提交代码收尾，原回执保存在恢复结果的 `previousReceipt` 中；没有新证据不会重写。此前有人要求停止时，结果记录停止及其原因；没有停止意图则记为中断。确认停止后再封存部分产出，封存失败保留可重试的中断记录，迟到的执行写入会被栅栏拒绝。

## 删除与存储

已删除常驻 Worker 池、supervisor、Worker 运行时、Worker 的在线转发、认领请求回执与租约扫描，以及对应的 CLI 命令和 health 字段；并发和活动仍用原有 `maxConcurrent`、`capacity` 与 `activeWork`。删除了只能靠外部认领运行的 `external` 适配器、示例和调用方法；历史执行记录仍可读取。Worker buddy 的角色与原生会话没有改名。

schema 23 删除 `workers`、执行上的 Worker 归属与认领、租约列，以及身份表的 Worker 三列和 ordinal 链；已无用途的派生认领 capability 也一并删除。显式升级从 schema 22 开始，按新建看板的 DDL 重建受影响表和索引，每次执行只保留最后一个完整身份，将中断证据 `worker-stopped` 转为 `orphan-stopped`，清除退休或改形的操作回执。命令响应只转换已知 task/attempt 投影，结果及事件只转换服务拥有的已知路径，模型和命令输出中的同名键或文本保持原样；不再产生的事件保留历史载荷。

安装仍要求空闲，先退休装着的 0.39.0 Worker，在备份后转换数据库，目标服务和保留数据验证成功后清理旧 `workers/` 与 `worker-pool.json`。失败沿原来的备份和运行时回滚路径处理。新备份不收 Worker 文件，私有原生日志不进备份且不转换。存储清点识别 daemon 与执行进程，运行时有被使用的命令行或打开文件时继续保留。检查运行器不再给 Worker 写停止请求，以私有服务和执行进程结束、私有根删除为收尾条件。

## 留给后续的边界

服务重启仍将未结束执行标成 uncertain，保留资源并使旧 Router 决定失效；执行照常提交结果。重新建立存活执行的长调用、补发停止、连不上时的“不知道”状态及服务接回孤儿属于 M3。本说明没有把这些写成已完成，也没有验证日常安装、中间号不变的升级、Windows 或 Linux 的实际运行。Windows 创建仍沿用现有 `owned_popen` 的挂起、命名 Job 和恢复规则。

## 周期事件与检查

续租与 `attempt.lease_expired` 的生产者已删除。执行控制仍每 0.25 秒观察当前原生活动，只在活动有变化时发布，存储按单调活动标识去重；预检与回执重连按退避重发内存里的最新提示，`waitingReason` 的重复交付仍可能产生 `attempt.waiting`。服务的时长和原生静默提醒产生 `attempt.reminder`，harness 健康与账户刷新可以产生 `harness.checked`、账户观察或未知事件，中断封存重试只在错误改变时产生 `attempt.interruption_seal_pending`。长调用与空的恢复扫描本身不写心跳事件；这些剩余生产者本轮只核对，没有改变事件保留策略。

所有 Python 验证使用 Host 指定解释器的 `PYTHONPATH=src <指定解释器> -m hey_my_buddy.cli.checks <文件或目录>`，进程数使用默认值，未向该解释器环境写入依赖，未运行完整检查。选择检查覆盖 Buddy、黑板、协议、安装及 CLI；首轮暴露的旧 Worker 夹具、旧列及旧回执断言已用于修正测试。Buddy 的 78 个文件在组合中通过，组合中的两个安装环境及原生日志旧断言修复后也已聚焦通过；黑板选择范围为 100 个文件，旧夹具失败经分批修正并复查。检出生命周期单文件最后 70 个用例通过。最后两批分别为执行入口、调度与真实 C-Two 的 3 文件 17 用例，以及恢复、容量和 stash 的 6 文件 66 用例，均退出 0 且检查运行器确认私有根已删除。不同批次有重叠，没有合计成一次完整检查；本说明不是 Host 验收。

故障验证包括启动材料写入失败、Popen 未创建子进程、父侧身份捕获失败后的执行自报接回、marker 写入失败、活着或未知的身份拒绝回收、真实执行被杀后的原生停止与端点清理、冻结执行约 8 秒后结束、服务重启后结果交付、无变化的准入不自唤醒、受阻候选窗口后仍有工作、schema 22 样板与新库结构一致、已知中断证据转换、用户结果保真、迁移失败的事务回滚及安装失败保留旧 Worker 目录。共享的进程句柄、启动函数与 `owned_popen` 已移到 `protocol/`，服务与执行侧使用同一份实现，没有新增两边之间的导入。
