# Native sandbox review proof

The 0.25.0 verifier correlated native calls by matching one model-written JavaScript and command spelling. GPT-6.1-Sol and GPT-6-Luna produced equivalent native outcomes with different input spellings, so request recognition changed the certificate result. The 0.26.0 verifier stopped reading command text but still required the model's own output envelopes to parse and to match the fixed probes; the third real 0.159.0 run (b37e7302) passed every fixed native challenge while Codex returned five exec `custom_tool_call` outputs that no envelope parser could decode, so unreadable model output failed the certificate. The current verifier moves the whole boundary proof onto the controller's fixed native challenges and judges the model tool stream structurally only; the old spelling recognizer and the output-envelope parser remain auxiliary diagnostics.

## Two evidence channels

The controller checks the private `buddy-router` configuration through config/read and thread/start, including exact filesystem grants, disabled network, no inherited permission profile, no MCP servers and typed requested controls. It then issues five fixed command/exec challenges under `permissionProfile:"buddy-router"`: read the inside marker, read the outside sentinel, write inside, write outside and contact the positive-control loopback endpoint. The official [0.159.0 command protocol](https://github.com/openai/codex/blob/rust-v0.159.0/codex-rs/app-server-protocol/src/protocol/v2/command_exec.rs) exposes this profile selector; the [command processor](https://github.com/openai/codex/blob/rust-v0.159.0/codex-rs/app-server/src/request_processors/command_exec_processor.rs) resolves it using the same configured permission implementation as thread/turn execution. The controller provides fixed argv and targets; the model cannot select the target, name the operation or fabricate its native response.

Each native challenge binds one controller operation to a unique pending JSON-RPC request ID, command/exec method and the private profile. Buffered results require integer exit code and both stdout/stderr streams, stay below the explicit 8 KiB per-stream cap and preserve native denial output privately. Duplicate, late or unrelated response IDs, unsupported profile/method, output at its cap and incomplete result envelopes fail. The deadline and native/controller stop contract remain unchanged; no permission fallback or unsupported-operation success exists.

The existing model turn still exercises the native tool path, but its stream is judged structurally. All five native requests and replies must correlate by thread, allowed turn and call or item identity with the paired type; every observed tool must belong to the allowed execution family — the exec function or custom tool and native `commandExecution` items — and high-level item pairs must close. Extra, duplicate or forbidden tools, unmatched or dangling calls, truncated capture, exceeded budget and any approval request fail. Output envelopes are never parsed or interpreted, and model results are no longer required to match the fixed probes: neither a model claim nor an unreadable Codex output envelope can establish or veto the boundary verdict, so response parse success survives only as an auxiliary diagnostic shape.

`boundaryDenials` and `internalRead` rest solely on the controller's five fixed native challenges under the same private profile: the positive marker read proves the inside read, and four nonzero native denials prove outside-read, inside-write, outside-write and network, with the outside sentinel and frozen input snapshots unchanged and the network endpoint positively checked by the Host while the fixture server remains alive. A nonzero exit without a permission denial, timeout, missing probe or mere unchanged files cannot prove denial. Model tool calls and the five controlled challenges share the existing 24-call bound; the model controller reserves five of those calls for the fixed proof.

## Retention and historical replay

The same whitelist filename `review-evidence.json` now carries `buddy-review-evidence-v3`. In addition to strict policy controls and correlated tool summaries, it retains fixed probe operation, request ID, profile/method match, exit code, output lengths, denial/marker comparisons and truncation. Each check's basis records the structural stream facts and the probe-derived boundary facts; the retired model-consistency facts are gone. Actual commands, paths, stdout/stderr, prompts, account fields and credentials remain private. Evidence publishes exclusively before confirmed-stop cleanup, preserving unknown stops or failed publication under the existing contract, and readers accept the v1, v2 and v3 formats.

The Sol and Luna v1 records retained generic denial booleans and marker comparisons, but no independent native request binding for the four boundary categories. Sol's same-run supplemental sanitized events are accepted only when their original canonical evidence hash and run ID match. Both historical records replay to a complete allowed tool stream; v1 marker-read and denial observations remain readable auxiliary facts, and both records consistently stay insufficient to certify all boundary categories, reporting `HISTORICAL_PROBE_BINDING_MISSING` without ever labelling categories by ordinal, output size, exit code or a model assertion, and without writing a new certificate. The 0.26.0 Luna v2 record (run `b37e7302`) carries complete fixed probes beside its unparseable model output envelope; under the current rules it replays to `checksPass` with `REPLAY_IS_NOT_CERTIFICATION`, because only a fresh explicitly approved native check may produce the certificate.

Schema stays 15; the contract version rises to 0.27.0. Account sources, credentials, OAuth, quotas, Worker sessions, daily-state migration and installation are outside this repair. The existing native check profile selection and requestId replay contract remain intact. Windows and a live 0.159.0 command/exec certification remain unverified until separately authorized: the three real 0.159.0 runs exercised the fixed probes natively, but none produced a certificate under the rules of its time.
