# Native sandbox review proof

The 0.25.0 verifier correlated native calls by matching one model-written JavaScript and command spelling. GPT-6.1-Sol and GPT-6-Luna produced equivalent native outcomes with different input spellings, so request recognition changed the certificate result. The current verifier correlates request/response identity and native result shape independently of command text; the old spelling recognizer remains only an auxiliary diagnostic.

## Two evidence channels

The controller checks the private `buddy-router` configuration through config/read and thread/start, including exact filesystem grants, disabled network, no inherited permission profile, no MCP servers and typed requested controls. It then issues five fixed command/exec challenges under `permissionProfile:"buddy-router"`: read the inside marker, read the outside sentinel, write inside, write outside and contact the positive-control loopback endpoint. The official [0.159.0 command protocol](https://github.com/openai/codex/blob/rust-v0.159.0/codex-rs/app-server-protocol/src/protocol/v2/command_exec.rs) exposes this profile selector; the [command processor](https://github.com/openai/codex/blob/rust-v0.159.0/codex-rs/app-server/src/request_processors/command_exec_processor.rs) resolves it using the same configured permission implementation as thread/turn execution. The controller provides fixed argv and targets; the model cannot select the target, name the operation or fabricate its native response.

Each native challenge binds one controller operation to a unique pending JSON-RPC request ID, command/exec method and the private profile. Buffered results require integer exit code and both stdout/stderr streams, stay below the explicit 8 KiB per-stream cap and preserve native denial output privately. Duplicate, late or unrelated response IDs, unsupported profile/method, output at its cap and incomplete result envelopes fail. The deadline and native/controller stop contract remain unchanged; no permission fallback or unsupported-operation success exists.

The existing model turn still exercises the native tool path. All five native requests and replies must correlate by thread, allowed turn and call ID/type; exactly one result reads the unpredictable inside marker and four report native denials. Command input, argument order, variable name, quoting and shell spelling do not decide an operation. High-level item pairs must close, every observed tool must belong to the allowed execution family, and extra/duplicate tools, unmatched replies, truncated capture or any approval request fail. These observed tool-stream results are independent of the fixed sandbox proof, so model prose cannot establish read/write/network enforcement.

The boundary check requires all five fixed native challenge results: positive marker read and four nonzero native denials, with the outside sentinel and frozen input snapshots unchanged. The network endpoint is positively checked by the Host while the fixture server remains alive. A nonzero exit without a permission denial, timeout, missing probe or mere unchanged files cannot prove denial. Model tool calls and the five controlled challenges share the existing 24-call bound; the model controller reserves five of those calls for the fixed proof.

## Retention and historical replay

The same whitelist filename `review-evidence.json` now carries `buddy-review-evidence-v2`. In addition to strict policy controls and correlated tool summaries, it retains fixed probe operation, request ID, profile/method match, exit code, output lengths, denial/marker comparisons and truncation. Actual commands, paths, stdout/stderr, prompts, account fields and credentials remain private. Evidence publishes exclusively before confirmed-stop cleanup, preserving unknown stops or failed publication under the existing contract.

The Sol and Luna v1 records retained generic denial booleans and marker comparisons, but no independent native request binding for the four boundary categories. Sol's same-run supplemental sanitized events are accepted only when their original canonical evidence hash and run ID match. Both historical records replay to a complete allowed tool stream, one observed marker read and four native-denial observations. They consistently remain insufficient to certify all boundary categories. The replay never labels categories by ordinal, output size, exit code or a model assertion, and never writes a new certificate. A fresh explicitly approved native check must produce the missing fixed proof.

Schema stays 15. Account sources, credentials, OAuth, quotas, Worker sessions, daily-state migration and installation are outside this repair. The existing native check profile selection and requestId replay contract remain intact. Windows and a live 0.159.0 command/exec run are unverified until separately authorized.
