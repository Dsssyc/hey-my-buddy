# Router turns over native structured calls in two modes

A **Router** is a peer role, not a Worker and not a workflow turn: it examines one governed goal and returns either one configuration choice inside the frozen routing bounds or an explicit abstention. Unlike a Worker's result, a Router's choice takes effect without Host acceptance because it exercises only the configuration authority the Host omitted. It receives no attempt turn identity, no agent credential, no completion tool and no artifact authority, and it cannot create goals, request assistance, use inquiry, publish evaluations, dispatch work or produce artifacts. The role and its boundaries are owned by [ADR-014](../decisions/014-router-buddy-and-read-only-routing.md), the two modes by [ADR-018](../decisions/018-routing-modes-and-host-workflow.md) (first part), and the terminology by [CONTEXT.md](../../CONTEXT.md).

One Router setting contains the ordered `configuration.routerProfileIds`, `routerRetryIntervalSeconds` (default 600 seconds), `defaultRoutingMode` (`fast`/`review`) and `routingBudget` (`brief`/`standard`/`deep`). Every item serves the same frozen request and mode; review also receives its immutable repository copy. Only authenticated human publication changes settings. `convert_legacy_router_settings()` is a pure upgrade helper: retain both old nonempty slots, put the old default mode's slot first, deduplicate identical IDs without reordering, preserve unavailable IDs, map `quick` to `brief`, and set the retry interval to 600. Its diagnostics retain both source slots. Ordinary reads and publications never call it; old settings report `router-settings-upgrade-required`, and the actual upgrade conversion belongs to L15.

## Program selection before a Router call

Python freezes the legal candidates after applying submitted configuration fields, required capabilities, availability, enablement, pins and exclusions. Exactly one legal candidate is selected directly in that transaction with reason `唯一合法候选，未调用 Router`, `routerCalled:false` and workflow source `single-candidate`. No Router task, attempt, reader lease, model call, frozen review mirror, budget, native identity, usage or stop receipt is invented. Router availability and the Router’s task-text byte limit do not block this path; a long goal retains its full original text and the existing bounded `taskReference` in the routing record.

The direct choice records the same program-derived `policyCheck` and task-preference outcome as model selection. Its `output.programSelection` also retains effective user preferences (including the pin that may narrow the set) and program policy facts, so historical preferences remain readable without a model input snapshot. Multiple candidates keep the ordinary Router path and its limits, validation, fencing and Host boundaries. Zero candidates still stop at the Host boundary with no Router task and no model call, and their workflow source is `no-candidate`, read from the record's own frozen zero `candidateCount` in `routingBasis`; a record without that frozen basis keeps its existing source marker instead of being relabeled from later state. Replaying a request returns the same decision and creates no duplicate events or execution.

Every new decision freezes `routingBasis:{candidateCount,excludedCount,excludedProfiles}` in its request. Excluded entries carry the configuration tuple, profile ID and the effective exclusion’s reason/source; they are configurations that pass the request’s other hard bounds but are user-excluded. The supported catalog’s exclusions are retained up to its existing 200-profile bound; an oversized table keeps the exact exclusion total alongside its bounded entries. `selection-get` exposes this basis plus `constraints` and `requiredCapabilities` without requiring `includeAudit`; workflow routing and CLI brief output carry the same frozen facts. Later preference or catalog changes never rewrite them, and historical records without this basis remain unknown. Unlocked reroutes display that reroute’s own constraints, independently of the original goal’s earlier constraints.

## Harness-neutral Python protocol

`src/buddy/router.py` owns protocol version 10, both instruction prefixes, the answer schema, the frozen candidate enum, the boundary check and the provisional budgets; `src/buddy/adapters/read_only.py` executes one generic native read-only structured call and `src/buddy/adapters/read_only.py::start_no_tool` executes one generic native tool-free structured call; `src/buddy/adapters/decision.py` is the `decision` adapter the Worker runtime claims for a Router attempt in either mode. The old DSH-specific Node decision helper, the `dsh.decision` runtime resource, the `BUDDY_DECISION_HELPER` override, the `decision_execution` capability and the `start_decision` path are removed with no compatibility layer. Routing packages, prompts, answer schemas, bound checks and records all live in Python; each harness only needs the generic structured capability of the mode it serves.

## Fast routing

Fast routing is a single native structured call with every tool disabled by the harness itself — file reads, shell, network and search, MCP servers and subagents — not by prompt wording alone. The adapter declares `no_tool_structured` and implements `start_no_tool_structured`; the harness must genuinely remove the tools, and Python inspects the native event stream. An answer is adopted only when the native stream is complete and contains zero tool calls; any observed tool call invalidates that answer for the call.

The Router receives only the task description, the frozen legal candidates with their evaluation cards, the effective user preferences and family notes, and the program-computed `policyFacts`. It receives no repository content, no frozen checkout and no historical execution evidence. Evidence references may cite cards, preferences and notes only; `file` evidence is not available in this mode.

Fast routing has no tool-call budget because there are no tools. Its deadline is 60 seconds. It uses the same single bounded answer-format correction as review routing, and the correction may never fix an out-of-bounds selection. Its eligibility is a harness capability, not a paid probe: an adapter that declares and implements the tool-free structured call is confirmed by simulated tests and one zero-tool-call check, and under an eligible harness any enabled, available configuration may serve as the fast Router. A harness that cannot reliably disable its tools cannot serve this mode.

## Review routing

Review routing uses `local_read_only_check()` without a model call or version certificate. Codex retains its native frozen-copy-only filesystem grants, default denial and disabled network; Claude Code retains only Glob/Grep/LS/Read and its native sandbox. The controllers check the effective native policy and existing tool stream during each run. DSH/ZCode review is unavailable with an explicit Worker-carrier-unimplemented reason. Their dedicated Router channels and static bundle proof were removed; the later L6 stage will reuse their Worker execution carriers. Free eligibility reads no installation bundle and launches no native process. Normal Worker/fast execution and the four adapters' normalized tool facts remain in stage 2; historical native checks are recorded separately. [ADR-021](../decisions/021-router-buddy-planes-and-routing-evidence.md) and [ADR-023](../decisions/023-harness-integration-principles.md) own this boundary.

The three budget presets are named 简要 / 标准 / 深入 and their identifiers are `brief` / `standard` / `deep`; the former identifier `quick` is renamed. The per-preset deadline, tool-call count and read volume are unchanged: `brief` is 60 seconds, 8 tool calls and 131072 bytes; `standard` is 300 seconds, 24 tool calls and 524288 bytes; `deep` is 600 seconds, 64 tool calls and 2097152 bytes; the default is `standard`. These values are provisional and await a separately authorized native measurement. An upgrade maps a saved `quick` to `brief`; the new public API refuses `quick` and accepts only `brief`, `standard` or `deep`. "快速" now names fast routing only and never a review budget.

The global preset is stored in `meta.router_budget_preset`, and an authenticated console user publication may update `configuration.routingBudget`; Hosts and Workers cannot change it. Actual usage is reported as `elapsedMs`, `toolCalls` and `bytesRead`, and an unavailable counter stays `null` rather than being invented. Neither current adapter can observe read bytes, so the read-byte limit is recorded but not enforced, and the console shows only the time and tool-call limits. A tool-call limit of N allows N native tool calls; the next call is interrupted.

## Answer shape

The Router returns exactly `profileId`, `reason` and `evidence`, following the supplied JSON Schema. `profileId` is either one identifier from the request-local frozen candidate enum or `null` to abstain; a value outside that enum is `router-out-of-bounds` and is never retried. `reason` is a nonempty string of at most 2,000 characters. `evidence` holds at most 32 `{kind, ref}` entries whose kind is `card`, `annotation`, `preference` or `file` in review routing and only `card`, `annotation` or `preference` in fast routing, and whose `ref` is a nonempty string of at most 1,024 characters without control characters. A `file` reference must be a checkout-relative path: absolute paths, `..`, backslashes, colons and `.` are rejected, and a file reference carries only a path, never file contents. The answer is parsed leniently from JSON text for transport, but the response object itself must carry exactly the three required fields with no extras.

When a Router is called, it is not required to cite a card that was supplied, and an unknown card or annotation identity is advisory rather than a veto. Deviating from a task or user preference is allowed when the reason and evidence are recorded; the program computes the outcome and stores it as `policyCheck`, but it never rejects an answer merely for preferring an alternative. Python freezes the legal candidates before the call: enabled, available, not `exclude`d, matching the goal's required capabilities and complete coding tuples, with any `pin` preference restricting the set to the efforts that are effectively pinned. The bounded request carries the candidates' effective preferences — `{profileId, mode, reason, source}`, where `source` says whether a per-effort override or the family default applied — and the family-form notes `{adapter, provider, model, text, revision, updatedAt}`, never one copy of a family note per effort. The model's judgment is not re-reviewed by the Host; only the boundary is checked.

## Program facts and correction

`selection_policy.policy_facts` and `selection_policy.expected_policy_check` derive the hard constraints and the legal user-preferred profiles from the frozen request, never from model prose or source filenames. A Router answer that stays inside the bounds is adopted with that program-owned `policyCheck`; the model is never asked to echo it and an echoed copy cannot change the facts. The retired task-local `routingPreferences` and their program validation are cancelled (ADR-021 decision 5): the `policyCheck` records `hardConstraints` and `userPreference` only.

A native structured controller may make at most one answer-format correction inside the same attempt and the same overall deadline, and only when the shape is malformed. It never corrects an enum violation or a candidate outside the frozen bounds: `correction_code` returns `NULL` for any enum error, so an out-of-bounds selection ends the call instead of being reformatted. Claude does not continue correction because its read-only path makes a single call. Budget exhaustion, deadline, cancellation, valid abstention, provider failures and bad input are not corrected.

## Frozen input materialization

A review Router never reads the Host's live checkout. `router_input.prepare` materializes a private read-only copy from `manifest.inputTree`: it first calls `workspace.verify(manifest, require_unchanged=True)`, reads that exact tree through `git ls-tree` and raw `git cat-file` blobs, rejects escaping or cyclic symlinks and unsupported entries, and digests the resulting mirror. Archive export attributes and checkout filters cannot omit or rewrite the frozen bytes. When the request has no file manifest, as in a public standalone `selection-request`, it reads only an empty private directory rather than borrowing any caller checkout; this is source behavior only; the daily runtime remains separately installed. "Unchanged" means the managed frozen input, including explicitly included untracked files; ignored files and caches are outside the manifest and are never read or hashed unless explicitly selected.

After the native process has stopped, `router_input.verify` re-runs `workspace.verify` on the original manifest and re-digests the private mirror. Any change yields `router-input-changed`; a missing or mismatched verification cannot be published as a recommendation. A `reroute` persists its intent in the route records, and a continuation prepares its new fixed manifest before routing begins, so the review Router always sees a prepared frozen input. All ownership, fencing, cancellation and stop-evidence rules of the ordinary Worker runtime continue to apply to the routing attempt.

Fast routing materializes no mirror: it never receives repository content, so it has no input to re-verify and its route record carries `inputVerification: null`.

## Process ownership and stop evidence

Each mode starts one controller process in its own session with a sanitized environment that drops `BUDDY_AGENT_*` and `BUDDY_WORKER_*` credentials. A review Router uses the frozen mirror as `cwd`; a fast Router uses an empty private directory, because it has nothing to read. The native deadline is 60 seconds for fast routing or the selected budget for review routing; process shutdown has its own bounded grace period. A run that exhausts its native tool budget or reaches its deadline first requests a native interrupt and then reaps the owned process group; `nativeInterruptRequested` and `nativeInterruptAcknowledged` are recorded separately from `processState.shutdownConfirmed`, so a forced stop is never reported as an acknowledged native interrupt. A result is imported only with the controller's own stdout payload and confirmed process-group shutdown; an unparseable or partial payload is `invalid-native-result`, and a killed controller with no durable result stays uncertain.

## Frozen Router setting and Host boundary

Each request freezes the full ordered Router identities, mode, retry interval, configuration revision, budget, legal candidate enum and program facts once. `router.current_router()` is the shared resolution entry. Each reached item gets a new internal task and immutable dispatch/attempt binding; the business request and decision ID remain the same. Later settings never refresh these frozen facts. Current actor fields come from the actual dispatch; historical requested/fallback JSON remains audit evidence.

A submission no longer carries `routingMode` or `allowRoutingFallback`: both are rejected as retired Host input at every entry (`submit`, helpers and `selection-request`), and the effective mode comes from `configuration.defaultRoutingMode`. A submission whose configuration is a complete explicit quadruple still delegates directly and calls no Router, exactly as before.

A Router with no usable answer advances to the next item only after the previous execution is positively stopped. This includes preflight unavailability, runtime errors, timeouts, invalid answer/tool evidence and budget exhaustion. A valid choice or valid null abstention stops the walk. Cancellation, changed input/settings/accounts/ownership/candidate legality, unknown stop, active retries, capacity and writer gates never trigger a spare Router call; capacity and gates queue. No mode downgrade occurs. Skip periods derive from each Router's latest recorded no-answer plus the configured interval; a valid adopted answer, including abstention, resets its own streak. Reading or skipping does not write a new failure or extend the window; no durable circuit state is added.

## Public configuration and routing reads

Published configuration accepts `routerProfileIds` (ordered unique complete profile IDs; `[]` clears), `routerRetryIntervalSeconds` (integer 1–2147483647; default 600), `defaultRoutingMode` and `routingBudget`. Null and old single/dual-slot spellings are rejected. Publishing the list validates every complete catalog identity; an item's temporary health, quota or mode eligibility does not block saving the list. Claim rechecks the frozen item before any model call. Omitted fields stay unchanged; a fresh board starts with `[]`/600/fast/standard. Legacy settings are never implicitly converted.

`profiles.capabilities` uses `routing:fast` for the no-tool capability, while `decision` denotes the locally eligible review capability. Only the user writes global configuration through the console; no permission is widened.

`selection-get` exposes frozen settings and candidates, the actual dispatch identity/index, `routerTrials`, `selectedProfile`, program `policyCheck`, `usage`, `budget`, native identity, stop/input checks and audit tool evidence. At a Host boundary, `routingBoundary` contains `kind`, program `code`/`reason`, every recorded Router trial, frozen candidates/facts, known `retryAt`, and structured continue/reroute/cancel command templates with the actual owner/revision and a control-file placeholder. Unavailable and changed boundaries explain why cancel/repost does not help. Unknown recovery stays null; unknown stop and unsatisfied hard gates block commands. A complete Host quadruple can continue the same governed goal under its existing hard constraints. Standalone selection has no fabricated workflow command.

## Native verification status

The 0.19.0 source declares Codex read-only structured routing verified on macOS, after native probes with codex-cli 0.157.0 and GPT-6 Sol high established frozen-root reads, denied out-of-root reads and writes, denied networking, unchanged input and confirmed shutdown. Each call checks the effective private permission configuration and native acknowledgement before model input.

Historical approved fast-routing probes and their limits remain in [0.20.0 acceptance](../acceptance/routing-modes-0.20.0.md). Current source eligibility, fixture checks and daily installation are separate facts. Codex/Claude review retains the existing native sandbox path without a paid certificate; DSH/ZCode review is unavailable until the separately designed Worker-carrier path is implemented and accepted.

## Relation to routing and maintenance

A routing decision is created by `selection-request` or governed routing. The `decision` adapter executes each frozen ordered Router dispatch in the common mode. An exhausted list settles at the Host boundary with its recorded trials. Evaluation maintenance stays Harness-owned: `evaluation-prepare` gathers facts without a model, synthesis occurs outside the blackboard, and a short card-only patch uses a maintenance writer grant ([evaluation maintenance](evaluation-maintenance.md)).

## Local review admission and quota eligibility

The paid verifier, `harness-verify`, `review-check`, certificates and console verification action are removed. Read-only eligibility is a local mechanism check, separate from health/account/quota availability and the runtime native-policy check. Historical certificates are not read or converted on ordinary board access; physical cleanup and old Router-setting conversion belong to explicit upgrade work.

Candidate selection and Router eligibility also exclude native-confirmed exhausted provider/limit pools. Billing labels do not affect candidates, pins or ordering. Display staleness never restores an exhausted pool; only its reset or a newer usable native observation does. Host-explicit configurations are not silently changed and receive an exhaustion reminder. A persisted exhaustion without a recorded reset carries one single-use retry window: one hour after the blocking observation (or the last consumed retry) one routing decision may admit the configuration again, the claim committing transactionally with the selected configuration so concurrent decisions cannot both retry; the publish-time bounds re-check still accepts the window that same decision consumed. Reads never claim a window, and an explicit `quota_redetect` opens one early without any model or balance call ([harnesses](harnesses.md#no-reset-exhaustion-recovery-adr-019-second-stage) owns the contract).

The four native adapters project facts into one ACP toolEvidence package before session filters: read, edit, delete, move, search, execute, think, fetch, switch_mode and other. Publication alone judges the claim-frozen policy: fast requires complete zero-call evidence; sandboxed review allows read/search/execute, other review read/search. Missing bindings, incomplete/foreign/child/late/truncated events or inconsistent counts invalidate the answer. Raw and typed Codex execution names join only by the same actual call identity and the documented execution aliases; MCP namespaces remain other.

DSH review uses the official AgentRegistry and ToolRuntime, restricting the native surface to read/glob/grep with a monotone guard and native schemas/header checks. The Python controller owns the private headless profile, free dump-config preflight, cumulative time/tool budget and at most one format correction. It preserves stop uncertainty and tool-event failures; it provides no OS sandbox guarantee. Native DSH model behavior is unverified until separately approved.
