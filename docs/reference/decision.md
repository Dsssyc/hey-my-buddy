# Router turns over native read-only structured calls

A **Router** is a peer role, not a Worker and not a workflow turn: it examines one governed goal read-only and returns either one configuration choice inside the frozen routing bounds or an explicit abstention. Unlike a Worker's result, a Router's choice takes effect without Host acceptance because it exercises only the configuration authority the Host omitted. It receives no attempt turn identity, no agent credential, no completion tool and no artifact authority, and it cannot create goals, request assistance, use inquiry, publish evaluations, dispatch work or produce artifacts. The role and its boundaries are owned by [ADR-014](../decisions/014-router-buddy-and-read-only-routing.md) and the terminology by [CONTEXT.md](../../CONTEXT.md).

## Harness-neutral Python protocol

`src/buddy/router.py` owns protocol version 9, the stable instruction prefix, the answer schema, the frozen candidate enum, the boundary check and the provisional budgets; `src/buddy/adapters/read_only.py` executes one generic native read-only structured call; `src/buddy/adapters/decision.py` is the `decision` adapter the Worker runtime claims for a Router attempt. The old DSH-specific Node decision helper, the `dsh.decision` runtime resource, the `BUDDY_DECISION_HELPER` override, the `decision_execution` capability and the `start_decision` path are removed with no compatibility layer. Routing packages, prompts, answer schemas, bound checks and records all live in Python; each harness only needs the generic verified read-only structured capability, which read-only review can share.

## Answer shape

The Router returns exactly `profileId`, `reason` and `evidence`, following the supplied JSON Schema. `profileId` is either one identifier from the request-local frozen candidate enum or `null` to abstain; a value outside that enum is `router-out-of-bounds` and is never retried. `reason` is a nonempty string of at most 2,000 characters. `evidence` holds at most 32 `{kind, ref}` entries whose kind is `card`, `annotation`, `preference` or `file`, and whose `ref` is a nonempty string of at most 1,024 characters without control characters. A `file` reference must be a checkout-relative path: absolute paths, `..`, backslashes, colons and `.` are rejected, and a file reference carries only a path, never file contents. The answer is parsed leniently from JSON text for transport, but the response object itself must carry exactly the three required fields with no extras.

The Router is not required to cite a card that was supplied, and an unknown card or annotation identity is advisory rather than a veto. Deviating from a task or user preference is allowed when the reason and evidence are recorded; the program computes the outcome and stores it as `policyCheck`, but it never rejects an answer merely for preferring an alternative. Python freezes the legal candidates before the call: enabled, available, not `exclude`d, matching the goal's required capabilities and complete coding tuples, with any `pin` preference restricting the set. The model's judgment is not re-reviewed by the Host; only the boundary is checked.

## Program facts and correction

`selection_policy.policy_facts` and `selection_policy.expected_policy_check` derive the hard constraints, the first matching task-preference rule and the legal user-preferred profiles from the frozen request, never from model prose or source filenames. A Router answer that stays inside the bounds is adopted with that program-owned `policyCheck`; the model is never asked to echo it and an echoed copy cannot change the facts. The request-local `routingPreferences` remain soft and cannot expand the hard candidate set.

A native read-only structured controller may make at most one answer-format correction inside the same attempt and the same overall deadline, and only when the shape is malformed. It never corrects an enum violation or a candidate outside the frozen bounds: `correction_code` returns `NULL` for any enum error, so an out-of-bounds selection ends the call instead of being reformatted. Claude does not continue correction because its read-only path makes a single call. Budget exhaustion, deadline, cancellation, valid abstention, provider failures and bad input are not corrected.

## Provisional budgets

Each routing call carries a preset budget of wall-clock seconds, native tool calls and read bytes. `quick` is 60 seconds, 8 tool calls and 128 KiB; `standard` is 300 seconds, 24 tool calls and 512 KiB; `deep` is 600 seconds, 64 tool calls and 2 MiB; the default is `standard`. These values are provisional and await a separately authorized native measurement. The global preset is stored in `meta.router_budget_preset`, and an authenticated console user publication may update `configuration.routingBudget`; Hosts and Workers cannot change it. Actual usage is reported as `elapsedMs`, `toolCalls` and `bytesRead`, and an unavailable counter stays `null` rather than being invented. Neither current adapter can observe read bytes, so the read-byte limit is recorded but not enforced, and the console shows only the time and tool-call limits. A tool-call limit of N allows N native tool calls; the next call is interrupted.

## Frozen input materialization

A Router never reads the Host's live checkout. `router_input.prepare` materializes a private read-only copy from `manifest.inputTree`: it first calls `workspace.verify(manifest, require_unchanged=True)`, reads that exact tree through `git ls-tree` and raw `git cat-file` blobs, rejects escaping or cyclic symlinks and unsupported entries, and digests the resulting mirror. Archive export attributes and checkout filters cannot omit or rewrite the frozen bytes. When the request has no file manifest, as in a public standalone `selection-request`, it reads only an empty private directory rather than borrowing any caller checkout; this is source behavior only; the daily runtime remains separately installed. "Unchanged" means the managed frozen input, including explicitly included untracked files; ignored files and caches are outside the manifest and are never read or hashed unless explicitly selected.

After the native process has stopped, `router_input.verify` re-runs `workspace.verify` on the original manifest and re-digests the private mirror. Any change yields `router-input-changed`; a missing or mismatched verification cannot be published as a recommendation. A `reroute` persists its intent in the route records, and a continuation prepares its new fixed manifest before routing begins, so the Router always sees a prepared frozen input. All ownership, fencing, cancellation and stop-evidence rules of the ordinary Worker runtime continue to apply to the routing attempt.

## Process ownership and stop evidence

The generic `read_only` adapter starts one controller process in its own session with a sanitized environment that drops `BUDDY_AGENT_*` and `BUDDY_WORKER_*` credentials, uses the frozen mirror as `cwd`, and gives the handle the preset deadline plus a 10-second shutdown margin. A run that exhausts its native tool budget or reaches its deadline first requests a native interrupt and then reaps the owned process group; `nativeInterruptRequested` and `nativeInterruptAcknowledged` are recorded separately from `processState.shutdownConfirmed`, so a forced stop is never reported as an acknowledged native interrupt. A result is imported only with the controller's own stdout payload and confirmed process-group shutdown; an unparseable or partial payload is `invalid-native-result`, and a killed controller with no durable result stays uncertain.

## Public routing reads

`selection-get` exposes the frozen `selectedProfile`, the recorded `policyCheck`, `evidence`, `usage`, `budget`, `nativeIdentity`, `stopEvidence` and `inputVerification`; `includeAudit:true` adds the exact persisted input, output and hash. `selection-list` stays a read-only history read that takes no model call or reader lease. `health` and `console-snapshot` add `budgetExhaustedCount`, `boundsRejectedCount` and `inputChangedCount` to `routingHealth`; these three counters are reported separately and are not counted as ordinary failures or abstentions.

## Native verification status

No native read-only structured capability is verified in this source candidate: every adapter keeps `read_only_structured_verified = false`, so the `decision` adapter reports itself unavailable and a routing request opens the Host boundary instead of calling a model. The candidate implementations are described only as unverified source, and no native probe has been executed for this work. Claude's controller restricts the native turn to read-only file tools (Read/Grep/Glob/LS), an empty MCP configuration and a sandbox whose network allowlist is emptied and whose write tools are denied, but an approved native probe has not established those boundaries. Codex's controller requests a `readOnly` sandbox restricted to the frozen root with a private `CODEX_HOME` that disables web search, apps and multi-agent features, but that path also remains unverified; Codex still exposes a shell, and a strict tool allowlist is not yet proven. DSH's native read-only mode does not restrict reads or network access, so DSH is intentionally kept unavailable. ZCode has no read-only structured implementation, remains on mock coverage without quota, and is unverified. These statements bound the claim; they do not report an installed or working Router.

## Relation to routing and maintenance

A routing decision is created only by `selection-request` or by governed routing; it cannot be created through public `execution-submit`. The `decision` adapter resolves the configured Router profile and requires a native adapter that declares a verified read-only structured capability; the current absence of any verified adapter means routing settles as `needs-host` rather than guessing. Evaluation maintenance remains Harness-owned and separate: `evaluation-prepare` collects facts without a model, synthesis happens outside the blackboard, and a short card-only patch uses a maintenance writer grant ([evaluation maintenance](evaluation-maintenance.md)). The Router selects execution profiles only.
