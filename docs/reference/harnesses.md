# Local harness discovery

The source implementation stores one service-owned `harness_health` record for each of DSH, ZCode, Codex and Claude Code. Schema 15 adds a separate retained `quota_json` observation; the separately installed daily version remains [0.20.0/schema 14](../acceptance/installed-0.20.0.md). Harness readiness and a verified read-only Router capability are separate: successful discovery never enables `read_only_structured_verified`.

## Discovery and environment

Discovery reads explicit manual paths, version-manager default records (nvm, fnm, Volta, asdf and mise), known installation locations and app bundles, Windows registry PATH, then process PATH hints. It never executes shell startup files. Numeric partial defaults resolve against installed version directories. A passing manual candidate wins; otherwise the default-manager tier precedes common locations and PATH, with newer versions preferred within a tier. Failed candidates have bounded diagnostic codes and repair advice. Version syntax is not a compatibility range: a successful handshake with unrecognized version text reports `unknown` and a warning.

Each candidate uses a bounded `--version` handshake and, where supported, a native login-status read. No model request is sent. A Node CLI uses its launcher directory before following its npm symlink and selects a companion Node interpreter. The complete candidate scan has a 20-second budget; an individual probe has a five-second budget and 16 KiB output limit. Model-catalog protocol initialization has its existing separate bound. POSIX probes own and reap their process groups; Windows forced termination remains explicitly unverified pending native testing.

Native child environments are built from an explicit allowlist of account/configuration directories, locale, temporary/system paths and service proxy variables. The allowlist also preserves the CA certificate path variables (`SSL_CERT_FILE`, `SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE` and `NODE_EXTRA_CA_CERTS`): they name trust roots, never credentials. Provider API keys, model endpoint overrides and inherited Host authority are excluded. The DSH bridge receives only its deliberately issued attempt credential and the paths needed to use it. Native authentication continues to belong to each harness. Exact fixture controls and CLI overrides remain available only to development tests. Neither health rows nor diagnostics store environment values, login output or account identities; a caller's PATH is an ephemeral discovery hint and is removed before task request identity or receipts are built.

## Health and execution

Ordinary submissions read recorded health and catalog metadata. Host configuration queries, submissions and console reads may trigger one asynchronous scan no more than once per three minutes; no periodic scanner runs without a call. Missing and login-required observations expire after three minutes. Ready observations have a one-hour handshake lifetime, while intervening calls check candidate and version-manager fingerprints at the scan limit. An explicitly named unavailable harness is rescanned before refusal.

Before claiming queued native work and again before starting a harness, the service checks path, real target, size, modification time and manager-record fingerprints. Discovery and model initialization run outside database transactions. A generation fences publication so a slow result cannot overwrite a newer setting or observation. Healthy changes refresh that harness's model metadata; unhealthy observations immediately exclude its configurations from effective availability, enabling and routing. User enablement, preferences, family notes and cards remain intact. New configurations start disabled and receive the console's new marker.

The Worker obtains its selected command through the named `harness_prepare` operation under the current attempt identity. The selection is written to a private attempt file for its trusted controller, recorded in execution events and retained in the result. A proven failure before any model input permits one rediscovery and retry. A started model, uncertain shutdown, cancellation or execution deadline does not permit this retry. A second proven startup failure invalidates the selected generation and ends through the existing failure/Host boundary. A running process keeps its selected command. A recorded harness-version change reconstructs a subsequent turn instead of treating an old native session binding as proven.

## Diagnostics and manual paths

`buddy adapters '{}'` reads the recorded status; `buddy adapters '{"refresh":true}'` detects all harnesses, and `buddy adapters '{"refresh":true,"adapter":"codex"}'` detects one. Responses contain each harness's `status`, `available`, selected path/command/version/source, bounded candidate diagnostics, `reasonCode`, `remedy`, `checkedAt`, `expiresAt`, `revision` and `manualPath`. `unknown`, `missing`, `login-required` and `unhealthy` are unavailable; `ready` passed the handshake. No diagnostic command invokes a model.

`buddy harness set codex /absolute/path/to/codex` sets a user-selected path and detects it; `buddy harness set codex --auto` clears the setting. The JSON form is `buddy harness-set '{"adapter":"codex","path":"/absolute/path/to/codex","expectedRevision":3}'`; a null path restores automatic discovery, and a stale revision is `REVISION_CONFLICT`. An attempt-scoped model credential cannot change this setting. The authenticated Buddy 配置 page offers the same detection and advanced path controls, including failed detection and login guidance.

The package's guarded `upgrade` migrates an idle supported board after verified backup and under exclusive owner locks. The current schema 14 → 15 step adds the retained quota column and the Host-workflow storage described in [architecture](architecture.md); old quota is unknown and all original columns retain their content fingerprints. Startup neither migrates nor populates health records, preserving cutover verification. The upgrade fence also blocks health/catalog publication and manual refresh. Source implementation, private verification, paid Router probes, actual installation and Windows native validation must be reported separately.

A saved manual path is an explicit override at the first candidate tier, as ordered by ADR-017; the console exposes it as an advanced recovery control. It stays selected while healthy until the user restores automatic detection. Review certification is data-backed and bound to the current native version/platform; an unknown version can remain available for coding without inheriting a certificate. The existing macOS 0.157.0 record is historical native evidence; an explicit successful check can certify another installed version.

## Native quota observations

`quota` is independent of readiness, discovery and enablement. Successful worker-result receipt import retains the newest native observation by `observedAt`; health refresh cannot clear it and a delayed older result cannot replace it. Known provider scope restricts submission reminders to matching configurations. An observation older than one hour, from the future, or without a valid time is stale; a window expires at its recorded reset. Stale records remain readable, with stale flags.

Codex uses native account rate-limit payloads and bounded optional metadata reads; Claude uses native rate-limit events; DSH records structured native quota errors and any reported windows. ZCode records recognized structured native failures but has no proven utilization-window surface, so percentages and resets stay unknown. A native quota failure may yield a limit-only observation, never an invented 100%. Neither collection nor reminders launch extra models, enable profiles or retry failed work. Fixtures verify parsing and persistence; fresh paid account behavior requires separate authorization.

## Review verification and native account observations (0.23.0)

Review certificates are data keyed by harness, native version and platform, projected as `reviewVerification` in health. The existing macOS 0.157.0 evidence is a packaged certificate, not an adapter version condition. A new version shows “新版本待验证” and review routing falls back to fast routing under the existing rule. `harness-verify` prepares a plan without a model; `execute:true` explicitly admits one internal `review-check` Worker attempt for an enabled `profileId`. It shares machine and model-family capacity, owns native process handles and imports its bounded check result with the durable receipt. Lost replies reuse `requestId`; a failed or cancelled verification requires a new explicitly authorized request, and an unconfirmed stop blocks another check. Only the Codex verifier is implemented. Equivalent native permission, correlated operation denials, unchanged inputs, budget and stop evidence remain mandatory; a model statement alone cannot certify anything.

`billingByProvider` records `{kind:subscription|metered|unknown,source,observedAt}` from native account/provider metadata; profile reads project it as `billing`. Codex uses read-only `account/read` and `account/rateLimits/read`, Claude uses native auth-status metadata, ZCode uses native provider access types, and DSH’s official DeepSeek API provider establishes metered access. Codex account queries borrow on-demand health refresh and are limited to one per 180 seconds, including forced refresh; there is no periodic scanner and no model turn. Failed reads keep quota unknown or retain previous evidence, without logging raw account responses. Billing labels never filter routing.

Native exhaustion is separate from display freshness: only explicit native quota denial/error or applicable zero balance excludes matching configurations, until the recorded reset or a newer available observation. Unknown or partial observations do not clear exhaustion; 90% or 100% utilization alone and transient rate-limit codes do not exclude. Existing `quota_json` remains the latest display observation and nonsecret per-provider/limit routing facts use existing `meta`; no schema change. Explicit Host configurations remain selected and carry `quotaWarnings`. Account-source separation and login are deferred until ADR-019’s private-directory prerequisite is integrated.
