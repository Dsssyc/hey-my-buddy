# Local harness discovery

The source implementation stores one service-owned `harness_health` record for each of DSH, ZCode, Codex and Claude Code. Schema 15 adds a separate retained `quota_json` observation; the separately installed daily version remains [0.20.0/schema 14](../acceptance/installed-0.20.0.md). Harness readiness and a verified read-only Router capability are separate: successful discovery never enables `read_only_structured_verified`.

## Discovery and environment

Discovery reads explicit manual paths, version-manager default records (nvm, fnm, Volta, asdf and mise), known installation locations and app bundles, Windows registry PATH, then process PATH hints. It never executes shell startup files. Numeric partial defaults resolve against installed version directories. A passing manual candidate wins; otherwise the default-manager tier precedes common locations and PATH, with newer versions preferred within a tier. Failed candidates have bounded diagnostic codes and repair advice. Version syntax is not a compatibility range: a successful handshake with unrecognized version text reports `unknown` and a warning.

Each candidate uses a bounded `--version` handshake and, where supported, a native login-status read. No model request is sent. A Node CLI uses its launcher directory before following its npm symlink and selects a companion Node interpreter. The complete candidate scan has a 20-second budget; an individual probe has a five-second budget and 16 KiB output limit. Model-catalog protocol initialization has its existing separate bound. POSIX probes own and reap their process groups; Windows forced termination remains explicitly unverified pending native testing.

Native child environments are built from an explicit allowlist of account/configuration directories, locale, temporary/system paths and service proxy variables. The allowlist also preserves the CA certificate path variables (`SSL_CERT_FILE`, `SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE` and `NODE_EXTRA_CA_CERTS`): they name trust roots, never credentials. Provider API keys, model endpoint overrides and inherited Host authority are excluded. The DSH bridge receives only its deliberately issued attempt credential and the paths needed to use it. Native authentication continues to belong to each harness. Exact fixture controls and CLI overrides remain available only to development tests. Neither health rows nor diagnostics store environment values, login output or account identities; a caller's PATH is an ephemeral discovery hint and is removed before task request identity or receipts are built.

## Health and execution

Ordinary submissions read recorded health and catalog metadata. Host configuration queries, submissions and console reads may trigger one asynchronous scan no more than once per three minutes; no periodic scanner runs without a call. Missing and login-required observations expire after three minutes. Ready observations have a one-hour handshake lifetime, while intervening calls check candidate and version-manager fingerprints at the scan limit. An explicitly named unavailable harness is rescanned before refusal.

Before claiming queued native work and again before starting a harness, the service checks path, real target, size, modification time and manager-record fingerprints. Discovery and model initialization run outside database transactions. A generation fences publication so a slow result cannot overwrite a newer setting or observation. Healthy changes refresh that harness's model metadata; unhealthy observations immediately exclude its configurations from effective availability, enabling and routing. User enablement, preferences, family notes and cards remain intact. New configurations start disabled and receive the console's new marker.

The Worker obtains its selected command through the named `harness_prepare` operation under the current attempt identity. The selection is written to a private attempt file for its trusted controller, recorded in execution events and retained in the result. A proven failure before any model input permits one rediscovery and retry. A started model, uncertain shutdown, cancellation or execution deadline does not permit this retry. A second proven startup failure invalidates the selected generation and ends through the existing failure/Host boundary. A running process keeps its selected command. A recorded harness-version change reconstructs a subsequent turn instead of treating an old native session binding as proven.

## Diagnostics and manual paths

`buddy adapters '{}'` reads the recorded status; `buddy adapters '{"refresh":true}'` detects all harnesses, and `buddy adapters '{"refresh":true,"adapter":"codex"}'` detects one. Responses contain each harness's `status`, `available`, selected path/command/version/source, bounded candidate diagnostics, `reasonCode`, `remedy`, `checkedAt`, `expiresAt`, `revision` and `manualPath`. `unknown`, `missing`, `login-required` and `unhealthy` are unavailable; `ready` passed the handshake. No diagnostic command invokes a model.

`buddy harness set codex /absolute/path/to/codex` sets a user-selected path and detects it; `buddy harness set codex --auto` clears the setting. The JSON form is `buddy harness-set '{"adapter":"codex","path":"/absolute/path/to/codex","expectedRevision":3}'`; a null path restores automatic discovery, and a stale revision is `REVISION_CONFLICT`. An attempt-scoped model credential cannot change this setting. The authenticated Buddy 配置 page offers the same detection and advanced path controls, including failed detection and login guidance.

The package's guarded `upgrade` migrates an idle supported board after verified backup and under exclusive owner locks. The current schema 14 → 15 step adds the retained quota column and the Host-workflow storage described in [architecture](architecture.md); old quota is unknown and all original columns retain their content fingerprints. Startup neither migrates nor populates health records, preserving cutover verification. The upgrade fence also blocks health/catalog publication and manual refresh. Source implementation, private verification, paid Router probes, actual installation and Windows native validation must be reported separately.

A saved manual path is an explicit override at the first candidate tier, as ordered by ADR-017; the console exposes it as an advanced recovery control. It stays selected while healthy until the user restores automatic detection. Review certification is data-backed and bound to the current native version/platform; an unknown version can remain available for coding without inheriting a certificate. The existing macOS 0.157.0 record is historical native evidence; an explicit successful check can certify another installed version.

## Native quota observations

`quota` is independent of readiness, discovery and enablement. Successful worker-result receipt import retains the newest native observation by `observedAt`; health refresh cannot clear it and a delayed older result cannot replace it. Known provider scope restricts submission reminders to matching configurations. An observation older than one hour, from the future, or without a valid time is stale; a window expires at its recorded reset. Stale records remain readable, with stale flags.

Codex uses native account rate-limit payloads and bounded optional metadata reads; Claude uses native rate-limit events; DSH records structured native quota errors and any reported windows. ZCode records recognized structured native failures but has no proven utilization-window surface, so percentages and resets stay unknown. A native quota failure may yield a limit-only observation, never an invented 100%. Neither collection nor reminders launch extra models, enable profiles or retry failed work. Fixtures verify parsing and persistence; fresh paid account behavior requires separate authorization.

## No-reset exhaustion recovery (ADR-019 second stage)

An exhaustion without a recorded reset would exclude its provider/limit forever: the excluded configuration is never routed again, so no newer observation can arrive (a zero DeepSeek balance after a top-up is the reported case). Such a persisted record therefore carries exactly one single-use retry window. One hour after the blocking observation — or after a consumed retry that produced no newer usable observation — one routing decision may admit the configuration again as a normal candidate; the claim is durable and transactional with that decision's admission, so concurrent decisions cannot retry in parallel, and reads (candidate listings, health, console, model profiles) never consume or open a window. If the retried call fails again, the newer observation restarts the hour; if it produces no usable observation, the window reopens one hour after the claim. A newer available observation still clears the exhaustion outright, an unknown or partial observation never does, and records with a known reset keep their existing scheduled recovery. Host-explicit configurations keep their existing reminder and are unaffected.

`buddy quota-redetect '{"adapter":"dsh","provider":"deepseek-official"}'` (the `quota_redetect` operation, also offered as the console's 重新检测 entry on a harness's 额度耗尽记录) opens that window immediately. The parameters are idempotent and non-secret: an already-open window is returned unchanged, no balance is queried, no model is called and nothing claims the quota recovered — the entry only gives one later normal routing call the chance to produce a real observation. This honesty rule is uniform, so a harness with an active account query (Codex) also never runs one implicitly from this entry. The reply lists every persisted exhaustion record of that provider with its recovery state (`records`, `opened`, `alreadyOpen`); records with a known reset are reported with their reset and no state change.

## Review verification and native account observations (0.23.0)

Review certificates are data keyed by harness, native version and platform, projected as `reviewVerification` in health. The existing macOS 0.157.0 evidence is a packaged certificate, not an adapter version condition. A new version shows “新版本待验证” and review routing falls back to fast routing under the existing rule. `harness-verify` prepares a plan without a model; `execute:true` explicitly admits one internal `review-check` Worker attempt for an enabled `profileId`. It shares machine and model-family capacity, owns native process handles and imports its bounded check result with the durable receipt. Lost replies reuse `requestId`; a failed or cancelled verification requires a new explicitly authorized request, and an unconfirmed stop blocks another check. Only the Codex verifier is implemented. Equivalent native permission, fixed-probe boundary denials, a structurally complete allowed tool stream, unchanged inputs, budget and stop evidence remain mandatory; model output content is never evidence, and a model statement alone cannot certify anything.

`billingByProvider` records `{kind:subscription|metered|unknown,source,observedAt}` from native account/provider metadata; profile reads project it as `billing`. Codex uses read-only `account/read` and `account/rateLimits/read`, Claude uses native auth-status metadata, ZCode uses native provider access types, and DSH’s official DeepSeek API provider establishes metered access. Codex account queries borrow on-demand health refresh and are limited to one per 180 seconds, including forced refresh; there is no periodic scanner and no model turn. Failed reads keep quota unknown or retain previous evidence, without logging raw account responses. Billing labels never filter routing.

Native exhaustion is separate from display freshness: only explicit native quota denial/error or applicable zero balance excludes matching configurations, until the recorded reset or a newer available observation. Unknown or partial observations do not clear exhaustion; 90% or 100% utilization alone and transient rate-limit codes do not exclude. Existing `quota_json` remains the latest display observation and nonsecret per-provider/limit routing facts use existing `meta`; no schema change. Explicit Host configurations remain selected and carry `quotaWarnings`. Account-source separation and login are deferred until ADR-019’s private-directory prerequisite is integrated. A no-reset exhaustion additionally carries the single-use retry window above; it changes when automatic routing may retry, never what the recorded observation claims.

## Harness private paths (0.24.0)

Service-selected command metadata remains nonsecret attempt evidence. Buddy-owned native bindings/sessions are under `harnesses/<adapter>/goals/<taskHash>/native/`; per-attempt credentials, settings, provider snapshots and Router roots are under that goal’s `attempts/<attemptId>/`. The future Worker independent account path is `harnesses/<adapter>/accounts/worker/`, reserved and protected without adding account operations. These areas never enter backup inventory. Confirmed stop removes attempt credentials/snapshots; unknown stop is retained and visible in storage plan. [Operations](operations.md#backup-upgrade-and-storage-contract) and [the classification](../design/private-directories.md) own details. Existing native login and account-source behavior remains the first-stage contract.

Review checks publish sanitized `review-evidence.json` in the evidence whitelist before recycling their private fixture and native home. Requested controls use the same typed comparison at native admission and evaluation, with exact filesystem grants. Codex 0.159.0 code-mode results use the observed two-block envelope; no model prose establishes a denial. Missing/unsafe evidence publication fails certification and retains private diagnostics. [The routing-validation design](../design/routing-validation.md) owns the retained fields and compatibility details.

Candidate inspection, unchosen providers, abstentions and missing Router configuration do not consume a retry. Adoption claims only the selected provider/limit within the same write transaction; a racing choice fails its bounds check. Retained pre-meta native exhaustion is imported only during explicit re-detection or decision admission, with observation ordering preserved. `quota-redetect` requires a stable requestId: its command receipt and event are atomic with the opened window, and replay after consumption never opens another. The console keeps that nonsecret request identity through unknown replies and detail reload.

The native review verifier (0.27.0) judges the model tool stream structurally — allowed exec and `commandExecution` types, call/item-ID-correlated completions, no approvals, no extra tools, no truncation — without parsing or interpreting any model output, and proves `boundaryDenials` and `internalRead` solely through five controller-owned `command/exec` challenges under the same private `buddy-router` profile, including the live network positive control. Model results need not match the probes, and an unreadable model output envelope cannot fail the boundary verdict. `review-evidence.json` retains the sanitized v3 proof; legacy v1 replay establishes observations without inventing missing boundary categories, and the passing v2 replay of run `b37e7302` never certifies. [Native sandbox proof](../design/native-sandbox-review-proof.md) owns details and the remaining live-verification boundary.

## Account sources and verified private paths (0.26.0)

Each harness defaults to `native` (shared local login, read-only management) and has one optional `worker` source under `harnesses/<adapter>/accounts/worker/`. Selection `revision` fences user edits; `credentialRevision` identifies the credential lineage. The service freezes the lineage in the claim transaction, including coding, routing and review-check attempts. Switching source affects later attempts and reconstructs continuation when its credential binding changes. A selected independent account never falls back to shared login.

The individually approved macOS checks admit Codex 0.159.0 browser login, correlated cancel, stdin API-key storage, metadata read and private logout. Claude Code 2.1.284 admits the API-key path only: an exact per-state Worker entry in macOS Keychain, injected solely into the actual Claude child environment. Inherited `ANTHROPIC_API_KEY` remains excluded. Claude OAuth, DSH/ZCode account mutation and Windows/Linux native account paths remain unverified and provide guidance with disabled operations. New native versions do not inherit these account capabilities. [Sub-batch ④ evidence](../acceptance/worker-accounts-batch4-0.26.0.md) separates private native checks, fixtures and installation.

Current quota display, billing facts, reminders, exhaustion filtering, retry claims, re-detection and the Codex 180-second read limit use the selected source plus credential revision. An old attempt receipt is attributed by its service-frozen account; it can retain historical evidence without replacing the current account or blocking its candidates. Existing untagged facts belong only to the initial native lineage. Credential changes also invalidate old native-session and catalog bindings. Billing labels themselves still do not filter routing.

Account mutations reserve credentials transactionally before native I/O and refuse active/uncertain attempts and metadata readers. The daemon owns bounded account-login handles; actual stop precedes adoption or removal, while loss of an owner retains a nonsecret uncertain reservation and the private contents. Upgrade refuses such reservations. Account directories are 0700 and native ordinary credential files 0600, excluded from backup inventory and protected from storage reclamation; restoring a backup cannot restore their credentials.
