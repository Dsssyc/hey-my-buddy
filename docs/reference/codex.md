# Codex native adapter

The `codex` built-in Worker adapter runs the installed Codex App Server over JSONL stdio. It uses the user's existing native ChatGPT account-plan login. `BUDDY_CODEX_CLI` can select the executable. The adapter removes `OPENAI_API_KEY` and `CODEX_API_KEY` from its native child environment, rejects an API-key account returned by `account/read`, and never starts a login or changes global Codex configuration. Codex thread storage uses the active native Codex home; the result reports `nativeSessionStorage: codex-home` and `nativeAppVisible: null` because App indexing visibility has not been verified. Buddy retains only a private binding under its state directory, not a copy of credentials or Codex history.

Discovery initializes the native connection, checks account mode, pages `model/list`, and advertises only nonhidden models with native `supportedReasoningEfforts`. It sends no model turn. The provider identity is `openai`. Coding validates the selected model and effort against a fresh native list, sets the model on `thread/start` or `thread/resume`, and sets model and effort again on `turn/start`; `observed` remains `null` because the served remote model is not independently attested. Codex's tool-free decision capability is not declared: the adapter has not verified a native tool-disabled decision mode.

Each governed attempt runs a Python controller and one separate Codex App Server child process group. The controller checks `thread/start` or `thread/resume`, `turn/start`, native `turn/started` and `turn/completed`, a completed final `agentMessage` item, and a strict JSON outcome constrained by `outputSchema` and Buddy's outcome validator. The result carries actual native thread, turn and final item IDs. Only an exit-zero controller receipt plus confirmed shutdown of both owned process groups may import the turn and seal its workspace. A final message cannot substitute for a completed native turn. User cancellation and deadline request `turn/interrupt` when the thread and turn are known, then close and, if necessary, terminate the owned native group. A completion already recorded before cancellation retains its completed result.

The adapter uses the allocated checkout as explicit `cwd`, selects `workspace-write` on the thread, and sets a `workspaceWrite` turn sandbox with that checkout as the writable root and network access disabled. An interactive native server request is rejected. If the model returns a valid structured `attention`, that outcome retains its native final-message provenance. If a correlated denied request is followed by a completed native turn but no valid attention, the controller emits its own `attention` outcome with `controllerAttention: true`, `outputSchemaValidated: false`, and the native request/thread/turn IDs; it does not attribute this outcome to the model. A failed or interrupted native turn never receives a completed attention record. The adapter does not declare an inquiry bridge; it cannot convert arbitrary assistant prose into a correlated inquiry answer. Internal Codex subagents remain available within the native turn and its owned process lifetime.

The private binding records the goal ID, native thread ID, checkout path, requested configuration and last completed native turn ID. Native continuation requires an exact binding plus `thread/read` proof that the last stored turn is still that completed turn. A changed configuration or unproven history requires an explicit `reconstructed-new-session` turn. A missing or mismatched native thread fails closed; no old PID is used as recovery authority. Binding storage and native session storage are separate dimensions, and Host acceptance remains separate from execution completion.

The controller writes attempt-private `activity.json` using the ADR-010 sidecar envelope: `version`, `taskId`, `attemptId`, `generation`, and bounded `activity`. It reports native phase transitions, timestamps, event sequence, native thread ID and known model/tool counts without prompts, tool arguments, output text or reasoning. The Worker must validate the binding and forward it through `worker_progress`; the sidecar is not itself a board receipt. The adapter supports no paid health probe. A real model turn and installed-runtime acceptance are required before public release.

The protocol implementation follows the [official Codex App Server documentation](https://learn.chatgpt.com/docs/app-server) and was checked against the installed `codex app-server generate-json-schema` output. The App Server is marked experimental by OpenAI, so a changed installed protocol must be reverified before relying on this integration.
