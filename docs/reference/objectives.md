# Work objectives and delegation timelines

Implementation contract for the user-authorized section X of the [Claude proposal](../decisions/012-claude-code-distribution-and-evidence-routing.md), introduced in 0.14.0 and revised by the authorized 0.15.0 presentation repair; schema remains 12. The separately authorized [0.14.0 daily installation](../acceptance/installed-0.14.0.md) on 2026-09-27 retained the previous schema-11 data through a verified offline copy; the 0.15.0 daily installation is recorded in [installed-0.15.0](../acceptance/installed-0.15.0.md), while the 0.15.1 candidate remains uninstalled. This feature supplies archival grouping and read-only browsing; it adds no scheduler, dependency graph, execution permission, result ledger or model-routing input.

## Submission metadata

`submit` accepts optional root-level `title`, and either `objective: {title}` or `objectiveId`. Titles are bounded, nonempty human labels of at most 200 characters. A new objective is created in the same transaction as its first admitted run; a failed admission leaves no empty group. Replaying the identical request recovers the same group/run, while changed metadata under the same request ID conflicts. An existing objective must belong to the same canonical source project and original submitting Host label. Labels remain attribution, not authority; existing run control capabilities still govern every decision, takeover and acceptance.

Helpers inherit the objective association from their parent. Continuation and takeover preserve grouping; takeover of a run does not implicitly change the group's original source attribution or grant another Host enrollment in it. Objective metadata and human display titles never enter execution specs, Worker turn input or selector packets. Attempt-scoped callers cannot use objective-list/timeline, and their task/claim views omit these new display fields.

The objective table stores the original project identity/path, source Host, title and creation time. Runs have nullable objective and display-title columns. Missing objective associations display as a standalone root delegation with its existing helper tree, identified by `run:<rootRunId>` in read APIs; this neither creates rows on read nor invents historical relationships. Explicit group identifiers use `obj-<uuid>` and only those can be reused on submit. In the 0.15.0 source, a group's own objective title is primary; delegation titles use explicit run title, original task first line, then 未命名委派. A Worker's latest concluded summary is returned separately as nullable `summary` (bounded first line, 200 characters), never substituted for the task's intent. Objective summaries have no synthetic aggregate result (`summary: null`); each returned delegation row carries its own recorded summary.

Latest activity is a derived event-sequence projection, updated in the same transaction as actual task/attempt/workflow events and propagated through existing helper/routing ownership links. It stores only sequence/time indexes for efficient reads, not independent task state. Snapshot reads and lease polls do not move an objective upward. State counts are derived from the existing runs and shutdown evidence; unknown stop is never counted as confirmed ended.

## Read APIs

`objective-list` maps to `objective_list`; `objective-timeline` maps to `objective_timeline`. Both are read-only Host/user operations with no model call, reader lease or publication. Authenticated console sessions, use GET /api/objectives and GET /api/objectives/<objectiveId>/timeline. The current console cookie/origin rules remain unchanged.

List parameters are limit (default 50, maximum 100), before (opaque keyset cursor), projectId, hostId, query (at most 200 characters) and filter (all, active, host, review). Filters match member delegations before paging; summaries retain overall counts and a matching count. The default order is latest activity sequence descending, then objective identifier. The response contains objectives, total, nextCursor, cursor (current event head) and changed. A cursor binds its filters; an activity update may move a record above an older page boundary, so changed tells the client to offer a refresh instead of silently claiming a fixed historical snapshot or reordering a reader's selection.

Timeline parameters are objectiveId, limit (default 100, maximum 200), query and filter. It returns an objective summary, observedAt, rows, spans, events, total counts, explicit truncation flags and scopeComplete. Up to 800 spans and 800 Host markers are returned. Further records remain accessible through filters and the existing run detail; truncated output is labelled, never presented as the complete objective. Each row identifies its run, parent/helper relationship, title, task/workflow state and shutdown evidence. Spans carry their recorded start/end, run/attempt/turn identity, kind (queue, routing, execution, host), frozen execution configuration where recorded, state and uncertainty. Host markers carry bounded summaries and existing record IDs, not raw event payloads or credentials.

Unfinished attempts extend visually to observedAt only with an explicit active/unknown state. A finished attempt without confirmed shutdown remains unknown. Missing or reversed timestamps are marked and not repaired into invented durations. Historical configurations come from the exact turn input/attempt, never a run's current configuration. The timer observes activity; it is not an execution clock or a cost metric.

## Read shapes

The response types are mirrored in `apps/console/src/objective-types.ts`. `ObjectiveSummary.titleSource` is `objective`, `title`, `task` or `none`; `TimelineRow.titleSource` excludes `objective`. Both carry nullable `summary` as described above. No new database column is introduced for this read projection.

Groups contain governed delegation trees only: a root with an objective belongs to `obj-<id>`, and every other root forms `run:<rootRunId>`. Helpers inherit their root's group, and a routing decision task belongs to the run it routed; plain `command`/`external` execution records belong to no group and stay in task history. A `run:` identifier whose root has an objective is `NOT_FOUND`, because that root is read through its objective.

An objective summary carries `objectiveId`, `kind` (`objective` or `standalone`), `title` with `titleSource` (`objective`, `title`, `task` or `none` for the 未命名委派 fallback), `project` `{id, path, label}`, `sourceHostId`, `currentHostIds`, `createdAt`, `lastActivityAt`/`lastActivitySeq`, overall `counts` `{roots, helpers, host, active, review, ended}`, the summary `state` (the highest-priority category present), `matchingRuns` for the current filters and `rootRunIds`. Categories are disjoint: `host` is an awaiting-Host run; `active` is queued, running, cancelling or reconciliation-needed work, or a governed run executing or waiting for helpers; `review` is the console's unaccepted-review condition, which requires proven stop; everything else is `ended`.

The list cursor encodes the last activity sequence, group identifier, a fingerprint of the filters and the event head of the first page. Reusing it with other filters is `INVALID_ARGUMENT`. `changed` is true when a matching group recorded activity after that first page, so the client offers a refresh instead of silently reordering.

Timeline rows arrive in tree order (roots by creation, each followed depth-first by its helpers) with `depth`, `title`/`titleSource`, workflow `state`, task `status`, `category`, `kind`, the current `configuration`, acceptance fields and `shutdownConfirmed`, which is true only when every recorded attempt finished with confirmed stop and a running task without any attempt record is never counted as stopped. Spans carry `startAt`/`endAt`, `state`, attempt/turn/request identity, the frozen `configuration` from the turn input (or the claimed model identity), `shutdownConfirmed`, `uncertain` and `clockSkew`:

| Kind | Interval | State |
| --- | --- | --- |
| `queue` | submission or continuation to the attempt's claim; a still-queued task has an open span | `claimed`, or `queued` while open |
| `execution` | attempt start (or claim) to finish; unfinished attempts have no end | the attempt execution state: `starting`, `executing`, `finalizing`, `uncertain` or `finished`; `uncertain` is set for uncertain ownership or a finish without confirmed stop |
| `routing` | a routing decision task's attempts, shown on the routed run's row | as for execution |
| `host` | a recorded request from creation to decision; an open request has no end | `open`, `approved`, `declined`, `superseded` or `cancelled` |

Execution and routing spans additionally carry `resultStatus` when their own durable receipt records `ok`, `failed` or `cancelled`. This is independent of execution state and the structured turn's disposition: a completed turn can contain a failed receipt, and a cancellation reason is not a failure. Missing receipts remain unknown; current task status cannot substitute for a historical attempt's outcome. Unconfirmed shutdown takes precedence over terminal outcome styling.

Host markers come from `task.submitted` (dispatch, 派发), `workflow.request_approved`/`request_declined` (decide, 决定), `workflow.continued` (continue, 续接), `workflow.integration_recorded` (integrate, 整合), `workflow.acknowledged` (accept 验收, or reject 验收问题 for a rejected verdict), `workflow.cancelled` (cancel, 取消) and `workflow.takeover` (takeover, 接管). Each carries `seq`, `runId`, `kind`, `at`, `label`, a bounded `summary`, `actor` and the record identities it names; raw payloads, notes and credentials are not copied. Automatic continuations are Worker-side and not Host markers.

`totals.rows` counts the filtered scope and `totals.allRows` every delegation of the group; `truncated` has one boolean per collection and `filtered` reports a query or filter. `scopeComplete` is true only without filters or truncation.

## Presentation

Hosts establish one objective for each user agenda on its first delegation and reuse that returned identifier for later submissions. Brief submit/get receipts retain the objective id; preserve it alongside run/control identifiers when handing off or compacting context. If it is lost, read a known run rather than guessing a group from titles. Continuations and helpers inherit the association. The API still accepts standalone work for explicit low-level use, but the skill's agenda workflow creates groups by default. Cross-Host membership and human reclassification of historical records remain separate unapproved changes.

The UI says 工作目标 and groups the left list by source project. Actual objectives are shown by default; standalone delegations stay in a collapsed 未归档委派（已加载 N） section with explicit category filters. Intent titles remain primary and a delegation's own Worker summary is secondary. The objective overview presents root-delegation cards in creation order, each with result, acceptance and pending matters; a single-root objective keeps that card and its own timeline in the same view. Helpers remain nested and configurations use recorded facts.

Overview metrics distinguish total span, execution occupancy (the union of valid execution intervals) and cumulative execution time (including concurrency). Queue, routing and Host wait time are excluded from execution totals. Active execution extends to the read timestamp; missing, invalid or unconfirmed endings are counted as incomplete and omitted from execution duration, without inventing a lower bound. Filters and truncation remain visible scope limitations.

A single click selects a span or a whole delegation row and pins facts in the inspector; row selection highlights all its fragments. Enter, double-click or the explicit Open action opens existing run/turn detail . Aggregated Host markers open a dismissible event list rather than choosing an arbitrary first event; selection remains distinct from opening. Details are read-only; record navigation has no draft or Host-command lock.

Idle gaps longer than 30 minutes fold by default and may be expanded. A gap can fold only when no returned span or Host marker occupies it and the timeline scope is complete. A running attempt, unresolved shutdown or waiting-Host interval occupies time; it is not an idle gap. Filtering, truncation or unusable timing disables automatic folding because omitted facts could occupy the apparent gap. Narrow layouts use a chronological list; failure/cancellation/unknown labels do not rely only on color. Reads refresh at the existing three-second cadence, preserving selections and paging position.

The 委派记录 page opens this view by default; 全部执行记录 keeps command/external history accessible. List refresh preserves the current order and selection while offering an explicit refresh when activity changes ordering or membership. Desktop detail docks beside or below the timeline, retaining macro context; at widths of 760 CSS pixels or less it uses a separate layer over the chronological view. Returning restores selection, scroll and visible keyboard focus. Settings drafts retain their separate publication protections. Both views keep their local state when switching; transient event popovers close when the timeline is hidden or inactive.

The desktop label column stays visible while the timeline scrolls horizontally. Folded gaps are 64 CSS pixels wide; their aggregate width stays within 40% of the canvas and unfolding retains the recorded timestamps. Unknown-ended executions occupy through `observedAt` even if a finish timestamp exists, and Host markers reserve a small surrounding interval. No fold is inferred from filtered, truncated or invalid-timestamp data. The preview helper `tests/probes/objective_console_preview.py` serves synthetic read-only fixtures and denies mutations, without connecting to the daily service or calling a model.

## Schema and verification


Startup accepts schema 12 only and contains no automatic schema conversion or version facade. The explicit offline preparation tool copies an idle, verified schema-11 board into a separate new destination, adds the grouping/display columns and derives activity indexes while preserving all original rows, secrets and relationships:

```sh
uv run --frozen python -m buddy.board_prepare --source "/path/to/schema-11-state" --destination "/path/to/new-schema-12-state"
```

It refuses a source whose daemon owner locks are held, a source with open tasks or attempts without confirmed stop, a source that is not schema 11 or fails its integrity/foreign-key checks, an existing destination and a destination inside the source. It reads the source through a read-only connection and the SQLite backup API, applies the schema-12 additions to the copy only, replays the recorded event order through the same activity projection the runtime maintains, and then verifies integrity, foreign keys, the exact schema shape of a fresh schema-12 board, unchanged per-table row counts, the preserved capability secret and the unchanged source file hash. It creates no objectives: historical roots stay standalone delegations. The production switch remains separate; this candidate is tested with private boards and synthetic historical fixtures.

Verification covers grouping/replay conflicts, cross-project and source-Host checks, helper inheritance, Worker/selector isolation, event-derived ordering, filters/keysets/truncation, recorded attempts/requests/markers, cancellation with uncertain shutdown, and idle folding across overlapping or incomplete data. The old records and the new grouping must survive explicit offline preparation without reconstructing missing history. Claude supplies the design; implementation and final correctness review remain separate verified work.

## 0.15.1 presentation and metadata

A new objective may include `description`, a nonempty plain-text description of at most 300 Unicode characters when supplied. The Host writes one or two sentences in the user's words at creation. Description is optional, immutable and display-only; omitted historic descriptions remain null. It participates in the existing presentation fingerprint and is stored in the first run's `workflow.objective_created` event payload in the admission transaction, with objective identity and description. Reads resolve this event through the existing per-task event index. No schema, columns, migration or historical backfill changes; schema remains 12. Neither execution specifications, Worker claims/turn input nor selector packets include the description. Installed 0.15.0 cannot submit this new optional field; support begins with separately installed 0.15.1.

Read projections add nullable `description` and `counts.accepted` to objective summaries and nullable `taskSummary` (first nonempty task line, at most 200 characters) to timeline rows. Accepted progress counts accepted root delegations; the denominator is `counts.roots`, independent of visible filters. Helpers are integrated and accepted through their root goal. Worker result `summary` remains separate. The header shows only status, accepted progress and latest activity beneath the title/description. Duration details live in collapsed “时间统计”, using “经过时间”, “有任务在执行的时间” and “各任务用时合计”; missing or uncertain facts remain explicit within that disclosure.

Each root overview card has three single-line content rows: “做什么” (intent title), “目标摘要” (taskSummary), “结果摘要” (Worker summary or “暂无结果”). A compact legend explains “工作目标 → 委派 → 协助任务 → 回合”. Host submissions always supply an intent-focused delegation title of at most 30 characters as a skill rule; the low-level API retains its existing optional 200-character title contract. For `titleSource: task`, lists, timeline labels and cards show at most about 40 characters on one line with “取自任务首行”; full task/title content appears only in detail, without rewriting historical rows or inferring groups.

Viewport width, not pane width, selects the layout. Above 760 CSS pixels, opening details collapses the objective list to an expandable narrow rail, leaving a horizontally adjustable timeline/detail pair. The timeline retains roughly 560 pixels of readable content or a horizontal scroll area at 900, 1024, 1280 and 1440 widths; labels remain meaningful. The separator supports pointer and keyboard adjustment. At 760 or below, retain layered list/timeline/detail navigation and restore selection, scroll and focus on return.

## 0.16.0 human presentation contract

All titles use explicit workflow.title, then the first task line labelled “取自任务首行”, then “未命名委派”; Worker resultSummary/summary appears only as a result. Never translate or call a model from the UI. Hosts specify the user's language in each task packet (Chinese for this repository).

Use one dismissible hierarchy help popup, approximately 36–40 Chinese characters wide but viewport bounded; outside click, Escape and focus leaving dismiss it. Its single explanation is “工作目标是一项议程；委派是交给 Buddy、单独验收的一项工作；协助任务是委派派生的子工作；回合是一次执行。” Remove the breadcrumb-like hierarchy text and duplicate timeline legend. Delegation cards show a bold two-line intent title with full tooltip, status at top right and one-line “结果：…” with a small “Worker 自述” label; task summary stays in details. Detail breadcrumbs use a short title; timeline provenance states only round/time; the large heading follows the title rule and the overview does not repeat it.

All accepted roots mean “已完成”; filters say “等待 Host” and “等待验收”. Hide internal V-number labels except optional tooltips. Refresh reads “自动刷新 · HH:mm”. Fold project/Host selectors into one “筛选” popup, use project name/count group headings, and list title / root count and acceptance / relative time with Host ID only in a tooltip. Historical standalone roots are “历史独立委派”. Format model names consistently in legend, rows and inspector (for example Claude Opus 5.5 · high, GLM-5.3 · max), preserving raw ids in tooltips.

The inspector presents type, delegation, round, configuration, time and result as structured fields. The Host event row is collapsible by default, uses icons with small counts and natural-language popup entries. A faint dashed interval from execution completion to its recorded acceptance marker shows the measured acceptance wait in a tooltip; do not invent an acceptance time. The header may compress/stick, delegation cards collapse, the timeline fills remaining height and the inspector stays visible as a bottom drawer. Default timeline scale fits observed activity; expose zoom in, zoom out and fit controls while preserving honest idle folding and uncertainty. Desktop/narrow split behavior remains accessible.
