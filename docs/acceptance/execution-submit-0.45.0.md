# Host 只经微任务委派，`execution-submit` 关掉：验收记录

2026-10-17，整合 Host。

- **微任务：** “关掉对 Host 开放的 execution-submit”（run `03974e3b`，Codex CLI，`gpt-6.1-sol / high`，一个回合）。
- **基点：** `22a429e8`。
- **产物与合并：** 产物 `609ba2c0`，合并为 `34766a3e`；参考文档、AGENTS.md 与 ADR-007 的补记是 Host 的 `b9e7e0ed`。
- **版本：** 0.45.0（contract 0.45.0，schema 24）。尚未安装。

## 决定

开发者 2026-10-17 定下：Host 只经微任务委派，`execution-submit` 这道不经微任务提交执行的门关掉；`command` 适配器留作执行层自己的、不调用模型的测试执行。审计在待办里“`execution-submit` 的去留”一条。开发者要求把这件事写在仓库里，免得以后忘了这道后门：AGENTS.md 的“Verification”一节与 [ADR-007](../decisions/007-neutral-core-and-single-current-contract.md) 的 2026-10-17 补记。

## 改了什么

- **门：** 删掉命令行的方法、传输表里的一项、客户端的 `submit`、控制契约上的 `task_submit` 操作、服务里的处理与白名单，以及帮助与错误消息里指向它的话。生产代码只删不加。
- **测试的提交路：** 检查套件用 `tests/python/support.py` 的 `submit_execution`，在私有服务运行时另开一个存储，直接写入一条排队的命令执行，服务的调度器在下一次两秒的扫描里取走它。另开的存储不做初始化，所有权锁仍在服务手里；它读服务实际的并发上限，好让写入时的排队原因与服务一致。实现方先在私有服务上查清了同一个库能否在服务运行时写入、所有权锁怎样约束这件事、调度器多快取走，新的 `test_internal_execution_submission.py` 守着这几点。
- **测试的意图：** 删掉的断言里，与 `execution-submit` 这个名字有关的随门一起去掉；请求编号冲突与重复提交两项改在内部的提交路上断言，一项不少。`test_current_core.py` 另加了几条断言，守住这道门不再出现在契约、服务、命令行与传输表里。
- **顺带：** 契约版本只留一处钉，`test_current_core.py` 改读 `contract_signatures.json`；`inquiry.py` 对 `LiveRegistry` 的引用改成只在类型检查时引入，任务一层不再在运行时引用服务一层。

## 核对

- **差异：** 读完生产代码的全部差异与测试的提交路；对照删掉的断言逐条找到去处。另开存储时不调用初始化，新测试把 `initialize` 换成一调用就失败的替身来守这一点；数据库对象的构造只建锁与空表。
- **完整检查：** 在产物上跑，262 个文件里 261 个通过，共 4,181 项，用时 543 秒。唯一的失败是 README 的安装命令还写着 0.44.0，这是 Host 该随版本改的文档；改后与另外 10 个读文档的测试文件一起在合并后的源码上重跑，11 个文件、154 项通过。
- **预览检查：** 实现方的检出里没有前端依赖，跑不了 `test_host_preview`，请 Host 补跑；它在上面的完整检查里通过了。
- **实现方写到范围之外的文件：** 调查时把一份文件清单写到了 `/tmp/hmb-command-files`，没有删；Host 看过内容，只是测试文件的路径，验收后删除。

## 顺带项，记进待办

- **另外三个执行方法：** `execution-cancel`、`execution-retry` 与 `execution-acknowledge` 管的命令执行，Host 已经建不出来；它们对微任务的执行一律拒绝，重试与确认也拒绝路由计算。要不要随之关掉，先像这一次一样审计。
- **存储层不经微任务的那一支：** 现在只有检查套件在用，它的 `owner` 默认值 `cli` 与对编程 harness 的拒绝都是命令行那条路留下的；`workflow.py` 还提到已经退役的 `external` 适配器；`test_rpc_config.py` 自己抄了一份内部提交的写法，没有用 `support.py` 的。
