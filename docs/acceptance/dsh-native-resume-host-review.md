## 这一批做了什么

- **第五步留下的清理。** 给 Worker 主循环里的四处接线、排队中的同号异内容请求、完成回执的输入摘要、就绪材料的两种异常、只有检查点的续接路径补了测试；删除了没有调用方的用量旁路读取函数与它的测试；回合不再写没有读取方的 `inquiry.json`；回合说明里去掉了"撤回"的说法；传输时间窗的上下限只留一处定义。
- **DSH 的原生续接。** 满足共同的资格时，继续同一个微任务会恢复它原来的 DSH 会话，不再每次重建；不满足时照旧重建并写明原因。会话记录按微任务存放，同一个微任务的几次尝试共用；凭据、启动配置与日志仍按尝试各自私有。旧版本按尝试存放的会话不能续接，以 `private-native-home-required` 重建。选定原生续接之后，会话不存在、被拒绝或身份不符都明确失败，不悄悄新建。恢复的回合只把这一回合新增的记录计入用量，边界证明不了时记为未知。DSH 现在声明 `native-session`。

## 变异

每处改动都在合并后代码的副本上做，不动工作检出；先在没有改动的副本上确认用到的 16 个测试文件本来是通过的。

| 核对的部分 | 改动 | 结果 |
| --- | ---: | --- |
| 续接的运行模块：只有 Worker 的回合能续接；会话的绑定必须存在，并与目标、检出、配置一致；恢复后回报的会话必须是请求的那一个；恢复之前重放的历史不算进本回合；恢复之后重新设置并读回模型配置；不悄悄新建会话；会话存放在微任务名下；没有确认停止不保存绑定 | 13 | 12 处有测试失败 |
| 用量的边界：基线读得不可靠、匹配的记录文件变了、冻结的前缀被改写、追加的行重复了旧记录、把以前的回合再算一遍、别的会话的记录、未知不能报成零 | 9 | 7 处有测试失败 |
| 黑板的选择与能力声明：旧版本按尝试存放的会话必须重建；DSH 声明原生续接 | 2 | 全部有测试失败 |
| 第五步验收时没有测试失败的 11 处，在新测试上重做 | 11 | 8 处有测试失败 |

新写的 24 处里没有测试失败的 3 处：

- **续接却没有给出上一个会话的标识。** 去掉这条检查后，回合随即在读取绑定时失败，只是原因码不同。属于另有一层的情形。
- **用量边界的两处判断，是测试缺口。** 记录文件的第一行不是会话头时，以及冻结时读到大小上限被截断时，基线都应当算作不可靠，这一回合的用量保持未知。去掉其中任何一处都没有测试失败。代码是对的，带到下一步开头补测试。

第五步的 11 处里，Worker 主循环的四处接线、两处排队中的冲突、完成回执的输入摘要、就绪文件不是普通文件，这 8 处现在都有测试失败。仍没有测试失败的 3 处都是另有一层的情形：就绪文件的路径防护与没有记录 Worker 实例的执行，与当时相同；只有检查点的那条路径上的停止条件，本 Host 追到了原因：这条路径有两层，没有确认停止就不读检查点，判断里又要求一次，各去掉一层行为不变，两层一起去掉时新测试失败。所以这一处不再是缺口。

## 真实的 DSH

两个真实的 DSH 回合是实现方在用户于 2026-10-09 批准后运行的，本 Host 没有重做，只独立读了留存的两次请求、两次结果与会话事实：

- 两次结果的会话标识相同；第二次请求写明原生续接，并指向同一个会话。
- 用作记忆证明的那段随机内容，只出现在第一回合的问询里，两次请求、两次输入与第二回合的问询里都没有，第二回合的结果里答了出来。
- 每个回合的用量等于它自己那几条原生记录之和：第一回合 4 条，未缓存的输入 12,072、输出 281；第二回合 5 条，未缓存的输入 12,913、输出 334。第二回合没有把第一回合的记录算进去。
- 两回合的原生进程组都已消失，控制器已停止，停止得到确认。

**更正了记录里的一句话。** 实现方的记录写第二次输入"没有重放旧摘要或消息"。留存的第二次请求表明，输入里照常带着续接的上下文，其中有上一回合的最后一条助手消息与检查点摘要。这是各 harness 续接时共有的做法，不是缺陷，也不影响记忆的证明；本 Host 已在那份记录里把这句话改成与证据一致，并注明原文。
