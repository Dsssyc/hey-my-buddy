# 额度改为冷却：验收记录

开发者 2026-10-18 定下：额度不再按读数判断与显示，用尽改为可以透明改派的冷却。决定见 ADR-021 第 22 条、ADR-019 第 6 条与 ADR-018 第 23 条同日的修改（`b8f88a66`），依据见[调研](../research/2026-10-18-quota-cooling-and-failover.md)，执行计划是[额度冷却的执行计划](../design/quota-cooling-plan.md)。各微任务在同一个宏任务里，实现都在 `socu/batch2` 上，随批次二的 0.46.0 安装，现在还没有安装。

## 执行计划（2026-10-18）

- **第 1 版：** 微任务“额度冷却的执行计划”（run `da0181bc`，Codex CLI `gpt-6.1-sol / high`），只写计划（`b23d2557`）。
- **两份审查：** Host 与一个独立审查者分别审，互不看对方的结论。独立审查是微任务“额度冷却计划：独立审查”（run `de0d87bf`，Claude Code CLI `claude-opus-5-5 / high`），全文留作 Host 的证据，没有进仓库。两份的方向一致：每次改派新开一次路由，复用 `_start_routing`，不在同一次决定里多轮重选；冷却表只留五列；全部冷却走现有的 no-legal-candidate 路径；credits 没有核实过的来源，这一批不做。独立审查另外指出被拒回合在回合模型里没有定义（首回合改派会撞上唯一约束，续做回合要先把它的 continuation 重新排队），据此加了 `rejected` 回合状态，改派判定照 `native_resume_refused` 的先例放在 `settle_turn`。它说“只删目录提醒的代码映射，真实看板会升级失败”，Host 验收微任务二时核对为不成立（见下）。
- **第 2 版（`e401285a`）：** 同一微任务的第二回合按两份审查改写，接受。
- **消耗：** 计划两个回合输入 1,030 万（命中缓存 996 万），输出 5.5 万；独立审查输入 498 万（全部命中缓存），输出 4.5 万。

## 微任务二：服务冷却、改派、存储与升级

- **微任务：** “额度冷却二：服务、存储与升级”（run `664c5b97`，Codex CLI `gpt-6.1-sol / max`，一个回合）。
- **基点与合并：** 基点 `e401285a`，合在微任务一的第一回合之后（`caadf88d`，按有调整验收）。
- **做了什么：** 表 `provider_cooling`（harness、提供方、连续被拒次数、冷却到何时、最后一次被拒的时刻），有行当且仅当次数大于零。冷却从 30 分钟起按次数加倍，最长 24 小时，原生给的恢复时刻在被拒之后时不晚于它；这个提供方上一次开始于最后一次被拒之后的成功删掉这一行；`quota-redetect` 只清掉截止时刻，保留次数。模型开始之前的额度拒绝把回合标为 `rejected`，同一个微任务新开一次路由；中途被打断、阶段不明、Host 明确指定或锁定的 buddy 仍停到 Host 面前，同样计入冷却。全部候选都在冷却时，原因是 `all-candidates-cooling {retryAt}`。删除 `quota_current`、`harness_quota_observations` 与单次重试。
- **核对（存储类）：** 差异读过。在日常看板的副本上，基点与候选各跑一遍 24 → 25 升级再逐行对照：只差删掉的两张表与新表，其余每一行相同，schema 25，完整性与外键检查通过。按 0.42.0 写入者的形状注入三种存量之后再升级：一条 `quota.redetect` 回执被删；`decision_requests` 与 `router_requests` 依据里的 `quotaRetryBuddyIds` 被摘掉；旧原因 “The selected quota retry was consumed by another decision”（`router-out-of-bounds`）转为 `router-out-of-bounds {bound: constraints-or-quota}`；除此之外与不注入的升级逐字节相同。改派的几种情形由 `test_provider_cooling.py` 守着：同一个 run 新开决定；中途、阶段不明、明确指定、锁定、停止未确认与已取消都不改派；限流不冷却；全部冷却的边界。
- **独立审查那条说法的核对：** 0.42.0 与 0.45.3 里，三个额度提醒代码只由 `native_observations.warnings` 产生，只在读微任务视图时算进 `quotaWarnings`，没有写入者把它们存进目录记录，日常看板上也一条都没有。升级里为它们留的转换（结构化原因那一批先写成映射，这一批改成丢弃）用不到，作为顺带项交给微任务三删除。
- **消耗：** 输入 856 万（命中缓存 834 万），输出 4.3 万。

## 微任务三：控制台

- **微任务：** “额度冷却三：控制台与预览”（run `916dd7f1`，Codex CLI `gpt-6.1-sol / high`，两个回合）。
- **基点与合并：** 基点 `1b5dbf49`。第一回合原样合并为 `7866f86b`，第二回合为 `b03b12b1`。
- **做了什么：** 删掉额度栏、窗口、近限与过期提醒、单次机会；冷却只在生效时出现：harness 一行写“冷却中 · 约 {time} 可再试”，这个提供方的模型名旁写同样的短字，详情里每个冷却的提供方一行，带“解除冷却”；解除读扁平的回复。微任务页把被拒的回合写成“额度被拒 · 已改派”，后面接新的路由决定；“所有候选都在冷却”的边界列出冻结的冷却候选及各自的时刻。合成预览换成多提供方冷却、到期、解除、改派成功、全部冷却与中途失败。顺带做了：中文停止说法里的空格；buddy 视图的 `providerCooling` 只给正在生效的冷却，与微任务视图一致；删掉升级里用不到的目录额度提醒转换与喂它的测试；夹具测试改用旧写入者的原句。
- **第二回合的起因：** Host 看真实数据的像素时发现，第一回合为了冷却出现时不让周围跳动，给每个模型行预留了一行：宽屏行高 41 → 57 px，390 宽 57 → 77 px，不论有没有冷却。这是 Host 的简报只写了“不跳动”、没写代价引出来的。用词也没跟术语表（“已交回重新路由”）。开发者看过截图后决定装之前修。修后冷却是模型名旁的行内短字：宽屏有无冷却都是 41 px，390 宽未冷却 57 px，英文的冷却行换行时 77 px。
- **核对：** 两个回合的差异读过。最终源码上 typecheck 通过，前端 84 个文件 1,026 项、浏览器 433 项通过，重新构建的资源与交付的逐字节相同；完整检查 282 个文件 4,484 项通过（在第一回合合并之后跑，第二回合只改控制台，随后重跑控制台、预览与文档卫生的 11 个文件 150 项）。同一份日常看板副本分别用删转换前后的源码升级，结果逐字节相同。真实数据回放：在升级后的日常看板副本上注入三条冷却记录（一个 ZCode 提供方在冷却、一个已到期、一个已解除），走遍 36 个宏任务、167 个微任务、1,137 步，中英文都没有读取失败或页面错误；Host 的回放脚本起初漏掉了控制台自己的失败文字，补上之后重跑仍然干净，命中的几处都是任务正文里的词。在冷却的提供方在 harness 一行、它的两个模型旁和详情里都显示了，到期与已解除的什么都不显示。
- **留给下一批：** 宏任务时间轴把被改派的那次尝试画成失败色的细边：只有微任务页在前端把回合状态并进片段，时间轴的回复里没有这个状态（[待处理问题](../design/backlog.md)）。
- **消耗：** 两个回合输入 2,874 万（命中缓存 2,829 万），输出 5.3 万。
