# 会话视图：验收记录

[ADR-024](../decisions/024-console-session-view.md) 的实现，执行计划见[会话视图执行计划](../design/session-view-plan.md)。各微任务在宏任务“0.46.0 之后：基点与会话视图”里，实现都在 `socu/session-view` 上，现在还没有安装。

## 执行计划（2026-10-19）

- **第 1 版：** 微任务“会话视图的执行计划”（run `d4c8473a`，Codex CLI `gpt-6.1-sol / high`）。它对 Codex 用两个来源：运行中写一份私有记录，结束后删掉它、改读 Codex 自己的 `thread/read`，再用来源切换、新的 C-Two 读取方法、64 KiB 分片、增量 JSON 解析与读取租约把两者拼起来，光 Codex 就拆成六个微任务。
- **两份审查：** Host 先写下自己的看法，再请一位独立审查者审（微任务“会话视图计划：独立审查”，run `22f263ab`，Claude Code CLI `claude-opus-5-5 / high`），互不看结论。两份一致：执行进程写的那份私有记录就是唯一来源，运行中与结束后都读它，服务直接读文件；Codex 的原生线程在用户自己的存储里，用户能改能删，守不住“随宏任务删除”的承诺。审查者指出的回收只保留失败执行的私有目录、控制台跑在服务进程里两点，Host 在源码里核实属实。
- **第 2 版（`171a521c`）：** 同一微任务的第二回合按此改写，接受：每个 attempt 一份 `session.jsonl`，按字节偏移分页，回收时保留它，删除沿用现有的私有根删除，各 harness 一张不提供内容的表，中间号移动一次；Codex 三项（A、B、C），之后 DSH、ZCode、Claude Code 各一项。它建议的 ADR-024 措辞修改等开发者看过再改。
- **消耗：** 计划两个回合输入 430 万（命中缓存 410 万），输出 3.5 万；独立审查输入 189 万（全部命中缓存），输出 2.4 万。

## A：Codex 投影器与会话记录

- **微任务：** “会话视图 A：Codex 投影与记录”（run `da71f9cf`，Codex CLI `gpt-6.1-sol / high`，四个回合）。
- **基点与合并：** 基点 `171a521c`；第二回合合并为 `af64331d`，最终的差量合并为 `e272ec64`（与 B 在原因码登记表上冲突，两边都保留）。
- **做了什么：** 执行进程在 Codex 已有的事件链上投影 ACP v1 的六种更新，追加写进 attempt 私有目录里的 `session.jsonl`；Worker 回合与 Router 调用都写；工具类别复用 L5 的 `normalize_tool_event`；`rawResponse`、账户、限额、用量类通知不写；回收检出时保留每个 attempt 的这一个文件。
- **打回与修正：** 第一回合在原生进程起来之前就以独占方式建文件，同一个 attempt 的启动重试与 Host 宽限内的收尾回合都会撞上已有文件而失败，Host 在下游测试里发现后打回；第二回合改为回合开始时以追加方式打开。按“改动删除路径的差异另请独立审查”的规矩，Host 请了第二次独立审查（run `a14f6e6f`，Claude Code CLI `claude-opus-5-5 / high`）：删除路径没有问题；但投影器出错会把原生已完成的回合判成失败，几条路径还会越过 `_run`，运行结果连同停止证据一起丢掉；输出增量与 diff 快照写成同样的内容块，读取方分辨不出。Host 核实后定了规则：原生内容对不上是数据，不报错；写入失败是这次运行的错误，原因码 `session-record-write-failed`，运行结果照常建出；追加与替换用显式的 `_meta.replace` 区分，并写明与 ACP v1 的差别。第三、四回合照此修改，并让回收的保留集合不留链接与同名目录、删掉没有使用者的模型与多余的可空判断。
- **核对：** 四个回合的差异读过；Host 在合并后的源码上跑 A 与 B 的下游测试，127 个文件 2,266 项通过。原生字段只经 Codex CLI 0.162.1 的离线协议样例与合成夹具核对，命令输出增量、推理的摘要与文本、计划步骤与子代理正文没有真实样本。
- **消耗：** 四个回合输入 1,635 万（命中缓存 1,575 万），输出 9.7 万；独立审查输入 340 万（全部命中缓存），输出 3.6 万。

## B：只读读取、空间、能力与版本

- **微任务：** “会话视图 B：读取、空间与版本”（run `bd808336`，Codex CLI `gpt-6.1-sol / high`，一个回合）。
- **基点与合并：** 基点 `af64331d`，原样合并为 `b3364e98`。
- **做了什么：** 控制台的 `GET /api/tasks/{taskId}/attempts/{attemptId}/session` 直接读记录：偏移在边界验证一次，只读到最后一个换行，每行严格校验；宏任务一旦有删除记录就回答已删除。存储检查新增 `session-records`，装着会话记录的私有根不再可被普通回收删掉。各 harness 一张不提供内容的表；版本 0.47.0，C-Two 方法签名不变。
- **核对：** 差异读过；在日常看板的副本上核对 Router 的路由任务属于宏任务的成员，它们的记录也能读到。Host 跑它的下游测试 102 个文件 1,490 项，以及上面合并后的 127 个文件 2,266 项，都通过。
- **消耗：** 输入 304 万（命中缓存 289 万），输出 2.4 万。

## D：DSH 投影器

- **微任务：** “会话视图 D：DSH 投影器”（run `e0728588`，Codex CLI `gpt-6.1-sol / high`，一个回合）。Host 把它排在控制台视图（C）之前：它只动后端，C 要等开发者看过设计、并决定能否联网装 AI Elements 的依赖。
- **基点与合并：** 基点 `3de9c0b9`，原样合并为 `e157c205`。
- **做了什么：** 在 DSH 已经消费的 ACP 更新上投影，写同一份 `session.jsonl`；Worker 回合与 Router 调用都写，同一个 attempt 的多次运行追加，恢复时不重放历史；写入失败照 Codex 的规则处理。
- **核对：** 差异读过；Host 跑 DSH 的测试与目录之外所有引用 DSH 模块的测试，59 个文件 976 项通过。ACP 夹具是合成的 fake agent 样本，真实 DSH CLI 给出的推理是否完整没有核实，所以它不提供内容的表留空。
- **消耗：** 输入 355 万（命中缓存 340 万），输出 2.3 万。

## E：ZCode 投影器

- **微任务：** “会话视图 E：ZCode 投影器”（run `55ac1efc`，Codex CLI `gpt-6.1-sol / high`，一个回合）。
- **基点与合并：** 基点 `c17e1a41`，原样合并为 `0bf9d81b`。
- **做了什么：** 在 ZCode 已有的原生事件接入点投影，写同一份 `session.jsonl`；Worker 回合、Router 调用与流末的排空都写，只收本次的 input、session 与 turn；写入失败照 Codex 的规则处理。
- **核对：** 差异读过，确认所有写入都经保留记录错误的路径，失败时原因正确；Host 跑 ZCode 的测试与目录之外所有引用 ZCode 模块的测试，35 个文件 693 项通过。ZCode 0.16.9 的脱敏样本证明有推理片段，但真实流给出的推理、工具参数与计划是否完整没有核实，它不提供内容的表留空。
- **消耗：** 输入 397 万（命中缓存 381 万），输出 2.6 万。
