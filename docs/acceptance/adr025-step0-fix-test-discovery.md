## 新增防护测试

`cli.test_checks_parallel.ScheduledModulesTests` 新增 `test_scheduling_covers_every_test_file_on_disk`：用 `os.walk` 独立遍历 `tests/python` 全树且不做任何包过滤，取磁盘上全部 `test*.py`（与生产相同的文件名谓词：`test` 前缀、`.py` 后缀）转为相对 `tests/python` 的点分模块名，构成既不依赖 `unittest discover` 也不依赖同包遍历的独立全集；再与真实 `checks.python_test_modules(REPOSITORY)` 的返回做双向集合比较——磁盘有而排程无的漏项以 `test files on disk are never scheduled: <模块名列表>` 点名失败，排程有而磁盘无的模块以对应消息点名。全集由遍历实时计算，不硬编码当前 158 的计数，也未新建第二个运行器。既有的 `test_this_checkout_schedules_exactly_what_discovery_loads` 把 `unittest discover` 与 `python_test_modules` 互相对照，而两种机制共享"只沿 `__init__.py` 链下降"这一前提，包链断掉时会一起漏掉同一文件、互相看不见；本防护以磁盘全集为第三方基准，补上这一类共同盲区。

## 真实故障注入：私有副本移除 console/__init__.py

防护测试自身用真实变异验证。先以 `git archive HEAD tests/python` 把 tracked 测试树原样提取为私有副本 `<worktree>/tmp/adr025-step0-fix-discovery/copy/tests/python/`（不含任何未跟踪文件；`git archive` 保留完整路径前缀致首次解包多出一层目录，已用 `mv`/`rmdir` 归位，并复核 27 个 `__init__.py` 与 `console/__init__.py` 在位）。驱动脚本 `run-guard.py` 按文件路径加载真实 `tests/python/cli/test_checks_parallel.py`，只把模块级 `REPOSITORY` 替换为副本根——不 mock `python_test_modules`、不替换防护断言、不改被测文件——再经 unittest 只运行防护测试这一个用例；驱动自身环境同样经 `checks.child_environment` 净化并落在容器内。先把 `REPOSITORY` 指向真实检出做健全性运行：退出码 0 通过（`sanity-pass.log`）。随后删除副本内的 `tests/python/console/__init__.py`（tracked 的 0 字节文件；真实检出中的同名文件未动，`git status` 无删除），同一驱动同一测试重跑：退出码 1，失败消息原文为 `AssertionError: ['console.test_console', 'console.test_console_access', 'console.test_console_cli', 'console.test_console_sessions'] is not false : test files on disk are never scheduled: console.test_console, console.test_console_access, console.test_console_cli, console.test_console_sessions`，回溯指向真实被测文件中防护断言所在行——正是用户第 3 项所指缺陷形态：`console/__init__.py` 缺失时 `unittest discover` 与 `python_test_modules` 会共同漏掉的恰是这 4 个 console 测试文件，防护逐一点名。以 `git show HEAD:tests/python/console/__init__.py` 按字节恢复副本内文件（仍为 0 字节）后，同一测试重跑退出码 0（`restored-pass.log`、`restored-pass.exit`）；变异阶段退出码存于 `mutation-fail.exit`，完整日志存于 `mutation-fail.log`。
