# Model-family concurrency backend — ADR-011 slice

This record covers the backend implementation of [ADR-011](../decisions/011-runtime-refinement.md) model capacity in an isolated parallel-development checkout at base `8762d9d`. It is source-level evidence only: nothing here is staged, installed or running against the daily board, the React console was intentionally not changed, and the plugin version and public contract constant were not bumped. The Host integrates this output and owns release metadata.

## Implemented contract

A model family is the exact adapter/provider/model tuple; effort variants share one family and one concurrent-task limit (default 2, integer 1–32, no effort dimension). The board uses one machine-wide concurrent-attempt ceiling, `BUDDY_MAX_CONCURRENT` (default 8, range 1–32); `BUDDY_MAX_DECISIONS` and the reserved decision lane are removed, and the managed worker pool is ownership-safely sized to the total ceiling under the existing manifest rules. Schema is now 11 — one current schema with the new `model_concurrency` settings table and frozen `model_adapter`/`model_provider`/`model_model` columns on `attempts` (plus a partial family index) — and startup still refuses every other schema marker without any importer or conversion branch.

Admission checks the machine ceiling first (queue reason `capacity`) and then the task's model family (queue reason `model-capacity`); workspace, exclusive-resource, lease and ownership checks are unchanged, and command/external work without a model counts only against the machine ceiling. A routing task's family is the fixed decision profile's actual tuple, resolved inside the claim transaction, quota-checked before the claim commits and before the selection reader is admitted, and frozen onto that attempt; business attempts freeze their resolved effective tuple at claim. The frozen identity is written once and never updated, so historical and shutdown-uncertain attempts keep exactly the family slot they were admitted under; family and total occupancy both follow the existing unresolved-attempt rule. The candidate scan filters full families out in SQL before its 50-row LIMIT, keeps routing tasks in their own bounded window (their family is mutable selector state and cannot be pre-filtered), preserves arrival order among eligible work, and an empty claim names the limit that is holding work.

The console snapshot and each `model_profiles` page carry `modelConcurrency`, one `{adapter, provider, model, limit, active}` row per family represented in that response, including defaults for families without an explicit override; `active` counts unresolved attempts and is observation only. `user_policy_publish` accepts a `modelConcurrency` patch of `{adapter, provider, model, limit}` entries only — the authenticated console writer validates family strings, integer limits 1–32 and duplicate families, rejects `active` and every other derived field, commits atomically with the existing draft/revision/receipt protocol, and `assessment_publish` cannot touch the field. Settings persist in `model_concurrency` independently of profile availability, survive discovery marking a model unavailable, apply at the next claim without a restart, and a decrease never terminates live attempts. `health.capacity` reports `{totalLimit, totalActive, models}` with per-family limit/active rows for relevant pending, active and configured families, and `health.maxConcurrent` is the total ceiling; the lane fields are gone. Attempt views expose the frozen family as an observation-only `modelFamily`.

## Verification

All verification ran in this checkout with `uv run --frozen python -m unittest` from `tests/python` against private temporary state directories, with inherited runtime, worker and agent-credential variables cleared in the daemon subprocess tests. The new focused suites pass completely: `test_scheduling` (10 cases: family rule, effort collapse, limit clamps, pool IDs), `test_store` (11 cases: schema 11 fresh-board shape, refusal of a schema-10 marker without migration, frozen identity incl. completion and unconfirmed-shutdown retention, family quota with default 2, effort variants sharing the limit, machine ceiling across families, capacity report), `test_model_concurrency` (17 cases: snapshot/model_profiles/health shapes, console-only patch, validation and atomicity, idempotent replay, unavailable-family persistence, lower-never-kills with next-claim holds, raise-at-next-claim, selector quota before reader grant, frozen selector tuple, blocked routing not hiding business work), `test_scheduler_lanes` (6 cases: the required demonstration that 101 queued tasks blocked on one full family cannot hide a later runnable other-family or command task behind the 50-row window, blocked backlog queue reasons, honest empty-claim reason, arrival-order fairness, shared ceiling), `test_worker_pool` (5 cases) and `test_daemon` (5 cases, including a real private daemon reporting schema 11, `maxConcurrent` 2, the new capacity shape and two managed supervisors). The updated `test_user_policy` passes 8 cases including the two new console-only modelConcurrency boundaries.

Existing suites over changed code paths pass unchanged in this environment: `test_evaluation` 33, `test_workflow_routing` plus `test_routing_preferences` 34, `test_workflow`/`test_workflow_cancellation`/`test_workflow_boundaries` 76, `test_console`/`test_catalog*` apart from the deltas below, and `test_decision` 29 with one failure that also fails at base `8762d9d` (a real-daemon case whose CLI child presents this session's inherited attempt credential and is refused). Base comparisons used `git stash` round-trips on the same machine. Pre-existing at base and unaffected by this change: ten environment-dependent real-daemon/install failures across `test_blackboard` (6), `test_ctwo_service` (1), `test_console` (2) and `test_repair_recovery` (1).

This change intentionally breaks assertions in test files outside this task's write scope, which the Host must update at integration: `test_current_core` (9 cases hardcoding `SCHEMA_VERSION == 10` and the "only schema 10" message), `test_parallel_dispatch` (21 of 28 cases asserting the removed lanes: `BUDDY_MAX_DECISIONS`, `decision-capacity`, lane-shaped `health.capacity`, `WorkerPool(business_limit=…, decision_limit=…)` and per-lane fairness) and `test_console` (1 case asserting the exact snapshot key set, which gains `modelConcurrency`). Their replacement coverage lives in the new suites above. The owning reference pages (`docs/reference/architecture.md`, `docs/reference/evaluation.md`) still describe the lane model and schema 10 and are outside this write scope; they must be updated with the integration. Deployment follows ADR-011: schema-10 boards are refused, so the cutover needs the separately verified offline copy and a stopped/idle switch; no runtime schema importer was added.
