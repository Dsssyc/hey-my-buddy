# 目录重读打断路由：缺陷与修复的验收

2026-10-12，整合 Host。[ADR-027](../decisions/027-model-catalog-trust.md) 与 [ADR-021](../decisions/021-router-buddy-planes-and-routing-evidence.md) 的应用。一个微任务，两个回合，Codex 的 Worker（gpt-6.1-sol / high）；最后一个回合的封存是 `b27ee0a6`，合入整合分支的提交是 `1b802b5f`。实现方的说明在 [catalog-reread-and-routing-notes.md](../design/catalog-reread-and-routing-notes.md)。

## 缺陷

用户发现另一个项目的 Codex Host 的微任务在控制台上全是“指定”。核对日常看板：那个 Host 提交时没有指定 buddy，一天里四次经路由的提交全部以 `router-table-changed` 停在 Router 派发前，它只好带理由给一个配置继续。每次提交后的几秒内，评价表的版本都被目录读取推进了。

原因是一条链：每个 Host 的调用把自己的 `PATH` 交给服务当线索，最新的排在最前；服务算 harness 的位置指纹时把没有东西的候选位置也按顺序算进去；指纹一变就重新检测并重读目录；每记下一次读取，评价表的版本就加一，不管内容变没变；Router 在派发前发现版本与冻结时不同就停下。Codex 给每个进程在 `PATH` 里加一个自己的临时目录，所以一个 Codex Host 的主进程与它的监视子代理就足以触发，不需要第二个 Host。日常看板上评价表的版本从 2026-09-29 起在活跃的日子里每天被目录读取推进几十次。

## 修复

- harness 的位置指纹只随“发现会找到什么”而变：可执行文件出现、消失或变了，存在的候选之间换了先后，版本管理器的记录变了。
- 调用方的 `PATH` 线索：只记住当时确实放着某个 harness 或 Node 可执行文件的目录，按第一次见到的先后排列，最多 64 个。
- 目录的记录只有在改变了评价表的内容时才推进版本、写修订行、发事件；同一份目录再读一次、不被采信而什么都没有替换的读取，只记下这次观察。
- `router-table-changed` 的两处检查用同一句理由，写明回应是 `reroute`。

## 核对

- **在私有服务上复现，修复前后各一次，不调用模型。** 私有的状态与运行时目录，真实的四个 harness，只做发现。

    | 调用 | 修复前的评价表版本 | 修复后 |
    | --- | --- | --- |
    | 强制发现一次 | 4 | 4 |
    | 再强制发现一次 | 没有做 | 4 |
    | 三分多钟后用同一个 `PATH` 调用两次 | 4 | 4 |
    | `PATH` 前面多一个不存在的目录 | 14 秒内到 8 | 4 |
    | 换回原来的 `PATH` | 17 秒内到 12 | 4 |

- **机械检查。** 受影响的 13 个测试文件 347 项通过；完整的 Python 检查在合并后的树上通过，218 个文件，3,708 项。控制台的源码没有变。
- **差异。** 源码 5 个文件读完。存储的形式没有变，没有改 schema；已有的修订行保持原样。升级后的第一次扫描会因为指纹的算法变了而重新检测一次。
- **扫描的开销。** 在这台机器上量 `candidate_snapshot`：每个 harness 约 0.002 秒，与修复前相同；接收一次 `PATH` 线索（31 个目录）约 1 毫秒。
- **规则守没守住。** 在副本上改错五处：每次读取都推进版本、版本永不推进、线索改回最新的排最前、空目录也记住，测试都有失败；把服务用的指纹改回对整个快照取哈希，没有测试失败。后一处的代码是对的，线索的规则已经让空位置不再变化，所以测试看不出来；记为顺带项，下一次动这一块时补一条测试。

## 打回一次

第一个回合的评价表判据、共用的理由与消费者的核对是对的，三处要改：给位置扫描加了文件内容的哈希，量出每个 harness 的扫描从 0.002 秒变成 0.8 到 1.0 秒，而这个扫描每次认领任务之前都会做；去掉了 `PATH` 线索的上限，服务活多久列表就长多久；把修订行里 `profiles` 这个数的含义从“读取里的条目数”改成了“变化的行数”，同一个键的含义不能随写入的时间而变。

## 验证的边界

- 已随 2026-10-12 的[第二次安装](install-0.30.0.md)装上；装后一个从不同 `PATH` 提交的经路由的微任务正常完成，评价表的版本没有变化。两个 Host 的真实交替没有等到。
- 最后一环，即版本不同时 Router 停下，没有在私有服务上用真实的 Router 调用复现，依据是日常看板的四条记录与测试。
- 评价表的内容确实变了的读取仍然会让正在路由的请求停下，这是原有的设计；是否改成由服务自己重新路由，记在待办里，待用户定。
- 只在 macOS 上核对。
