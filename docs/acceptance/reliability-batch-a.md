# 可靠性小批次（A 批）的验收记录

2026-10-15，整合 Host。按[执行计划](../design/reliability-and-step3-plan.md)的 A 批，三个微任务都由 Codex `gpt-6.1-sol / high` 做，在宏任务“可靠性小批次”下。版本随后改为 0.38.0：`health` 与 `workers` 多了字段，存下的结果多了一项事实。看板仍是 schema 21。

## A1：Codex 回合里多条最终回答，取最后一条

**起因。** Lead 第二次试跑里，一个 Codex CLI 0.162.1 的回合跑了约 40 分钟，被判为 `invalid-result`。Host 读了这个回合在用户 Codex 目录里的原生会话记录，只看消息的种类、时间与长度：

- 第一条最终回答 680,985 字符，结果 JSON 写到一半，后面接了约 68 万个空白字符；
- 16 秒后 Codex 在同一回合里给出第二条，1,027 字符，是合法的结果；
- 产品见到第二条就报错，中止了回合。

日常看板记下的 19 个 Codex Worker 会话、48 个回合里只有这一次。开发者没有给 Codex 配过钩子，因此没有付费复现。

**交付。**

- 回合的结果取完成前的最后一条最终回答。
- 被取代的那几条记在结果的 `nativeCheckpoint.supersededFinalAnswers`：条数，以及各条的长度、SHA-256、能否解析。
- 旧的“只认恰好一条”的补救逻辑删掉了。
- 顺带改了 ZCode CLI 探针的变量清单。

**打回一次。** 起初只在有被取代的回答时才写这个键，于是“没有这个键”在新记录里是一条也没有，在旧记录里是没有记这项事实，这是随写入时间而变的含义。改成每个回合都写，没有时计数为 0。

**核对。** 合并之后，Codex、角色层与探针的 468 项测试通过。

## A2：一直起不来的 Worker 在 `health` 里看得见

**起因。** 0.36.0 装上之后，Worker `local-2` 每次启动都失败，一直重启了 11 个小时，`health` 却照样说有 7 个 Worker。

**交付。**

- `health` 与 `workers` 用 `workerSupervisors` 列出池子管着的每个 Worker（期望的与多余的）：supervisor 发布的状态、最后的错误与它的时刻、起来的时刻。文件缺了或内容不对时报 `unknown`，不猜成正常。
- 重新注册的 Worker 把看板上这一行重新开始，前任的执行结算之后不再把活着的 Worker 显示成 `lost`。

**打回一次。** 第一次交付把 `managedWorkerIds` 改成了期望加多余。Host 在合并后的树上跑下游的读者，`test_parallel_dispatch.py` 里缩容的那一项失败。改回原来的含义，supervisor 的事实放进不撞名的新字段。

**核对。**

- 重新注册时清空的那一列，只用于显示与结算时的匹配；认领不看它，重新挂接时会再设回去。Host 读代码确认。
- 合并之后，连同下游读者 29 个文件、355 项测试通过。

## A3：没有正常完成的执行，原生证据不随回收删掉

**交付。** 回收检出时，状态不是成功、或终止原因不是 `completed` 的执行，保留它的 `attempts/<执行>/`，先清掉其中的凭据文件，其余照旧删，不跟随链接。存储回收在运行被验收或写结论、过了宽限期之后，可以删掉留下的目录。

**独立审查。** 改的是删除路径，按约定请看板上的 Opus 5.5 盲审一次，记录在它的产物里。审查找到三条，Host 读代码逐条核实后打回：

- 由 Host 写结论结束的运行，留下的证据在存储回收里永远删不掉：存储回收把不是 `accepted` 的运行一律当作还能续做；
- 结果导入失败的执行，状态是失败而终止原因仍是 `completed`，被当成了正常完成；
- 留下的目录里可能还有凭据文件。

另有两处多余的东西一并去掉：

- 存储清单里三个没有读者的字段，其中一个是写死在服务里的中文；
- `remove_tree` 里一道保护不了任何东西的保留路径校验。

**Host 的故障注入。** 对 `remove_tree` 做了五处：

- 保留的目录被换成链接；
- 要删的部分里有指向外面的链接；
- 保留的路径在要删的目录之外；
- 之后整棵删除时，保留的目录是链接。

外面的文件都在，越界的保留路径在删除之前就被拒绝。

**核对。** 合并之后，回收、存储回收、私有目录与角色层 30 个文件、461 项测试通过。

**留下一处。** 借用同一检出的协助任务以失败或取消结束、上级已经结束时，存储回收仍把它当作还能续做。已记进待办，随下一次动存储回收时改。

A2、A3 第一次交付时，Host 在验收结论出来之前就把它们合进了整合分支，打回之后又撤了出来（只在本地）。以后先在检查用的工作树里合并、测试，验收通过才合进整合分支。

## 验证的边界

- 完整检查在改版本号之后、安装之前跑，结果写进安装记录。
- 控制台没有改：显示在重启的 Worker 的提示，随第 4 步做。
- A1 的新行为只用夹具的原生程序验证过，没有用真实的 Codex 回合。
