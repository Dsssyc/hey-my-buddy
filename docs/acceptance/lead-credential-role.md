# Lead 的凭据与按角色认 Lead：验收记录

## 起因（2026-10-15）

- 开发者批准在真实看板上试跑一次 Lead（付费调用）。试跑的宏任务是“控制台的小批次”，Lead 是 `codex / openai / gpt-6.1-sol / high`。
- 三分钟之后它就停下请 Host 处理：它在自己执行的命令里调用启动器，环境里没有这次执行的凭据，启动器把它当成普通 Host，提交成功了一个没有名下关系的微任务，那个微任务记着 Lead 自己填的 `hostId: lead:<runId>`。Lead 发现之后没有绕过去，停下来报告。
- Host 取消了那个微任务，确认停止，并在本机复现了原因：用 Codex CLI 0.162.1 跑 `codex sandbox -- /usr/bin/env`，命令里只看得到 `HOME` 与 `PATH`，黑板交给 harness 进程的变量一个也到不了它执行的命令。
- 开发者定下两件事（[ADR-026](../decisions/026-delegation-authority.md) 与 [ADR-030](../decisions/030-harness-layer-scope.md) 2026-10-15 的修改）：
  - 凭据经 Lead 的角色说明到达；
  - 角色由角色定义区分，不靠字符串前缀。

  Host 先前提出保留 `lead:` 前缀，开发者指出那是在字符串上打补丁，Host 撤回了。

## 两个微任务

1. **把升级基点挪到 0.36.0**：路由交给 `codex / openai / gpt-6.1-sol / max`。
   - 它做了三件事：样板看板从 `6b385e53` 重新生成；从 19 到 20 的转换整段删掉；安装与备份只接受 schema 20。
   - Host 在它的产物上重跑了升级、备份与中断恢复的 58 项测试，合并为 `3a14206e`。
2. **Lead 的凭据与按角色认 Lead**：`codex / openai / gpt-6.1-sol / high`，五个回合。
   - **第一回合**：后端改完。
   - **第二回合**：补控制台。它改到了不在写入范围里的合成预览，这是 Host 的说明自相矛盾：要它改，却没把文件放进范围。Host 以“采用”处理，并补进范围。
   - **第三回合**：Opus 盲审（[review](../design/lead-credential-role-review.md)）找到并由 Host 复现的一条，与其余几处一起改。那一条是：名下的微任务仍发 Host 的控制文件，不带凭据也能以 Host 的身份取消它，发起者被记成一个编造的身份。
   - **第四回合**：Host 在日常看板的私有副本上演练升级，升级失败了：24 个微任务里有 18 个，升级“还原不出原始请求”。原因是升级为了重算请求指纹，从存储的字段穷举去猜客户端当年的请求。改为升级时清空旧的请求指纹，旧请求再重放就以 `SUBMISSION_REPLAY_UNAVAILABLE` 拒绝。
   - **第五回合**：合并之后的完整检查有两个文件没过，都是测试还按旧的形式断言：一处期望发起者是字符串 `service-stop`，一处还用已经删掉的令牌变量。实现方改好了这两处，并清掉了各测试里对那个变量的引用。写入范围之外剩下三处：`AGENTS.md` 与 `docs/reference/operations.md` 由 Host 改；ZCode CLI 探针的变量清单只是多清一个没人设的变量，记为下一批的顺带项。

## 交付的内容

- **凭据经角色说明到达。** Lead 的角色说明写明这次执行的凭据文件，Lead 每条启动器命令都带上；凭据文件里写着发出它的看板。
  - 经环境往下传的那一条整个删了；
  - 直接放令牌的环境变量也删了。
- **按角色认 Lead。**
  - 名下的微任务没有 `hostId`，也没有 Host 的控制能力，只有 Lead 的执行凭据能动它们；
  - 所有者从名下关系推出，整合方存成角色加标识；
  - 发起者在事件与五张表里存成“角色”与“标识”两个字段，角色限定在六种以内，表上加了约束。
- **从 schema 20 到 21 的升级。** 只有一条换算规则，认不出的值让升级失败。旧的请求指纹清空，只为 schema 19 存量留下的那张表清掉。
- **版本 0.37.0。**

- 最终的树 `d29e6514`（两次合并 `7f310509`、`b00f2905` 与 Host 的文档提交）：

## 验证的边界

- 已随 0.37.0 安装（[安装记录](install-0.37.0.md)）；修正之后，真实的 Lead 还没有再跑过。
- 凭据经角色说明到达，测试里是一个自己读提示词的夹具 harness；真实的 Codex CLI 回合是否每条命令都带上，要等 Lead 再跑一次。
