## Implemented behavior

1. DSH session grouping requires explicit `workspace:true`; ordinary and routed submissions default to false. The Worker passes an attempt-private session root, and standalone runs also use a private session directory. Explicit grouping still requires its bridge and fails honestly when unavailable. `workers.md`, `operations.md`, `runner.md`, CLI help/reference, the READMEs and the shared skill describe these defaults. Existing stored specifications are not rewritten; a changed default can make a historical request-id replay conflict, preserving idempotency rather than reinterpreting its input.
2. Ordinary Codex coding stores native threads and SQLite state in the goal-private `native/codex-home/`; eligible continuation reuses the same home. Only the selected file-based native login is linked there. Pinned directory handles prevent parent replacement from redirecting credential creation/deletion. Collection removes the link or an ordinary private refresh replacement only after native and controller stop; unknown stop retains credentials, and cleanup failure retains valid turn/stop evidence with a separate diagnostic. Bindings include home and credential source/revision. A frozen `runtime.workerAccount:{source:"worker",revision:N}` consumes only the reserved Worker account home and never falls back to shared credentials; account configuration/login and API-key admission remain owned by the later account slice. Old user-store receipts reconstruct with `private-native-home-required`, retaining the previous assistant evidence without modifying native history.
3. `worker-sessions` provides board-only DSH and Codex lists. DSH plan reads the owning bridge, and explicit apply verifies the stopped board binding, native root header, revision and group membership before native archive/detach. Same-plan replay survives a lost reply and tolerates only its own completed sibling removals. Ordinary journal files are fsynced before mutation, guarded against links and included in verified backups. Results report real `sessionsArchived`, `groupsRemoved`, `groupsRetained`, retention reasons and failures. Native logs remain stored by DSH.
4. The user explicitly chose to retain DSH groups that cannot be safely removed. The published SDK does not atomically report creation ownership, and its group deletion can race an independent attach operation; the bridge therefore reports `created:false`, never calls group delete and reports `groupsRemoved:0`. Mixed groups and unrelated sessions are preserved. [The SDK delete path](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/workspace/workspace/src/index.ts#L3014-L3045) and [entity membership writes](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/workspace/workspace/src/entity.ts#L810-L885) document this boundary. This is the user-approved scope, not an unreported cleanup success.
5. Codex lists deduplicated board-proven threads, labelled user-store or goal-private, including older strict native turn receipts that predate checkpoint metadata. Creation, task and attempt provenance are required; titles and filesystem searches cannot grant ownership. Codex mutation through this command is refused. Actual archive/delete requires separate user confirmation and a native Codex interface.
6. Runtime inventory individually reports malformed entries, missing/damaged/nonordinary READY markers and links. Recognized early READY formats with exact content/root/interpreter identity can be reclaimed after successful process/open-file inspection; current/previous, occupied and unknown-use runtimes remain protected. One malformed entry does not abort pruning. Counts reflect actual removals and explicit skipped entries.
7. Upgrade does not automatically change native DSH groups or Codex history. Existing decision-11 private-file relocation remains after verified backup under its fixed-identity journal and rollback. A failed-switch fixture verifies the backup before DSH session relocation, restores its old layout and leaves an external mixed native-group sentinel unchanged. Any future native-group upgrade migration must preserve the same verified-backup, validation and reversible-journal boundary.
