Host 的核对：

- 说明与核心代码读过：前提的判断、归档的发布、删除之前的再次比对、带设置的那一段、失败之后的退回。合入后的树上 27 个测试文件 304 条通过。
- **在真实数据上的演练。** 取日常环境最近一份已校验的备份（装 0.34.1 时在看板空闲时做的：1,116 个任务、198,282 条事件、158,433 条命令回执、14,340 个历史文件），恢复成一份私有副本，在命令沙盒里、进程内按协调器的顺序走，不起服务，沙盒之外什么都写不了；升级的代码没有启动任何子进程。副本用完已删除。
  - 四种前提各改一处再还原：有等 Host 的微任务、有已交付而没有结论的微任务、有停止未确认的执行、有留着的受管检出。每一种都以 `UPGRADE_NOT_IDLE` 拒绝，列出的正是被改的那一个，看板的字节不变，没有产生归档；全部还原之后放行。
  - 归档发布之后改动一个现场的历史文件：以 `UPGRADE_ARCHIVE_CHANGED` 拒绝，看板仍是 schema 18、任务仍是 1,116 个，历史文件一个不少，归档留着。
  - 成功的一次用时 190 秒：归档里的看板逐字节等于升级前的看板，14,340 个历史文件全在归档里、现场为 0，归档通过产品自己的校验；新看板是 schema 19，没有任何历史行，六张设置表逐行相同，Router 的四项设置相同，密钥是新的，结构与新建的看板相同。
- **两处定向变异。** 让退回时什么都不恢复：两条测试失败。让删除之前不比对现场与归档：测试仍然通过。代码是对的（上面的演练里它拒绝了），是测试没有守住，记为第 2 行的顺带项。
