## 重构部分

- **公共的启动与收集。** 四个适配器与 Router 的旧通道改用同一个 237 行的模块；各条路径原有的差别（读取上限、截止时间的含义、停止的判定）都作为显式的参数保留。本 Host 对照了 ZCode 适配器的改动，是等价替换。
- **角色的调用点。** Worker 运行时改经角色模块的入口调用，这些入口现在只是直接转调。已登记新接口的 harness 不允许再落回旧通道。
- **四个 harness 仍走原来的载体。** 新接口的登记表是空的，本步没有接入任何 harness。

## DSH 的 ACP 客户端

第一次核对时打回了两处：子进程环境收得过窄，强制了私有的 `HOME` 并丢掉代理等变量；测试在源码目录里留下目录和台账。整改后：

- **环境。** 取自项目已有的 `native_environment`，只强制私有的 `DSH_HOME`，`HOME` 默认继承。
- **测试。** 71 个通过；运行后检出里没有新增任何东西，测试的临时根是空的。去掉"拒绝用户默认 DSH 目录"的检查后测试会失败。
- **真实握手。** 本 Host 用这个客户端对已安装的 DSH 做了一次不调用模型的握手，使用私有的 DSH 主目录：初始化成功，新建会话成功并返回模型与推理强度两个配置项，关闭后进程退出码为 0、进程组消失；用户日常的 DSH 目录没有变化。

列出会话、恢复会话、提交提示词、取消与权限应答，对真实的 DSH 仍没有验证。

## 接受的偏离

- **一处行为变严。** 合并严格解码之后，Codex 与 ZCode 也拒绝溢出成无穷大的数字（如 `1e999`），原来只有 Claude Code 拒绝。这是"合成一份"的直接结果，真实的原生输出里几乎不会出现；本 Host 接受，作为"只重构、不改行为"之外的一处例外记在这里。
- **Codex 自己改了一处代码缺陷。** 瘦身时一个字段的形状检查退化，属于微任务范围内的缺陷，Codex 没有打回而是直接改了，并在记录里如实披露。改动是对的，撤销它会有测试失败。
- **任务发错了会话。** 用户把瘦身的任务发到了另一个 Codex 会话，它直接在实施分支上工作，随后由原会话核对。它曾改动 ADR-025，已被恢复；本 Host 核对过，决定文档、术语表、`AGENTS.md`、README、待办与 skill 都与集成分支一致。它在系统临时目录留下两个参数文件，里面没有令牌，本 Host 没有动。
- **Codex 改了两处测试。** 把注入点改到新的角色调用点；把一个发现测试的断言从只接受"输出超限"放宽为也接受"停止未确认"，并补了后一种情形的断言。被测的发现代码在本步没有改动。

## 带到第二步的事项

- **补两处测试。** 整帧大小上限、普通字段的严格类型。大小上限如果在字段各自的上限之下永远触发不到，写明这一点即可。
- **清理过时的说明。** 公共启动模块里仍写着三个 harness 的解码函数各不相同，并为此保留了一个参数；它们现在是同一个函数。
- **先让 ZCode 走通。** 它是这套格式的第一个使用方。走通后列出没有被用到的字段与类并删除，再并行接入其余三个 harness。到第四步结束，这几个模块里不应再有没有生产使用方的内容。
- **基类里的自定义规则要盯住。** pydantic 的公共基类有 356 行，里面有几条自己的规则：有默认值的字段在传输时仍然必填、数组与元组的对应、用"unknown"表示缺失。接入 ZCode 时逐条确认是否真的需要。

## 结论

第一步与 ACP 客户端都验收。只在 macOS 上核对过。
