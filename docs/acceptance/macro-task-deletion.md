## 执行计划（2026-10-17）

- **第 1 版：** 微任务“删除宏任务的执行计划”（run `e3eb1848`，Codex CLI `gpt-6.1-sol / high`，8 分钟），只写计划。
- **两份审查：** Host 与一个独立审查者分别审，互不看对方的结论。独立审查是微任务“删除宏任务的计划：独立审查”（run `013e0d87`，Claude Code CLI `claude-opus-5-5 / high`，约 12 分钟），审查全文留作 Host 的证据，没有进仓库。
  - **Host：**
    - 计划说查不到 Codex 永久删除会话的接口，实测有；
    - L7 的先后要开发者定；
    - 先提交数据库再删文件，逼出一整套待清理项的表与各处的围栏；
    - 几处没有使用者的机制。
  - **独立审查者另外查到的事实，Host 逐条核对后采用：**
    - 每次执行的证据目录 `<state>/attempts/<taskId>/` 存着任务全文与问答，第 1 版没有列；
    - 换过 Router 的决定里，较早的 Router 任务只在派发表里，照第 1 版删除会因外键失败；
    - 引用的有界视图最多返回 64 个；
    - 旧布局的私有根，以及 CLI 按任务写的控制与提交文件；
    - 存储检查列不出状态目录里其余的残留；
    - 用全文扫描判断共享，一行坏 JSON 会让所有删除被拒；
    - 还有与 Host 同方向的几处过度防御。
- **开发者定（2026-10-17）：**
  - L7 之前的删除不保留结果事实，名下路由执行的 Router 回答记录也随宏任务删除（[ADR-028](../decisions/028-macro-task-deletion.md) 的补充）；
  - 先打删除标记，再删文件，最后一个事务删记录；
  - 授权 Host 实测 Codex 删除会话。
- **Codex 删除会话的实测：** Host 用临时的空 CODEX_HOME，不登录、不起回合、不调用模型，测的是 Codex CLI 0.162.1 的 app-server。
  - `thread/delete` 返回 `{}`，删掉会话的 rollout 文件、shell 快照与 `session_index.jsonl` 里的那一行；
  - 对早先另一个 app-server 进程写下的会话同样有效；
  - 已经删过或从未存在时返回 `-32600`，消息为 `no rollout found for thread id <id>`；编号格式不对也是 `-32600`、消息不同，所以“已经没有了”只能靠消息认出；
  - Codex 自己的诊断日志库里留着几行提到这个编号。
- **第 2 版（`daa02f32`）：** 接受，入库 `2482ec83`。Host 随后做了三处修改：
  - 删去两项修复，它们针对的情况在日常看板上只读计数都是 0（无宏任务的 Lead 分组、已结束而停止未确认的执行），移到待办；
  - 把实现拆成五个微任务（`45978e8d`）；
  - 删掉“安装时按明确转换验证”一句（`c5520a5c`），理由见微任务 1。
- **消耗：**
  - 计划两个回合：输入 627 万，其中命中缓存 602 万，输出 4.3 万；
  - 独立审查：输入 1,027 万，几乎全部命中缓存，输出 5.3 万。
