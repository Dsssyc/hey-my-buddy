## 第一次安装回滚与修正

- 2026-11-01 23:08 UTC 第一次安装，升级在 32 → 33 给旧仓库写标记时回滚：一个旧位置上 Git 报 `fatal: not a git repository`，按“其余 Git 错误让升级失败”整次中止，备份核验通过，服务回到 0.58.4 / schema 32。
- Host 只读试跑日常黑板上全部 19 个候选位置，3 个是这种情形：
  - gridmen 草稿里的两个仓库，`.git` 里的文件在 11-02 00:00（北京时间）被清空、只剩目录。清空它们的是 macOS 每天 0 点的 `tmp_cleaner`（launchd 的 `com.apple.tmp_cleaner`，Host 读过脚本与定义）：它删掉 `/tmp` 下 atime、mtime、ctime 都超过 3 天的文件，空目录要它自己的 mtime 也超过 3 天才删，而删文件刷新了目录的 mtime，所以只剩目录。会话的草稿目录在 `/private/tmp` 下，在那里建的仓库用户也会碰到；黑板这时照“仓库不在”处理，不删除任何东西；
  - `~/Documents` 下一个 Codex app 会话建的分析目录，安装进程列目录得到 `Operation not permitted`。Host 实测，运行它的 Claude app 里的进程能列出 `~/Desktop` 与 `~/Downloads`，读不了整个 `~/Documents`。
- 原因：计划第 57 行写明升级与运行时共用一个“仓库不在”的判断，但升级那一节只写了位置不存在，实现照它做；Host 的验收、两次独立审查与五次演练都没发现，样本只含已验收的微任务，Host 对日常黑板的试跑也只读了数据库的行。
- 修正微任务“升级：Git 说不是仓库就不写标记”（`76fa96f8…`，修正 `45635916`，gpt-6.1-sol / high，两轮，合入 `09e1b1c0`）：
  - 第一轮让 Git 报不是仓库的位置跳过。独立审查（Opus 5.5 high）指出 Git 在读不了时也报不是仓库，Host 用 `chmod 000` 的 `.git` 复现；
  - 开发者 2026-11-02 定读不了的位置不算不在（ADR-002 那一段），第二轮改为：位置与它的 `.git` 都读得了、Git 报不是仓库才跳过，读不了失败并点名位置，升级与 `repository_at` 一起改。
- Host 的核对：
  - 合并后的完整检查：Python 368 个文件 367 过、前端过；失败的 `test_discovery_stop_timing` 两项是满负载下真实子进程的停止计时，这一批没碰，单独重跑 3 次都过，记入待办；
  - 从 0.58.4 起在新导出的样本上演练正常安装：25 秒，0.59.0 / schema 33，68 张表，完整性与外键检查通过，40 个 Host 视图可读；
