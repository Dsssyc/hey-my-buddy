# 封存与核对不设路径上限：验收记录

2026-10-19，整合 Host。开发者定下不为用户的规模设上限之后，修正封存时写死的路径上限。实现在 `socu/session-view` 上，随 0.47.0 安装，现在还没有安装。

- **微任务：** “封存不设路径上限”（run `69e16cbd`，Codex CLI `gpt-6.1-sol / high`，五个回合），合入为 `c52e02c6`。
- **起因：** `blackboard/tasks/workspace.py` 写死 `OUTPUT_ENTRY_LIMIT = 512`，封存只记前 512 条改动并标记截断，累积补丁与核对超过就拒绝。整理文档的微任务改名 304 个文件（新旧路径各算一次），活做完了，回合却被判失败，原因还写成了 `harness-error`。
- **经过：** 第一、二回合把截断标记做成 schema 25→26 的升级，从 Git 重算截断的记录，接进安装器的升级、回滚与中断恢复（Host 起初漏划了安装器的范围，修订后续做）。Host 请的独立审查（run `4f6d4e99`，Claude Code CLI `claude-opus-5-5 / high`）指出：升级只认六种产物，日常看板上有 303 行 `turn-input`，真实看板必然升级失败（Host 在日常看板上只读核实）；`changedEntries` 没有任何读者（Host 在源码里核实）；回滚重新推导文件，转换被拒时会卡死；`workspace-error` 会盖掉真正的失败原因；越界证据还有 256 条的同类上限；回复会随路径数超过传输上限。第三回合按“所有副本一起转”改，自己发现改写快照会让回合输入、原生检查点与 shared-refs 的摘要绑定全部断开，停下交回。开发者定：已经封存的内容不允许改写；随工作规模增长的事实经文件交接（写进 AGENTS.md、[ADR-002](../../decisions/002-host-directed-assistance-and-workspaces.md) 与 [ADR-031](../../decisions/031-one-process-per-execution.md) 第 12 条）。第四回合按此去掉整个升级，第五回合修了一处按旧回执形状读取的测试。
- **结果：** 封存、累积补丁、核对与越界证据都不设数量上限，改动按一次原始树差异读取；新快照不写 `changedEntries` 与截断标记，写 `snapshot.version`，旧快照原样保留；执行进程只交回执文件的位置与摘要，服务自己算出位置、经受保护的打开读取并核对一次后入库，改名 3,000 个文件、内嵌会超过 8 MiB 的产物请求也小于 2 KiB；回复与视图给数量、有限的样例与补丁位置，存储完整；`workspace-error` 只给本来会完成的回合。schema 仍是 25，没有待执行的升级。
- **核对：** Host 读了差异；第四回合合并后的完整检查 290 个文件里只有一处测试按旧回执形状读取（第五回合修好），前端 87 个文件 1,037 项通过、重建的产物与提交一致；第五回合合并后，该文件与文档卫生、首次安装 32 项通过。旧的两条截断产物经 Git 推导照常验收与回收，由测试覆盖；没有在日常看板的副本上演练（这一批不再改存储形式），安装前的演练随 0.47.0 一起做。
- **消耗：** 五个回合输入 6,631 万（命中缓存 6,559 万），输出 18.5 万；独立审查输入 964 万（几乎全部命中缓存），输出 5.2 万。
