## 独立审查（2026-10-14）

开发者定了 Lead 先行、要求不因此返工之后，整合 Host 请 claude / anthropic / claude-opus-5-5 / high 独立审了这份计划（微任务「第 3 步计划的独立审查」，只写了[审查](../design/router-planes-and-lead-plan-review.md)一份文件，原样取进整合分支）。它是新看板上的第一个微任务。它的发现是线索；整合 Host 核对过的三条：Router 调用的预算与 Worker 的硬时限共用 `timeoutSeconds`，Router 的切换认终止原因 `deadline`；四个 harness 都已经声明了“放开”一档；协助任务的表 `workflow_children` 的批准命令一列不能为空、状态是协助任务的取值，名下的微任务不能直接塞进去。据此计划开头加了“Lead 先行的顺序”一节。消耗：输入约 565 万 token（几乎都是缓存命中），输出 5.4 万，约 10 分钟。

## 预期时长取代 Worker 的硬时限（2026-10-14）

Lead 主线的第一步。微任务「预期时长取代 Worker 的硬时限」（codex / openai / gpt-6.1-sol / high）分三个回合交付，合并为 `36408448`。第二回合是 Host 的提示词漏了 `tests/probes`：四个探针还用着旧字段，Host 补了写入范围让它改；第三回合是打回：第二回合改了 Router 探针的字段，钉着它的单元测试没跟上，完整检查因此不过。

- 改了什么：微任务与命令执行的 `timeoutSeconds` 改为 `expectedSeconds`，1 到 86400 秒，默认 1800，到点不停止任何东西，没有“不设预期”的写法；旧字段被拒绝并提示更名。Worker 不再到点停掉微任务与命令。只有 Router 调用保留硬预算，换成它自己的字段 `routerBudgetSeconds`（取自 Router 设置的预算档，加上停机的余量），到点照旧停下，终止原因 `deadline` 从此只表示 Router 的预算用完，黑板拒绝把它记在别的执行上。预期时长记在任务与每个回合上；`tasks` 表里两种时长各占一列，行按种类只填其中一个，约束写在表上。
- 存储：这是挪基点之后第一次改存储形式，开始了从基点（schema 19）到 schema 20 的显式升级（`blackboard/store/upgrade.py`）。存量里的旧字段在任务、回合、微任务的提交记录、路由请求与命令的回执里换算；`timeoutSeconds: 0` 换成默认的 1800；不是 Router 调用的执行上旧的 `deadline` 清掉，因为它的含义已经变了。
- Host 核对：读了源码的差异与升级模块；完整检查 234 个文件里 233 个通过，失败的那一个就是上面打回的测试，修好后 Router 那一组 517 项通过；前端全量 1,091 项、浏览器检查 96 项通过；在副本上把三处新的判断各改坏一次（Router 预算不再到点停、`deadline` 不再只留给 Router、旧字段不再被拒），测试都失败；真实进程的升级：空的主目录里装 0.35.0、放进一个带 `timeoutSeconds: 900` 的已结束微任务，再装候选，升到 schema 20 之后这个微任务读出来是 `expectedSeconds: 900`，没有残留旧字段，备份已校验。
- 照实写的：清掉旧 `deadline` 丢掉了“当年被 Worker 的时限停下”这一事实；日常看板装上 0.35.0 才几小时，这类记录可能一条都没有。终止原因在有序收尾那一步（11）重新定全时，再看要不要给它一个如实的取值。
- 消耗：三个回合合计输入约 1,174 万 token 以上（第一回合 1,174 万，其中 1,151 万是缓存命中），输出 4.2 万以上；后两回合见看板。
