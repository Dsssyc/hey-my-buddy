# 第 3 步（Router 的几个面与 Lead）的验收记录

整合 Host 写。第 3 步是到首次发版为止的顺序里的第 3 条（[待办](../design/backlog.md)开头）。

## 执行计划（2026-10-14）

微任务「第 3 步的执行计划：Router 与 Lead」（codex / openai / gpt-6.1-sol / high）只写了[计划](../design/router-planes-and-lead-plan.md)一份文件，在 0.35.0 安装之前交回，原样取进整合分支（只取这一个文件，不合并它基点上的草稿提交）。它按源码清点了 ADR-021 的各模块、ADR-022 与 ADR-026 的各条决定，把余下的工作拆成 45 个微任务，到 Lead 可用的最短一条路是 16 个。整合 Host 读了全文。消耗：输入约 659 万 token（其中 639 万是缓存命中），输出 5.2 万。

计划写得很挤，满篇缩写，是整合 Host 在提示词里给的字数上限造成的。

## 独立审查（2026-10-14）

开发者定了 Lead 先行、要求不因此返工之后，整合 Host 请 claude / anthropic / claude-opus-5-5 / high 独立审了这份计划（微任务「第 3 步计划的独立审查」，只写了[审查](../design/router-planes-and-lead-plan-review.md)一份文件，原样取进整合分支）。它是新看板上的第一个微任务。它的发现是线索；整合 Host 核对过的三条：Router 调用的预算与 Worker 的硬时限共用 `timeoutSeconds`，Router 的切换认终止原因 `deadline`；四个 harness 都已经声明了“放开”一档；协助任务的表 `workflow_children` 的批准命令一列不能为空、状态是协助任务的取值，名下的微任务不能直接塞进去。据此计划开头加了“Lead 先行的顺序”一节。消耗：输入约 565 万 token（几乎都是缓存命中），输出 5.4 万，约 10 分钟。
