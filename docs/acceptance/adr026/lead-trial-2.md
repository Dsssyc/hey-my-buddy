- 宏任务是“控制台的小批次”，Lead 是 `codex / openai / gpt-6.1-sol / high`（Codex CLI 0.162.1），基点 `31a2184f`。

  4. 名下微任务的委派方显示 Lead。

## Lead 走过的路

这是试跑要看的部分。

- **凭据。** 角色说明给出这次执行的凭据文件，Lead 每次调用启动器都设了 `HMB_AGENT_CREDENTIAL_FILE`。两次提交都成了名下的微任务：没有 `hostId`，发起者记为 Lead，看板上没有再出现不带凭据的提交。
- **叫醒。** 名下微任务交回与失败都把 Lead 叫醒，在原生会话里续上；新的执行凭据随角色说明到达。
- **范围修订与打回。** 预览那个微任务第一回合失败之后，Lead 先修订了它的写入范围，再用 `continue` 打回，第二回合交回。
- **验收与整合。** Lead 把名下产物的差异合进自己的检出，以实际的提交作为验收的目标，四次验收都核实通过。
- **名下 4 个微任务，都经路由：**

  | 微任务 | buddy | 打回 |
  | --- | --- | --- |
  | A 标识、命令执行、委派方 | Codex CLI `gpt-6.1-sol / high` | 0 |
  | B 预览的 Lead 场景 | Codex CLI `gpt-6.1-sol / max` | 1 |
  | C 测试里的类型错误 | DSH CLI `deepseek-flash / max` | 0 |
  | D Host 打回的那一处 | ZCode CLI `GLM-5.3 / max` | 1 |

  1. 06:19Z Lead 停下请示。已验收的 A 在测试里留下两处 TS2352：`npm test` 不做类型检查，Lead 验收 A 之前没跑 `typecheck`。已验收的微任务不能再打回，任务说明又不许 Lead 自己改代码。Host 答复：另提交名下的返修微任务（C）；以后验收改了控制台的微任务之前，先跑 `typecheck`。
  2. Host 验收时发现第 2 项只做了一半，打回给 Lead，Lead 另提交 D 修好。命令执行的“记录细节”里仍显示 `undefined · undefined / undefined`，因为看板给命令执行存的 buddy 是 `{"adapter": "command"}`。

## 发现的问题

都已记进待办：

- **Codex 回合被判失败。** B 第一回合约 39 分钟，Codex 正常退出，产品因为同一回合里出现两条最终回答而判它失败。
- **失败回合的原生证据被删掉了。** 回收检出时一并删除；Lead 自己存下了 `get` 与 `result` 的原始回执。
- **时间轴刻度挤在一起。** 时间轴跨好几天时刻度挤成一团。这是新的预览场景照出来的旧问题。
- **预览还缺一个场景。** 合成预览里还没有由 Lead 发起的停止。Host 当初在待办里写的“Lead 的停止”含糊，Lead 把它做成了停止宏任务时的确认范围。
- **buddy 一栏有两种形状。** `workflow_runs.buddy_json` 有时存 buddy，有时存适配器约束。

Lead 自己的教训都写在说明文件里：

- 验收控制台的微任务之前先跑 `typecheck`；
- 已验收的微任务晚发现缺陷，另提交返修微任务；
- 续做之后要用 `get` 给出的检出路径，不按工作区标识去猜。
