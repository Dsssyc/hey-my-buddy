# 升级到 C-Two 0.10.0：Host 验收

2026-10-30。微任务 `045309c0`（“采用 C-Two 0.10.0”，Codex CLI gpt-6.1-sol / max），输出 `e7fb1130`，合入整合分支 `4e23430a`，在宏任务“采用 C-Two 0.10.0”里。0.10.0 与 0.9.x 不互通，所以这是契约变化；它随还没安装的中间版本 0.58.0 一起装，版本号不再变。没有安装。

## 交付了什么

- 依赖钉到 `c-two==0.10.0`。锁里本项目支持的六个平台都有 cp312 的 wheel，没有要从源码构建的，没有 `fastdb4py`。
- 契约变化的安装在每次起服务之前重建私有的 IPC 根 `state/ipc`，向前起新服务、有备份的回退与有备份的恢复三处都是。原因：0.10.0 的 Unix 命名空间升到格式 3，自定的根跨格式两个方向都起不来，而 C-Two 不公开格式号。
  - 重建之前，空闲在持着属主锁的同一段里、对活着的板子证明；证明不了就停在 recovery-required，不覆盖、不删根。
  - 切换开始之前就中止的两条路径保留原来的根，因为抢先接入的执行可能还在用它。
  - 删除只经状态目录的描述符删 `ipc` 本身，拒绝链接与不私有的目录。Windows 没有这个根。
- 冷启动预检改用公开的 `cc.Runtime()`，源码里不再导入 `c_two._native`。启动失败时报启动错误本身，沙箱拒绝绑定仍是 `LAUNCH_ACCESS_DENIED`。关停完成就删掉这个一次性的探针目录；只有关停没完成时才保留目录，报 `LAUNCH_IO_ERROR`。
- 执行端点的描述改用 `cc.server_credential()` 给出的凭据，去掉了轮询 `inspect_endpoint` 的循环。Windows 上描述第一次带上内核管理的凭据；描述只有一种形式，空凭据的读法删除。
- `local_rpc_error` 带上 C-Two 的三个新字段：`endpoint_unverified_reason`、`local_protocol_version`、`peer_protocol_version`。

## 核对

- **先行实测。** 探针在 macOS 上由 Host 跑，在 Windows 11 上由微任务 `333b9dd7` 跑，Host 读过原始输出。
  - 本项目用到的全部 C-Two 调用在 0.10.0 上照常。
  - `cc.Runtime()` 的预检干净；`server_credential()` 与检查得到的凭据相同，Windows 上是 schema 1 的命名管道凭据。
  - 0.9.0 与 0.10.0 两个方向混用都在约 40 毫秒内报 `early eof`，两个平台一样。
  - 自定的根跨格式两个方向都起不来。
  - 格式 3 的标记不再存设备号；标记被改动时，报 `coordinator-replaced`。
- **审查。**
  - Host 读完差异，同时请 Opus 独立审查了一次（`763cec7f`，Claude Code CLI claude-opus-5-5 / high，只读）。消耗：输入约 397 万 token，几乎全部命中缓存；输出约 3.9 万。审查方没有 Bash，读不到 C-Two 的发布说明，审的是候选的完整源码。
  - 双方都指出两处问题：预检在 `finally` 里抛错，盖掉了启动错误，每被拒一次还会留下一个探针目录；恢复与回退都先用备份覆盖、再证明空闲，证明的其实是备份。退回原微任务修好，另外把空凭据的读法也删掉了。
  - Host 实测过启动被拒之后的关停结果：`completed=true`，`runtime_barrier_error` 里是同一个权限错误，目录是空的。
  - 审查的其余发现：回退时删根持续失败会停在 recovery-required，记入待办；三个新字段的名字已在真实的 0.10.0 上核对。
- **Windows。**
  - 微任务 `703ee07b` 在测试机上跑 Python 全套：356 个文件里 342 个通过。
  - 对照微任务 `3b806dae` 在升级之前的 `a9ce8e3d` 上逐个跑了失败的 13 个文件：12 个以相同的首条错误失败，是此前就有的测试欠账，记入待办。
  - 剩下的 `install/test_backup.py` 在基线上通过、在候选上两次失败（WinError 32）。那个测试用 sqlite3 的 `with` 语句开连接而不关闭，路径不经过 C-Two。
- **完整检查。** 在合入后的 `4e23430a` 上以单进程跑：Python 356 个文件、5,321 项（跳过 29 项），前端 1,193 项，全部通过。
- **安装演练。** 在 `f4d94497` 上跑，空 HOME，经启动器，起真实的私有服务。
  - 从 0.57.2 起三次：
    - 正常一次：7 秒装好，schema 31 → 32，IPC 根的标记从 41 字节变成 33 字节；
    - 新服务起不来一次：整体回退；
    - 新服务起来后数据被改动一次：整体回退。
    - 后两次回退之后，旧服务都在重建后的旧格式根上起来。
  - 从 0.54.1 下限起两次，新黑板与下限样板各一次：链跑到 32，IPC 根重建成格式 3，完整性与外键检查都通过。
  - 五次都没有留下进程。

## 验证的边界

- 安装演练只在 macOS 上跑过；Windows 上只跑了 Python 全套与基线对照，没有跑安装演练。
- C-Two 0.10.0 在 Windows 2025 的 CI 上有一个关停的偶发失败：零期限观察退休结果时可能撞上锁竞争，C-Two 那边还在查。本项目的 C-Two 调用都不用零期限，默认 30 秒，预检 20 秒。安装等 C-Two 确认原因之后再定。（后来：C-Two 0.10.1 找到原因并修好，本项目随之采用，见[那份记录](c-two-0101.md)。）
- 带版本号的协议不一致报错，要等 C-Two 出了更晚的 IPC 版本才能实测。
