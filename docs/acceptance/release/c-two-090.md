# 升级到 C-Two 0.9.0：Host 验收

2026-10-25。微任务 `b07d11d1`，输出 `78083304`，合入整合分支 `14708dd5`。开发者同日定在首次发版之前升级：0.53.0 本来就改了契约，C-Two 的 IPC 协议变化随它一起，不再多动一次中间版本号。没有安装。

## 交付了什么

- 依赖钉到 `c-two==0.9.0`，锁文件里只有 C-Two 一条变化。
- 服务的生命周期锁被占用而服务不回答时，提示不再猜“服务可能在同一用户的另一次 Windows 登录里”：0.9.0 的 Windows IPC 按用户定作用域，同一用户的各次登录推出同一个端点。其余对无响应服务的判断照旧。
- 新增一个测试：0.9.0 在核对服务端身份不符时拒绝连接，这种拒绝没有操作系统错误码；它不会被当成服务已停，也不会再起一个服务。

## 核对

- 先于升级的实测（Host 自己做，脚本 `tmp/ctwo-090/probe090.py`，C-Two 单独运行，不含本项目代码）：
  - macOS 上，本项目用到的全部 C-Two 调用在 0.9.0 下都正常：注册与地址、取端点凭据及其读写与核对、带时限的连接与调用、连接事件、服务被杀后回收端点、连不上时的 `CoreError`、启动超时。
  - Windows 11 上（另派 Worker `d8a96fd9`）同一个探针也都正常，端点凭据照旧是“不适用”；两次独立的 SSH 登录（登录 SID 不同、同在会话 0）一边起服务、另一边调用成功，0.8.2 时这一步失败。
- 0.8.2 与 0.9.0 混用：两个方向都快速失败，macOS 上报 `early eof`，Windows 上报找不到文件（新旧版本的管道名不同），都说不出是版本不同。本项目的安装用各运行时自己的客户端连自己的服务，碰不到混用。
- Host 读完差异。Worker 在最终源码上的完整检查：323 个文件 4,940 项（跳过 11），前端 1,123 项，退出 0；合并之后 Host 跑了传输与协议相关的 6 个文件，102 项通过。

## 验证的边界

- 服务端身份核对（同一用户、完整性不低于 Medium）只依据 C-Two 的发布说明，本项目没有做这类实验。
- 跨登录只测了两次 SSH 登录，没测远程桌面或控制台登录与 SSH 之间。
