## 完整检查纳入前端检查（`80c5cb68`，输出 `f17267f2`）

- 不带路径的完整检查跑前端的 `tsc --noEmit` 与 `vitest run`，作为运行器线程池里的一个作业排在最前；Vitest 只用一个 worker，`--jobs` 仍是整轮的并行数。找不到 Node 或前端依赖时这一项失败，说明先运行 `npm --prefix apps/console ci`，不跳过。只给路径的聚焦运行不跑它。过期的 `SLOWEST_FILES_FIRST` 与它的排序、测试一并删掉。
- Host 核对：读完差异；在副本里放进一个类型错误，运行器收进了 `TS2322` 并退出 1；放进一个会失败的前端测试，这一项报 1 个失败并退出 1。Worker 在最终源码上的完整检查用时 569 秒，其中前端一项 199 秒；合并后 Host 的完整检查：323 个文件、4,939 项，前端 1,123 项，退出 0。

## 并行派发的偶发超时（`cf537562`，输出 `7d1efc04`）

- 没能复现：机器负载在 20 到 224 之间、另加 32 个占满 CPU 的进程时，27 次执行启动都在 0.6–3.3 秒。60 秒的超时因此不是“忙时偏慢”，是原因未知的停滞；失败信息里的服务日志正常时就是空的，进度记在事件与执行自己的日志里。
- 改动只在测试：等执行启动或完成超时时，失败信息带上任务与执行的状态、问题、最近的事件、执行日志的末尾与启动文件；收集只读、有界，自己出错时不掩盖原来的失败；时限不动，不加重试。Worker 用注入核对过（让命令在写启动标记之前失败），这些事实出现在真实的失败信息里。Host 跑了这个文件：11 项通过。
- 顺带项：测试里的注释用了内部代号“R2”，下一次改这个文件时改成说明本身。
