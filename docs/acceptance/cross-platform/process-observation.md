# 进程观察：读不到的同账户进程（2026-10-26）

微任务“进程观察：读不到的进程”（run `9f52cd33`，Codex CLI 的 `gpt-6.1-sol / max`），基点 `92a75e2f`，四轮，最终产物 `bedb1a93`，合入整合分支 `cbae2275`。依据开发者 2026-10-26 定的三条（[跨系统适配计划](../../design/cross-platform/plan.md)“开发者已定的”）：读失败按身份再读一次；再读后系统仍拒绝读路径的记下身份、不挡判断；其余读不到照旧未知。

## 改了什么

`process_observation.py`：读一个同账户进程失败时，经 psutil 自己的身份比较（单调创建时间）确认仍是同一个进程再读一次；cwd、映射、描述符各读各的，再读后仍是 `AccessDenied`（Linux 描述符目录的 `PermissionError` 同样算）就记成结构化的被拒记录（pid、创建时间、名字、读取项、错误），交给调用方。存储回收把每个被拒身份每次计划写一行到服务的标准错误，`reasons` 只留原因代码；检查运行器把它们放进清场的 notes 并打印。命令行、身份、进程组与 Job 的观察照旧，读不到就是未知。顺带：测试支持的停止确认按服务那一代记。

## 核对

- 读完四轮差异。第一轮把被拒记录放进了存储计划的 `reasons`（任务书措辞所致），打回。
- Opus 子代理独立审查第一轮（240,442 tokens，33 次工具调用，约 19 分钟）：身份复核比的是墙钟换算的创建时间，校时会把活进程当成已消失（不安全的方向）；15 个字符以上的进程名让 macOS 上的 `SystemError` 逃出；Linux 描述符走不到例外。Host 在 psutil 7.2.2 的源码里核实前两条，三条打回第三轮修好。
- 变异（候选上各跑新测试）：放宽成所有路径错误、命令行读不到不再算未知、再读前不核对身份、身份改回墙钟比较，四处都被抓住；未改动时通过。
- 持续集成第 12 轮（`c5395d67`）：Ubuntu 四片全部通过（此前 326 个文件里 30 个失败），macOS、前端、浏览器通过；日志查清 Ubuntu 运行机上内核不让看的同账户进程是用户的 `systemd` 与 `(sd-pam)`。同一轮 Windows 多出这一批新测试的一处失败（全局改了 `os.name`），第四轮改为在 Windows 上跳过。
- 合入后的整合分支上跑受影响的 7 个文件，183 条测试通过。

## 边界

第四轮之后没有再推持续集成，Windows 上这一批的测试结果随下一次推送核对。macOS 上“一时读不到、再读成功”的情形 Worker 没能在本机复现，由回归测试证明；清场“0 个进程、状态未知”的偶发失败是否因此消失，要看之后的完整检查与持续集成。
