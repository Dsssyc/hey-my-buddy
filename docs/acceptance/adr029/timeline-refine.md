# 时间轴精简：在已定规则之内去掉多余的记号（2026-10-27）

微任务“时间轴精简”（run `630b0adf`，经路由，Router 选了 Codex CLI 的 `gpt-6.1-sol / max`），基点 `67858e3d`，三轮，产物 `05b83ca3` 与 `4be0855a`，合入整合分支 `fc5e2cab` 与 `c38b37fe`。第二轮没有改动，只是因为要改的预览文件在写入范围之外而停下来请求扩大范围。

起因：开发者觉得宏任务时间轴的图标太多太乱。Host 先后画了三版从头重画的草图，每一版都推翻了已定的东西：每段带 harness 标记、有名字的事件点、圈里的钩与叉、等人时的橙色菱形、斜纹折叠。开发者指出“这波大改直接导致所有之前的设计全推翻了”之后，Host 改为先读 `docs/reference/console.md` 里已定的规则，只针对截图里的具体毛病提出修改，逐条由开发者定下。

## 改了什么

1. **身份标识只画在需要区分的段上。** 只有一段的 harness、provider、model 与行名上的 buddy 不同（例如交接之后），条上才画 harness 标记和型号名。执行记录不带 effort，所以不比较它。悬停与聚焦照旧给出每一段记录下的身份。
2. **标记与红叉不越出条外。** 标记放得下就画在条内，放不下画在条旁，两边都没空就不画。失败的条比红叉还窄时，红叉画在条尾之后。条的长度照旧是真实长度。
3. **Host 的一次动作只画一个记号。**
   - 送回重做在同一次写入里依次记下 `reject` 与 `continue`，只画一个“打回”。服务侧测试 `test_timeline_action_pairing.py` 钉住两者在同一事务里相邻，并验证出错时两者一起回滚。
   - 验收的圈钩带上它所记录的整合。
   - 成簇的规则不变。
4. **空闲斜纹更稀、更淡。** 宽度仍是 54 像素，斜纹周期 14 像素、不透明度 0.4，图例与时间轴共用同一个组件。
5. **等待的菱形保留。** 等 Host 或 Lead 的那一段，结束后起点的橙色实心菱形照旧留着（开发者定）；仍在等的部分照旧是一直画到“现在”的橙色虚线。

## 核对

- **读过差异：** 前端的事件配对、轨道与图例，以及那项服务侧测试。
- **真实数据的像素：**
  - 从日常看板只读取得宏任务“发版准备”的时间轴：22 个微任务、104 段、94 个事件，经 `macro-task-timeline` 读出，不复制看板。
  - 把它替换进合成预览的时间轴读数，并把响应的时间设成读出的时刻，分别用改动前（`67858e3d`）与改动后（`c38b37fe`）的资源，在深浅两种主题下各画一遍。
  - 两边都没有解析错误。条上的身份标识从 43 个降到 0 个：这个宏任务的每一段都由各自行名上的 buddy 执行。成簇记号从 11 个降到 7 个，剩下的都是时间挨得近的几次独立的 Host 动作，例如相隔 20 分钟的两次打回、先取消后结论、连续几次续接。
- **第一轮在真实数据上没有生效，责任在 Host 的任务书。**
  - 任务书要求按包含 effort 的完整身份比较，而真实读出里的执行段都没有 effort（尝试记录不存这一项），于是每一段都算作“与行名不同”，标识照旧画；剩下的 15 个只是因为其余的放不下才被省掉了。
  - 合成预览给执行段带了 effort，所以实现方的检查没有暴露这一点。
  - 第三轮改为比较 harness、provider、model。前端夹具与合成预览里的执行段改成和真实读出一样不带 effort，预览还会拒绝凭空带 effort 的执行段。
- **更正：** Host 在设计阶段说过“这个宏任务会少掉 29 个记号”，这个数把从来不画的 `integrate` 事件也算了进去。配对实际少掉的是并入“打回”的 11 个续接记号。
- **第四轮：CI 上的浏览器检查。**
  - CI 第 26 轮（`cc8731f8`）里，`polish.check.ts` 的“单击打开微任务、悬停框出片段”在 390 宽下超时；重跑一次又失败，浅色、深色两个组合都挂了。在 macOS 上用同一份构建跑 60 遍全过。
  - 打回之后，实现方确认了原因，在 macOS 和 Linux 上都复现出来：预览服务的时间随它运行的时长往前走，时间轴的拟合比例跟着变；到了 390 宽，检查悬停的执行组中心点会落在画在条上的问询菱形上。问询按设计就压在条的上方，所以产品没有错，错的是检查选的那个悬停点。
  - 第四轮只改检查：悬停执行条的上半部，并保留 Playwright 对遮挡的原生检查；另加一项回归，把时钟往后拨 140 秒，核对条和问询都能悬停。此外，CI 上浏览器检查失败时会把 trace 留在已上传的日志里。合入 `65502f34`。
- **实现方的检查：** typecheck、前端 1,135 项、浏览器检查 668 项，两份 Python 文件 16 项，全部通过。0.54.1 安装之前，Host 在最终源码上跑一次完整检查，其中包括前端全量与打包资源的核对；CI 另跑浏览器检查。
