# 微任务详情：步骤条与概述联动（Host 验收）

2026-10-27。微任务“步骤条与概述联动”（run `4b557d17`，经路由交给 Codex CLI 的 `gpt-6.1-sol / max`），依据[执行计划](../../design/adr029/detail-strip-linking-plan.md)。基点 `725c6c11`，封存提交 `0ec48334`，合入整合分支 `0f978447`。

## 起因

开发者在日常控制台上发现：在详情顶部的步骤条上点问询标记，概述不会聚焦到对应的问询框。Host 在日常控制台上复现：点了只会切到那条问询所在的回合，地址只记步骤号，问询框既不滚动也不高亮。原因是步骤条只能选整个步骤；“聚焦某一项”的机制已经有，但只在从宏任务时间轴点问询进来时才用到。

## 改了什么

- 步骤条上代表步骤内部某一项的标记，都成了单独的目标：问询、等待、验收的结算与验收事件。点击它（或在它上面按回车、空格），会选中它所在的步骤，并聚焦这一项；概述把对应的条目滚进视野，用“选中”的颜色框出来。
- 反过来，鼠标停在概述里一个在步骤条上有标记的条目上，或者键盘聚焦到它时，步骤条上它的标记会亮；点条目上的时间，就聚焦这一项。
- 聚焦的一项仍然只有一个状态，就是原来的 `origin`。停留时的联动用 CSS 的 `:has()` 实现，没有第二个状态；问询专用的高亮写法删掉了。
- 等待在概述里补了一行，这样步骤条上的等待片段也有地方可以聚焦。
