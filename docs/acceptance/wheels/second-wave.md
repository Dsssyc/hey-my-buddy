# 用成熟库替换自造的轮子：第二波的验收记录

2026-10-24，整合 Host。宏任务“用成熟库替换自造的轮子”的第二波：C 的前后端两半与 D。第一波见[第一波的记录](first-wave.md)。C2 与 D 随 0.52.1 装上。

## C1：后端的请求模型（只做了计划）

只读微任务 `a316202a`（输入 783.8 万 token，其中 764.0 万命中缓存；输出 6.9 万）写了执行计划：请求改用 Pydantic 模型声明，`help` 从模型推出，代替 `cli/cli_help.py` 读语法树的两千多行。计划列了 55 个入口、6 批，先录下现有回复作为对照。还没有实现：计划第 4 节问的是现有回复里的怪异之处逐字节保留，还是作为契约变化一并简化，待开发者定。

## C2：控制台的解析改用 Zod

- **微任务：** `6fb08294`，一个回合（输入 457.7 万 token，其中 443.3 万命中缓存；输出 5.6 万），合入 `2ceceb7f`。控制台读取接口的解析函数改为用 Zod 声明结构，类型由 `z.infer` 推出，不再手写 `typeof` 与数组检查和第二套类型；每个解析函数接受与拒绝的东西不变（原来拒绝未知字段的用严格对象，其余用宽松对象，不做类型转换，原有的不一致照旧保留）。产品源码净少 324 行。
- **Worker 的核对：** 类型检查、前端 1,121 项与构建通过；8,476 个输入在新旧实现上结果相同。Worker 的沙箱挡住了两组 Python 检查。
- **Host 的核对：**
  - 用日常控制台只读接口抓下的真实回复（快照、5 页宏任务列表、82 条时间线、运行时版本、存储计划，共 94 次读取）驱动新旧两套 API 客户端，结果逐一相同，两边都没有拒收；
  - 合并树上前端全量 95 个文件、1,121 项，浏览器检查 645 项通过，Host 在合成预览上看过浅色与深色的像素；
  - 在沙箱外补跑 `cli.test_host_preview`、`tests/python/console/` 与 `install.test_distribution`，共 13 个文件、179 项通过。

## D：标准库与内部复用

- **微任务：** `7538735f`，两个回合，合入 `53dabefb`。第一回合停在边界上：Codex 的检出写沙箱在 macOS 上读不到启动会话，也列不全进程，检查运行器收不了尾，冷启动的测试失败；Host 以 `full` 权限续做，第二回合跑通。两个回合合计输入 754.0 万 token（其中 731.5 万命中缓存），输出 4.1 万。
- **做了的：**
  - 原生时间戳的 UTC 格式化收成根包里的一个函数，只合并输出逐字节相同的几处；格式或精度不同的留原样，存储的值不变；
  - 进程内把标准输出与标准错误设成 UTF-8 的做法收成一个函数，UTF-8 截断也只留一份，都放在根包；必须在导入产品包之前运行的引导代码与子进程脚本保持标准库写法；
  - 没有产品调用者的 `validate_private_dir` 删去；
  - 顺带：`OwnedJob.close` 在 `CloseHandle` 失败时也清掉句柄，只有关闭成功才记为 Job 已空；FileRenameInfoEx 的 kernel32 入口在导入时加载；Toolhelp 的线程枚举与管道期限改为按行为测试。
- **没做的：** S6 的 `_shell_quoted` 留原样：`shlex.quote` 对不含特殊字符的词不加引号，单引号的转义写法也不同，输出与现在不一致（Host 逐例核过），任务书要求输出完全相同。F5 已由更早的一批做掉，`installation_lock` 已经经 `private_dirs.open_lock_fd` 打开。
- **Host 的核对：** 读完差异；候选 `53dabefb` 上完整检查 317 个文件、4,824 项，退出 0。
- **Windows 11 x64：** 另派的 Worker 复跑（`ec7f885d`，输入 464.4 万 token，其中 446.1 万命中缓存；输出 5.6 万），候选 `53dabefb` 对基线 `2ceceb7f` 跑 25 个受影响的文件。Host 自己解析了逐个文件的原始输出：候选 380 项、基线 373 项，候选失败而基线通过的 0 项，反过来的 0 项，两边都失败的 76 项（Windows 上已有的失败）；候选新增的 7 项全部通过。真机核对：`CloseHandle` 失败后候选不留句柄、不再查询调用者自己的 Job，基线留下归零的句柄并查到 1 个活动进程；200 次并发发布两边都成功；私有服务的中文标准输出与标准错误两边都是严格的 UTF-8。
- D 第一回合的 `report.json`（逐项的实施与跳过原因、各处时间格式与落点）留在 Worker 的检出里，验收收回检出时一并删除了，Host 没有先拷出；上面“没做的”两条是 Host 自己核对的结论。

## 没有验证的

- C2 没有在 Windows 上复跑：它只改控制台的前端，前端与浏览器检查在 macOS 上跑过。
