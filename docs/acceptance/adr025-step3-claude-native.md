# ADR-025 第三步微任务 3-B1：Claude Code 原生运行主体验收记录

基线 `5d31114b3a17e71c6714fabe026aa1598db598a4`；独立受管 worktree，唯一可写范围为 `src/hey_my_buddy/buddy/harnesses/claude`、`tests/python/buddy/harnesses/claude` 与本记录两份验收文件。本微任务只交付可独立调用的原生模块 `claude/native_run.py`（`run` 与 `run_discovery`），不注册运行接缝、不删除旧入口、不迁移角色接线测试；它们属于本线后续微任务，本项不构成整条线完成。未新增公共类或公共字段；公共值、角色模块、注册表、共享测试、依赖与打包配置未修改。

## 交付与界面

新模块 `src/hey_my_buddy/buddy/harnesses/claude/native_run.py` 共 956 行，实现 `run(request, *, observer, services, cancelled) -> RunResult` 与 `run_discovery(*, cwd, invocation_root, native_root, timeout_seconds, cancelled) -> dict`（返回目录收据形状，与已注册发现的调用方约定一致）。组织函数 `run` 本体 97 行（含中断闭包与异常映射），未复制 ZCode 的长 run；按阶段拆分为：`_prepare`（请求门与冻结启动决策，54 行）、`_spawn_native`/`_probe_version`（受管原生进程，29+15 行）、`_initialize`/`_check_catalog`（握手与目录核对，15+13 行）、`_TurnCollector`（工具投影、回合证据、活动与角色观察者的活收集器）、`_send_and_settle`（Worker 与 read 共用的发送/等待/drain 原语，28 行）、`_check_terminal`（显式终态判据，30 行）、`_stop_native`（保守停止，20 行）、`_build_result`（事实组装，含逐包守卫与组装回退）。复用本 harness 既有协议与纯策略帮助（`Connection`、`TurnEvidence`、`ReadOnlyToolEvidence`、`execution_args`、`sandbox_settings`、`runner._catalog/_interrupt/_latest_rejected/execution_deadline`），不调用旧 `runner._run` 或旧 fast/review 完整运行分支。

请求门如实保持能力事实：`tool_scope="none"` 拒绝（无 fast 能力）、`services` 非 None 或 `session_services` 非空拒绝（无会话内服务）、`continuation.mode="native-session"` 拒绝（无原生续接）、initial 携带前驱拒绝、reconstructed 必须分配新 uuid4 会话；observer 只接受 continue/stop，correct 以 INVALID_ARGUMENT 拒绝（本 harness 的 -p 回合在 result 处结束，无纠正载体）。发现只做 initialize，不发用户消息，`--no-session-persistence`，不检查 settings policy（旧发现路径同样豁免），第三方 provider 拒绝仍适用。

## 事实保真

保留的既有事实：第三方 provider 覆盖拒绝与 isolated settings 策略门（执行前检查传入环境）；私有 `settings.json` 沙盒（`failIfUnavailable`、无未沙盒回退）；initialize 目录核对 provider/model/effort（`invalid-configuration`）与第一方账户核对（含缺失 tokenSource 的同可执行文件 auth status 读回）；用户消息边界（早于用户消息的模型输出先投影工具事实再拒绝）；显式成功判据（subtype 恰为 success 且 is_error 恰为 false，配额拒绝先分类）；背景任务沉降（终态闭集相等比较）；完整结构化 result/EOF（`drain_until_closed` 只认传输观察到的流结束）；额度与 token 用量（result usage 优先、按消息 id 去重的 assistant 回退、缓存计数不把未知当零）；观察模型集（有界集合非身份）与费用；`modelStarted` 仅从发送用户帧起算（basis `input-sent`），发现/握手不算模型开始；停止证据双确认，未确认即 unknown，ok 额外要求退出码 0；`resolved` 语义转为 requested/checked 分列（provider 基 `native-readback`、model/effort 基 `catalog-membership`，不声明不存在的 effort 回读）。

角色材料未移入驱动：无 HARNESS_PREAMBLE/ASSISTANCE_HINTS 拼接（输入全文来自 `request.input_text`）、无 `validate_outcome` 完成规则、无 `_attention_outcome` 改写（被拒权限请求以 `denied_interactions` 三元组加 `denied-interactions` 证据引用报告，原生事实部分存 `native-turn-facts` 证据供角色组装回合记录）。StructuredOutput 真实来源修正未做，属 3-C 独立微任务；本模块的工具投影维持现状（StructuredOutput 交付仍按现行投影计数），未在公共词汇表加任何按名豁免。

## 两项有依据的姿态决定（供 Host 在接线微任务确认）

其一，`config.execution_args` 的 MCP/Web/Agent 追加拒绝条件由"带 outputSchema"改为"read_only 且带 outputSchema"：统一界面下每个请求都带 schema，若维持旧条件，write 回合会被连带禁用 Agent/Task 子代理（行为回退）；改为按 scope 判定后，旧三路径（worker-write 无后缀、worker-read 无后缀、审阅带后缀）的现有测试结果逐一不变（`test_claude_config.py`、`test_claude.py` 全绿）。其二，read scope 统一采取审阅姿态：网络白名单清空（write 保留包注册表白名单）；旧 worker-read 与审阅在工具允许表上本就相同，差别只剩 MCP/Web 追加拒绝与会话级子代理硬拒，而两者都不在 READONLY_TOOLS 允许表内，实际能力不变。另在用户消息边界前加 20ms 有界停顿后二次排空（`_BOUNDARY_SETTLE_SECONDS`）：旧控制器的回合文件读取给了读线程同等裕量，进程内主体缺这段裕量会让与 initialize 响应同写的早输出帧越过边界；用户消息发出前不存在合法帧，故该停顿只会把更多前置输出正确标记，不会误拒。

## 公共接口缺口与无使用方内容

已按 Host 问询逐项回答（收据 `8552864f`）：① 原生 schema 完成有效性——驱动报 `schema_status="unknown"`（机制 `native-schema`，raw+parsed），旧 `parse_structured_output` 完成规则留在角色；现有读取方 `roles/run_execution._worker_result` 要求 `schema_status == "valid"`，公共投影下 claude Worker 回合现必被拒，需 Host 定夺（接受该载体配角色侧 `validate_outcome`，或定义驱动可设的核验依据）。② 被拒权限——`denied_interactions` 三元组加两份证据引用承载旧 controllerAttention 所需全部事实，读取方为角色 outcome/记录组装。③ 配额窗口——`RunResult` 无非失败配额观察字段，存 `native-observations` 证据；旧读取方为 AdapterOutcome 的 `quota`。④ 原生额外用量事实——`sessionModel`/`observedModels`/`totalCostUsd`/`unsupportedNativeRequests` 同存该证据；旧读取方为适配器结果相应键。⑤ 活动文件位置——请求无该字段，zcode 经 services 对象携带，claude 无服务故 sidecar 落 `private_state.invocation_root/activity.json`；读取方为 Worker 运行时活动转报。⑥ read 工具预算——经 observer facts 的累计 `toolCalls` 由角色 stop 执行，无需接口变更。

本模块填写的 RunResult 诚实留空项（非新增占位）：`unknown_events=None`（本 harness 投影不分类未知事件，observer facts 同样报 None 而非伪造 0）、`native_error=None`（无白名单原生失败归因来源）、completion 的 `call_id/receipt_ref/receipt_verified`（原生 schema 机制无回执）、value 的 `validation_basis/correction_count`（无纠正载体）。新模块自有类（`_Preparation`/`_Spawn`/`_RunState`/`_TurnCollector`）与全部字段均有生产读写方；`native-observations` 与 `native-turn-facts` 两类证据引用的接线期消费者属 3-B2 公共接线，登记如上。
