# Brief CLI output and the Claude Code wait flow: 0.13.0 candidate

## Scope and boundary

On 2026-09-26 the user asked a Claude Code Host session to continue the Codex thread `01a0c252-f073-7e13-9a5f-033260938176` after that thread ran out of Codex quota, and to fix the Host-side token overhead found in its analysis first. The user also chose background waiting for Claude Code Hosts and asked that the Codex waiting behavior stay unchanged. This change is added to the uninstalled 0.13.0 source candidate: the named C-Two contract, RPC responses and schema 11 are unchanged, and only the CLI printout, the skill and the owning references change. The daily board remains the installed 0.12.0 runtime.

## Evidence for the change

The interrupted thread's local rollouts were measured with their own `token_count` records. Over 3,173 model requests in its two latest segments, input averaged about 350,000 tokens per request, 98% of it cached; the 828,400-token window was compacted at roughly 600,000 tokens and restarted near 130,000. With cached input priced at a tenth of fresh input and output at six times fresh input (the current Codex rate-card ratio), re-reading the cached context was about 70% of the thread's cost, so every token a tool prints is paid again on each later request until the next compaction.

A complete governed lifecycle was then captured from the real in-process service over real temporary Git checkouts (a 2,400-character packet and a 1,900-character turn summary, `o200k_base` token counts). The pretty-printed outputs a Host reads for one delegation — `submit`, `await`, `get`, `integration-record`, `acknowledge`, `workspace-cleanup-plan` and `workspace-cleanup-apply` — totalled 39,962 tokens. The largest sources were duplicates and echoes: every governed mutation returned the whole governed view with the goal packet under `goal` and again inside the execution summary `task`; cleanup responses printed the same plan as `plan` and `cleanup`; `list` printed identical `runs` and `tasks` arrays; `status` carried the full runner payload; and the governed `await` envelope repeated its turn summary and artifacts at two levels.

## Implementation

`src/buddy/cli_views.py` projects each printed response; `cli.main` prints compact one-line JSON and strips the CLI-local `output` option before RPC. `"output":"full"` prints the unmodified response. The brief views keep every identifier a following command needs, the complete open boundary, conflicts, errors, nonzero truncation with counts, and the complete shutdown report whenever shutdown is not fully confirmed; they omit the caller's own packet and workspace intent, duplicates and history. [cli.md](../reference/cli.md#output-views) owns the per-command fields. `console` keeps its complete response and error envelopes are never projected.

The same lifecycle printed 5,852 tokens (−86%): `submit` 2,615→308, `await` 1,988→840, `get` 4,267→1,020, `integration-record` 6,122→916, `acknowledge` 6,110→911, cleanup plan 8,362→890 and apply 10,498→967. `list` with one task fell from 9,427 to 143 tokens, `status` from 4,693 to 683 and `result` from 6,617 to 1,480. `health`, `capabilities` and other unprojected responses only lose their indentation (about 30%).

The skill now states the brief output, asks packets to reference files rather than paste them, and starts verification from changed paths and patch statistics. Its new waiting section keeps the Codex foreground `await` unchanged and gives Claude Code one background `await` per running goal, whose exit notification arrives during the turn or wakes the idle session; [usage.md](../reference/usage.md#waiting-from-claude-code) owns that flow. The skill text shrank from 9,946 to 9,106 bytes despite the two new sections.

## Verification

New `tests/python/test_cli_views.py` drives the real `cli.main` against the in-process service and real Git worktrees: the local option never reaches RPC and an invalid value fails before it; a submit receipt names the control file with no token or packet; brief `get` keeps the revision, final artifact, output artifact, turn summary, workspace and scope while `output:"full"` equals the service view; integration, acknowledgement and cleanup receipts stay small and complete; `list`, `status`, `result` and `await` drop their duplicates; and unit checks keep unconfirmed shutdown, truncation counts and unknown receipt fields. The complete suite located every existing caller of a field the first projection had omitted; `taskId`, `createdAt` and `workerId` on execution views, `manifestSha256` on output artifacts, the governed `counts`, and the `artifacts`, `attemptId` and complete `resultMeta` on `result` were restored. Three integration tests that inspect deep evidence (nested execution summaries, the native-session and provenance payloads) now read it explicitly with `"output":"full"`, and one reads the acknowledgement verdict from the receipt.

The first complete run inside the Claude Code Host session exposed an environment fact rather than a regression: Claude Code exports `ANTHROPIC_BASE_URL` to its commands, and the Claude adapter correctly refuses that third-party override, so 14 Claude fixture tests failed identically on the unchanged base commit `5b59e75`. `buddy.checks` now removes the adapter's override variables from test subprocesses, and the [Claude reference](../reference/claude.md) records that a service cold-started from a Claude Code session cannot run Claude Workers. With the variable still set in the parent shell, the stripped environment passed all 43 `test_claude`/`test_claude_worker` tests.

The complete `uv run --frozen python -m buddy.checks` then passed: 1,112 Python tests in 985.5 seconds (2 skipped) and all 207 Node tests in 25 suites with no failures, cancellations or skips. No model, daily board or installed runtime was used; the daily board was only read to measure the Host outputs.
