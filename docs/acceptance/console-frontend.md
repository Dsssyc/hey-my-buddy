# 控制台前端重建：Host 的记录

Claude Code Host。依据 [ADR-029](../decisions/029-console-frontend-foundation.md) 与[执行计划](../design/console-frontend.md)。这条线由本 Host 主持并动手，本文按步骤记录做了什么、亲自核对了什么、没有核对什么。每一步之后由开发者看截图验收；本文写的是 Host 自己的核对，不是开发者的验收。

## F0 打底

2026-10-11。在分支 `socu/console-frontend` 上完成，等开发者看截图。没有合入集成分支，没有安装，日常运行时不受影响。

### 做了什么

- **样式与组件（`f6dfd59c`）。** 接入 Tailwind 4 与 shadcn。旧样式表放进一个层叠层，夹在 Tailwind 的基础样式与工具类之间：还没有迁的页面保持原样，新组件的工具类又压得过旧样式表里按元素写的规则。工具类直接读 `tokens.css` 里已有的语义变量，明暗两套不变。从 shadcn 4.21.4 取了九个基础组件：按钮、复选、对话框、输入、浮层、滚动区、选择、页签、提示。危险按钮的文字改用新增的 `--on-danger`，因为深色下的危险色是浅色，承不住白字。
- **外壳与 i18n（`a72f191b`）。** 顶栏、连接中断的提示与启动页换到新基础上，文字来自 react-i18next 的两份文案（中文与英文），每个页面一个命名空间。语言跟随浏览器的语言列表：第一个中文或英文的条目决定文字，它的完整标签决定日期与数字的写法，两者都没有时用英文；没有开关。时间一律 24 小时制。页签改名为 `任务`、`伙伴`、`设置`（`Tasks`、`Buddies`、`Settings`）。所显示快照的核对时间移进顶栏，当天的只写时刻，更早的带日期，原来顶栏下面的那一行取消。浏览器标题改为 `Hey my buddy`。新增一个按状态含义分四种色调的标签组件。旧样式表删去只有旧外壳用过的 35 行。
- **浏览器检查（`31045567`）。** `npm run test:browser` 先构建，再用 Playwright 在仓库已有的合成预览（`tests/probes/objective_console_preview.py`）上跑 `apps/console/browser/` 里的检查，中文与英文、宽 1440 与窄 390 各一遍。检查断言的是事实：每一项都在它的框内、两两不重叠、文字没有被裁掉、页面不横向滚动；页面报错或浏览器控制台出现错误也算失败，内容安全策略的拒绝正是在那里报告的。先写了两条：顶栏的几何，页签上数字的提示在悬停与键盘聚焦时出现并且留在窗口内。
- 页面内部还是旧的写法与旧的用语，只有中文；这是 F1 的工作。

- 浏览器检查 8 项通过（两条检查 × 两种语言 × 两种宽度），Chromium headless shell（Playwright 1.64.0），macOS。

## F1 第一步：打底改到设计上

2026-10-11，Host 自己做。分支 `socu/console-frontend`，没有合入整合分支，没有安装。

### 做了什么

- `tokens.css` 换成设计稿的那一套颜色，名字也用稿里的（纸、面、墨三档、线两档，进行中、等人接手、失败、记录，以及顶栏自己的几种）。Tailwind 的主题映射随之改写：生成的组件用的那组名字指向它，另加设计自己的一组。
- 旧样式表还在读的名字移到新文件 `legacy-tokens.css`，在旧样式表所在的那一层里引入，全部指向同一套颜色；只有按 buddy 着色与偏好这两组颜色在新设计里没有位置，仍带着自己的值。这个文件随旧样式表在 F3 删除。
- 圆角：控件与浮层 4px，标签 2px。
- 顶栏照稿重做：明暗两种主题下都是标志的墨色，标志换成顶栏自己的配色，当前页签下是一条绿线，等待 Host 的数目是浅橙底，右端只写时刻，它是什么时刻在悬停时与对读屏说明。

两处偏离了开发者看过的稿，原因都是对比度：最浅的一档文字在白底上只有 3.1 比 1，在纸色底上 2.8，改深到在它出现的每一种底色上都不低于 4.5（浅色 `#626D66`，深色 `#89928C`）；顶栏上的数目原来是橙底深字 3.8 比 1，改为浅橙底深字 6.8。静态稿的 `base.css` 同步改了，待开发者看过。

- 像素：在合成预览里截了 7 张，看了 5 张：任务页中文浅色与深色 1440、任务页中文浅色 390、Buddy 页英文深色 390、设置页中文浅色 1440。还没有迁的页面已经是新的配色。

## F1 第二步：Buddy 页的导航（B0 的第一部分）

### 做了什么

- Buddy 页有了自己的导航，照稿放在页面顶部并贯通左右：两个分区"目录"与"角色"，目录打开时下面是"模型"与"Harness"的切换。三个视图各有地址：`#buddies/models`、`#buddies/harness`、`#buddies/roles`，后面可以跟一个目标；`#buddies` 之下别的地址一律打开模型。原来的 `#buddies/router` 不再有效，没有留转向。
- 原来的全局状态条删除。哪里有事等用户处理，改成分区与表上的一个橙色圆点，悬停、键盘聚焦与读屏时说明是什么：没有指定 Router、Router 不可用、路由连续失败、Router 设置需要升级，或者某个 Harness 的额度接近上限。目录收起表的切换时，圆点落在"目录"上；顶栏的 `Buddy` 页签在没有未保存的修改时带同一个圆点。判断规则从状态条原样搬到 `src/buddies/attention.ts`，成了一个有单元测试的纯函数。

## F1 第三步：Buddy 页的模型一项（B1、B2 与 B0 余下的部分）

2026-10-11，Host 自己做。分支 `socu/console-frontend`，没有合入整合分支，没有安装。

### 起因

上一步做完之后，Host 把"新的导航套着旧内容"的截图当作进展发给了开发者，开发者指出它与认可过的方向稿完全不一致。他说得对：那一步新做的只有顶上的导航，下面整页还是旧组件；连新做的那一条也与稿不同，稿里表的切换与搜索、筛选在同一行，实现里它单独占了一行。Host 因此改了顺序：模型一项由 Host 照稿整页做出来，和稿并排看过之后再给开发者看，不再拿新旧混搭的中间状态当进展。

对照时还发现，入库的 `buddies.html` 自己已经被后来加进 `base.css` 的规则画坏了（见静态稿的说明），开发者认可的是更早的一张截图。稿已修好，修好之后的样子与那张截图一致。

### 做了什么

- 模型一项照稿重做，代码在 `src/buddies/` 之下：`models.ts` 算出表的内容（筛选、分组、排序、默认收起、未保存的标记、原因的写法），`ModelsTable.tsx` 画表，`ModelPane.tsx` 画右栏，`ModelsView.tsx` 是工具栏与两者的容器。原来的列表、家族详情（`FamilyDetail.tsx`）与更新记录（`EvaluationHistory.tsx`）删除，连同旧样式表里只有它们在用的 89 处选择器，以及没有了调用方的几个显示函数。

## 目录的交互修改与遗漏核对（2026-10-12）

开发者看过上一批的真实页面之后指出的交互问题，连同一次对上一批重做有没有遗漏的核对：开合与颜色的过渡、节头的两个手势、选中不被悬停盖掉、控制带在窄宽度下的折行、英文界面里的中文，后来又加上把实心三角换成细线的折角。一个微任务做完，四个回合，Claude Code 的 Worker（claude-sonnet-5-5 / high），在已安装的 0.29.0 上运行。核对的结果在 [console-frontend-catalogue-audit.md](console-frontend-catalogue-audit.md)。

### 核对

- 最终源码上：类型检查通过；前端全量 79 个文件、1,145 项通过（这一批之前是 74 个文件、1,120 项）；浏览器检查 96 项全部通过（之前是 62 项）。三样都是 Host 跑的，浏览器检查在沙盒外。测试标题比这一批开始时少 2 个、多 27 个；少的 2 个是角色的两条，随拒绝原因改成代码而改了名。
- 像素：Host 在最终构建上拍了中文 1280（收起、抽屉展开、展开的行悬停、别的行悬停、刻度格悬停、节头悬停、账户展开、收起一节）、暗色、700 与 800 宽的控制带、英文 1280、中文 390。点击之后的一帧里量到内容上 200ms 的 `collapsible-down`、折角 200ms 的转动与行上 150ms 的颜色过渡；展开的行悬停时是加深的绿，不变灰；抽屉里备注框与 Buddy 面板的底边是同一条线（414 对 414），与稿一致。
- 遗漏核对的记录本身：Host 用脚本从 `7a6438f5` 取出旧测试的标题重新比对，在现在的树里没有同名测试的正好是记录列出的 38 条；记录第一节引用的 63 个测试标题都在。数据与编辑层的八个文件、`package.json` 与锁文件没有被改动。

### 打回了三次

1. 第一次交付：浏览器检查 88 项里 12 项不过，逐条看过都是检查写错（在 React 提交之前读样式、在动画未止时量几何），页面没有问题。
2. 第二次交付：2 项不过，是页面的真问题：抽屉里备注框的底边比 Buddy 面板低 8px。这是上一批重做留下的，Host 当时没有看出来，是这一批新写的检查量出来的。同一次交回的还有三处：开发者说实心三角难看，改成折角；控制带折成两行时分区页签的字与下划线分开了三十多像素；共用的 `Hint` 在有没有说明之间会重建子元素，键盘焦点会丢，要在根因上改。
3. 第三次交付：`Hint` 改成永远包一层之后，被它包着的控件（单选、开关、输入框、工具条的按钮）的 `data-slot` 全被提示触发器的名字盖掉，2 项检查找不到元素。样式不依赖这些名字，页面没有变样；改法是 `Hint` 用不带名字的触发器，检查不动。

### Worker 跑不了的

这个 Worker 始终启动不了浏览器，头两个回合还各发起了 24 次与 3 次要人批准的命令，全部被拒，两个回合都以“请求 Host 处理”结束，第二个停在半途。第三个回合里连 `npm` 与 `node` 也全部被当作要批准的命令拒掉，原因没有查明（第一个回合里同样的命令能跑）；所以第三、第四两个回合是盲改，每一处都由 Host 跑过。各回合报告的用量（缓存的输入 / 输出）：第二回合 234 万 / 3.6 万，第三回合 373 万 / 3.2 万，第四回合 34 万 / 0.6 万。这是把前端其余页面排到 harness 一层的收束与 Worker 权限档位之后的原因（见待办）。
