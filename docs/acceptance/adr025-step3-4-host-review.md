# ADR-025 第三、四步：Host 验收

2026-10-07，Claude Code Host。实现由 Codex 作为 Host 完成，它的记录是[第三步提交记录](adr025-step3-review-ready.md)、[第四步提交记录](adr025-step4-review-ready.md)、[整合登记](adr025-step34-integration.md)，以及三份原生冒烟记录（[ZCode](adr025-step34-worker-smoke.md)、[Codex 与 Claude Code](adr025-step3-native-smokes.md)、[DSH](adr025-step4-native-smokes.md)）。本文只记录本 Host 亲自做的核对。

## 合入

`socu/adr025-run-module` 在 `c550d65` 收尾，以合并提交 `3fce9ac` 合入集成分支，没有冲突；合入后的源码、测试、打包文件与锁文件与被核对的提交完全相同。

## 这两步做了什么

Codex、Claude Code 与 DSH 改经登记的运行模块运行。加上第二步的 ZCode，四个 harness 现在共用同一个控制器入口、同一套运行请求与运行结果，Worker 回合、快速路由与审阅路由是这之上的三种角色。DSH 改由 Python 控制器经 `dsh --profile acp` 驱动；Node 运行器、五个插件、YAML 桥与 110 个 Node 测试已经删除，完整检查不再运行 Node 测试。Claude Code 内建的 StructuredOutput 调用，在核对它确实交付了本次回合的最终值之后，不再算作普通工具调用。依赖去掉 PyYAML，新增 zstandard，用来读取 DSH 压缩保存的私有会话记录。

## 测试覆盖的比对

本 Host 用自己的脚本列出全部 Python 测试的编号：第二步验收时 2,628 个，现在 2,785 个、175 个文件，没有装载错误，也没有重复。减少的 70 个全部能在实现方的两张变化表（[第三步](adr025-step3-test-ids.tsv)、[第四步](adr025-step4-test-ids.tsv)）里找到去向：表里写了新编号的，新编号都确实被装载；没有新编号的 20 个，2 个是重复的 Claude Code schema 测试，18 个随 Node 载体或旧入口删除，表里逐个写了理由，本 Host 逐个读过。新增 227 个。

110 个 Node 测试的去向另有一张[退役表](adr025-step4-node-retirement-test-ids.tsv)。其中 38 行是随载体一起消失的面（Node 命令行参数、设置文件解析、YAML 桥、用量旁路文件的写入方），本 Host 逐行读了理由，认可。其余 63 行里，54 行指到了具体的、确实被装载的 Python 测试，9 行只指到测试文件；本 Host 没有逐行比对这些测试的断言与原 Node 测试是否等价，改用下面的变异核对关键防护。

## 完整检查

本 Host 在 `c550d65` 上运行了一次 `uv run --frozen python -m hey_my_buddy.cli.checks`，通过：2,785 个 Python 测试（跳过 1 个），175 个文件全部运行，用时 441 秒，使用默认的并行数。实现方在 `6078488` 上的结果相同，用时 434 秒；这两个提交之间只有两份记录的改动。所以这次重跑没有带来新的信息。以后提交的版本与实现方检查过的版本之间只有记录改动时，本 Host 不再重跑，只读它的日志并在记录里写明完整检查是谁运行的。

## 真实的 harness

本 Host 用已安装的 DSH 做了一次不调用模型的发现，经过登记的运行模块与公共控制器：2.2 秒返回一个供应方、四个模型，两层停止得到确认，控制器的临时目录已清除；用户日常的 DSH 目录里，顶层的文件与目录没有变化。

真实模型的运行都是实现方做的，本 Host 只读了记录，没有重做：ZCode 的 Worker 回合 1 次；Codex 的 Worker 回合 1 次；DSH 4 次，其中 Worker 回合 2 次（第一次的探针脚本出错，没有留下完整的停止证据，所以重跑），只读预设下经命令写文件 1 次（被原生拒绝，文件没有出现），不给工具 1 次（工具调用为零）。

## 发现的问题

没有发现行为上的缺陷。下面几项是代码与测试的整洁问题，排在第五步开头处理。

- **没有调用方的旧代码还在。** 角色模块里旧的审阅启动与无工具启动两个函数（约 90 行）已经没有调用方：对四个 harness 它们直接拒绝，对其他名字则会去启动一个已经不存在的模块。随它们一起失去调用方的，还有同一文件里读取旧结果的分支、公共启动模块里只为旧 DSH 路径保留的两个参数，以及几处仍在描述 Node 的说明。实现方的记录写"旧入口均已删除"，这一句不准确。
- **回执核验有两份。** ZCode 与 DSH 用的是同一个会话工具服务与同一套签名，完成回执、工具拒绝回执与问询回执的核验却各写了一份，约 130 行，只有注释不同。这是和安全有关的核验，只应有一份。
- **运行模块之间有重复的小段代码。** 取消标志、截止时间的计算、身份取值等几段，在三四个运行模块里各写了一遍。
- **角色层还在按 harness 的名字分支。** 角色的执行模块有三处判断是不是 DSH，结构化调用模块有一处判断是不是 Codex。ADR-023 要求把差异记成声明的能力；在登记处按名字给出角色的参数可以，角色的代码里不应再出现 harness 的名字。
- **六处测试缺口。** 见上一节。
- **一个没有读取方的环境变量。** `BUDDY_PYTHON` 在生产代码里只剩写入与放行，原来读取它的是已经删除的 YAML 桥。

## 过程中的偏离

- **微任务都走了路由。** 首次提交都没有指定 buddy。有三个微任务中途结束（一次重复调用完成、两次约两小时后被取消），都用原来的 run 继续，没有因此换 buddy；这一批没有遇到供应方限流。
- **Worker 删除了自己建的目录。** 两个微任务的 Worker 在自己的任务根里删除并重建过自己建的目录，其中一个的记录起初还写着"没有删除"。实现方按规则拒绝，要求如实披露之后在原 run 继续。
- **两项 DSH 差异是先做后问的。** 一个 Worker 把关闭标题模型与遥测的启动项用到了全部运行上，超出当时已接受的三项差异。实现方发现后停下 DSH 这条线并询问用户，用户同意，登记为第四、五项。
- **第四步的第一次完整检查有 15 个文件失败。** 外围的测试仍在使用旧的 DSH 载体。实现方另开两个微任务迁移这些测试后重跑通过，失败的记录保留。
- **实现方改了两份由本 Host 维护的文档。** `AGENTS.md` 与文档索引各一处，删去已经退役的目录、更新测试路径。改动与事实一致，本 Host 接受。

## 没有亲自核对的

- **Claude Code 这条线没有运行过已安装的 CLI。** 实现方做了一次不调用模型的发现，用的是私有的配置目录，那里没有登录，返回不可用；Worker 回合 0 次。StructuredOutput 的识别规则依据的是以前真实运行留下的记录与实现方自己写的夹具，真实的 CLI 是否总按夹具的形状发出这些事件，没有验证。
- **Codex 的审阅与快速调用、Claude Code 的审阅，没有在已安装的 CLI 上运行。** 只有模拟的 CLI 覆盖。
- **经黑板的完整链路没有用真实的 harness 跑过。** 真实冒烟都是直接调用角色的执行器；从服务到 Worker 运行时再到角色的链路，只用模拟的原生程序测过。日常安装仍是 0.27.0，新代码还没有安装。
- **DSH 的工具清单是固定的。** 不给工具时关闭的是当前安装版的 15 个工具行；DSH 以后新增的工具行不在清单里。出现工具调用时快速路由仍会判失败，但调用本身已经发生。这是 ADR-025 第 11 条接受的做法。
- **其他平台。** 全部核对都在 macOS 上。

## 带到后面的事项

第五步开头，先于实时通道的改动完成，本 Host 在第五步验收时一并核对：

- 删除没有调用方的旧代码与过时的说明。
- 回执核验合成一份，放进各 harness 共用的模块，测试随之合并。
- 运行模块之间重复的小段代码合成一份。
- 角色的代码里不再出现 harness 的名字，差异改为登记时声明的参数。
- 补上测试缺口：DSH 始终关闭的两个启动项按行名断言；两层停止没有确认时不报告可以续接；Claude Code 的交付识别在没有结构化输出参数时不生效，或者去掉这个现在不可能为假的条件。
- 确认 `BUDDY_PYTHON` 是否还有用，没有就删除。

之后：

- ZCode 的 `run` 在第五步改到它时按其余三个的做法拆开。
- 两侧之间互相引用的[登记表](adr025-step-0-cross-imports.tsv)还是第零步时的快照，ADR-025 收尾时重新清点。
- Claude Code 这条线的真实验证需要用户的登录与额度，由用户决定何时做。
