## 计划与范围

只读微任务 `32c3bae6` 写的第一版执行计划，把随工作增长的事实几乎全部改成文件交接，每一处新开一种封存形式，另为安装器配了一套新的协议。Host 与 Opus（`0a184070`）各自独立审查，结论都是不能照做：输入早已经启动文件交给执行进程，结果也早已以位置加摘要交回，跨进程的文件规则已经满足；要做的只是删掉库里的重复副本、去掉凭猜测定的截断，安装器沿用 27 → 28 用过的做法。Host 在日常看板上做了只读计数，又对缩小后的方案做了回归审查，纠正了两处会丢冻结证据的删除：0.46.0 之前 70 个 Router 派发的输入与快照不同，回合结果被截断的记录在 2 个旧回合里还有值。开发者 2026-10-24 定下范围：

- 存储整理：Router 按轮次记录，删掉可推导的副本；停止来源只留一列；运行的 manifest 必填，来源 Host 冻结成列；去掉事件索引的守卫；活动只存一份；同义键与问询送达里的常数；
- 限值盘点的第 1 批：在源头去掉截断，库里每个事实只留一份，不搬进文件；
- Windows 阶段 D 与 E 按原设计；
- 旧布局的 `harnesses/*/goals/`（约 4.8 GB，看板里没有记录指向它）与几样没人读的旧文件，在升级核验之后删除；
- 0.46.0 之前的 70 个派发文档按 0.46.0 对快照做过的同一转换处理，之后派发文档与它的摘要都由快照推出。

## D1：Windows 上服务独立启动，Job 的基础

- **微任务：** `bd23bf47`，三个回合（合计输入 1,215.5 万 token，其中 1,178.5 万命中缓存；输出 7.3 万），合并提交 `f9f5968f`。

- **Host 的核对：**
  - 读完三个回合的差异；
  - Windows：Host 读过复跑的原始输出，独立启动、183、探针进 Job、单句柄的核对与终止都通过；第三回合改的那项测试，由下面的调查在最终候选（`0dffb619`，即 D1 合在 `eaee43da` 上）与基线上复跑，双方都通过，两个文件 71 个共有用例的结果逐项相同；
  - 合并候选 `345bd263` 上完整检查通过（同上）。
- **Windows 调查**（微任务 `bed8c1bb`；输入 932.3 万 token，其中 918.4 万命中缓存；输出 6.9 万；Host 读过报告与原始输出）：
  - 新的 SSH 登录连不上前一次登录启动的服务。C-Two 0.8.2 在 Windows 上把管道名推成“登录 SID 的摘要加地址摘要”，每次 SSH 登录的登录 SID 都不同；A 还活着时 B 就连不上，所以起因是换了登录。服务比启动它的登录活得久之后，这一点更容易撞到。C-Two 是否应当支持跨登录互连，开发者要 astra 研判（微任务 `81879013`）；

  - harness 发现的测试在 Windows 上有两处在候选与基线上都失败（按冒号拆 PATH、要建名为 `lts\*` 的文件），是测试本身的问题，记入待办，随 D2。
