# 中断后的接续：验收记录

## 按进程身份结算被中断的执行（2026-10-15）

- 起因：2026-10-14 开发者的机器断电，重启之后，断电时在跑的两次执行停在“重启后状态未知”：只有握着子进程句柄的那个 Worker 能报告结果，而它已经不在，产品里没有出路，两次执行一直占着名额和检出，还挡住了升级。开发者定下的做法写在 [ADR-010](../decisions/010-production-workflow-repair-plan.md) 的 2026-10-14 补充里：每次执行记下完整身份，开机标识变了或这套身份已经不存在就是停止证据；身份仍在而原 Worker 已经没了，新 Worker 核对之后停下它。覆盖断电、重启、死机与进程崩溃，休眠与断网时原 Worker 仍在、照原来的对账接上；macOS、Linux 与 Windows 都要支持；每个 harness 都要能接着做。
- 第一回合：Host 在空主目录的私有服务上用真实进程做了两种情形，一是杀掉 Worker、留下子进程，二是 Worker 与子进程一起杀掉。两种在租约到期之后都结算为 `interrupted`、停止已确认，留下的子进程也被停掉了。Host 又在日常看板的私有副本上演练了升级，断电留下的两例不再挡升级。Opus 盲审（[review](../design/interruption-review.md)）与 Host 的核对一起打回九条。最要紧的三条：
  - 进程启动时刻取自 psutil 的 `create_time()`，会随墙钟与休眠变（Host 读 psutil 7.2.2 的说明与源码证实），合盖睡一觉，活着的 Worker 就可能被判成已不在；
  - 封存遇到确定性的错误时，已证明停下的执行永远卡在未知；
  - 每个空闲 Worker 每次空等结束都跑一遍完整的恢复扫描。
- 第二回合把九条都改到了：
  - 启动时刻改取内核记下的原始值：Linux 是开机之后的节拍数，macOS 是 libproc 给的创建时刻，Windows 是 `GetProcessTimes` 的创建时刻；
  - 进程组是否已空改用 `killpg(pgid, 0)`；
  - 确定性的封存错误走回合正常结束时已有的出口；
  - 结算只由服务的启动对账与租约清扫做；
  - 存量规则加了一小时的余量；
  - 原 Worker 保持 `lost`；
  - 两处只写不读的存储删掉了。
- 合并：合到整合分支时，与“控制面的时限”在 Worker 的执行函数里冲突。时限那边让同一个续租线程从预检起就在，拉起子进程之后先把 Host 已经记下的停止交给新句柄，有测试钉着“交接先于任何文件与 RPC”；中断这边在拉起之后记身份、写标记、上报。Host 的解法：
  - 先交接句柄，再记身份、写标记；
  - 第一次上报同时清掉预检留下的等待原因；
  - 上报失败的身份交给同一个续租线程，每次续租时重试；
  - 时限那边的一个测试替身补上了 `identity`。

  后两回合的改动用同一个三方合并接上；每一次 Host 都核对过：合并的结果正好等于这个解法加上各回合的增量与版本号。
- 第二回合合并之后：完整检查 255 个文件 4,176 项全部通过；两种杀 Worker 的实测与日常看板副本上的升级演练都重做了一遍，结果同上（副本用完即删）。但 Host 量出了空闲占用的回退：空闲的 Worker 每个等待窗口都要调一次 `worker_recover` 找孤儿。量法是在私有服务上让 6 个 Worker 空闲 60 秒，统计这个私有根下全部进程的 CPU 时间：

  | 被量的源码 | 占一个核 |
  | --- | --- |
  | 整合分支 | 0.37% |
  | 合入之后 | 3.49%，重量一次 3.15% |
  | 合入之后，只去掉那次调用 | 0.43% |
- 第三回合：Worker 只在启动时、以及等待的事件里出现执行被标为未知（`attempt.uncertain`、`attempt.lease_expired`）时才找孤儿，等待的回复用 `recoveryNeeded` 说明；游标只由处理过的等待推进，免得空认领的快照跳过未知事件。一并改了三处小的：停孤儿的宽限与 `ProcessHandle` 共用 3 秒，`worker_result` 拒绝 Worker 报来的 `interrupted`，原生日志只读一次。实现方量的空闲占用从 4.07% 回到 0.36%。合并之后的完整检查有四个文件失败：README 里的版本号（Host 的，已改）；另外三个是这一回合的后果：七个续接测试原来靠 Worker 报中断来造回合，新测试文件导入了别的测试类，使 11 项被排了两次，还有一个空闲 Worker 的测试钉着旧的游标语义。打回第四回合。
- 第四回合：续接测试改由服务的恢复路径造被中断的回合，去掉重复收集，空闲测试改到新的语义上，空认领回复里已经没有读者的 `cursor` 删掉。
- 安装之前在最终的树上（整合分支 `0d4f24c1`，带着 0.36.0 的版本号与文档）：完整检查 256 个文件 4,185 项全部通过；空主目录私有服务上两种杀 Worker 的实测结果同上；6 个空闲 Worker 占一个核的 0.49%，与整合分支在同一水平（量过两次，0.37% 与 0.43%）。看板上的验收绑定整合分支，整合记录 `int-8d47265b…`，检出已回收。
- 验证的边界：
  - Linux 与 Windows 的启动时刻、开机标识与作业对象只经可控来源的测试，没有在真机上跑过，排在发版准备的全平台检查里；
  - 真实的合盖休眠没有做。所依据的是：启动时刻取内核记下的原始值，休眠改不了它；Worker 一侧用“暂停超过租约再恢复”测过；
  - 各 harness 中断之后的原生接回没有用真实的 CLI 跑过，这要付费，逐次请开发者批准。
- 留到以后的小处：替身 Worker 与前任共用一个标识时，前任的执行结算之后这个标识显示为 `lost`，直到它下一次认领；只影响显示。
- 消耗：
  - 四个回合合计输入 4,620 万 token（4,560 万命中缓存），输出 13.7 万；
  - Opus 盲审输入 551 万（全部命中缓存），输出 5.4 万，13 分钟；
  - 版本号由路由交给 `dsh / deepseek-official / deepseek-flash / max`，输入 38 万（35 万命中缓存），输出 4,564。
