# 有界保存：验收记录

2026-10-16，整合 Host。做法见[有界保存](../../design/adr028/bounded-history-design.md)，规则记在 [ADR-028](../../decisions/028-macro-task-deletion.md) 的补充里，开发者同日定下两条：命令的记录保留、不设期限，只存标识这次提交的内容；心跳这类周期性状态是替换式记录。微任务“有界保存：命令回答与活动事件”（Codex CLI，`gpt-6.1-sol / high`，三个回合：方案约 15 分钟、实现约 20 分钟、返修约 10 分钟），基点 `c605b127`，产物 `d46010a7`，合并为 `d9b5f57c`；两份独立审查合并为 `ba3beeae`。版本与契约 0.42.0，schema 24，尚未安装。

## 做成了什么

- 十种 workflow 命令的收据只存这次提交的身份（runId 加上请求、续接、整合、结论、范围版本、冲突或清理计划的编号；局部恢复保留它第一次的结果），丢了回复之后的重放从当前的表重建回答；小回答照旧原样保存。同一编号、不同请求仍是 CONFLICT，原有的授权检查不变。
- `execution.result` 不再写收据，它的提交身份就是 attempt：同值的重投答“已提交”，异值为 CONFLICT，旧代为 STALE_GENERATION。只为那份收据存在的命令编号一并删净：执行进程不再生成它，持久回执不再带它，`attempts.result_command_id` 列删掉。
- `attempt.activity` 每次执行只留最新的一条，`harness.checked`、`harness.probe_unknown`、`harness.account_observed` 每个 harness 每种只留最新的一条：写新的一条时在同一事务里删掉旧的，序号不回退，观察者的游标落在被删的位置时从下一条继续。删除带着 `task_id` 条件，落在已有的索引上。没有维护线程，也不在启动时改数据。
- 23→24 的升级在空闲安装的备份之后运行一次：剥离收据、删掉 `execution.result` 的收据与那一列、收起周期状态；失败就整个回滚。

## Host 的核对

- 读完两轮的差异。第一轮完整检查有 3 个文件失败：一条测试把契约版本钉在 0.41.0、一条测试的 meta 写入点清单缺升级那一处，以及 README 的版本号；前两处与软件版本号打回由实现方改（写入范围在 Host 的说明里漏了 `pyproject.toml` 与 `uv.lock`，扩大范围后补上）。
- 按开发者事先的同意请 Opus 盲审两次（Claude Code CLI，`claude-opus-5-5 / high`）：方案一次约 8 分钟（[记录](../../design/adr028/bounded-history-design-review.md)），实现一次约 15 分钟（[记录](../../design/adr028/bounded-history-implementation-review.md)，输入约 1,523 万 token、几乎全部命中缓存，输出约 6.5 万）。实现审查没有阻塞的发现；Host 核对之后，把执行结果命令编号的残留、替换删除走索引、升级转换先取完再改、共享的 JSON 编码、两处重复判断、`backup.create` 两种调法、takeover 存两遍的代次、取消说明的两份文字和一条缺的重放测试交回返修；“每种回答一个构造函数”记进[待办](../../design/backlog.md)。
- 在返修的产物上跑完整检查：257 个文件、4,127 项，只有 README 的版本号一项失败，由 Host 随合并改掉；合并之后跑查文档与版本的 6 个文件、37 项，都通过。
- 在日常看板的私有副本上经启动器演练（空 HOME，不调用模型，副本用完删掉）：装 0.41.0（`dd8ab2b0`）并在副本上起服务，再装 0.42.0，12 秒完成。事件从 16,410 条变为 2,817 条；活动事件从 115 次执行的 13,426 条变为每次执行一条；每个 harness 每种状态从最多 150 条变为一条；命令回答从 7.87 MB 变为 56 KB；`execution.result` 的 12 条收据删掉。备份为 schema 23 的看板与两个状态文件并校验通过，留存数据的指纹核对通过，完整性与外键检查通过，新服务以 0.42.0、schema 24 起来，安装标记清除。
- 故障注入：同样的演练里先把副本上的一条验收收据去掉 `integrationId`，转换失败，安装以 `UPGRADE_ROLLED_BACK` 退出，服务回到 0.41.0、schema 23 与原来的运行时，看板原样（事件 16,410 条，命令 258 条），安装标记清除。

## 没有验证的

- SQLite 文件不会因此立刻变小：删除与更新后的页留给以后重用，没有加 VACUUM 之类的回收。
- 比 0.40.0 更早的版本写下、形状不同的收据：日常看板的副本里没有，转换在这种行上会失败并回滚，不会改数据。
- Windows 上的升级只经检查套件的模拟。
