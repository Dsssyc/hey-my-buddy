# 检查命令只跑给定文件与清扫的验收

2026-10-13，整合 Host。起因与做法见[待办](../../design/backlog.md)里“只跑几个测试文件没有现成的命令”一条；开发者于同日同意做。一个微任务，一个回合，Codex 的 Worker（gpt-6.1-sol / high）；封存是 `1128dbed`，合入整合分支的提交是 `b420cd23`。实现方的说明在 [focused-notes.md](../../design/check-runner/focused-notes.md)。回合以请 Host 注意结束：它的沙盒不许列出进程，有 4 条测试跑不了，它建的一个临时目录也删不掉。

做了什么：检查命令后面跟上 `tests/python` 之下的测试文件或目录，就只跑这些，私有根目录、并行与收尾与全量相同；`--jobs 1` 改成逐个文件依次跑，原来“一个进程发现全部测试”的串行路径删掉了。退出码分开：测试没过是 1，用法错误是 2，测试通过但收尾不完整或观察不到是 3。每个私有根目录记下创建它的进程号；`--sweep` 清掉创建者已经不在、并且没有活进程牵连的目录，创建者还活着的跳过，观察不到的照旧连证据保留。

- **差异。** 检查程序 166 行，读完；收尾的判定规则没有动，仍然不发信号、不杀进程。
- **按使用者的方式试。** 三类用法错误都以 2 结束，没有建目录。给出五个文件并重复其中一个：跑五个文件，54 条，其中包括实现方跑不了的那 4 条，都通过，以 0 结束，私有根目录已删。在 Host 自己的沙盒里（不许列出进程）跑一个文件：测试通过，以 3 结束，目录保留；再跑一个会失败的：以 1 结束。随后在沙盒外清扫：这两个目录与实现方留下的那一个都被删掉；清扫的同时另起一次运行，它的目录被跳过，运行结束后自己删掉了。
- **完整检查。** 合入后的树上由新的检查命令来跑：233 个文件（多了它自己的一个测试文件），3,963 条，以 0 结束，私有根目录已删，临时目录下没有残留。

边界：`AGENTS.md` 验证一节已于同日按开发者确认的措辞改了，写明了两种用法与四个退出码。Linux 与 Windows 上清扫找目录的位置只有测试，没有实跑。
