# CI 偶发失败与分片：Host 验收

2026-10-27。微任务“CI 偶发失败与分片”（run `3b9e636d`，经路由交给 Codex CLI 的 `gpt-6.1-sol / max`，七轮）。基点 `8e6e2235`，最终封存提交 `83ec1391`，合入整合分支 `7e04767f`。

## 改了什么

- **执行启动按 C-Two 的 `retryable` 重试。** 执行进程检查自己的端点时，另一个进程正占着命名空间的锁，得到的是 `io-error / WouldBlock / retryable`。以前按失败处理，这正是 `test_parallel_dispatch` 偶发超时的根因；现在每 0.05 秒重试，不设上限，外层由静默提醒兜着，Host 按核实过的身份取消。不可重试的失败报出 status、reason 与 io_kind。回归用例用真实的第二个进程拿住 `.gate`。
- **冷启动预检改走 C-Two 自己的绑定。** 旧预检在 TMPDIR 下用完整路径绑 Unix 套接字，TMPDIR 一长就超过 `sun_path`（Host 复现：20 个字符通过，133 个字符失败）。现在在状态目录下建一个临时根，用一个独立的 C-Two 运行时真正起一次本地端点、ping 通，再把它收干净。
  - 实现方先量过预检值不值得留：在拒绝绑定的沙箱里，有预检时 0.004 秒报出准确的权限错误；没有预检要 2.9 秒，还会先物化运行时、建库、起守护进程，最后报出误导人的 `CONSOLE_PORT_IN_USE`。
  - 代价：用到了 C-Two 的私有接口 `c_two._native.RuntimeSession`，记为 Host 维护的 C-Two 缺口清单第 18 条。开发者同日让 C-Two 公开这个能力，C-Two 发版之后这里换用公开接口。
  - 检查运行器里为旧套接字路径在 macOS 上改用 `/tmp` 的特例，随之删除。
- **偶发失败。** 观察线程、Codex 取消、C-Two 集成夹具、Claude 夹具的预算、预览的日期、wait 通道与 RPC 的计时等多处等待，改为等事实出现或用门闩；Windows 清理时把 WinError 5 与 32 一样重试；安装 fence 只补了失败时的诊断（15 次自然运行都没复现）。
- **分片。** 一个 Python 矩阵分 16 片：Ubuntu 1、macOS 2、Windows x64 7、Windows ARM 6；加上前端 1 个、浏览器 3 个，共 20 个作业。分片按实测的文件用时，从重到轻依次放进当前总量最小的一片，规则简单，结果确定。中间几轮试过手列的重文件名单、对排队时间的预测常数，以及等浏览器作业结束才起跑的接力分片，都已删除。

## Host 核对的

- 读了产品与检查运行器的改动（`execution.py`、`transport.py`、`cli/checks.py`），以及 CI 配置与分片规则；第四轮之前的差异逐轮读过。
- 真实 CI 每轮都跑：

  | run | 候选 | 墙钟 | 结果 |
  | --- | --- | --- | --- |
  | 40459165153 | 第二轮 | 15.6 分钟 | macOS 一处偶发失败 |
  | 40468217639 | 第四轮 | 15.2 分钟 | macOS 一处偶发失败 |
  | 40475105412 | 第五轮 | 12.45 分钟 | 只有预期中的长 TMPDIR 回归失败 |
  | 40486080021 | 第六轮 | 17.5 分钟 | 三处失败 |
  | 40490854570 | 第七轮 | 14.8 分钟 | 20 个作业全部通过 |

  改动之前，发版时那一次 PR CI 的墙钟是 18.6 分钟。第四轮的数据证实了“重文件分在同一片会互相拖慢”。
- 合并后，改过的 20 个 Python 测试文件、461 个测试全部通过。

## 后续，不在这一批

- **浏览器作业的依赖安装偶尔很慢。** Playwright 的 `--with-deps` 走 apt，最近两次各有一个浏览器作业在这一步用了 9 分钟以上，其余作业只要 0.2 分钟。第七轮的墙钟就是被它拖到 14.8 分钟的。
