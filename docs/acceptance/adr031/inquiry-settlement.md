# 问询的结清：验收记录

2026-10-22，整合 Host。依据是[问询投递诊断](../../design/inquiry-delivery.md)与 [ADR-031](../../decisions/031-one-process-per-execution.md) 里的“问询”一条：结清一次执行之前，服务先从这次执行的问询日志导入送达与答复，再结清余下的问题。两个微任务都在宏任务“问询送达”里。验收通过，没有安装：开发者要等 C-Two 0.8.0 验证并升级之后，与它一起装。

## 结清执行时导入问询答复

- **微任务：** “结清执行时导入问询答复”（run `21d9dd37`，Codex CLI `gpt-6.1-sol / high`，四个回合），基点 `ae353579`，最终输出 `56f2c744`，合入为 `e437161e`。
- **做了什么：**
  - 结清一次执行时，服务先经 `protocol/inquiry_journal.py` 这一个读取器导入这次执行的问询日志，按 task、attempt、generation、turn 与问题摘要绑定，再结清余下的问题。从未送达的以 `inquiry-queued-at-attempt-end` 结清；已送达却没答复的以 `inquiry-delivered-at-attempt-end` 结清，保留送达时刻；根回合结束之后才提的问题以 `inquiry-root-turn-ended` 拒绝，不再注入旧通道。问询桥与 Worker 的会话工具用同一个读取器。
  - 消息只在内容变化时写入，导入重复的记录不再推进 `revision`。`waitMs` 一直等到问题被答复或已不能再答复，至多到给定的时限。
  - 问的人：经认证的控制台会话与 Lead 凭据分别记进 `author_role` 与 `author_id`，回复里给 `author` 对象；服务共享令牌证明不了 Host 的身份，不记。
  - schema 28：`messages` 删掉恒定的 `author`、恒为空的 `recipient` 与每次读取都变的 `attempts_count`。`CONTRACT_VERSION` 与签名表改为 0.51.0。
  - 控制台：中英文分别说出三种情形；合作式送达的问题排队时写明“在 Worker 下次检查点时送达，现在尚未送达”；通用的“无法送达”说法不再断言问题从未送达。合成预览加进这三种状态各一条，另加一条浏览器检查。
- **返修：** 第一回合做完实现；版本号、fixture 的库存与升级的归位超出它的写入范围，交给下一个微任务。Host 在合并树上跑完整检查时 `protocol/test_reasons.py` 失败：`store.py` 与 `inquiry_journal.py` 各有一处用条件表达式动态选原因码，打回改成字面量（第二、三回合）。第四回合按 Host 的要求在合成预览里加进三种状态，好让 Host 看像素。
- **消耗：** 输入 4,432 万（命中缓存 4,389 万），输出 8.7 万。

## Host 的核对

- 两个微任务的差异都读过。根因在诊断时已由 Host 用复现脚本独立跑过（见诊断记录）。
- 完整检查跑在这一批与“Windows 阶段 B：私有目录边界”的合并候选上：307 个文件、4,687 项，两个文件失败，原因都在环境或文档。`install.test_first_install` 失败是因为 README 还写着 0.50.1，Host 改了 README 之后通过；`cli.test_host_preview` 失败是因为那个检出没有装前端依赖，在最终源码上通过。
- 最终源码（与 `e437161e` 同一棵树）：受预览影响的三个 Python 文件 39 项通过；前端 94 个文件 1,102 项通过；浏览器检查 615 项通过，重新构建的产物与提交里的一致。
- 像素：在合成预览上，三种状态各拍 390px 与 1440px，中文浅色、深色，英文浅色。1440px 下，时间与状态句各占头部一端，都在一行之内，深浅两色都清楚。390px 下文字完整、没有横向溢出，但头部挤成了一行，留作下一批的顺带项（见下）。
- 安装演练：脚本 `tmp/inquiry-fix/reh-051.sh`（不进仓库）。基线 0.50.0，候选 `a5a9db05`（代码与最终源码相同，只差合成预览与它的检查）。空 HOME 下经启动器装 0.50.0，把它新建的看板换成导出工具写的样本（schema 27：171 个任务、201 次尝试、2,461 条事件、100 个工作流、4 条问询，空闲），在样本上起 0.50.0 的服务，再装候选。
  - **正常路径：** 升到 schema 28；备份已校验（schema 27，2 个文件）；服务 0.51.0，54 张表，`meta` 两项，完整性与外键无误；计数与封存内容的五项摘要与装前相同；4 条问询保留的字段摘要不变，旧行的 `author_role` 与 `author_id` 为空；安装日志已清，`upgrade-last` 为 `verified`。

## 没有验证的

- 没有用真实的 harness 跑带问询的回合；修复之后的结清只在测试与假 app-server 里覆盖。

- Windows 上没有验证。
