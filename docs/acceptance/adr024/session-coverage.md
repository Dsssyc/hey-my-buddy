### 改了什么

- ZCode 探针的两处漂移修好：目录为空时不再断言有警告；失败回合改从失败结果里取原生会话，不再找只在成功时写的绑定文件。

### 记作 C2 的顺带项

- **来源用了行号。** 声明的 `source` 引用文档与夹具的行号，检查只核对行号没有超出文件的长度；文档一改，引用就会悄悄指错地方。改为只写文件，文档再加小节标题，检查核对文件与标题都在。
- **控制台收到了用不上的字段。** 会话读取把 `version` 与 `source` 都发给控制台，控制台一个也不显示，解析时却要求它们非空。改为在“有证据”旁边显示版本，`source` 不再发给控制台。
- **Codex 也该补证据。** Codex 的消息、工具输入与计划仍是未核实。它的协议样本里有 `plan` 条目，投影把它写成一条标记正文（`[plan]` 加计划文字），不是 ACP 的计划更新；声明要照实际的样子定。计划里原来的 C2 只有 Claude Code 与 DSH。

## C2：Claude Code、DSH 与 Codex 的证据

2026-10-27。微任务“三家 harness 的会话证据”（run `667f5467`），经路由交给 Codex CLI 的 `gpt-6.1-sol / high`。基点 `aa578a0e`，封存提交 `86c8debf`，合入 `5642dc68`。

### 改了什么

- 三个探针：`tests/probes/claude_session_content.py`、`dsh_session_content.py`、`codex_session_content.py`。它们照 ZCode 的做法，让本机安装的 CLI 连一个回环的假模型，用私有的 HOME、配置与会话目录和写明不是秘密的假密钥；sandbox-exec 只放行回环网络，并禁止读真实的 harness 目录。录下的原始事件精简、脱敏后写成测试夹具。
- **Claude Code 的思考被覆盖（缺陷）**：同一条消息的几个块分在几帧里送来，旧投影把后来的帧都写在第一个块的位置上，还会把多出来的块清空，正文就盖掉了前面的思考。现在按帧给块定位。实现方把旧代码放回去，新加的两项检查就失败。这解释了 Host 10-27 只读比对时看到的情况：Claude Code 的记录里没有思考。
- **Codex 漏了工具输入（缺陷）**：模型实际发出的参数在原始的 `function_call` 条目里，旧投影不读这类条目。现在按 `call_id` 把它与命令执行的条目合成同一个工具。
- DSH 的投影不用改：同一回合的 ACP 通知与它自己存下的会话逐类对得上。
- 两件顺带项都做了：
  - 声明的来源改为文件，文档再加小节标题；检查核对文件与标题都在。
  - 控制台在“有证据”旁边显示版本，会话读取不再发 `source`。
