## P3 Git 交付与干净的三方合并

2026-11-05。微任务“ADR-032 Git 交付与三方合并”（`max`，两个回合）。封存在 Worker 的 HEAD 不同于输入、树与封存一致、输入是它的祖先时直接用 Worker 的提交；整合来源分成 Worker 的起止提交与固定补丁；验收用 `merge-tree --write-tree --merge-base` 核对干净的三方合并，`beforeCommit` 除了顶端是包含产物的合并以外都要给。

第一回合（`222000ae`）打回：Host 在它的提交上跑 45 个受影响与下游文件，`test_macro_task_deletion_workspace` 失败，原因是 Worker 没提交也没改动时封存被标成 worker，和同一回合 Host 封存的快照摘要分开，产物登记不再去重。同一轮还删掉多余的补丁回放核验、新封存的重复核验和没人读的 `artifactAncestor`。第二回合（`da9d3b1b`）全部修好。

Host 的核对：`da9d3b1b` 上 46 个文件、704 项测试通过；日常黑板只读普查 1,588 条真实封存记录，新的记录校验通过 1,586 条，另 2 条 Host 产物在基线代码上同样不过；四个针对关键规则的变异（三方合并的结果、脏输入只给补丁、复用要求祖先、统计看实际调整）都被测试拦住，不改动的对照行通过。最低 Git 版本因此是 2.40（`merge-tree --merge-base`，已在 Git 2.40.0 的发布说明核实），只写进文档，不加版本检查。Worker 的两个提交原样快进进整合分支。

## P4 项目、空宏任务与不带检出的微任务

2026-11-05。微任务“ADR-032 项目、空宏任务与 none”（`max`，五个回合）。第一回合停在 Lead 的项目建键冲突：项目身份只有服务能完整解析，Lead 也无权先读项目。Host 决定新建键改由服务在 `create` 与 `submit` 的入口推出，`get` 按 `cwd` 读项目时保持只读，并改了 ADR-032 第 4 条与计划（`1e993407`）。

第二回合交付后，Host 的完整检查与独立审查（微任务“审查 ADR-032 项目与 none”，一个回合）共同打回 11 条。审查用探针复现了两条阻塞：none 配 `route` 抛 `KeyError`；原生回收之后结果读不到。Host 自己的发现包括：回合与续派上 `checkout` 的新旧含义不一（删去重复列，只在运行上存）；Git 项目的路径改存仓库主根目录；删掉写死的中文提示。审查的 C5 没有采用：那种情形没有真实发生过。第三回合全部修好，完整检查只剩样板来源记录的摘要不一致；第四、五回合用最终的生成器统一重新生成全部库存，两个冻结的 oracle 由各自原来的实现重算，统计值与行数不变。

Host 的核对：`c4d623fe` 上完整检查 Python 386 个文件里 384 个、5,545 项通过，前端 107 个文件通过，没过的两个仍是归 P6b 的前端解析测试；在日常黑板上只读地空跑 34→35 的转换（914 个运行、200 个宏任务、29 个项目），没有错误，新约束全部成立，项目名与原来的推法一致。Worker 的四个提交原样快进进整合分支。
