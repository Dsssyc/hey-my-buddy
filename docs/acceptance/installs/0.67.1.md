# 安装 0.67.1 的记录

2026-11-10，整合 Host。补丁版本：契约仍是 0.67.0，存储形式仍是 schema 39，不需要黑板空闲，也不做备份。这一版修 0.67.0 装上之后查出的两处 Router 维护的问题，并带上开发者试用 Buddy 页之后定的修改。

## 内容

- **DSH 的 none 一档保留执行器行**（微任务“DSH 担任维护时开不了回合”，ZCode `bigmodel-api-2 / GLM-5.3 / high`，两个回合；整合为 `51ae4156`、`561e7313`）。日常黑板上维护自 2026-11-07 17:21Z 起连续 5 轮以 `native-prompt-refused` 失败，DSH 的话是 “The selected tool executor is unavailable”，最后一次成功在 11-06 21:16Z。根因是 0.65.0 的 `59539b42` 让 none 一档按 DSH 的工具清单全部关掉，连 DSH 自己开回合要用的执行器行也关了。Worker 用真实的 DSH CLI 与无凭据的私有目录对照复现，没有付费：只改这一行，错误就从执行器变成缺凭据。修法是 none 一档保留执行器行，其余工具行照旧全关。第二个回合补强了 none 一档的付费探针。
- **看不到模型开始的 harness 不套开始等待**（微任务“Router 调用在看不到模型开始的 harness 上不套开始等待”，同一个 buddy，两个回合；整合为 `5384a3a4`、`bc2ce158`）。DSH CLI 0.2.2-rc.1 经 ACP 一步做完才送出（[调研记录](../../research/2026-11-09-dsh-acp-step-delivery.md)），DSH 的 max 档担任 Router 时有 8 次被误判为没回应，维护在 60 秒的等待下每轮都会被取消。照 ADR-021 第 2 条 2026-11-09 的修改，`protocol/capabilities.py` 的 `MODEL_START_UNSEEN` 声明 DSH，执行进程对它的 Router 调用不套这个等待，由 DSH 自己的流空闲超时兜底。服务层的 3 项恢复测试改用 Codex 的夹具，另补了重启后接回的 DSH Router 没有兜底期限的测试。顺带修了探针把模型回答的 `none` 当成工具名的毛病。
- **Buddy 页试用后的修改**（微任务“Buddy 页试用后的修改”，Codex `openai / gpt-6.1-sol / high`，两个回合；整合为 `3598975f`、`b8dcc282`，Host 删去旧构建产物并改文档 `3b10f4ae`）。照[重做计划](../../design/adr029/buddy-router-redo-plan.md)“装上之后的修改”：领域树改成按数量排序的大纲加计数条，每一段按自己的数取青、绿、黄的色带；Buddy 页的图形用 logo 的色调；评价的样本条与 Router 记录里的数点开才显示；Router 设置的说明收进问号圈；分区页签垂直居中，下划线压在分隔线上。顺带：任务页写出排队的原因，维护失败的原因不露出校验标识，会话视图那项偶发失败的测试修了根因（测试里的假观察器认错了实例，组件挂上观察器之前就去检查），时间轴上停止的发起者写成“由 Host 停止”这类说法。
- 文档：ADR-029 第 8、13 条与 ADR-021 第 2 条 11-09 的修改，调研记录，`harness-integration.md` 与 `decision.md`，计划与待办。

## 验收

- **执行器行**：Host 在交付的提交上跑 DSH 与依赖它的 20 个文件 338 项，通过。这一处放宽了权限限制，请 Codex `openai / gpt-6-luna / high` 盲审（输入 624,943 个 token，其中缓存 550,016；输出 9,261），它指出探针证明不了“没给模型工具”，打回一轮补上。开发者批准了一次付费核实（DSH `deepseek-v4-flash / max`，输入 593、输出 677 个 token）：回合能开，DSH 自己的组合清单里没有启用的工具行，没有工具调用，服务的判定通过，执行器行保留；“模型看得见的工具”一项因探针把回答 `none` 当成工具名而判失败，模型的原话是看不到任何工具，这个探针的毛病随第二个微任务修了。
- **开始等待**：Host 在交付的提交上跑协议、执行、角色、各 harness、路由、服务与安装这几棵测试，227 个文件 3,516 项，通过。这一处拿掉了一道时限，同样请 `gpt-6-luna` 盲审（输入 462,619，其中缓存 384,896；输出 3,614）。它唯一的发现是声明写着 0.2.2-rc.1，判断却不分版本。Host 认定这是有意的：按版本卡，DSH 每升级一次维护就会被取消；不分版本的代价只是换下一个 Router 要等 DSH 自己的超时。这一点写进了 `harness-integration.md`。
- **Buddy 页**：第一轮打回：中位数的用量格式回退成“7,066,067.521 tokens”，两项浏览器检查没跟上新设计（分区页签的下划线、旧失败记录的按钮），问号圈缺 DSH 那句；Host 另定了领域树的子领域段按自己的数取色（开发者同意由 Host 定）。第二轮 Host 在另建的工作树里跑前端 114 个文件 1,424 项、浏览器全量 891 项，全部通过。日常控制台的读取只读地抓下一份快照（会话字段抹掉），在新构建的预览里回放出图，深浅两色都看过：81 个节点的领域树、评价与路由记录照设计呈现。
- 每一批交付都没有动日常黑板与日常服务。
