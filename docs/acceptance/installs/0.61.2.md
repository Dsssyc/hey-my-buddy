# 安装 0.61.2 的记录

2026-11-05 17:27 UTC（北京时间 2026-11-06 01:27），整合 Host。这是补丁版本：契约仍是 0.61.0，存储形式仍是 schema 35，所以不要求黑板空闲，也不做备份。从整合分支的提交 `17cb6f34` 安装。

## 内容

- **ZCode 在只读档交得了货**（微任务“ZCode 在只读档交得了货”，四个回合；整合为 `70827a40`、`8b14f51d`）。read 级别的 ZCode 回合过去映射到 `plan` 模式，那个模式连黑板挂载的交付工具也要审批，无界面的会话里没有谁能批，回合以 `duplicate-finish` 失败（11-03、11-05 各一次）。ZCode 没有真正的只读模式，也不能为无界面的会话按工具预先放行（[调研记录](../../research/2026-11-06-zcode-read-only-mode.md)）。现在 read 与 write 同用 `yolo`，能力声明里 ZCode 的 read 改为约定，review 路由随档位一起改；只读靠约定，Git 检出在封存时核对指纹。被拒的权限请求另外记下它请求的工具与操作。开发者定：不为某个 harness 或某种组合单列拒绝。记在 [ADR-023](../../decisions/023-harness-integration-principles.md) 的 2026-11-06 修改里。

## 验收

- Worker 只查公开资料，没有读本机的 harness 主目录、配置或安装包。它第一次交付时，写入范围外的两个测试还钉着 ZCode 的只读是强制的；Host 核实路由与资格只看有没有这一档、不看强度，让它把测试改为钉住代码真正读的东西。它的代码注释引用了外部网址与别人仓库里的条目，按规矩改为引用我们的调研记录；它第一个提交的信息里也有那个条目，所以前三个提交压成一个 Host 提交整合。合并后 Host 跑受影响的测试，review 路由的一个测试还期望 `plan`；ADR-023 定各角色共用一套档位，所以交回它改为 `yolo`。
- 合并后的树上，受影响的 135 个测试文件、1,890 项通过。

## 安装前的检查

完整检查在 `17cb6f34` 上运行：385 个 Python 文件通过；`test_blackboard`、`test_checks_parallel`、`test_console_sessions` 三个文件失败，原因是 Host 用 shell 的 `&` 把检查挂到后台，这样启动的进程忽略 SIGINT，而这三个文件里的测试都要中断子进程。机制已复现：同样启动的 Python 进程报告 SIGINT 被忽略；正常重跑这三个文件，74 项通过。前端 108 个文件、1,311 项通过，打包资源与新构建一致。这一版没有推到 CI。

- 只验证了 macOS 上的 ZCode CLI 0.17.1；这一版的改动没有在 Linux 与 Windows 的 CI 上跑过。
