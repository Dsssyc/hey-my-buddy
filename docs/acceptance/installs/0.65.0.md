# 安装 0.65.0 的记录

2026-11-07，整合 Host。这一版改了契约，契约版本到 0.65.0：Router 的三个面只限模型开始作答之前的等待，四个 harness 统一报出“模型开始作答”，运行证据记下每次工具调用的成败，Router 的协议到 18。也改了存储形式，schema 37 升到 38。安装要求黑板空闲，并先做备份。开始前已告诉开发者。

## 内容

按 [Router 第五步的执行计划](../../design/adr021/router-step5-plan.md)，起因是 0.64.1 装上之后开发者的几次画像运行（[0.64.1 的记录](0.64.1.md)“装上之后”一节）：

- **画像建议只认同一个模型，撤回删掉最近一次改动**（同名微任务，ZCode `bigmodel-api-2 / GLM-5.3 / high`，两个回合；整合为 `72c62d46`、`008c0b5c`）。画像面的 Router 只能建议程序给出的候选里的同一个模型，名字不变的换代只由用户标出。撤回删掉这个模型服务最近一次改动：撤回要带上那一行的 `correspondenceId`，不是最新的一行就 `CONFLICT`；一次保存结束后，删掉没有任何引用的模型；37→38 一步把禁止删除的触发器换成只允许删一个服务最新的一行（[ADR-021](../../decisions/021-router-buddy-planes-and-routing-evidence.md) 第 24 条 2026-11-07 的修改）。
- **模型开始的事实统一并在运行中报出**（Codex `openai / gpt-6.1-sol / high`，四个回合；整合为 `bb554491`、`24021068`、`5bb7b53b`、`874d65cb`，Host 另删被替换的构建产物 `a8ad4340`）。四个 harness 都以根会话里模型的第一个输出报出 `modelResponded`，在运行中交给观察者；模型之前的重试只看请求是否发出；`inputFailure` 写第 2 版，读第 1、2 版；旧的 `modelStarted` 留在存量里，不再解释。
- **Router 调用只限模型开始之前的等待**（Codex `openai / gpt-6.1-sol / high`，六个回合；整合为 `3e494dff`、`251ae680`、`8cdade10`、`3a755254`，Host 合并时另有 `ae621fbf`、`cb157c6f`、`032c51a7`）。路由、维护、画像三个面都只限模型开始作答之前的等待，设置是 `modelResponseWaitSeconds`（整数 1–86400，默认 60）；开始之后不设时限与工具调用上限。执行进程自己在到点时取消并记 `router-not-responding`，路由面据此换列表里的下一位；预算文件的截止多 10 秒余量，调度器只作兜底。审阅的三档预算、快速的 60 秒与画像预算都删掉；`router-budget-exhausted` 只作旧记录的原因码留着。37→38 一步删掉 `router_settings` 的两列预算，加上等待（ADR-021 第 2、14、16 条 2026-11-07 的修改）。
- **运行证据记下每次工具调用的成败**（Codex `openai / gpt-6.1-sol / high`，两个回合；整合为 `b2eebff2`）。工具证据第 3 版逐次记成功、失败、未知，按工具名汇总；最近一次画像运行的汇总在读的时候算出，旧版证据写成未知。不改存储。
- **DSH 的两档改用白名单的写法**（Codex `openai / gpt-6.1-sol / high`，一个回合；整合为 `59539b42`）。只联网与不用工具两档启动之前读出 `acp` 配置档现有的 `tool-` 行（`--dump-default-config`，用 PyYAML 只组装节点），只留这一档要的，其余全关；读不出或认不出格式时只联网一档不运行并写明原因，不用工具一档照旧运行（[ADR-023](../../decisions/023-harness-integration-principles.md) 第 10 条，2026-11-07 开发者定）。
- **修好合并后失败的 6 个测试文件**（ZCode `bigmodel-api-2 / GLM-5.3 / high`，一个回合；整合为 `b205a840`）。会话内容的投影改用只做归类的 `classify_tool_name`，原来四个 harness 遇到很长的工具名都会让投影失败；其余是测试夹具跟上新代码，安装测试的运行时补上 PyYAML。
- **控制台跟上撤回与工具调用成败**（Codex `openai / gpt-6.1-sol / high`，一个回合；整合为 `0f066f45`，Host 另删被替换的构建产物 `ab362c16`）。撤回带上这一行的 `correspondenceId`；最近一次画像运行在用量下按工具名列出调用、失败与未知。Router 设置里的等待由上面的微任务改好。界面的重做以后再说。
- **参考文档跟上只限模型开始之前的等待**（ZCode `bigmodel-api-2 / GLM-5.3 / high`，一个回合；整合为 `e89f5707`），Host 另删一句早已过期的“等待安装”（`6e67e7db`）。
- 文档：ADR-021 第 2、14、16、24 条的修改（`54cb532a`、`480338b0`）；ADR-023 第 10 条（`501de88f`）；执行计划（`8d0cf1dd`、`50e7b95c`、`d8cefa12`、`e408449a`、`39acedfd`）；DSH CLI 0.2.2-rc.1 的复查（`217fa9c2`）；参考页（`f68bde62`、`2ea08357`、`59a729ac`、`4ee7acdb`）；README 的安装命令（`2f2555d5`）；0.64.1 的记录（`10f4df41`、`ea48b970`）；待办（`a5f40ad3`、`a942be30`、`ac29f7d7`、`55a2fddf`、`3f2795e5`）。

## 验收

- **画像建议与撤回**：这一批里有改删除路径的差异，Host 在第一轮交付时请 `claude / anthropic / claude-opus-5-5 / high` 做了一次盲审，双方互不看结论（输入 4,978,416 个 token，其中缓存 4,978,324 个；输出 31,810 个）。Host 核对后采纳 3 条，打回原来的微任务：撤回带上 `correspondenceId`、只撤最新一行；一次保存结束后统一删掉失去全部引用的模型，清空备注也算；模型的名字取现在的对应关系与执行记录；引用模型的表从 schema 读出。合并后受影响与下游的 16 个文件、255 项通过。
- **模型开始的事实**：Host 读完差异，合并后 45 个 Python 文件与前端 1,338 项通过。
- **Router 的等待**：Host 读完差异，并请 `claude / anthropic / claude-opus-5-5 / high` 盲审（输入 14,587,206 个，其中缓存 14,587,040 个；输出 70,658 个）。Host 核对后打回：调度器与执行进程用同一个截止，到点时调度器抢先强停，路由被记成取消，不会换下一位；等待没有上限，超过 `threading` 的等待上限会让调度器的监视线程崩掉；另有几处重复的核对与死代码。第二轮让执行进程先停、文件截止多 10 秒余量，等待限在 1–86400 秒，旧原因码留着；合并后的完整检查又查出 5 处没跟上（含导出样本的工具），第三轮修好。合并时 Host 解决了 5 个测试与构建产物的冲突，重新构建控制台，重钉 Router 提示的摘要（协议 18）。审查提出的另一处风险是 Claude Code 不开部分消息时，高档推理可能 60 秒内没有第一个输出，留给下面的真实调用去量。
- **工具调用的成败**：Host 读完差异，合并后 41 个文件通过。
- **DSH 的白名单**：Host 读完差异；插件的行在默认配置的输出里，依据是 DSH 的公开源码。合并后的回归由修正微任务修好，20 个文件、611 项通过。
- **控制台**：Host 读完差异，看了深浅两种主题、1440 与 390 宽的截图。
- **参考文档**：Host 逐处读了差异，抽查了用量与工具证据一致的核对、控制台的标签与路由事实的投影，与代码一致；文档检查与读参考页的 3 个测试文件通过。
- **真实调用**（开发者 2026-11-07 逐项批准，每项一个原生回合，经 `tests/probes/`，用开发者自己的 harness 配置与登录）。Router 的三次是只读档位的探针，量的是从开始等待到第一次报出模型开始作答的时间（轮询间隔 0.25 秒）：
  - DSH CLI 0.2.2-rc.1，`deepseek-official / deepseek-v4-flash / max`：15.2 秒开始作答，24 秒结束。
  - Codex CLI 0.164.0，`openai / gpt-6-luna / high`：18.5 秒开始作答，24 秒结束。
  - Claude Code CLI 2.1.312，`anthropic / claude-opus-5-5 / high`：6.5 秒开始作答，15 秒结束。
  - 三次都在运行中报出 `modelResponded`，没有被等待截断，进程的停止都已确认。写入要么被拒绝、要么没有写入工具；读外部文件的结果各 harness 不同，这不是这次要量的。
  - DSH 只联网一档，`deepseek-v4-flash / max`：启动补丁关掉 15 个 `tool-` 行与计划模式，只留 `tool-web`、`tool-working-directory`、`tool-executor-native`；模型只看得到 web_search、web_fetch 与 working_directory，读文件、命令、MCP 都做不到，搜索与抓取成功。输入 4,983 个（其中缓存 3,712 个），输出 5,400 个。
  - 但同一次运行的工具证据交给服务按只联网一档判定，结果是 `router-tools-forbidden`：这三个工具在归类表里都是 `other`，只联网一档只认 `fetch`。装着的 0.64.1 是同一张表，所以这不是这一版引入的；DSH 从 0.64.0 起就完成不了画像，此前它的画像都在更早的地方失败，没走到判定。探针不跑服务的判定，所以 0.64.0 的核实没发现。记进[待办](../../design/backlog.md)，随 0.65.1 修。

## 这一版的边界

- 模型开始作答的时间各 harness 只量了一次，任务是一个小的只读探针。真实路由的输入更长，Claude Code 高档推理在第一个输出之前想得更久时，仍可能超过 60 秒；那时它被记为 `router-not-responding`，列表换下一位。
- DSH 担任画像 buddy 仍然完成不了，见上面的真实调用；Codex 担任画像 buddy 在 0.64.1 上跑通过，Claude Code 担任画像 buddy 没有完整跑过。
- 撤回与删掉失去引用的模型只在测试与演练的副本上做过；日常黑板上那条错的 `gpt-6-sol` 对应关系等开发者在控制台撤回。
- 控制台只做了最少的接线，像素只在合成预览上看过。
- 只在 macOS 上验证；这一版没有推到 CI，没有在 Linux 与 Windows 上跑过。
