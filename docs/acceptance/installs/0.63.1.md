2026-11-06 13:45 UTC（北京时间 21:45），整合 Host。这一版只修一处缺陷，不改契约（仍是 0.63.0），不改存储形式（仍是 schema 36），按补丁安装，不要求黑板空闲，不做备份。从整合分支的提交 `ee0afbbe` 安装。

## 内容

**会话为空的证明在一次观察内完成**（微任务“会话为空的证明在一次观察内完成”，Codex `gpt-6.1-sol / high`，一个回合；整合为 `4ac68b1d`）。起因见 [0.63.0 的安装记录](0.63.0.md)的“装上之后发现的问题”：执行进程正常退出时，服务常短暂记一条 `EXECUTION_UNKNOWN`，0.63.0 的门铃会把它送给正在等的 Host。

证明会话已空仍要连续两次扫描都为空，但两次现在都在同一次观察里完成：第一次扫到空，当场再扫一次，两次都空才算已空；第二次看到成员就按第二次的结果。第二次的进程列表在第一次结束后才读，补的仍是第一次扫描时漏掉的子进程。原来不持久的检查和停止时的等待已经这样做，这次连同持久的观察者一起统一成这一种。只为跨调用的计数而存在的东西一并删掉：计数本身、打断计数的调用、调度器与句柄里把“空了一次”当成“未知”的映射、等待里对它的特殊处理。真正的未知照旧是未知：扫描失败、没有成员证据、Windows 上没有 Job 的根，结论都不变；执行已交回结果、还在等停止证明时，观察结果是未知，照旧记 shutdown 问题。

## 验收

- Host 读完差异（8 个文件），按原样整合。Worker 跑了任务书列出的 13 个测试文件，244 项通过；它第一轮有一个文件失败（新加的调度器测试夹具漏带一个字段），补齐后只重跑那个文件。
- 真实服务上的探针：在私有服务上跑 40 次很快结束的命令执行，统计 `execution.issue`。0.63.0 的源码（`300bf36a`）上，40 次里 18 次记了 shutdown 阶段的 `EXECUTION_UNKNOWN`；改后（`4ac68b1d`）0 次。两边 40 次都确认了停止。
- 隔离复现：用产品的进程句柄包住一个很快退出的子进程，改前每次都是 alive → empty → gone，改后只有 alive → gone。
- 变异：把证明减为一次扫描，4 个测试失败；换回跨调用的旧证明，新的真实进程测试因看到 `empty` 失败。
- 这一版删掉了停止证据里跨调用计数的那一种写法，所以并行请 `claude / anthropic / claude-opus-5-5 / high` 做了一次独立审查，双方互不看结论。它从代码推理出：证据没有变弱，没有哪条路径把未知当成已停，锁内多扫一次不会死锁，所有调用方都不依赖“只扫一次”或 `empty`。它的发现都在测试上，Host 核对过：新加的两条调度器测试替换掉了句柄的观察，在旧代码上也会通过，守住这次修复的是观察层的测试；第二次扫描时根已经失去进程号、又看到无法归属的成员，应当是未知，代码是对的，但缺一条测试。这两条记为下一批的顺带项。它另提到扫描只看同一账户的进程，这是早已存在的边界，没有发生过，这一批不处理。这次审查用了输入 1,182,371 个 token（其中缓存 1,182,343 个），输出 21,806 个（其中推理 14,070 个）。
