## 安装之前

  - **等待路由测试的竞态：** `test_ctwo_service.py` 的一条测试只在根检出里失败，这是测试本身的问题，装上的产品不受影响。
    - 机制：测试在任务离开排队时就读事件游标。执行进程报“executing”的那条事件，可能落在持有者占到等待名额之后、第二次等待之前，把持有者放走。
    - 根检出的虚拟环境里有依赖的预编译字节码，执行进程起得快，于是每次都撞上。新检出没有字节码，起得慢，所以通过。
    - Host 在隔离实验里复现：同一个新环境，预编译之前四次都通过，预编译之后两次都失败。
    - 修正：改为等尝试进入 executing 再读游标，由微任务“等待路由测试的竞态”完成（ZCode app 0.16.9，`bigmodel-api-2 / GLM-5.3 / max`），只改测试，在安装之后合入为 `a8aab192`。
    - 核对：根检出用它自己的虚拟环境跑三次都通过；有字节码与没有字节码的新环境都通过；让等待不再限定任务的变异被它抓住。
- **升级演练：** 验收时在日常看板的副本上做过，候选是 `f3dd3246`，结果见[验收记录](../adr023/shared-levels.md)。从它到 `d9e8df5d`，只改了 harness 层的五个文件，存储、升级与安装的代码没有动，所以没有重做。

## 安装之后：升级基点挪到 0.48.0

25 → 26 这一次升级已经在日常看板上用掉。同日由微任务“把升级基点挪到 0.48.0”（Codex CLI `gpt-6.1-sol / high`，一个回合）完成，合入为 `2fcc50fd`，之后没有待做的升级。

- **做了什么：**
  - 基点改为 `d9e8df5d`（schema 26），从它重新生成样板看板。生成器补上了路由认领与结果（应答与未应答各一条）、经文件交接的执行回执、会话记录、带改动的封存，以及越界之后的恢复记录。
  - 删掉用掉的转换、安装里的转换阶段与备份校验里的试转换；安装、启动与备份只接受 schema 26。
  - 顺带做掉备份那一批留下的几件小事：
    - 回滚只还原 `console-settings.json`：另外三个状态文件要么由回滚自己重写，要么在核验通过之后才写；
    - 备份校验不再试开一次看板，改为直接核对 schema 标记、完整性、外键与指纹；
    - 删掉同一份备份的第二次校验与 restore 里重复的恢复；
    - 失败时的措辞按有没有备份区分；
    - 补上“原生状态不写进执行证据目录”的反向断言，删掉钉着已删名字的测试与没有调用者的参数。
- **核对：**
  - 差异读过，删掉的核对逐条判为边界之内的重复。创建备份之后的第二次校验与快照合并本来不改变任何值：两份快照算法相同，取自同一块停下的看板。试开能拒绝的东西，现在都直接查了。
  - 合并后的源码上，受影响与下游的测试 112 个文件 1,617 项通过。
  - 在日常看板的副本上演练：先装 0.48.0，候选的契约临时调高到 0.49.0，以便走改契约的安装。
    - 正常安装 10 秒完成，备份只含看板与 `console-settings.json`，装后核验指纹一致；
    - 让候选的服务一启动就退出：安装回滚，回复说“Upgrade failed; the previous runtime and backup were restored”，与实际相符，0.48.0 重新稳定运行，数目、完整性与状态文件都复原。
  - Opus 独立审查（Claude Code CLI，`claude-opus-5-5 / high`，只读检出，run `6aef064b`）：没有阻塞项。只读一档没有 shell，它读不了差异，逐条比对由 Host 完成。它报的残留由 Host 核实后记进待办。
- **消耗：** 实现方输入 1,067 万（命中缓存 1,037 万），输出 3.0 万；独立审查输入 456 万（几乎全部命中缓存），输出 4.7 万。
- **安装：** 这一批改了安装与备份的代码，契约与存储形式不变。下一次改契约的安装才用得到它们，所以不为它单独装。
