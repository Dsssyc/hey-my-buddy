# 安装 0.66.0 的记录

2026-11-08，整合 Host。这一版改了契约，契约版本到 0.66.0：Host 面的 `conclude` 能直接结束还在运行的工作，ZCode 与 DSH 的 Worker 在结束之后再调用工具不再让回合失败。不改存储，schema 仍是 38。安装要求黑板空闲，并先做备份。开始前已告诉开发者。

## 内容

按 [0.66.0 执行计划](../../design/adr032/conclude-and-finish-plan.md)，起因是一个 Host 取消了不再需要的微任务就离开了，那个微任务一直停在“等 Host”（[待办](../../design/backlog.md)“委派与 Worker”一节），以及 ZCode 的 Worker 在结束之后调用了待办工具、整个回合判失败：

- **结束直接停下运行中的工作**（同名微任务，Codex `openai / gpt-6.1-sol / high`，三个回合；整合为 `57876183`、`5e44997a`，Host 另删被替换的构建产物 `dfb712f6`）。服务一侧把 Lead 原有的“先取消，停止没确认就返回 `SHUTDOWN_UNCONFIRMED`”推广到每个微任务：排队、运行、停在边界或正在停的，先走与 `cancel` 相同的取消与有序收尾；取消之前对整棵树查会被取消弄得解不开的条件（打开的工作区冲突、未决的续接），有就拒绝，什么都不取消；已经失败或交付的保留记下的结果，只请求停下。CLI 一侧的 `conclude` 复用 `await` 的分片等待与升级交接，等到整棵树停下再重发同一请求，等待用与 `await` 相同的 `waitSeconds`；到时停止仍未确认，回复写明取消已记、结论没记。名下的成员随之结束：Lead 的用 `lead.owned-concluded`，普通 helper 树的用新的 `micro-task.owned-concluded`，Host 的说明只记在目标上（[ADR-032](../../decisions/032-host-interface-delegation-loop.md) 第 1 条 2026-11-07 的修改）。第一回合停下来问：契约改成 0.66.0 时项目版本要一致，Host 把版本号所在的四个文件加进写入范围。
- **结束之后的工具调用记成事实**（同名微任务，ZCode `bigmodel-api-2 / GLM-5.3 / high`，一个回合；整合为 `9cd1bd8d`）。ZCode 与 DSH 以结果通过校验那一刻固定的结束回执为答案；此后的根工具调用，包括再一次结束调用，以及结果之前重复的结束调用，记进回合 `provenance` 的 `postFinishToolCalls`，不再判 `duplicate-finish`；结束工具对回执固定之后的调用照实回答 `turn-ended`。ZCode 的结束调用还没有结果时插进别的工具，仍判失败（[ADR-030](../../decisions/030-harness-layer-scope.md) 只保留三类拒绝）。
- 文档：ADR-032 第 1 条的两条修改，其中一条是开发者确认的界线“微任务的去向只由 Host 决定；用户在控制台只能停止，或删除整个宏任务”，以及 ADR-021 第 21 条一句过时理由的更正（`eacf4ed6`、`cc1b9008`）；执行计划（`eacf4ed6`）；参考页（`975e9443`、`eaae5f3a`）；待办（`728c5a4b`、`2dd9e40a`、`cc1b9008`、`a58d5082`、`5991fbcd`），其中有开发者 11-07 提出的宏任务暂停与继续，方向已定，排在以后。

## 验收

- **结束直接停下运行中的工作**：这一处动了停止与结论的路径，Host 在第一轮交付时请 `claude / anthropic / claude-opus-5-5 / high` 盲审（输入 5,070,999 个 token，其中缓存 5,070,915 个；输出 50,186 个），双方互不看结论。审查指出 1 处会出错、4 处应改与几处可以顺带；Host 读代码核对了两处重的：后代的工作区冲突要到取消之后才查，而取消会关掉解冲突要用的请求、祖先取消之后续接又被拒绝，这棵树就结束不了；已经失败而停止未确认的目标，取消时被改写成取消，结论记成取消。Host 在合并后的树上跑受影响的 186 个文件，又查出新测试在模块顶层导入了带测试的类，有 17 项被排了两次，完整检查会不过。这些连同 CLI 对结论是否记下的说法、重试时重复写后代的取消事件、普通 helper 级联结论与 Host 直接结论分不开，打回原来的微任务；第二轮逐条先用测试复现再修，还修了它自己查出的同类问题：Router 的停止请求在重试时也重复写事件。合并后 blackboard、cli、protocol、console 268 个文件 3,510 项通过；前端 1,345 项里会话面板的一项在全量里失败过一次，单独重跑三次都过，这一批没有动它，记为偶发。
- 原计划在私有服务上像 Host 那样做一次付费实测；实现方的 `tests/python/blackboard/tasks/test_conclude_service.py` 已经在真实的私有服务、执行进程与 CLI 上，用离线的 ACP 夹具跑完“运行中直接结束”：取消、等待、真实进程的停止、封存与回收检出，并做了停止一直确认不了时的故障注入（超时不记结论，放行之后再调一次完成）。它在 Host 的运行里通过，所以没有做付费调用。
- **结束之后的工具调用**：Host 读完差异与报告，合并后受影响与下游 157 个文件 2,649 项通过，含排程检查。

## 这一版的边界

- `conclude` 直接结束运行中的工作，只在测试与私有服务上用离线夹具跑过，还没有在真实的 harness 上被 Host 用过。
- 新的原因码 `micro-task.owned-concluded` 的中英文字只在单元测试里核对过；合成预览里没有 helper 随父任务结束的例子，像素上没有看到。
- ZCode 的结束调用还没有结果时插进别的工具，仍判失败。
- 失败之后、或停在边界时 Host 离开，微任务仍会停在“等 Host”；补救是任何一个 Host 会话替它下结论，或删除整个宏任务（开发者 2026-11-07 定，不另做机制）。
- 只在 macOS 上验证；这一版没有推到 CI，没有在 Linux 与 Windows 上跑过。
