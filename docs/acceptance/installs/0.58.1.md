## 内容

- **没结束的失败与取消算等待 Host**（微任务“没结束的失败显示为等待 Host” `b9fa1c94`，合入 `2fd94463`；依据是 ADR-016 2026-10-31 的那一段）：
  - 失败或取消、还没被 Host 结束的根微任务，在它自己的执行停下之后，计入宏任务列表、计数、“等待 Host”筛选、顶栏的待处理数与详情头，用手形标记，词里仍说失败还是已取消。
  - 停止还没证实的仍算进行中；Lead 名下的算等待 Lead；helper 失败或取消之后由父微任务接手，保持原来的样子。
  - 只有被结束为失败的才计入失败。
  - 控制台不提供结束或续做的操作。
  - 顺带：删除宏任务撞上正被占用的检出时，对话框说明稍后重试，不再显示原始的错误码。
- **它漏改的一个下游测试**（微任务“修 Host 等待计数的下游测试” `f1a6e483`，标为修正上一项，合入 `c6789264`）：取消之后的回复带 `waitingForHost: {"host": 1}`，是新规则下应有的结果，测试原来断言没有它。
- **Windows 测试欠账第一批：测试自身的问题**（微任务“Windows 测试欠账：测试自身” `813e7825`，合入 `b3ece25d`）：8 个测试文件只改测试，各修在自己的原因上：UTF-8 的读取与子进程解码、浮点容差、关闭 SQLite 连接、POSIX 记录的停止用例在 Windows 上跳过、假观察器改用各平台都有的信号、LF 写入。
- **skill**：
  - 写明失败或取消的工作在续做或结束之前一直占着检出（`244aee1c`）；
  - 这一句曾让 SKILL.md 超出 4 KB 的预算，`50623949` 压回 4,093 字节。
- **记录**：

## 验收

- **等待 Host 的显示**，两轮：
  - 第一轮打回三处：
    - helper 也被算成等待 Host。根验收之后，它们会让宏任务一直挂在等待 Host 下。
    - 停止还没证实的取消也被算成等待 Host。
    - 顶栏的待处理数没跟上新规则。

    Host 在封存的树上直接调用分类函数，复现了前两处。
  - 第二轮之后，Host 在合并后的树上单进程跑了：
    - 受影响与下游的 19 个 Python 文件，298 项通过；
    - 两处有针对性的变异（去掉根层的限制，去掉执行停下的条件），都被测试抓住；
    - 前端全量 102 个文件，1,258 项通过；
    - 浏览器检查 726 项通过（`7daad3a3`，之后控制台没有再改）；
    - 七张截图看过，含 helper 的行。
  - 顶栏的数改用与筛选同一个判断。Host 在日常黑板上只读对照过查询计划，仍走 state 索引。
- **Windows 第一批**：
  - Host 读完差异；本机单进程跑这 8 个文件，通过。
  - `test_process_members` 里一个真实进程的计时用例，在别处的编译把负载推到约 119 时失败过一次，重跑两次都通过；这批改的是它的假观察器用例。
  - 它在 Windows 上的结果由实现方自己跑出，不算验收。第二批的 Worker 在测试机上独立复跑了这 8 个文件：7 个通过；`test_lead_workspace.py` 的补丁应用用例仍失败，第二批查明原因在测试夹具的 Git 设置，修正不在这一版里。
- **SKILL.md 超出预算**：是 Host 自己改 skill 时只跑了文档检查造成的，由 Windows 第一批的 Worker 在基线全套里发现。
