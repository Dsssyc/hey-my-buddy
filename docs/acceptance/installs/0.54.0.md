## 冒烟：新版本上的第一个真实微任务

微任务“Windows 发版前最终复跑”（run `c9b7c68b`）经路由，Router 以快速模式选了 Codex CLI 的 `gpt-6.1-sol / max`；一个回合约 64 分钟，交付、停止确认，用量照常记下（输入 1,254 万，其中缓存 1,240 万；输出 8.3 万）。它的路由决定以当前形式写下（带 `overloadedModelServices` 与 `coolingBuddies`，不带两个计数），尝试结果没有 `quotaFailure`。补丁为空，Host 以不需要整合的方式验收，原样输出留在整合工作树被忽略的 `tmp/storage/win-final-0540/`。

它在测试机（Windows 11 专业版 x64，内部版本 26200，代码页 936，`LongPathsEnabled` 为 0，开发者模式未开）上对 `4a9fce3e` 跑完整检查：Python 334 个文件里 333 个通过，共 5,095 项（跳过 128 项）；前端 95 个文件 1,129 项通过，打包的控制台资源与新构建相同。唯一的失败在测试里：`install.test_upgrade_archive` 的 `setUp` 用普通路径读样板写下的一个 267 个字符的文件，没有长路径支持时读不到；样板的加载器与产品都经 `native_path`。CI 的 Windows 运行器开着长路径，没有分辨出来。修正只动测试与 CI（另一个微任务），不改进包的文件。

联接的说法在真机上核实了：一个进程先从自己的令牌里去掉 `SeCreateSymbolicLinkPrivilege` 并确认它已不在，再用产品的 `WindowsFileAPI().junction` 建目录联接，经联接读到目标里的文件；同一进程里 `os.symlink` 报 WinError 1314。SSH 的提权令牌带着这项权限，所以只有去掉它才证明得了“不需要开发者模式，也不需要创建符号链接的权限”。
