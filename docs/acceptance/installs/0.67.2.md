# 安装 0.67.2 的记录

2026-11-10，整合 Host。补丁版本：契约仍是 0.67.0，存储形式仍是 schema 39，不需要黑板空闲，也不做备份。这一版只改控制台，带上开发者在 0.67.1 上看过之后定的几处修改（[重做计划](../../design/adr029/buddy-router-redo-plan.md)“0.67.1 之后”）。

## 内容

微任务“Router 记录的区域、左边列表与升级后的刷新提示”，Codex `openai / gpt-6.1-sol / high`，两个回合；整合为 `fd18348c`、`690940ea`，Host 删去旧构建产物并改文档 `6e479fa2`。

- **记录放进固定高度的区域**：路由的最近失败、维护的轮次与画像的记录各自在大约六行高的区域里滚动，最新的在上，正在跑的一轮维护固定在最上面，表头不动；领域树因此就在记录下面。
- **Router 左边三项工作收紧**到与评价分区左边列表相近的密度。
- **升级之后提示刷新**：控制台的读取带上服务运行时的标识，开着的页面发现它变了，就在顶栏下面提示“控制台已更新，刷新后使用新版本”并给出刷新按钮。只在控制台自己的读取里，不动 Host 一侧的契约。
- **目录的模型行去掉行首的箭头**，整行就是按钮，悬停与打开时的底色与评价分区的列表一致。
- **设置的问号圈点得开**：原来用的是悬停提示，按下就关，点击什么也打不开（开发者报的缺陷）；改成点击开合的浮层，默认模式那行说明发给提供方什么的小字收进它的问号圈。
- **Router 记录里的失败写成短话**：路由、维护与画像的记录能记下的失败码补了 57 条中英文说法，认不出的码写一句通用的话，原码在悬停里；加了一项测试守住每个会产生的失败码都有说法。
- 顺带：复制编号的按钮点击区放大到 24 像素。
- **控制台的运行时标识由服务传入**（微任务“控制台的运行时标识由服务传入”，同一个 buddy，一个回合；整合为 `1922b044`）：安装前的完整检查在 `install/test_upgrade_ipc.py` 失败，因为刷新提示让控制台在构造时自己调用 `resolve_runtime()`，测试里不完整的运行时记录一碰就抛错。改为守护进程把启动时记下的运行时标识传给控制台，快照字段统一叫 `runtimeIdentity`，控制台不再导入安装模块。

- 第二轮 Host 在另建的工作树里跑前端 115 个文件 1,432 项、浏览器全量 905 项与控制台 Python，全部通过。日常控制台的只读快照在新构建里回放：问号圈点击打开、按 Esc 关上；维护的记录收在区域里，失败写成“harness 拒绝了任务提示”；目录的模型行没有箭头。深浅两色都看过。
