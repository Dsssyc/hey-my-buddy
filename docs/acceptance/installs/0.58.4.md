## 内容

微任务“Windows 测试欠账：产品侧” `3182a9e3`（四轮，合入 `1c075934` 与 `03682085`）：

- **宏任务删除不再把“跳过”当成“已删除”。** 任一物理阶段有跳过或出错，删除停在 `deleting`，业务行与删除标记都留着，同一个 deletionId 重试接着删。失败清单列出每个被跳过的对象，带路径与原因；系统错误另带 errno 与 winerror。
- **仓库不在原位置时删除照常完成**（开发者 2026-10-31 定，见 ADR-028 那一段）：仓库被删、被移走或换成别的仓库时，只凭黑板私有区的分配记录清掉这个宏任务自己的检出与记录，不调用 Git，也不碰那个路径上换上来的仓库；权限不足等其他读取错误照常让删除失败。
- **被占用的检出删到一半之后能收敛。** 先删检出的文件，原来带锁的 Git 登记留到文件删完再删；删不掉时计划停在 applying，fence 与服务问题都在，下一轮维护接着删。续做时，封存时没变、已被删掉的排除文件算作删除进度。
- **Windows 上带只读属性的文件与目录**经句柄删除，不改同一文件别的硬链接的属性，遇到联接或其他重解析点就拒绝。
- **准入挡住别的宏任务借用正在删除的受管检出**，包括经子目录或嵌套仓库借用。
- **删除对话框如实说明**：已开始的删除重开时显示“删除已开始”并给出重试；失败时逐项列出对象、路径、原因与能否靠重试解决。
- **私有状态内的删除只查叶子**：第三轮一度加上的祖先链接检查删掉了，`_delete_cli_files` 里早就有的两处同类检查一并删掉（经链接搬走的 `controls`、`submissions` 原先会悄悄留下文件却报告已删除）。
- **测试运行器**只留一个 `TemporaryDirectory` 机制（删掉 `tests/python/temporary.py`），Windows 上被推迟的夹具清理（错误 5、32、145）列在汇总里，退出码的规则不变。
- **Windows 上测试自身的问题**：夹具仓库的换行规则、中断夹具的 site 目录、升级样板的分配身份等。
