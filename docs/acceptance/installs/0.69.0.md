# 安装 0.69.0 的记录

2026-11-12（北京时间；UTC 2026-11-11 18:18），整合 Host。这一版改了存储形式与契约：schema 40 → 41，契约版本到 0.69.0。

- **暂停、继续与结束：** 控制台的停止换成三个动作（[ADR-033](../../decisions/033-macro-task-pause-resume-end.md)，开发者 2026-11-11 定）。暂停用 harness 自己的中断停下回合、挡住排队的工作；继续由黑板自己续接；结束给没了结的微任务写上用户的结论，已交付的留给 Host。
- **暂停的记号：** 暂停在控制台里是一个状态记号，两道竖线（[ADR-029](../../decisions/029-console-frontend-foundation.md) 第 8 条，开发者 2026-11-12 定）。

安装要求黑板空闲，并先做备份。批次开始前已告诉开发者。

## 内容

宏任务 `macro-88403013`“宏任务的暂停、继续与结束”，按[执行计划](../../design/adr033/plan.md)分两个微任务。

- **服务、存储与 Host 面**（`6c259c40`，Codex `openai / gpt-6.1-sol / high`，四个回合；整合为 `954df938`、`1a4f3eff`、`aab493df`、`280d895c`，Host 另删被替换的构建产物 `75540fc1`）。
  - 新一步 40 → 41 自带定义：新表 `work_pauses`，每个暂停的单位一行（宏任务或独立微任务，两个外键恰好一个不为空）；`attempts` 重建，加上 `stop_purpose`（`pause`、`end` 或空），存量一律为空。
  - 控制台操作 `macro_task_pause`、`macro_task_resume`、`macro_task_end` 取代 `macro_task_stop`。暂停时，Codex 与 DSH 用 harness 自己的中断，ZCode 与 Claude Code 直接强制停下；被中断的微任务记下一次挡住的续接，输入是 `buddy/roles/texts/` 里的一段固定文字。结束等停止确认之后才写结论，确认不了的不写。
  - 回合的结束原因加 `pause`，任务的排队原因加 `paused`；`get` 的宏任务视图带 `paused`，`await` 在因暂停中断时返回一次 `paused`。
  - 计划里读代码推出的那处缺陷（排着的续接被停下之后，之后的 `continue` 要么重放旧回复要么冲突）先写测试复现，再在 `_continue_replay` 的根因处修好。
- **控制台**（`33582ab8`，Codex `openai / gpt-6.1-sol / high`，五个回合；整合为 `44c19ba0`、`56c034b6`、`705417d8`、`8bff3e08`，Host 另删被替换的构建产物 `438071c4`、`c3c0e0d4`、`80260331`）。
  - 视图的 `paused` 是 `{pausedAt, shutdownConfirmed}`，后者在单位里每个执行（含 helper、Lead 名下的微任务与 Router 调用）都证明停下时为真，停止证明只用 `micro_task.UNCONFIRMED_STOPS_SQL` 一套定义。计数里 `unfinished` 是结束会了结的成员数，取代只为旧停止对话框而设的三个计数。
  - 三个动作的回复都只是回执 `{macroTaskId, duplicate}`，界面从视图读结果。
  - 页头统计里“进行中”在暂停时换成“暂停中”（呼吸）或“已暂停”，数字照旧，没有在跑的工作时不带数字；列表的行优先画暂停记号；被暂停挡住的微任务在行与详情头里写“已暂停”；被暂停中断的回合，条末画同形的标记。结束只有确认对话框，确认按钮在等回复时转为忙碌；没有结果的文字，结果由计数与各行的状态表达。
  - 页头与它的菜单只用一份摘要：时间轴读到了用时间轴的，之前用列表那一行。
  - 摘要缓存的复用标记加上单位的暂停行，以及暂停时单位里每个执行的停止证明。这是第一个微任务留下的缺陷，见下面的验收。

## 验收

- **服务一批：** 第一个回合在 Host 授权改合成预览之后继续；第二个回合从事件的时间推断暂停的意图，结束的栅栏也从事件来，打回一轮，改为在 `attempts` 上明记 `stop_purpose` 并删去栅栏；第三个回合缺新的原因文案，完整检查不过，Host 的任务书没把 `apps/console` 放进范围，补上开发者批准的文案后打回一轮。最终完整检查通过（Python 5,888 项，前端 1,456 项）。
- **一处第一批验收时漏掉的缺陷：** Host 写控制台的任务书时发现，宏任务列表在缓存热的时候不随暂停变化：`get` 与时间轴都显示暂停，列表仍是 `paused: null`。Host 在隔离的测试里复现之后，修正随第二批合进来，候选上复跑同一个实验，列表随暂停与继续立刻变化。
- **控制台一批：** 前两个回合停在边界上，问的都是 Host 任务书里没核对过的话：
  - 视图里原来分不出“暂停中”与“已暂停”。Host 定了停止证明、`unfinished` 与回复的形状。
  - “停止未确认的可以用同一请求重试”其实只会重放回执。Host 定为重新确认当前范围、发一次新的结束。
  - 第三个回合交付后，开发者看了像素，觉得文字太多（结束后多行的结果、列表与页头里的“已暂停 · 时刻”），改为暂停记作计数里的一项状态，样稿开发者看过并同意。Host 原想把暂停的时刻放进悬停提示，违背 ADR-029 第 11 条，用问询当场更正。
  - 第四个回合交付后，浏览器全量里 `header-controls` 的中英文两项失败：页头改成了“列表与时间轴谁新用谁”。Host 定为页头只用时间轴那份摘要，打回一轮，比较读取时间的代码一并删去。
  - Host 读差异时看到的两处，没有打回：结束逐项写结论时接住了所有 `BoardError`（记进待办）；“列表刷新时不让打开的详情消失”的快照随这次删掉，只剩选中之后、时间轴读到之前的一瞬间没有保护。
  - **最终：** 合并后的树上完整检查通过（Python 412 个文件、5,895 项，前端 119 个文件、1,461 项，打包资源与新构建一致）；浏览器全量 1,173 项通过。全量里 `time-stats-r13` 失败过一次，单独重跑与之后的全量都通过，像是负载下的时序问题。
  - **像素：** 在合成预览、导出的真实样本与真实调用上，深浅两色、中英文都看过：页头的“暂停中”“已暂停”与不带数字的那一项、列表的暂停记号、被挡住的行、结束确认的忙碌状态。
- **真实 harness：** 开发者批准 Codex 与 DSH 各跑一个小微任务，暂停之后继续。
  - 第一次放在演练的环境里（空的 HOME，清掉了 harness 的环境变量），两个回合都没走到模型：DSH 报没有 `deepseek-official` 的 API key，Codex 以 `harness-error` 结束而没有留下细节。这次没有验证到什么。
  - 开发者同意之后，在候选源码起的私有服务上重跑，用真实的 HOME，状态与运行时目录私有、新建，只启用 `codex / openai / gpt-6-luna / high` 与 `dsh / deepseek-official / deepseek-v4-flash / off`。两边都在执行命令时暂停（Codex 的 `commandExecution`，DSH 的 `bash`）：刚暂停时视图是暂停中，`await` 返回 `paused`；第一个回合记为 `interrupted`，结束原因 `pause`，排队原因 `paused`；继续之后第二个回合 `resumeMode` 为 `native-session`，会话 id 与原会话相同，两个微任务都交付了。
  - 消耗：Codex 两个回合输入 119,463 个 token（缓存 88,320），输出 763 个；DSH 输入 55,126 个（缓存 34,560），输出 644 个。

## 安装前的检查

- **完整检查：** 在 `80260331` 上跑，退出码 0（见上）。之后只改了记录（`b86bb9a1`），没有重跑。
- **升级演练：** 用的是从日常黑板只读导出的样本（schema 40：168 个任务、330 次 attempt、49 条路由决定、4,311 条事件，31 个宏任务与 7 个独立微任务，所有 buddy 都未启用）。以 0.68.1 的 `d0319e74` 为基线，经启动器在空的私有 HOME 里安装。
  - **无故障：** 7 秒装完，备份已校验，schema 41。变了的只有 schema 版本、`attempts`（多了 `stop_purpose`，全为空；330 行原有各列连同 rowid 逐行相同，7 个索引都在）与新的空表 `work_pauses`；外键没有违反，完整性 ok；40 个 Host 视图只差契约版本。
  - **Host 面：** 经私有控制台暂停、继续与结束一个新建的宏任务，以及样本里的一个宏任务和一个独立微任务：回复只是回执，同一请求重放得到 `duplicate: true`；暂停后热缓存的列表、时间轴与 `get` 一致；重启服务之后暂停仍然有效；结束给等 Host 的微任务写上 `macro-task-ended` 的结论，暂停随之解除。
  - **故障注入：** 服务停着时，在私有黑板的副本上把暂停单位里一个成员的执行改成停止未确认，候选的读函数立刻把它读作暂停中。演练在候选 `d0d10b79` 上另跑了三种故障，都回滚：40 → 41 在重建并填回 `attempts` 之后失败，`UPGRADE_ROLLED_BACK`；新服务起不来，`UPGRADE_START_FAILED`；启动时篡改一条事件，`UPGRADE_VERIFY_FAILED`。三次黑板都留在 40，71 张表的摘要不变，Host 视图逐叶相同。这三种故障检验的是安装与 40 → 41 这一步，之后的提交没有改它们。
