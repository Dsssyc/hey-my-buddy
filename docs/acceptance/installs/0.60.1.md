# 安装 0.60.1 的记录

2026-11-04 14:03 UTC（北京时间 22:03），整合 Host。这是补丁版本：契约仍是 0.60.0，存储形式仍是 schema 34，所以不要求黑板空闲，也不做备份。从整合分支的提交 `386762aa` 安装。

## 内容

0.60.0 装上之后，第一次推到 `ci/0.60.0` 的 CI（run `41778224722`）在每个系统上都有失败。日常环境是 macOS 与 Apple Git 2.54，不受影响。这一版是三轮修正，都在宏任务"0.60.0 的跨平台失败"里。

- **诊断**（只读，`d094f9f1…`）：13 个原因，其中 4 个在产品里，其余在测试里。
- **产品侧修复**（`3db6d8c1…`，合入 `bd50b93c`）：
  - Git 2.56 把"不是仓库"说成 `gitfile does not point to a valid repository`，旧代码只认 Apple Git 2.54 的说法。现在 Git 以 128 退出之后，按目录结构证明仓库不在，不再比对错误文字。
  - 删除、回收与工作流清理，过去在什么都没准入时没有下界。现在三处共用一条：分配目录里 `request.json` 的修改时间（`allocation_created_at`）。`first_execution_time` 与它的 SQL 一并删掉。
  - 实际失败过的两类私有路径，在 Windows 上超过 260 个字符时改经原生拼写：`workspaces/<ws>/outputs/` 之下，以及原生会话的绑定与记录。
  - 导出工具的记录路径改用正斜杠。
  - ZCode 拒绝反向请求时的 `-32601` 文字，不再说要 attention。
  - 删除路径改动过，按开发者的规矩，交付后由黑板上的 Opus 5.5 独立审查（`031d5e46…`）。审查没有发现删除安全的问题，发现了一处 Windows 上相对 gitfile 目标的缺陷与四处小问题；退回修正之后才合入。审查用量：输入 7,342,852（其中缓存 7,342,740），输出 56,757。
- **测试侧修复**（`eb53f805…`，合入 `cb3b0883`）：长路径、编码、只读的 Git 对象、`.lock` 的读取、联接的错误码、链接对象的斜杠、时区替身。
- **Worker 角色文字**（`6f925698…`，合入 `68dfeaf2`）：加了一句"项目的文件与历史用项目自己的词，不用黑板的词"。钉着提示词哈希的测试由修正微任务 `e553abef…` 跟上（`6dad09bc`）。
- **第二轮**（run `41800507042`）：
  - Windows 上清理测试的长路径，与 macOS 上 README 预览冒烟的超时（`24a160ce…`，合入 `29c07aa5`；预览服务器像产品的控制台一样不再查 FQDN）；
  - Linux 上控制台的两处布局（`1dd4dd2c…`，合入 `6708aff5`）。
- **控制台：** 时间轴画到视口的右边缘（`7fe10fe8…`，`87323bc3`）；README 截图换成现在的界面（`78f35c70…`，`18d45d9d`）。
- **第三轮**（run `41820335798`，只有 Windows 的 5 个分片失败）：
  - `test_schema_32_33` 的修正（`5c75213c…`，标为修正 `24a160ce`，合入 `89329392`）：清空的是哪个仓库，取决于两个 id 的排序。轮到夹具仓库时，它的输出 ref 完整路径约 265 个字符，CI 关了长路径，测试自己的遍历与删除改经原生拼写。上一轮按"边遍历边删"修的假设不对。
  - 三处计时余量（`6fe44803…`，合入 `c4308b14`）：ZCode 反向请求的用例改为期限 30 秒、上限 15 秒；Codex 期望成功的用例期限由 3 秒改为 30 秒；public_state 的就绪等待改用共用的 180 秒。
  - 回收的盘点不再把 `workspaces/` 的修改时间当变更戳（`361d7f5e…`，合入 `386762aa`），每 60 秒一次盘点都重新列目录。依据是 Windows 测试机上的实验（`78ecf774…`）：在 NTFS 上建一个子目录再马上删掉，父目录的修改时间 200 次里有 99 次不变；隔 1 毫秒时 2 次不变，隔 2 毫秒以上 0 次；删掉的名字 1800 次里一次也没再列出来。

文档也随这一版一起，都不改产品行为：README 重写；术语表的"三方交叉验证"；调研笔记 `docs/research/2026-11-04-delegation-landscape.md`（开发者审阅后改过一次）；ADR-021 执行计划的现状表按源码重核。
