# 安装 0.64.1 的记录

2026-11-07 06:50 UTC（北京时间 14:50），整合 Host。这一版只改说给模型的话，不改契约（仍是 0.64.0），不改存储形式（仍是 schema 37），按补丁安装，不要求黑板空闲，不做备份。从整合分支的提交 `c02c9da6` 安装，它在 `dd0e9b2b` 之上只多了 ADR-021 与待办的文档改动。

## 起因

2026-11-07 开发者在日常黑板上为 gpt-6.1-sol 构建画像，画像 buddy 是 `dsh / deepseek-official / deepseek-v4-flash / max`，画像预算“深入”（600 秒、64 次工具调用）。两次运行都以 `router-budget-exhausted` 失败，都是工具调用到了 66 次，用时 341 秒与 336 秒，没有到时限；开发者从界面上读成了超时。Host 只读核对日常黑板：

- 01:27Z 那次只有一个会话：搜索 52 次、抓取 14 次，没有交出答案。
- 05:13Z 那次第一轮用了 31 次（搜索 19、抓取 12）后交出答案，被打回，错误全是 13 条说法的 `sourceDate` 不是 `YYYY-MM-DD`；打回后新开的会话又用了 35 次（搜索 21、抓取 14）。

原因在产品里：校验（`blackboard/routing/profile_data.py` 的 `validate_answer`）要求日期是 `YYYY-MM-DD`，给模型的说明却只写了要有来源日期；输出格式里日期只是不超过 10 个字符的字符串，共用的格式子集没有 `pattern`，写不进去；打回时还叫它“需要时重新联网调查”。模型只能在被打回之后才知道格式。第二轮的 35 次调用用在哪里，记录里只留了工具名；按错误全是日期，推断是在重新找日期。0.64.0 验收时 Codex 在私有服务上的那次画像也被打回过一轮，Host 当时没有查它被打回的原因。DSH 在这台机器上抓网页会被拒（[0.64.0 的安装记录](0.64.0.md)），只能靠搜索摘要，完整的日期更难找到；这两次的记录只有工具名，没法逐次确认。

## 内容

**画像调用写明校验的格式**（微任务“画像调用写明校验的格式”，ZCode `GLM-5.3 / high`，一个回合；整合为 `a7297e02`）。画像的说明加上：每个候选只建议一次；来源链接是 http 或 https 的绝对地址；来源日期是来源自己给出的发布或最后更新日期，写成 `YYYY-MM-DD`；来源没有完整日期的说法或建议不写，不猜日子。打回的话改为只改错误指出的地方、其余不动，改不了的条目去掉，不再叫它重新调查。包的版本到 0.64.1，README 的安装命令跟着改（`dd0e9b2b`）。
