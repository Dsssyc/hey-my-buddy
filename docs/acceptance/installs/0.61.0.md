## 内容

ADR-032：Host 面只覆盖委派那一圈。逐项的验收在 [ADR-032 的验收记录](../adr032/adr032.md)。

- Host 面是十个命令：`create`、`amend`、`submit`、`await`、`get`、`inquire`、`continue`、`accept`、`conclude`、`cancel`，另有 `help` 与 `console`。Host 不再持有控制凭据，回复写明下一步的 id 与合法的命令。
- 项目成为一等的记录，分 Git 仓库与普通文件夹；宏任务可以先建、后提交微任务；不带检出的微任务直接在文件夹里做。
- Git 交付保留 Worker 的提交，干净的三方合并直接验收。
- `relocate` 记录项目的新位置；Worker 与 Lead 的角色文字随之改写。
- 点名 buddy 用控制台的写法 `harness / provider / model / effort`。
- 控制台加了项目与交付的视图，并做了开发者改定的五处：会话标签不设页头，联动跟随选择，打开微任务前后同一底色，详情顶栏与栏头对齐，成功提示约 4 秒后淡出。
- 34 → 35 生成项目记录，删去 Host 控制的字段，回收证据里抄来的控制字段一并删掉；事件、封存内容与按摘要绑定的内容保留原字节。
- skill 与参考文档按新的 Host 面重写，加了各 Host 共用的等待指南 `host.md`。
- 导出工具带上所选运行的回收计划，源里检出还没回收的运行不进样本。

## 这一版的边界

- 日常环境是 macOS。Windows 与 Linux 只有 CI，没有真实使用。
- Windows 上，封存的 ref 在仓库路径较深时会超过 260 个字符；产品自己的 Git 调用都打开了长路径，但在另一个克隆里 fetch 这个 ref 时，源仓库也要打开 `core.longpaths`。产品自己不做这样的 fetch，Host 按提交整合时也用不到。
