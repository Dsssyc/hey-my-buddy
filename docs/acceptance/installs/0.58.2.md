# 安装 0.58.2 的记录

2026-10-31，整合 Host。这是补丁版本：契约仍是 0.58.0，存储形式仍是 schema 32，所以不要求黑板空闲，也不做备份。从整合分支的 `660ab5b5` 安装。

## 内容

- **存储计划量到正在变的树时不再整体失败**（微任务“存储计划不因检出在变而崩” `d99c1ace`，合入 `7b20ddd1`）：
  - 起因：C-Two 那边的 Host 当天约 16:00 报告。一个检出正被 cargo 增量编译改动，`storage-plan` 因 `FileNotFoundError` 整体失败；当时开发者的磁盘只剩 13 GiB，正需要这份计划。
  - 扫描中途有条目被别的进程删掉（列出之后 `scandir` 或 `lstat` 时找不到），这棵树记为正在变：原因 `changing`，大小是近似值，没有指纹，不可回收。
  - `storage-apply` 照旧以指纹核对，正在变的树对不上，不会删。其余错误照旧抛出。
  - 控制台存储页补了中英两种文字。
- **记录**：
  - 三份调研：ZCode 与 DSH 能不能在回合中送入输入，各看本机安装包与公开资料，以及 DSH 在进程边界上的接口；
  - ADR-006 与 ADR-030 记下 ZCode 问询改为实时送达的决定，以及为维持回合契约设定自家私有会话参数的规则；
  - 参考文档里存储计划的措辞，与待办的几项。

## 验收

- Host 读完差异，在合并后的树上跑了下文的完整检查。
- 这处改动挨着删除路径，照开发者的规矩请 Opus 独立审了一次（Claude Code CLI claude-opus-5-5 / high，只读）：
  - 第一轮它想读日常的状态目录，被只读权限挡下；Host 让它只看自己的检出，第二轮完成。
  - 没有阻塞性的发现。
  - “文档说过了头”一条由 Host 改正：只有扫描中途被删掉条目的树才记为正在变，别的改动由删除前的指纹核对挡住。
  - apply 时正在变的三条路径，以及 `scandir` 那一支的单独测试，记为下一批的顺带项。
  - 两轮消耗：输入约 91 万与 52 万 token，几乎全部命中缓存；输出约 1.8 万与 1.0 万。
- 稳定的树，指纹的算法没有变；Host 在差异里核对过。
