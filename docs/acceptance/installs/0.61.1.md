- Worker 第一个回合停下来问：安装的恢复日志 `upgrade.json` 里专门记着 Claude Code 的链接，按 harness 记就要改它的形式，而任务书写了“不改存储形式”。Host 定：任务书说的是黑板的存储，这份日志是安装器自己的恢复文件，可以改，随补丁版本。第二个回合改掉了引导脚本里的写入预告与一道多余的旧键检查。
- Host 读完差异；合并后的树与 Worker 封存的累积补丁相同，受影响的 25 个测试文件、258 项通过。
- Host 在空的私有 HOME 上用 0.61.0 与 0.61.1 的 wheel 演练：装着 0.61.0 时新出现 `~/.gemini/antigravity`，升到 0.61.1 时它的链接被建出来；已经有一个手动建的、指向共享 skill 的链接时，升级认作已链接；链接的位置被一个真目录占着时，安装以 `SKILL_TARGET_CONFLICT` 拒绝，skill 仍是 0.61.0，目录里的文件原样保留，旧服务照常。三个私有服务都确认停下。第一遍演练因为日常控制台占着默认的控制台端口，私有服务起不来；第二遍设了 `HMB_CONSOLE_PORT=0`。
