## 实现与边界

Worker 与快速路由经注册表调用同一个 ZCode Python 运行模块；请求真实编码到私有文件并解码，结果真实从控制器 stdout 解码并核对完整执行身份。角色持有任务书、完成服务、结果判断、纠正机会和检出封存；运行模块报告原生事实。旧 ZCode adapter 执行入口与旧 runner 模式入口已删除。模型发现仍为无输入操作。黑板问询和 Worker 活动使用同一 LiveChannel，本步后端仍是现有桥与文件，第五步再替换为 C-Two。

工具范围保留现有能力：不给工具使用原生空 allowlist 等设置，可写沿用现有工具；只读仍没有原生强制能力，不因此取得审阅资格。发出的配置、回读配置、工具事实和两层停止证据分别保留；运行模块不替角色或黑板作结论。本步没有安装或升级日常运行时，没有改变用户配置、登录、凭据或日常数据，没有读取凭据文件内容。

## 格式与使用方

默认值缺省采用 Pydantic 自身行为；JSON 数组到不可变序列使用字段配置，元素继续严格验证；缺失可选文本使用 None/null。安装版 Pydantic 2.13.5 不拒绝重复键，因此保持先公共严格解码、再模型验证。规范化编码和解析前帧界共用根包实现。公开 CLI 的 schemas 与帮助生成不变。

没有生产用途的请求值、结果占位、实时预留位、重复封套、角色准备值字段和六个 live 编解码包装已删除。请求/通道的完整绑定、幂等表、条目序号、分页尺寸和原生 socket 回复关联均保留。当前运行格式 117 个字段、实时格式 60 个字段、角色准备值 14 个字段已逐项核对，保留理由是实际执行/投影消费，或有原生来源并经 runner-stdout 的位置、字节数与摘要交付的事实；后一类明确不称为业务判断。详见[使用清单](adr025-step2-format-usage.tsv)与[删减记录](adr025-step2-format-usage.md)。

清理前后以 `a13d3b1` 与最终源码对照：run_contract 的 Pydantic 模型 28→26、字段 154→117；live 模型 11→10、字段 74→60。run_contract/live/internal_models/roles.controller 四份模块合计 2,118→1,974 行。当前清单没有为将来预留的无使用方字段或类；后续各步仍须重新报告实际使用方。

## 验证

完整命令为 `uv run --frozen python -m hey_my_buddy.cli.checks --jobs 2`，使用私有 HOME、DSH_HOME、状态与运行时根，并清除继承的 Worker/runtime 环境。共运行两次：第一次在 `e03397d` 上因两份测试夹具漏迁失败；范围内问题由原 2-D run 修正，范围外 Router 探针夹具由 Host 修正并登记。第二次在 `f583a8b` 上退出码 0，用时 777.339 秒：2,628 项 Python 测试、171/171 个模块通过（测试自身条件跳过 1 项），Node 110 项通过。没有因记录更正重复跑测试；第二次完整检查由实际失败和修正所需。

相对第一步的 2,497 个编号，最终集合包含 2,485 个未变编号、9 个明确改名、3 个有理由的删除，以及 134 个新增编号。修正后再次只收集编号，仍为 2,628 个唯一编号、171 个模块，装载无错误；未变集合相等，没有未登记的增删。整步[编号对照](adr025-step2-test-ids.tsv)只列变化，2-D 内部的中间变化另见其对照表。三项旧测试删除分别对应被删除的预留事件位、账户引用类和无生产入口的 live codec；本步内新增后又随空 codec 删除的两个 parser 见证也已在 2-D 记录说明。真实生产 RunRequest/RunResult 的解析前限长及严格标量见证继续保留。

迁移防护的失败见证记录覆盖解析顺序、普通严格类型、完成服务签收与原生身份、拒绝应答/观察顺序、工具事实完整性、问询绑定/拒绝/分页，以及 Host 修正的离线“不启动”防护。相关微任务只跑受影响测试；本步末尾的小修没有重复旧矩阵。Host 补充的 Router 探针 17 项通过，注入准备阶段调用 ZCode 入口的故障后两项失败，恢复后通过。Worker 曾因净化 PATH 缺少 Node 跳过安装版 ZCode 五项，且未留存部分早期全文输出；该事实、后续补存证据和撤回均保留在原记录。正常完整检查里的这些安装版 localhost fixture 测试两轮均通过。
