聚焦取证确认四类基线失败(均在迁移前的原始检出上复现):test_zcode 成功用例读 inquiry.json 的 token 报 KeyError: 'token';Codex 与 Claude 活动用例读 attempt 目录 activity.json 各报 FileNotFoundError;ZCode checkpoint/refusal 流程调用已删除的 blackboard.tasks.inquiry.bridge_request 报 AttributeError;另有任务描述三类之外的第四类——test_codex 的 test_worker_selection_resolves_the_private_account_home_in_run_services 以旧关键字(invocation_root/native_root/activity_dir)调用现行 prepare_run_services(account, tool_scope) 报 TypeError,该文件在唯一可写范围内,已一并迁移并在 ids 表登记。原始基线(原始测试文件加未改动源码副本)复核留证于 mut-00b-original-tests。

迁移逐项落在新入口上,不恢复兼容、不复制旧 backend。test_zcode 成功用例:inquiry.json 与 role-run-control.json 的 inquiry 节断言只剩 attempt 私有 resultsPath(等于 attempt 目录 inquiry.results.jsonl,0600);live 凭据是持有者自己的 control.live 材料(instanceId/token/readyFile 三键)加 ready descriptor(address/name/instanceId/hostPid/socket,0600,hostPid 等于被持有控制器 pid),token 不出现在 descriptor 也不出现在结果报告。ZcodeFixtureCase 新增共享 helper(own_handle/live_channel/ready_channel/ask/inquiry_results_path/inquiry_records/release/native_log/wait_file):持有侧经 roles/live.handle_live_binding 绑定真实 C-Two channel,问题经 channel.request 真实排队,ready 观察 observe(limit=1, fields=observation),journal 经 attempt 私有 resultsPath 读取;own_handle 按先停组、后仅清理自己 captured endpoint 的顺序收尾并断言 owned endpoint 不遗留。checkpoint 十项与 refusal 两项全部走该通道:保留原始询问文本、questionSha256 关联、六项完整身份(channel.identity 与 handle.role_run_identity 全等)、有序 queued/delivered/answered、签名完成/拒绝、checkpoint/answer 工具证据、子 root 不得交付、伪造回执整轮失败、取消两层停止等全部 guard;并发隔离用例改以两个控制器各自的 live 材料(instanceId/token)与 ready descriptor 地址不同来证明端点分离,journal 隔离断言保留。

两个 Host 撤回流程删除并在 ids 表逐项映射原因:传输级 discard 随 raw-socket backend 一起退休,整合后的 C-Two seam 只有 inquiry 请求与观察(test_inquiry_owner.test_retired_transport_entrypoints_are_absent 断言 bridge_request/_discard 不存在),端到端撤回没有可驱动的生产机制;已撤回事实的通道级重放(buddy.harnesses.test_live_channel 的 committed-withdrawal 用例)与 service 级重放(blackboard.tasks.test_inquiry 的 withdrawn-replay 用例)、迟到有效答案对终态的竞赛(owner 级 test_zcode_inquiry 用例)仍在各自层覆盖。夹具的 inquiry-discarded 与 inquiry-discard-race 分支因此不再被任何测试驱动,属遗留死分支,处置归 Host。只随文件机制退休的 metadata/privacy 断言逐项映射:inquiry.json 的 token(64 位)/socket/errorPath 与 0600 模式断言由 control.live 材料、ready descriptor 的形状/模式/hostPid 绑定与 token 不泄漏断言接替;activity.json 的 attemptId/activity.phase/nativeSessionId 断言由解码保留 RunResult 的 identity 绑定、activity.phase/nativeSessionId 与投影相等断言接替。

Codex/Claude 活动用例改为解码控制器自己发布的真实 RunResult 帧(其 stdout 日志):断言 identity 绑定该 attempt、保留 activity 的 phase 为 finishing、nativeSessionId 等于回合 sessionId、counts 为原生事件实际驱动的值(modelTurns 1/toolCalls 0)、投影 activity 等于保留回执的 phase/eventSeq、已退休的 activity.json 不存在。边界如实记录:这是最终事实解码,不是过程观察;未捏造任何 published 成功(未断言 live 发布),过程可观察性仍由 zcode 的 LiveActivityTests 持有者实测覆盖;计数与元数据确实由原生事件驱动(变异 M7 将其清零即红)。
