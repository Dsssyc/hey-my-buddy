# Model-family concurrency editing in the console

Verified on 2026-09-25 as isolated frontend work at base commit `8762d9d38c473c69714feaaf7abe02efe51b3f35`, implementing the console side of [ADR-011](../decisions/011-runtime-refinement.md). Only `apps/console/src` was changed; no Python, plugin version, public contract constant or release metadata was touched, and the Host builds the compiled assets and release records after integration.

The console now speaks the exact wire contract. `Snapshot` and `model_profiles` pages carry `modelConcurrency: [{adapter, provider, model, limit, active}]`, one entry per represented model family, and both the snapshot reader and the retained-page parser reject an envelope without the array instead of inventing defaults. The local draft carries only `{adapter, provider, model, limit}` settings; occupancy is dropped when the draft is made and therefore cannot be published. `user_policy_publish` receives a `modelConcurrency` patch of limit-only entries, emitted only for families whose limit actually changed. The family key is the exact adapter/provider/model tuple; effort never enters it. The accepted range is the integers 1–32 with default 2, declared once in `console-data.ts`.

Editing lives only in the existing human edit mode, on the selected model card's 偏好与启用 panel. A single accessible number field shows the family's shared limit; every effort variant of the family inspects and edits the same setting. Current occupancy is displayed read-only beside the field and in the read-only facts, and accompanying text states that all effort variants plus routing and execution share the count, that a saved change applies immediately to subsequent claims, and that lowering the limit never terminates running attempts and only holds new claims until occupancy falls below the limit. Unavailable families stay editable, and an out-of-range input is shown as invalid, never committed, and resets to the committed value when the field loses focus.

The new field reuses the existing draft, rebase, conflict and recovery machinery unchanged. Family limits participate in the dirty fingerprint, the per-profile change tuples, the publication patch and the field-level three-way rebase: a limit another writer published first is a visible `并发上限` conflict that keeps the draft at its own revision, and a family missing from the refreshed table stays unresolved until a retained page read at that revision supplies it. Occupancy changes alone never make a draft dirty.

Verification was source-level only, and this record states that boundary explicitly. With Node v24.21.0, `tsc --noEmit` passed with no errors and the full console suite passed: 18 test files, 207 tests, including 14 new cases covering patch emission, range refusal, occupancy-as-observation, the three-way rebase, the revision-bound unresolved case, the rendered field and occupancy facts, cross-variant sharing, unavailable-family editing, out-of-range input handling and the discovery-conflict/reload flow through the real `App` component. The Vite production build was deliberately not run: the Host compiles assets after merge. Nothing was checked against an installed or running runtime, and no publication was sent to a live board; the backend counterpart of this contract is developed independently, so end-to-end verification against the running service remains open until the Host performs the integrated cutover it owns.
