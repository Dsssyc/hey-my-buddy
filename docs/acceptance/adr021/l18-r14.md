# ADR-021 L18 R14：运行时版本诊断一致

本记录由 R14 Worker 在分配的检出中产生，依据固定提交 `f489086e27408f7372cb1cf0882090fbb6cf30b3` 的 Host 复核“第三轮”及 `3ff85dea` 设计末段的续修要求。首轮产物 `c1ed715993454fca065498f73c37db7fc5da11c9` 未获验收；本轮只修 Claude 主进程创建交接，修改 Claude native_run.py、横向 test_runtime_version.py 和本记录。第二轮五项已接受的返修没有重做；本文不是 Host 最终验收。

## 根因与边界

Claude Code 使用独立的 `subprocess.run`，Codex 将已确认停止的版本诊断失败升格为 `native-version-probe-failed`，ZCode 又维护自己的可选版本规则。三家现在只调用 `version.probe_version`，由公共 `discovery.probe` 执行有界读取与原有停止观察。运行事实统一为 `str | None`；空输出、空白和 `unknown` 诊断文本归为 `None`，只在目录/显示边界表示为 `unknown`。DSH 仍从已有 initialize 的 `agentInfo.version` 取值，不增加进程；initialize 协议失败仍失败。

公共 probe 在创建处保留 `created`、`shutdown`、`exit_code` 事实，版本层直接消费该 receipt，不从错误码推断创建或停止。尤其 `scan-timeout` 可能发生在创建前或创建后，两者 receipt 不同。普通非零、超时、空输出和已停读取异常继续；停止未知才报告 `native-shutdown-failed`，禁止后续主进程创建，False 沿 owned、运行结果收集和目录异常保留。没有增加停止算法、兼容 wrapper 或旧别名。

首轮 Claude 在日志 FD 关闭之后才登记主进程句柄，且未消费创建方失败 receipt；版本的已停 True 因而会遮蔽已经创建的主进程。现版成功创建后立即登记实际 ProcessHandle，再关闭日志 FD、建立 Connection；之后失败复用 Codex/ZCode 已用的公共 `halt_owned_group`，以实际主进程停止结果替换 receipt，并关闭 stdout。停止观察自身抛错时保留实际句柄，运行结果和目录异常均发布未知，不默认 gone/True。调用前 owned 明示真正未创建；`owned_popen` 自身失败直接消费其 `owned_popen_evidence`，区分未创建、已创建已停、已创建停止未知，不构造假句柄或另写停止算法。

已删除三份被取代规则、旧拒绝测试的函数/断言内容和 operations.md 的被取代说明。没有整文件退休或需要 Host 机械删除的文件。
