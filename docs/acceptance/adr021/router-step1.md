## R2：用量与推理强度的代价

开发者在 R1 之后看到日常的 Router 又把控制台微任务给了 Sol max，它的理由是 max“覆盖最重的情况”，于是加做 R2（[计划](../../design/adr021/router-step1-plan.md)的 R2 一节）。微任务 run `f83d64fd`，经路由交给 DeepSeek Flash max；任务书开头写了一句难度，Router 的理由引用了这一句。基点 `9a8af56a`，封存提交 `48fd6bd2`，合入 `0441f70e`。

- **改了什么**：统计里加上每个同型 buddy 的用量（只算能力回合都报了完整用量的样本，给输入、缓存输入、输出 token 的中位数）；Router 的说明加上“用量是成本的证据；推理强度越高越费额度、越慢，只在任务需要时才选高的”；R1 记下的两件顺带项都做了（原则只留在调用说明里，探针先 `prepare` 再 `start`）。
- **Host 核对的**：读完差异；候选代码在日常黑板上只读推导一次，14 个候选，没有报错；Codex、Claude 与 DSH 的样本都有完整用量，ZCode 报的都是 partial，GLM 的用量如实为不知道；合并后 56 个路由与 Router 角色测试文件、787 个测试全部通过。
- **发现**：Sol max 的用量中位数（输入约 290 万、输出约 2.7 万 token）低于 Sol high（约 820 万、3.3 万）。这反映的是两种强度接到的任务不同，不是 max 更省；按强度比较代价，要等第二步有了任务类型，才能在同类任务里比。推导一次的时间在日常黑板上从约 0.24 秒涨到约 0.95 秒，路由请求时可以接受，记下以便日后对照。

## 装上之后发现的回归

- **现象**：0.55.0 装上之后的第一次真实路由（微任务“会话内容逐类声明与检查”）停在 Host 边界：DeepSeek Flash 与 Luna 两个 Router 的答案都被拒，代码 `router-evidence-out-of-bounds`。黑板上当时只有这一个微任务撞上。
- **原因**：R1 要求 `statistics` 依据的引用恰好等于某个候选的 buddyId，而真实的 Router 写的是 buddyId 加一段摘要，例如 `codex:openai:gpt-6.1-sol:max — samples 266, successes 259, …`。依据只是给人看的理由，没有程序读它，这条校验没有使用者；决定结果的 `buddyId` 另有校验。
- **为什么验收没发现**：Host 只用一次真实调用核对，那一次正好只写了 buddyId。模型自由书写的文字，一次通过证明不了它的写法；对这类文字加的格式要求，先问有没有程序读它。
- **修正**：修正微任务“统计依据的引用校验过严”（run `63625be0`，路由坏着，Host 按边界恢复指定 DeepSeek Flash max）删掉这条校验；回归用例改为带摘要的引用能通过、`buddyId` 越界照旧被拒。它还改了 `docs/reference/decision.md` 里写着旧规则的那句，这个文件不在任务书的范围里，是任务书漏写了，Host 以 adopt 收下。原因代码 `router-evidence-out-of-bounds` 仍由“快速路由不能引用文件”使用，保留。合并后路由、Router 角色与文档卫生共 10 个文件 223 个测试通过。随 0.55.1 装上（[安装记录](../installs/0.55.1.md)）。
