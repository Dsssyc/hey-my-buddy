# 各角色共用一套档位：Router 的不用工具与只读两档（2026-10-20）

- **微任务：** “Router 并入共用档位”（run `25fb38d4`，Codex CLI `gpt-6.1-sol / high`，四个回合）。按[执行计划](../../design/adr023/shared-levels-plan.md)做 [ADR-023](../../decisions/023-harness-integration-principles.md)“各角色共用一套档位”中的不用工具与只读两档。开发者于 2026-10-20 定下，把 ADR-021 的 L6 提前到首次发版之前。
- **基点与合并：**
  - 基点 `dcc1b120`。
  - 第一回合 `3599db59` 打回。
  - 第二回合 `84e286a3` 交回后，完整检查发现一行被误删的类头，第三回合 `f3dd3246` 补上。
  - 真实运行发现审阅的提示词缺答案格式，第四回合 `e3029818` 补上。
  - 压成 `d1eae33e` 合入整合分支。
- **做了什么：**
  - **一张档位声明表**（`PERMISSION_LEVELS`）。每个 harness 逐档声明做不做得到、强制还是约定。它取代了 Worker 的档位表、`no_tool_structured`、`read_only_structured` 与 `local_read_only_check()`。
  - **运行请求只带档位。** 同一档在各角色上用同一种原生配置。删掉了 Codex 的 Router 权限配置和 Claude Code 的审阅专用参数；ZCode 的审阅用 `plan`，DSH 用它的只读预设。
  - **资格就是声明。** 只在选择 Router 时与运行入口各检查一次。由声明推出的能力只在一处推出，不再存进 buddy 行。
  - **判定按档位，一张表，只用于 Router 的运行。** 不用工具一档不允许任何调用。只读一档允许读取、搜索、执行命令与联网；其余类别、未登记的名字与 MCP 工具一律作废答案。
  - **审阅的提示词附上答案的 JSON schema**，与快速运行相同。
  - **25 → 26 的升级，接进安装与备份校验：**
    - 路由认领表删掉重复存储的策略列；
    - harness 健康记录删掉退役的键；
    - buddy 行删掉由声明推出的能力；
    - 路由面的值 `work` 改为 `routing`。
  - 契约 0.48.0。
- **独立审查：** run `b970cee4`，Claude Code CLI `claude-opus-5-5 / high`，在只读检出上进行，双方互不看结论。共 10 条发现。会影响结论的几条由 Host 在源码里复现：网络检查、存储形式、读取时剔除、Codex 的声明、`Skill`、能力的两个来源、路由面的值。死代码一类由 Host 抽查，其余照单交给第二回合，并读了改动。

## 打回

- **第一回合：**
  - 完整检查不过：一个测试 patch 了已删掉的 `base.sys`。
  - 存储形式改了，没做升级：
    - 路由认领的策略列换了形状，新旧两种形状并存；
    - harness 健康记录里的退役字段，每次读取时才剔除；
    - 由声明推出的能力存在 buddy 行里，旧行与新行的内容随写入时间不同；
    - 路由面的值仍是 `work`。
  - Codex 审阅在回执报“不联网”时拒绝运行，与“档位不管网络”相反。
  - 其余几处：
    - Codex 的不用工具一档误标为强制；
    - Claude Code 的 `Skill` 会被误判作废；
    - 同一份声明在五六层重复检查；
    - Router 适配器的判断过宽；
    - Codex 的沙盒映射会落空到放开；
    - 一批死代码；
    - 一次偶发失败的浏览器检查。
- **第二回合：** 删辅助方法时误删了 `class AdmissionTests` 这一行类头。5 个测试落进被另外 5 个文件导入的基类，各被加载了 6 次。
- **第三回合**（真实运行之后）：
  - 审阅的提示词没有附答案格式（快速运行附了）。DSH 与 ZCode 从最后一条消息取答案，因此交不出有效答案。
  - DSH 的写入工具名没有登记。
  - ZCode 被拒的调用没有结束事件，答案被判为证据不全，而不是越权。

## 核对

- **测试（Node 24.21.0）：**
  - 第二回合的产物上：完整检查 292 个文件里只有那行类头失败，补上后单独通过；前端 91 个文件 1,057 项、浏览器 573 项通过。
  - 第四回合的产物上：受影响的 83 个文件、1,400 项通过。
  - 安装前在合并后的源码上跑一次完整检查。
- **升级演练：**
  - 做法：空的私有 HOME，经启动器先装 0.47.0（`1cfbbe64`），换上日常看板的只读副本并让它跑起来，再装候选。
  - 结果：
    - 用时 13 秒，备份校验通过，之后为 schema 26；
    - 270 个任务、410 次尝试、6,731 条事件、191 个微任务，数目不变；
    - 完整性与外键检查通过；
    - 77 条路由认领的策略列已删；
    - 77 条路由结果与 154 条事件改为 `routing`；
    - 4 条健康记录的退役键与 138 个 buddy 行里存着的声明能力都已删掉。
- **故障注入：**
  - 让一条已回答事件的面与它的结果行不一致：备份校验阶段的试转换就失败了，安装回滚，看板没被动过。
  - 让新服务一启动就退出：转换完成后回滚，从备份恢复到 schema 25，数据原样。
- **真实运行：** 开发者逐次批准，共 8 次付费调用。都用探针 `tests/probes/router_readonly.py`，在私有状态目录里用开发者自己的 harness 配置运行。探针的任务故意尝试写入与联网，不是一次真实的路由。

## 没有核对的

- 真实运行用的是探针的任务，没有跑过一次真实的路由。在真实的路由里，模型尝试写入会使答案作废，这是有意的设计。
- 只联网一档与画像面没有做。
- ZCode 的两个模型首次回复都要两到三分钟，审阅需要纠正时，标准预算的 300 秒不够。这是事实，不是产品缺陷。
- 还没有安装。
