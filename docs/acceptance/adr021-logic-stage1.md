Claude Code Host 于 2026-10-02 验收 Codex Host 交付的 `socu/adr021-logic`（`59f711c`，基线 `004f805`）。内容是 [ADR-021](../decisions/021-router-buddy-planes-and-routing-evidence.md) 工作分解中的 L1、L2、L8 与 L3，各模块的实现与检查记录见 [L1](l1-adr021.md)、[L2](l2-adr021.md)、[L8](l8-adr021.md) 和 [L3](l3-adr021.md)。分支合并为 `f2e90c5`，没有冲突；`28bb4a3` 把两份记录中的机器路径换成 `~`。源码为 0.28.0、schema 15；没有安装，日常运行时仍是 0.27.0。

## Host 核对的内容

**测试覆盖。** 用 `unittest discover` 比较合并前后的测试 ID：1,855 个变为 1,894 个，移除 46 个，新增 85 个，没有加载失败。被移除的 46 个逐一有去向：验收与回收的 11 个改名或按第 19 条的对照表迁移；提交契约与任务偏好的 21 个改为拒绝入口或等价情形（第 5、17 条）；DSH 分组的 14 个随功能退役或迁移到备份与私有会话的测试（第 18 条）。Node 套件由 165 个减为 106 个，减少的是分组桥接、安装脚本与会话捕获观察器的测试；被删除的 `session-capture` 观察器与 `--attach-session` 只服务于分组，在第 18 条的范围内。

**独立探测。** Host 另写了 6 个不在仓库中的用例，通过看板接口实测新操作，全部通过：成果与目标不一致时 `accept` 拒绝并列出路径，带 `adjusted` 确认后验收并自动回收；目标中没有成果时拒绝；`accept` 与 `conclude` 缺少 `note` 时拒绝；相同请求重放返回同一记录，改动 `note` 冲突；对已交付的委派 `conclude` 会把封存之后的改动封存为部分成果、回收检出，之后不能再验收；`keepCheckout` 保留的检出可由 `reclaim` 回收。

**完整检查。** 在 `28bb4a3` 上通过：1,894 个 Python 测试（跳过 1 个）、136 个文件，Node 106 个，398 秒。

**看板。** Codex Host 的四个委派都已验收，受管检出已回收，子任务分支已删除。

## 留给后续模块

- `model_facts` 表通过初始定义中的 `CREATE TABLE IF NOT EXISTS` 出现在已有的 schema 15 看板上，相当于启动时的隐式变更。L15 必须把它收进显式的 15 → 16 升级；`workflow_host_conclusions` 的约束与评审事件索引同样在该升级中重建。在那之前，已有看板上对已交付委派的 `conclude` 会被旧约束拒绝。
- `accept` 与 `conclude` 的帮助没有把 `note` 标为必填，实际上必填。
- 控制台的命令白名单没有开放三个新操作，展示由 U5 处理。

## 过程中的发现

四个委派各承担了一整个模块，执行 60 至 229 分钟；最长的一个在执行中被 Host 用问询追加了七项修复，并被路由到轻量的 buddy。例证补入了 ADR-021 与 [ADR-022](../decisions/022-expected-duration-and-graceful-stop.md) 的背景；开发类委派怎样才算边界清晰，尚待确定后写入 skill。
