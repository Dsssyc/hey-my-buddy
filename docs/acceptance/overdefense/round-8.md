# 第八轮过度防御删除：验收记录

2026-10-23，整合 Host。宏任务“删除过度防御（第八轮）”。依据是 2026-10-22 的第八轮审查：53 条发现另加 C1–C4，开发者 2026-10-23 定下 C1 与 U2。按模块各写一份任务书，每批之后请 Opus 独立审查一次，审查的发现只算线索，由 Host 复现之后才打回。六批都已验收，随 0.52.0 在 2026-10-23 装上（[安装记录](../installs/0.52.0.md)）。

## 各批

- **根模块与私有路径**（微任务 `08b6c00d`，两个回合，合入 `ed630097`）：私有路径收成一个机制，状态根在每个进程的边界上查一次，所有者的入口建立或修复它，其余入口只查；阶段 B2 留下的各条一并做掉（见 [B2 记录](../cross-platform/phase-b2.md)末节）。Opus 审查的四条“会出错”由 Host 复现后打回：系统临时目录可被有写权限的 Worker 写入（Host 用 Codex CLI 0.162.1 的 app-server 探针证实）、经本人链接的上层被放行、0755 的根被拒而不是由属主修好、冷启动的错误诊断；连同完整检查查出的导出工具与扫描顺序测试，第二回合全部修好。合并树上完整检查 312 个文件、4,671 项通过（跳过 11 项）。持续集成 run 39907621374 的 Windows 失败 627 条，与基线 624 条逐条比过：新出现 9 条，其中 6 条是本批第二回合改的测试把故障注入在 `os.open` 上，而 Windows 的私有打开不走它，是测试的缺陷，交给轮子盘点的 D 批顺带修；其余 3 条是已知的偶发与既有类别。产品代码没有引起新的失败。
- **角色**（`e492af1d`，两个回合，合入 `17008c67`；修正微任务 `c1592a40` 合入 `26e8818f`）：角色不再复查自己刚做过的事，回合记录在内存里交接，由服务校验一次。Opus 审查 `3d166293` 的两条（`resolved` 被误删、记录的关闭失败抛进运行）由 Host 复现后打回，第二回合修好。合并树的完整检查首次有 3 个文件失败，根因是 Host 任务书的检查范围漏了下游测试，由修正微任务修好；之后完整检查 313 个文件、4,682 项通过。
- **安装**（`2dce95b6`，两个回合，第二回合因模型容量中断后续交，合入 `81f03a6f`）：安装器在每个边界查一次，运行时目录只在没有 READY 条目时才删。Opus 审查 `0dcf74f0` 的七条由 Host 核实后打回（契约变化时竞争收进的新工作让回滚与恢复卡死、经安装恢复会丢结果、删除失败盖掉原来的错误等），第二回合全部修好。合并树上受影响与下游测试 49 个文件、641 项通过；从 0.51.1 在空 HOME、导出的看板样本上经启动器演练了五种情形，看板的封存摘要前后一致。
- **执行进程与连接**（`d45a3f56`，三个回合，合入 `1e216566`，随后的版本提交 `44a5a810` 定为 0.52.0）：C1 落地，服务对每个执行持一条连接，执行的活动契约去掉等待操作（见 [ADR-031](../../decisions/031-one-process-per-execution.md) 第 4 条）；回执的递交按三分规则：服务不在时重试，被拒的回执不再重放、尝试以失败结束并留下拒绝原因，其余结果算不知道、回执留给恢复（见[架构](../../reference/architecture.md)）。第一回合的几个卡点由 Host 改定方案；Opus 审查 `9f885d8c` 的发现由 Host 在代码里核实后打回第三回合（确定性的拒收让尝试结不了账、提示的内部错误中止回合、零排空的停止漏掉退避中的执行、全局唤醒、细节拼进问题文字），全部修好。合并树上完整检查 310 个文件通过，另 3 个由 Host 补进合并或版本提交后复跑通过。
- **协议边界**（`e1b5a559`，五个回合，合入 `6c10ea84`）：不可信覆盖与旧拼写的两种拒绝让位于一份白名单；协助任务只按 `role` 区分；问询记录的读者不跟随链接、按界限读；Router 的工具证据改为每次调用一份摘要，写进私有的、按摘要绑定的文件，去掉 128 条事件的上限；服务客户端按 C-Two 失败的结构化原因分类，只有监听者不在时才起服务；POSIX 冷启动的探测把权限拒绝报成 `LAUNCH_ACCESS_DENIED`，Windows 的回环探测删去；绑定失败的系统原因写进 `startup-error.json`。Opus 审查 `4b641864`（输入 1,303 万 token，全部命中缓存；输出 5.7 万）的发现由 Host 复跑、读码核实后随第二回合打回。合入时 Host 手解了 4 个文件的文本冲突与 2 处两批之间的语义冲突；合并树（连同控制台一批）上完整检查 314 个文件、4,733 项，修正这两处后全部通过。
- **控制台的排序与主题**（`fd56d943`，合入 `b56e2d0f`）：排序拆成依据按钮与升降按钮，主题在没有存过选择时跟随系统，跟随系统排第一。最终源码上前端全量 1,103 项、浏览器检查 645 项通过，重新构建的资产与提交的逐字节一致，Host 看过像素。待办里主题的那一条随之删去；同节“中文的停止说法里多了空格”一条，核对时代码里已经改好（“控制台停止”“黑板停止”“桥接停止”），一并删去。
