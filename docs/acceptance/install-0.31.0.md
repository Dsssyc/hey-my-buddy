# 安装 0.31.0 的记录

2026-10-12，整合 Host。开发者为这一次安装明确授权，并批准了装前的一次真实调用与装后的两个冒烟微任务。装的是整合分支的 `c939df99`，版本 0.31.0，带存储的 schema 17 到 18 的升级。带上的是 [ADR-030](../decisions/030-harness-layer-scope.md) 的批次 4（[验收记录](adr030-batch4-host-review.md)）与 Worker 权限档位的第 1、2 步（[验收记录](worker-permission-levels-host-review.md)）。日常环境此前是 0.30.0、schema 17。

## 安装之前

- 最终的完整检查通过，记在批次 4 的记录里。
- 存储的升级当天在日常看板的一份新副本上用最终的树演练过，副本是看板空闲时取的：516 个微任务、914 个回合、133 个 buddy。升级用时 19.7 秒；回合的档位是写检出 822、只读 92，都等于所属微任务当时的选择；Codex 的 44 个 buddy 带上只读、写检出、放开三个能力字符串，另外三个 harness 的带只读与写检出；其余 55 张表逐行未变，形式与新建的看板一致，完整性与外键检查通过；读取各项记录的命名操作都读得出来。故障注入三处：升级到一半杀掉进程后仍是 schema 17 并且随后升级成功；不认识的档位被拒绝并回滚；重复升级被拒绝。副本用完已删除。
- 一次真实的 Codex 无工具快速调用（gpt-6-luna / high），在最终的树上经产品自己的角色控制器：7.7 秒正常结束，答案被留下；工具证据完整、零次调用，服务对快速调用的判定通过；`account/updated` 记成一条未知事件；配置回读、模型、线程回执三项都已证实；进程组确认停止。批次 4 的那几次真实调用都在第二个审查者之后的修正之前，这一次确认修正没有碰坏这条路径。
- 备份预检通过，没有被拒绝或需要处理的项；日常服务状态正常；没有排队或在跑的工作。
- 记下了 133 个 buddy 的名字、启用与可用状态（启用 11，可用 117），用来与装后比对。

## 安装

从 `c939df99` 构建 skill，运行它的 `scripts/buddy install`，用时约 4 分 40 秒，退出码 0。安装报告：skill 更新为 0.31.0；升级前的备份已校验（schema 17，163 MB，13,431 个文件）；升级后 schema 18，保留数据的指纹一致，没有源码泄漏；没有回滚；清掉了一份旧的运行时。

- 服务状态正常，契约 0.31.0，schema 18，完整性检查通过，外键没有违例；新的服务进程与 7 个 Worker 起来了，没有遗留的旧进程。

- 装上的 skill 是从 `c939df99` 构建的 0.31.0，Claude Code 的链接完好。
