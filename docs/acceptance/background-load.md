# 黑板的后台占用：验收记录

## 黑板空闲时不空转（2026-10-14）

- 起因：开发者的笔记本在黑板运行时发烫，充电线烧过一次。整合 Host 在日常服务（0.35.0）上量到：没有执行时服务约占一个核的 10% 到 12%，7 个 Worker 各约 0.5%；对空闲服务抽调用栈，忙的时间大多在 SQLite 的 SQL 解析里，因为每次读写都新开连接、重新解析整套表结构，而 7 个 Worker 每 2 秒各认领一次。
- 交付：服务的每个线程保留一个连接（按线程标识，因为 C-Two 的原生回调会重建 Python 线程状态，`threading.local` 留不住），服务停止时统一关闭；事务的边界不变，提交本身失败也回滚。空认领返回它看到的事件游标，空闲的 Worker 在一条保持着的等待连接上等之后的任何事件（每次最多 2 秒、到点续等），有事件才再认领，不再轮询；认领与等待之间进来的活经游标找到。没有读者的 `heartbeat.json` 删掉。仓库观察没覆盖到要开始的那件活时，认领回滚重采一次，仍不覆盖就报 `CONFLICT` 稍后再领，不再返回一个像空队列的结果。实现方在私有服务上用 60 秒窗口量：服务加 7 个 Worker 合计从单核的 9.33% 降到 0.42%。
- Host 核对：读了差异；合并无冲突，合并后的源码与实现方的检出一致，实现方在相同代码上逐个跑过 14 个相关测试文件。另做三件：2,000 个短生命线程之后，连接登记只有 6 个、文件句柄 17 个（macOS 上线程标识会被复用；Linux 与 Windows 上没有量）；把空认领返回的游标加一（漏掉认领与等待之间进来的活）、去掉事务出错时的回滚，两处变异都被测试抓住。CPU 的数字是实现方量的，装上之后 Host 在日常服务上再量。参考文档里连接、空认领与仓库观察的几句已改；完整检查在安装前跑。
- 留意：现在任何一个事件都会叫醒全部空闲的 Worker 各认领一次；执行在跑、事件多时，认领次数可能不比原来的每 2 秒一次少。装上之后在日常服务上看一看。
- 消耗：输入 844 万 token（823 万命中缓存），输出 5.5 万，28 分钟。
- 验收之后发现的缺陷（同日）：Host 试做“只跑受影响的测试”的覆盖率实验时，在整合分支上跑到 `test_lead_lifecycle.py`，失败；它在 Lead 与空闲修复各自的检出上都通过。按线程复用连接之后，同一线程在一个事务里再开事务，SQLite 报 `cannot start a transaction within a transaction`：`conclude` 在读事务里经 `_board_adopted_paths` 再开读，这条路合入 Lead 之前就有；另一处是 `get` 开读时连接上已经留着事务。漏掉的原因在 Host：改的是所有读写都经过的地方，受影响的就是全部测试，Host 却采信了实现方逐个列出的 14 个文件，没有在合并后跑完整检查。修正另开一个微任务（同一线程嵌套的事务照旧各用各的连接，并跑一次完整检查），合入之前整合分支不安装。
