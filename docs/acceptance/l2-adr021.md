## 实现的移除

1. 提交端 `workspace` 开关从 `SUBMIT_FIELDS` 与 `normalize_spec` 删除：任何提交（含 helper 规格）携带 `workspace` 字段都是 `INVALID_ARGUMENT`，错误带 `field=workspace`。`decision.py` 与 `harness_review.py` 内部构造的 spec 不再写入该键。注意：这是规范化 spec 字段的删除，老看板里已存任务的 `spec_json` 原样保留，同一 `requestId` 的新提交因指纹不同会按既有幂等规则冲突，不做改写。
2. `harnesses/dsh/scripts/run.mjs` 删除 `--workspace`、`--no-workspace`、`--workspace-socket`、`--workspace-timeout` 与整个 `--attach-session` 附加模式：这些旗标现在是用法错误（exit 2），任何付费子进程都不会启动。每次运行都通过 `session-persistence-jsonl` 的 per-run patch overlay 写入执行私有会话根：适配器传 attempt 私有根，独立调用默认用本次运行日志目录下的 `sessions/`。结果 payload 删除 `workspace` 对象与 `logPaths.capture`；`nativeStorage` 保留并如实报告 `task-private-sessions`/`run-private-sessions`。
3. 删除文件：`harnesses/dsh/plugins/workspace-bridge.mjs`（宿主桥接插件）、`harnesses/dsh/plugins/session-capture.mjs`（分组专用会话捕获观察器）、`harnesses/dsh/scripts/install-workspace-bridge.mjs`（安装脚本）、`harnesses/dsh/scripts/lib/workspace-host.mjs`（runner 侧桥接客户端库）、`harnesses/dsh/tests/manual/`（real-workspace/real-observer 两个手动脚本）。`packaging/runtime-assets.json` 声明的是目录级资产，无需改动。
4. `src/buddy/worker_sessions.py` 收缩为 Codex 只读列出：`adapter` 只接受 `codex`（默认值从 `dsh` 改为 `codex`），`action` 只接受 `list`；`dsh` 请求是 `UNSUPPORTED`，`plan`/`apply` 是 `INVALID_ARGUMENT`，`planDigest`/`selectionDigest` 成为未知字段。桥接 socket 客户端、归档 journal（`worker-session-cleanup/`）及其写入路径全部删除；Host 审查后保留 `backup.py` 对历史归档收据的备份与路径保护；产品不再创建这些收据。DSH 分组的 `_native_session` 捕获来源（capture/workspace 观察器、`sessionIdConflict`、`ambiguous`）随之删除，会话 ID 只来自已验证的受管 turn 记录，没有 turn 就如实报无。
5. 保持不变：`executionWorkspace` 的 Git 隔离契约（`workspace.py`、`workspace-resolve`、`workspace-cleanup-*` 等一概未动）；DSH 适配器的 `workspace` capability 声明（指 executionWorkspace 能力）未动；ZCode/Codex/其他 adapters 的会话存储与 worker-sessions Codex 列出未动；`attempt_evidence.py` 中 `session-capture.json`/`capture.json` 证据名按 `decision-input.json` 的先例保留为历史证据白名单，否则带分组历史的老看板备份会被拒。
