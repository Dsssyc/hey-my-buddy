# ADR-025 两项可行性核对：Host 验收

2026-10-03，Claude Code Host。两项核对由 Codex 作为 Host 委派并审查，记录是 [DSH 的 ACP 模式](adr025-dsh-feasibility.md)与 [C-Two 临时端点](adr025-ctwo-feasibility.md)，整合经过见 [Host 整合登记](adr025-host-integration.md)。本文只记录本 Host 亲自做的核对与由此带到后面的事项。第零步此时仍在进行，不在本次验收之内。

## C-Two 临时端点

本 Host 另写了一个不调用模型的探针，用项目锁定的 C-Two 0.6.0 和合成字符串重跑了第五步依赖的几项事实，结果与记录一致：

| 事实 | 本 Host 的实测 |
| --- | --- |
| 两个进程用同一个名字注册 | 都成功，地址不同，按地址调用分别到达各自的进程 |
| 只给名字、不给地址去连接 | 失败：名字不能跨进程解析 |
| 同一个进程重复注册同一个名字 | `ValueError` |
| 注册之后再调 `set_server` | 被忽略，只有一条警告 |
| 先作为客户端连接过别的服务，再注册自己的资源 | 成功，之后仍能调用别的服务 |
| 注销并关闭之后 | 地址回读为空，套接字文件消失，再调用立即失败 |

探针启动的进程全部正常退出，没有留下套接字文件。

## DSH 的 ACP 模式

本 Host 没有另外启动 DSH，也没有调用模型，核对的是留存的原始帧与摘要是否支持记录里的两条关键结论，都支持：

- **不给工具。** 用公开的启动配置关掉 14 个工具行和 plan-mode 之后的那次真实运行里，工具事件只有交付结果的那一个 MCP 工具，没有权限请求，没有产生文件，进程退出码 0，进程组消失。
- **只读。** `DSH_PERMISSION_MODE=read-only` 下的那次真实运行里，四次写入全部失败，其中两次请求升级权限，客户端都答了拒绝；读取成功；工作目录内外都没有产生文件。

记录如实写明了一次越界：F-D1 的一次诊断调用没有设私有主目录，在用户日常的 DSH 目录里创建了 `profiles/acp/`，随后删除，留下上一级目录修改时间的变化。此后的调用都经过只接受私有主目录的启动包装，F-D2 各回合前后日常目录的快照没有差异。

## 结论

两项都验收。DSH 的六个问题都有了基于真实运行的答案，改用 ACP 可行，不需要退路；C-Two 用于每次运行一个临时端点可行。两项都只在 macOS 上核对过。

## 带到后面的事项

第四步：

- **工具范围靠启动配置，不靠权限应答。** 默认的可写预设下，工作目录里的写入和命令不发权限请求，控制器无从拒绝。"不给工具"用关闭工具行的启动配置，"只读"用只读预设，控制器只回答升级权限的请求。ADR-025 第 11 条已按此改写。
- **只读预设只验证了写入工具。** 那次运行里唯一的命令是读取；用命令写文件在只读预设下会不会被挡住没有测过。第四步的真实冒烟要补上这一项，补上之前不把只读写成对命令也有原生强制。
- **工具类别要自己归。** DSH 的 ACP 更新里每个工具的类别都报 `other`，统一词汇的归类得由本项目按 DSH 的原生工具名来做，认不出的保持 `other`。
- **实际模型与逐步用量不在协议流里。** 协议流只给上下文占用；实际使用的模型和每一步的 token 数只在 DSH 自己的私有会话记录里。读这份记录等于依赖 DSH 的存储格式，只能作为可选来源：读不到时如实记为未知。那份记录默认是 zstd 压缩的，不为它新增对系统命令的依赖。
- **关闭工具行的清单会随 DSH 版本变化。** 清单之外出现新的工具行时如实报告，不当作已经限制；真正的把关仍是事后对工具事件的判定。
- **仍未验证的。** 允许路径、真实回合之后的原生续接、取消的中断事实、HTTP 形态的 MCP、额度与费用、其他平台。

第五步：

- **路由靠地址，不靠名字。** 没有 relay 时名字不会跨进程冲突，也不能跨进程解析。随机人名保留，用途只剩显示；"重名就换一个"在跨进程时不会发生。ADR-025 第 13 条已按此改写。
- **两项设置都要在进程启动时做。** `set_server` 与 `set_client` 在第一次注册或连接之后会被悄悄忽略。Worker 运行时先作为客户端连接服务、后注册自己的端点，两项都要在此之前设置好。
- **被杀的进程会留下套接字文件。** 文件留在全机共用的 `/tmp/c_two_ipc` 里。核对当天这个目录已有约 27,000 个文件，其中 21,000 多个超过三天，是现有用法累积的；每次运行一个端点之后，每个被杀的控制器还会再留一个。持有控制器的一方在确认进程组消失后，应当删除它自己那个端点的文件。
- **仍未验证的。** Windows 与 Linux、relay 模式、"注销加关闭"与被杀之外的退出路径。

其他：

- **DSH 有公开的只读预设。** ADR-021 第 4 条把 DSH 归在没有系统沙盒的一档。做 L6 之前按这个事实重看，前提是先补上用命令写文件的那项核对。
