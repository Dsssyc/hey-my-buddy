# buddy 配色：验收记录

2026-10-23，整合 Host。依据是 [ADR-029](../decisions/029-console-frontend-foundation.md) 第 13 条，调研见 [buddy 配色](../research/2026-10-23-buddy-palette.md)。

- **微任务：** “12 个精选的 buddy 核心色”（run `f3548556`，Codex CLI 上的 `gpt-6.1-sol / high`，三个回合），基点 `928f9ff3`，输出 `76c25801`，合入整合分支 `593d9a15`。消耗：输入 2,011 万（命中缓存 1,985 万），输出 10.3 万。没有安装。
- **第一回合：** 12 个核心色，最小色差从 16.5 升到 27.2。Host 量出两个问题，打回：
  - 色相太集中，12 个里有 6 个蓝青；
  - 失败与未确认标记直接画在底色上会被淹掉，例如浅色主题下深玫红上的叉号对比度只有 1.16:1。
- **第二回合：** 按开发者的意见放宽色相，状态标记垫上轨道纸色，12 色最小色差 30.9。开发者看过像素：正红太艳，珊瑚红太像失败的叉号，其余认可。Host 另外看出，自带颜色的 harness 图标落在相近的底色上看不清，开发者同意也垫纸色。
- **第三回合：**
  - 核心色为开发者认可的 10 个，最小色差 38.9，字色对比度至少 5.39:1；
  - 被否掉的两个颜色记为保留色，生成的颜色离它们和离状态色一样，至少 25；
  - 自动生成的第 11、12 个是亮薄荷绿与亮品红，Host 提出它们是荧光色，开发者看过后接受；
  - 图标垫纸色；只给测试用的两个字段删掉。

Host 的核对：

- 每回合的差异都读过，像素在两种主题下都看过；色差、对比度与离状态色的距离用同一套库自己复算过，与交付一致。
- 合入整合分支后，前端全量（94 个文件，1,103 项）与浏览器全量（645 项）通过，构建产物与提交一致。
- 浏览器检查覆盖：12 种底色上的失败、未确认、取消标记以及 harness 图标，在两种主题下都与底色隔着纸色，量的是渲染出来的几何。
- 色盲模拟（iwanthue 2.1.1 自带）：第二回合时，红色盲下最小 8.66，绿色盲下 3.45（深蓝与深紫）。条上写着 buddy 的名字，没有设门槛。
- 只在 macOS 的 headless Chromium 上验证过，别的平台与浏览器没有验证。
