# ADR-025 第二步 2-D：内部格式的生产用途盘点与删减

2026-10-06，源码基线 `a13d3b17ea8fcc17498970c38e101de56c0c32d1`（2-C2 已整合），在隔离 worktree 按固定说明逐类逐字段复核当前源码后实施。本项只删减本步新增内部格式中没有生产使用方的内容，并做必要的构造与测试适配；不改行为、公开 CLI、公共 `protocol/schemas.py`、其他 harness 或依赖。逐字段的生产写点、读取或交付点、处置与理由见配套 [usage TSV](adr025-step2-format-usage.tsv)；测试编号对账见 [test-ids TSV](adr025-step2-format-test-ids.tsv)。执行计划 2-D 小节与 Host 准备材料的候选，凡在当前源码复核出实际生产用途的均已撤出删除并在下文列明依据。

交付链与分类依据：请求值由角色写入（`run_execution.worker_request`/`fast_request` 构造 `RunRequest`，经 `run_controller.execute` 编码到私有 `role-run-request.json` 再解码）；结果由 ZCode 驱动 `_build_result` 构造，经 `run_controller` 的 stdout 全帧交还，`run_execution._read_run` 按当前模型解码并核对完整执行身份。分类 A 是执行或判定代码实际读取的字段；分类 B 是有真实非占位原生来源、虽无字段级角色判断、但随完整 RunResult 进入固定 runner-stdout 产物（`run_execution._artifacts` 把 runner stdout/stderr 的确切位置、字节数与 SHA 登为黑板产物）而对外交付的事实；分类 C 是仅测试、编解码自循环或恒定占位。单凭 `to_payload`/`model_dump` 不算使用方。

## 请求侧复核结论

`RunRequest.network`/`NetworkPolicy`：仅两处角色构造写 `requested=False`，ZCode 驱动不读取该字段（工具范围由 `tool_scope` 投影，ZCode Worker 的注册表白名单与 Router 禁网差异都在角色与既有投影层保持），删除类与字段。`RunRequest.frozen_account`/`FrozenAccountReference`：仅从控制文件 `account` 键转抄，驱动不读取；账户环境选择本就由 `structured_call._account_environment` 直接取自运行时上下文，与该字段无关，删除类与字段及控制文件里两处随之无消费的 `account` 写入。`RunBudget` 只保留 `timeout_seconds`：驱动唯一读取点是 `execution_deadline(request.budget.timeout_seconds)`，`max_output_bytes`/`tool_calls`/`bytes_read` 无任何读取，原有字节/协议上限由各 harness 自己的常量与事实包界限执行，不借格式改变。`RunContinuation` 只保留 `mode`/`previous_session_id`：`_continuation_of` 与角色构造都只用这两项，四个关联字段从未被填写或读取。`SessionService` 只保留 `tool_names`：唯一读取点是 `_check_service_descriptions` 的挂载一致性核对；`service_id`/`kind`/`input_schema`/`output_schema`/`delivery_mode` 无业务读取，实际挂载 schema 来自 mount 并与 `request.output_schema` 对照（该对照保持原样）。

## 结果侧复核结论

删除的恒定占位：`RunResult.quota`/`QuotaPackage`（驱动从不产出，公开结果的 `quota` None 键由 `collect` 的既有归一化保持，`test_adapter_usage` 既有断言不变）；`ResultConfiguration.observed`（驱动从不填写，`_base_result` 改为常量 `None`，公开 `observed` None 键行为不变，`test_zcode` 既有断言不变）；`ModelStartEvidence.event_sequence`、`CheckedValue.native_identity`、`RunValue.errors`、`DeniedInteraction.request_id`/`native_identity`、`UnknownEvents.truncated`、`PolicyFact.reported`/`limitations`、`ContinuationFacts.checkpoint_ref`、`EvidenceRef.retained`——全部从未被写入或读取，被拒交互的完整记录（含原生请求身份与时间戳）仍在 `denied-interactions` 证据引用里，未把删去字段藏进别的 JSON 槽。`EffectivePolicy.network` 恒为 `PolicyFact(enforcement="unknown")`，唯一读取点是 `native_evidence` 对 `tools.requested` 的读取，network 无消费者，删除字段。`StopEvidence.controller` 从未被填写（外层停止由持有方 `handle.shutdown_confirmed()` 实际确认，`_role_stop` 与 `_base_result` 读的是 `native.group_state`），删除字段。`InterruptEvidence.acknowledged` 被驱动显式写常量 `None`（本原生无可核对回执），删除字段，`requested`/`basis` 保留。

撤出删除、确认有真实生产读取（A 类）的字段：`identity` 全部、`harness`、`end.status/reason_code/message/native_exit_code`、`harness_version`、`model_started`、`native_identity`、`value.raw/parsed/schema_status/correction_count`、`tool_evidence`、`usage`、`native_failure`、`native_error`、`last_assistant_message`、`activity`、`continuation.resumable`、`stop_evidence.native.group_state`、`evidence_refs.kind/location/size_bytes/sha256`；2-C1 增加的 `effective_policy.tools.requested`（`native_evidence`）与 `completion_evidence.stream_end`（`native_evidence`）以及 Worker 读取的 `completion_evidence.native_identity.turn_id`（`_worker_result`）均在。确认属 B 类保留的真实原生事实（无字段级角色判断，随完整 RunResult 经 runner-stdout 产物交付，位置/字节/SHA 由 `_artifacts` 登为黑板产物）：`model_start_evidence.basis/native_identity`、`root_identities`、`checked` 各值的 `basis/source`、`configuration.checks`、`value.validation_basis/mechanism`、`completion_evidence.call_id/event_order/receipt_ref/receipt_verified/native_outcome`、`denied_interactions.method/action/reason`、`unknown_events.counts/total`、策略的 `enforcement/requested/basis`、`continuation.native_session_ref/binding_ref/basis`、`stop_evidence.native` 除 `group_state` 外的实际观测、`interrupt.requested/basis`、`end.signal`。这是事实产物用途，不写成业务判断。

## Live 复核结论

删除未实现的预留：`FinishNoticePayload` 类、`"finish-notice"` kind 及其在 `ExistingLiveChannel.request` 的 unsupported 分支、`LiveCapabilities.finish_notice`/`session_content` 能力位、`ReservedEvents`/`_no_events` 与 `LiveSnapshot.events`；`LiveRequest` 只余 inquiry 一种 kind，payload 类型收敛为 `InquiryPayload`（pydantic 类型即拒绝其他形状，原手写 kind/payload 匹配校验随之删除），身份与 requestId 对完整 kind/payload 摘要的幂等语义不变。删除只被测试调用的旧 journal list 形状（`_read_journal_fact` 的列表分支与 `_journal_record_ids`），绑定必须返回生产绑定实际产出的 availability fact；`roles.live.handle_live_channel` 包装（仅测试调用，生产消费方 `runtime/worker.py` 用 `handle_live_binding`）删除。一并删除无生产与测试引用的孤立导出 `LIVE_KINDS`、`INQUIRY_DELIVERY_MODES`、`LIVE_REPLY_STATUSES`、`INQUIRY_STATES`、`REPLY_STATES` 与 live.py 里从未被本模块执行的 `MAX_WAIT_MS`（wait 上限的真实执行点在黑板 `tasks/inquiry.py`，测试改为直接钉住该值）。保留且有真实消费者的：分页与 `sequence` 游标、`fields` 选择、`inquiry_id` 点查、`InquiryState` 的答案来源字段（黑板 `tasks/inquiry.py` 逐字段投影）、`LiveJournal` 可用性/拒绝、`LiveObservation` 全部字段、`LiveReply` 的 observed/state/error_code 语义、完整身份核对（黑板按控制绑定与回合输入核对，Worker 按 handle 携带身份核对）。
