# ADR-025 第二步：Host 验收

2026-10-06，Claude Code Host。实现由 Codex 作为 Host 完成，它的记录是[第二步记录](adr025-step2.md)、[整合登记](adr025-step2-integration.md)、[格式使用清单](adr025-step2-format-usage.md)与[原生冒烟记录](adr025-step2-native-smoke.md)。本文只记录本 Host 亲自做的核对。

## 合入

`socu/adr025-run-module` 在 `5859475` 收尾，以合并提交 `8f8058e` 合入集成分支，没有冲突；合入后的源码、测试、打包文件与锁文件与被核对的提交完全相同。

## 这一步做了什么

ZCode 的 Worker 回合与快速路由都经登记的运行模块运行：角色把运行请求编码成文件交给控制器，控制器把运行结果写回，持有方解码并核对执行身份。ZCode 旧的运行器与两个旧的启动入口已经删除。问询与活动经同一个实时通道的接口，后端仍是原来的桥接与文件。其余三个 harness 仍走原来的载体。

## 测试覆盖的比对

本 Host 用自己的脚本列出全部 Python 测试的编号：第一步验收时 2,497 个，现在 2,628 个。减少的 12 个里，9 个是随接口改了名，3 个随被删除的代码一起删除，实现方的[对照表](adr025-step2-test-ids.tsv)逐个列出；新增 143 个。

## 规模

生产代码增加 5,164 行、减少 2,624 行。

| 部分 | 第一步验收时 | 现在 |
| --- | ---: | ---: |
| ZCode 的包 | 3,557 | 4,096 |
| 角色模块 | 1,086 | 2,330 |
| 各 harness 共用的顶层模块 | 2,968 | 3,458 |

角色模块增加的部分是公共代码，其余三个 harness 接入时复用；其中完成服务的逻辑是从 ZCode 的包里搬出来的。ZCode 自己的包仍然变大了，主要因为运行结果要上报的事实比原来多；它的 `run` 是一个 483 行的函数。

## 格式

这套格式现在有了第一个真实的使用方。实现方逐字段核对后删除了 41 个没有写入也没有读取的字段；留下的字段分两类，68 个有读取它的生产代码，18 个有原生来源、随结果一起交付但没有业务代码读取。第一步留下的两处测试缺口已经补上：去掉解析前的整帧大小上限、关掉严格类型，现在都有测试失败。

## 变异

| 做法 | 结果 |
| --- | --- |
| 运行模块总是上报模型已经开始 | 测试失败 |
| 完成时不再检查有没有未答复的问询 | 测试失败 |
| 不完整的工具调用也可以被排除出工具证据 | 测试失败 |
| 不再核对运行结果的执行身份 | 测试失败 |
| 去掉解析前的整帧大小上限 | 测试失败 |
| 关掉严格类型 | 测试失败 |
| 运行模块总是上报原生进程组已消失 | **没有测试失败** |
| 实时通道绑定时不再比较执行编号 | **没有测试失败** |

每次改动后都已还原。两处没有被抓住的，代码本身是对的：运行模块在停止没有确认时上报"未知"，实时通道比较了完整的身份。缺的是测试。前一处关系到"未知不等于已停止"，现有测试只在格式和角色两层断言了"未知"，没有一个测试让运行模块自己走到停止未确认的情形。

## 完整检查

`uv run --frozen python -m hey_my_buddy.cli.checks` 在 `5859475` 上通过：2,628 个 Python 测试（跳过 1 个），171 个文件全部运行，Node 测试 110 个，用时 436 秒，使用默认的并行数。日志在被忽略的 `tmp/` 下。

## 没有亲自核对的

- **真实模型的运行。** 实现方用已安装的 ZCode 做了一次真实的无工具运行，经过新的请求与结果格式，通过。本 Host 没有调用模型，只读了[记录](adr025-step2-native-smoke.md)。
- **真实的 Worker 回合没有冒烟过。** 带完成工具、问询或续接的回合，只有测试夹具覆盖：完整检查里有 5 个测试用已安装的 ZCode 程序对接本机的模拟模型服务。Worker 回合是日常使用的主要路径。
- **其他平台。** 全部核对都在 macOS 上。

## 过程中的偏离

- **限流。** ZCode 的 GLM-5.3 被供应方限流，两个微任务因此中途失败。第一次由路由改选了别的 buddy；第二次路由仍然选中被限流的 buddy，用户随后允许在第二步余下的微任务里、失败之后指定完整的配置继续。两个产品问题记在[待办](../design/backlog.md)。
- **一个检出没有回收。** 准备工作那个微任务的受管检出，黑板两次以"未登记的检出"拒绝回收，而 Git 的工作树列表里仍有它，目录也在。实现方没有手工处理，记在待办。
- **测试留下临时目录。** 新增的问询传输测试单独运行时在临时根里留下 8 个目录；在完整检查里它们随运行器的私有根一起删除。

## 带到后面的事项

铺开其余三个 harness 之前：

- **补两处测试。** 运行模块在原生进程组的停止没有确认时上报"未知"；实时通道绑定对身份的每个组成部分都拒绝不一致。
- **补一次真实的 Worker 回合冒烟。** 经新的运行模块，用完成工具交付一个最小的任务。
- **问询传输的测试清理自己建的目录。**

之后各步：

- 每一步结束时继续报告没有使用方的字段和类。18 个"有来源、无读取"的字段到第四步结束时要么有了读取方，要么删除。
- 其余三个 harness 的运行函数不要照搬 483 行的写法，按阶段拆开。
- 完整检查使用默认的并行数。

## 结论

验收。
