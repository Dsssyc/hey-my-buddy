# Codex 会话正忙时排进的消息，以及接连排进的几条

## 问题

给 Host 推通知要用 harness 自己的输入通道（开发者 2026-10-14 认同的方向，`await` 留作兜底）。对 Codex，通道是 `codex queue`。要弄清两件事才能设计：Host 正在跑一个回合时排进消息，会不会打断它；短时间里接连排进几条，是合成一回合还是一条一回合，顺序保不保持。前两份记录见[会话能不能被叫醒](2026-10-14-waking-an-idle-host-session.md)与[开在 Codex app 里的会话](2026-10-14-waking-a-codex-app-session.md)。

## 看了什么

- 自己的实验，开发者批准：Codex CLI 0.162.1，gpt-6-luna / low，在终端里开一个会话，六个很短的回合。只读了会话文件里各条记录的类型、时间与几个约定的短回答。没有读源码。Codex app 没有做这一项。

## 看到的事实

- 实测：会话正在跑一个回合（回合里执行 `sleep 40`）时排进一条消息，这条消息没有在回合中途插进去，也没有打断它；那一回合结束的同一秒，它作为一个新回合开始。
- 实测：同一秒里接连排进三条，按排进的顺序各成一回合，一回合结束接着下一回合，没有合并。
- 实测：给空闲的会话排进一条，约 6 秒后开始回合；上一份记录里同样的情形是 2 秒。

## 取了什么，没取什么

- 取：黑板给 Codex Host 推通知时要合并，同一时间最多只有一条在排队，之后发生的事并进下一条；否则每个事件都会单独花掉 Host 一个回合。
- 取：通知不会打断 Host 手上正在进行的回合，也就不会打断用户与 Host 正在进行的对话，只是排在它后面。
- 没取：不借排队去插话或打断，Host 的回合怎样结束仍由它自己定。
