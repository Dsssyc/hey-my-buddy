# README 怎样写得轻：几个开源项目的首页结构

## 问题

开发者 2026-10-23 嫌 README 文字太多、太笨重，问能不能学一学写得好的开源项目。当时的英文 README 约 3,200 词：安装一节里塞着 0.42 到 0.51 的逐版本改动，控制台、路由与执行几节写的是参考文档层面的细节（并发上限的数字、恢复语义、路由的两种模式），还有几段已经过时或无处归属。问题是：同类项目的 README 放什么、不放什么，篇幅多大，深的内容怎样交出去。

## 看了什么

2026-10-23 读了七个项目主分支上 README 的当前版本，都是公开的 Markdown 原文，由抓取工具概括结构与篇幅，没有逐字通读：

- uv（Python 包管理工具）
- ripgrep（命令行搜索工具）
- zoxide（命令行目录跳转工具）
- Ollama（本地模型运行工具）
- llm（命令行访问模型的工具）
- Codex CLI（编码 agent 的命令行）
- Ant Design（前端组件库，读的是它的中文 README，看双语怎样并排）

## 看到的事实

以下都是对方 README 的结构，由抓取工具概括，篇幅是约数：

- **第一屏**几乎都是：名字或标志、一句话说清是什么、少量徽章，有时一张图或一段演示，再加一行跳转链接。先回答“这是什么、为什么要用”，然后才出现命令。
- **亮点**用一行一条的短要点（uv 有 11 条，Ant Design 有 6 条），有的要点直接链到下文对应的一节。
- **安装**是一两条可直接复制的命令；平台不同就分成几个带标签的代码块，平台多的（zoxide）收进可折叠的 `<details>`，Codex CLI 把手动下载也收了起来。
- **上手**只给三五条命令或一小段示例，带上注释。
- **深的内容**一律交给文档：几乎每一节都以一个链接结尾（uv、Ollama、llm 尤其明显）。版本历史只放一个链接，不放正文。
- **诚实的限制**：ripgrep 专门写了“什么时候不该用它”；限制写清楚反而更可信。
- **篇幅**：Codex CLI 约 400 词，uv 约 1,300 词，ripgrep 约 3,000 词（大部分是性能对比与各平台安装）；Ollama 约 1,500 词，其中七成是社区集成的列表。
- **双语**：Ant Design 在页首放一行语言切换，当前语言不加链接，两种语言的结构对称。

## 取了什么，没取什么

取了：第一屏只放定位、一句话说明与跳转链接；一组一行一条的亮点；三步说清怎样工作；安装只留两条命令，“让 agent 来装”的提示词收进折叠块；上手只给一句话的示例与两条命令；一节诚实的现状与限制；其余全部交给参考文档。逐版本的改动不再写进 README，它们本来就在各版本的验收记录里。双语两份结构完全对称，语言切换照旧放在页首。

没取：徽章（还没有发布，版本、下载量与持续集成的徽章没有内容可指）；演示动图与截图（控制台还在变，先不放会过时的图）；性能对比与长长的平台安装表（不是我们的卖点，平台支持也还在做最后的准备）；社区与集成列表（还没有）；从文档自动生成 README 的做法（目前两份 README 手写更直接）。

这次改写把 README 从约 3,200 词减到约 870 词，测试钉着的安装命令、skill 路径与运维文档的锚点照旧保留。原 README 里一条只写在那里的隐私提示（由路由选 buddy 时，任务文字会发给 Router 所在的模型供应方）留在了现状与限制里。

2026-10-24 在“怎样工作”一节加了一张架构图，中英各一份，各分浅色与深色。它画的是机制，不是控制台截图：上下分层（你、Host 与仓库；黑板；Router、打回与封存三个关口；Worker），一个微任务的路径是一条左右对称的 U，图里的几何标记照搬控制台自己的标记。图由代码画成，没有用生图模型：两轮生图出的概念稿对不齐，同一个意思的标记大小不一，也画不出控制台真实的图标。

## 时效

首次发布之后要重看：那时有了发布渠道与版本，安装一节可以只剩一条命令，徽章也有了内容；控制台定型之后可以考虑放一张截图。控制台的标记、Router 的几个面或打回的流程变了，架构图要随之重画。
