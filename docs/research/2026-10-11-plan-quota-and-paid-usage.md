# 调研：订阅额度用完之后：付费用量、供应方的拒绝与恢复

日期：2026-10-11。调研人：Claude Code Host，应开发者的要求。

## 问题

订阅额度用完之后，harness 可能改用用户购买的 credits、额外用量或按量余额继续工作。黑板要不要为这个过程建模；什么时候把一个 buddy 移出路由，移出多久，怎样回来。为 [ADR-021](../decisions/021-router-buddy-planes-and-routing-evidence.md) 第 22 条服务。

## 看了什么

- magpie，一个把多种编码代理接到多家模型供应方的本地网关。读的是它 2026-10-11 的公开 README 全文与参考文档的前 10 万个字符；参考文档全文约 14 万个字符，后面的部分没有读。没有读源码。页面由工具抓取后经一个小模型按问题摘要，没有逐句对照原文，摘要可能有遗漏或出入。
- 本项目整合分支当天的源码：把五种额度观察交给路由的判定函数，看哪些会把 buddy 移出候选。

## 看到的事实

对方文档自述（经摘要）：

- 一个成员被拒绝后进入休息，同一个请求立即交给下一个候选，前提是还没有向调用方发出任何内容。
- 拒绝分几种，休息的时长不同：说明额度已用完的 429；短暂限流的 429，按供应方要求的时长，最多一小时，或从一分钟起逐次加倍，最多三十分钟；余额不足，半小时；其他失败，从一分钟起，重复则加长，最多十分钟。
- 休息的时长取已知的第一项：拒绝里给出的重置时间；最近一次读到已经用满的那个窗口的重置时间；供应方给出的重试间隔，上限一小时；都没有时十五分钟。最长不超过八天。
- 回来的办法：立即重读这个账户的用量，读数显示用满的窗口已经重新开始就马上恢复；五小时窗口的重置不清除仍然用满的周窗口；其余按定时结束；只剩它一个时仍然会试它。
- 订阅额度与 credits 只写了一种账户：持有 credits 的账户在窗口用完后继续应答，默认继续花；每个账户有一个开关可以关掉，关掉之后窗口用满即视为用完，直到窗口重置。别的订阅有没有额外用量，文档没有提。
- 用量表用来排序而不是判断能不能用：几种路由方式分别按最快重置的优先、用得最少的优先、按周的配速排序，用到九成与九成八的排在后面。

本项目实测：

| 观察 | 是否移出路由 |
| --- | --- |
| 订阅窗口 100%，别的没说 | 否 |
| 窗口 100%，harness 说仍可使用 | 否 |
| harness 说不允许继续使用 | 是 |
| 真实回合被拒绝，原因是额度用尽 | 是 |
| 余额为零 | 是 |

## 取了什么，没取什么

取：能不能用只听明确的回答，用量与计费方式只是给 Router 与界面的事实，这与本项目已有的判定一致，据此把第 22 条从两个 harness 推广到所有 harness；移出时长按已知的第一项取值；新的观察显示可以使用时立即恢复。

没取：每个账户一个"是否使用 credits"的开关，用户买了它们就是允许这样继续，偏好可以写在已有的偏好说明里；在一次请求之内换下一个账户，本项目的单位是微任务的一个回合，换谁由 Host 与路由决定；按用量表排序的固定方式，本项目由 Router 依据程序事实判断；只剩一个候选时仍然尝试，本项目在没有候选时把事实交回 Host。

## 时效

对方的做法随版本变化，这里记的是当天文档的说法。本项目的判定对应整合分支 2026-10-11 的源码；第 22 条实现之后（ADR-021 的 L9），移出与恢复的规则以实现与它的验收记录为准。
