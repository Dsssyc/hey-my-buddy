# 调研记录

决定之前查过什么，记在这里：别的项目、论文、产品以及本机安装的软件是怎样做的，我们从中取了什么。它与验收记录对称：验收记录证明交付被核对过，调研记录证明决定有据可查。决定（ADR）只留结论并指向这里的记录，不重复调研的内容。

## 一份记录的写法

一个问题一份，文件名是日期加主题。五段，都要短：

1. **问题。** 想弄清什么，为哪条决定服务。
2. **看了什么。** 每个来源写名称、材料的种类（公开文档、论文、本机安装的软件、自己的实验）、版本或日期，以及读到哪里为止。没读的部分明确写上，尤其是有没有读源码。
3. **看到的事实。** 用我们自己的话写，逐条分清是对方文档的自述、我们的实测，还是我们的推断。
4. **取了什么，没取什么。** 各自的理由，以及落到哪份决定的第几条。
5. **时效。** 什么变化会让这份记录过时。

## 规矩

- 不贴别的项目的代码，不写它的仓库地址，也不写仓库里的文件路径。论文与厂商的公开文档可以链接。
- 实现照调研记录与我们的决定来写，不读对方的源码。能直接用的只有许可明确的库或框架，以依赖的方式引入。
- 记录写完不再改动。同一个问题再查一次，就写新的一份，说明与上一份相比变了什么。 例外只有一次：2026-10-13 把各份记录里指开发者的“用户”改成了“开发者”，别的字没有动。
