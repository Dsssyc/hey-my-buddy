# DSH 0.2.1-rc.2 把会话记录写成 v4，我们只读 v3

## 问题

Router 维护面上 DSH 的维护记录，2026-10-29 03:43 以前都有用量，13:44 以后全是“未记录”。要弄清 DSH 0.2.1-rc.2 把会话记录写在哪里、叫什么、是什么格式，为 DSH 接入读用量的修法提供依据（`docs/reference/workers.md` 里“用量从私有会话记录读”那一条）。

## 看了什么

- 公开资料（2026-11-02，只读）：DSH 官方 GitHub 仓库 `dsh-v0.2.1-rc.2` 标签下的源码与文档片段：会话 JSONL 持久化插件的 README 与它的格式模块；会话格式包里给每一代日志命名的函数；核心会话类型里当前写入的格式号与助手消息事件的字段；LLM 包里的用量类型与模型来源类型；格式变更记录里 v3 到 v4 的那一份、各发布标签所写格式号的索引、格式状态页。另读了官方发布说明页（0.2.1-alpha.2 至 0.2.2-alpha.2）。只读了这些片段：没有读迁移的实现、ACP 应用与 profile 组合的代码，也没有读 0.2.1-rc.3 以后的源码。
- 本仓库：DSH 接入读会话记录的代码、启动补丁、读取的调用处，测试里假代理写的记录，以及 2026-10-27 对 DSH CLI 0.1.5-rc.1 的探针留下的夹具。
- 日常黑板（只读计数）：2026-10-26 至 11-02 每天 DSH 尝试的回执里有没有用量。
- 没有读本机安装的 DSH 包，没有看私有状态里的会话文件，没有为此调用 DSH。

## 看到的事实

标注：〔源码〕＝公开仓库的源码或文档自述，〔本仓库〕＝读我们的代码与夹具，〔黑板〕＝只读计数，〔推断〕＝我们的推断。

- 〔源码〕0.1.5 的各个标签写的会话格式号是 3；0.2.1-rc.2 当前写入的格式号是 4，格式状态页把 4 记为已发布，证据标签是 0.2.0-rc.2。
- 〔源码〕每一代日志的文件名：第 0 代是 `session.jsonl`，以后每一代是 `session.vN.jsonl`，压缩时再加 `.zstd`，默认压缩。文件第一行是 header，它的版本号与文件名里的代数相同。文件放在 `<root>/--<规整后的工作目录>--/<转义后的会话 id>/` 下；转义只改字母、数字、`.`、`_`、`-` 以外的字符，UUID 原样不变。平铺在根目录下的旧布局不再加载。
- 〔源码〕一个会话目录里可以同时有几代文件：写打开时把旧一代迁成新一代，新的一代写在旧的旁边，旧的不动；运行时只取代数最大的那一个。v3 到 v4 的变更记录写明，只认 v3 的读取方会拒绝更新的一代。
- 〔源码〕v4 的助手消息事件仍带 `turn`、`step`、`message` 与可选的 `usage`；用量字段仍是 `inputTokens`、`outputTokens` 与可选的 `totalTokens`、`cacheReadTokens`、`cacheWriteTokens`、`reasoningTokens`；消息的模型来源仍是 `kind` 为 `model`，带 `provider` 与 `model`。v4 改动的是工具结果的消息角色等，与这几项无关；`turn/end` 的原因多了 `forked`。
- 〔源码〕持久化插件的配置键仍是 `root`，我们启动补丁里那一行仍然成立。
- 〔本仓库〕我们的读取只认 `.v3.jsonl` 与 `.v3.jsonl.zstd`，并要求 header 的版本是 3，所以 v4 的记录既不会被列为候选，也不会被折算，结果是“没有记录”，控制台显示“未记录”。0.1.5-rc.1 的探针夹具里，真实 DSH 写的是会话目录下的 `session.v3.jsonl.zstd`；测试里的假代理却写平铺的 `<会话>.v3.jsonl*`，这种布局真实的 DSH 并不写，测试因此一直是绿的。
- 〔黑板〕DSH 的尝试回执：10-28 的维护 14 条里 13 条有用量；10-29 03:43 是最后一条有用量的；此后到 11-02，维护 12 条、其余 60 条，全都没有用量。同一时间，模型名从 `deepseek-flash` 变成 `deepseek-v4-flash`。
- 〔推断〕开发者在 10-29 03:43 与 13:44 之间把 DSH 从 0.1.5-rc.1 升到了 0.2.1-rc.2（10-27 的探针记着前者，10-29 的计费代码与 10-31 的调研记着后者），此后 DSH 写 v4，我们一条也读不到。没有在本机复现：没有看私有状态里的文件名，也没有调用 DSH。

## 取了什么，没取什么

- 取：在会话目录里只读代数最大的那一代，header 的版本必须与文件名一致；接受 3 与 4，因为我们读的几项字段在这两代里相同；不认识的代数照旧当作未知。只读最大的一代，是因为迁移之后新旧两代同在，两份都读会重复计数。
- 取：假代理改写真实 DSH 的布局与当前一代；平铺布局的查找随之删掉，因为 0.1.5 与 0.2.1 都不写它。
- 没取：不自己把 v3 迁成 v4，我们读的字段两代相同。不为不认识的代数另设报告：那种情形已经停在安全的一边，显示为未记录。
- 落到哪里：修法的微任务，以及 `docs/reference/workers.md` 读用量的那一句；不另起决定。

## 时效

DSH 再升格式号（v5 及以后），改了用量、模型来源或 `turn/end` 的字段，或者改了文件名与目录的规则，这份记录就过时。
