# C-Two 0.7.4 里对端没了怎样知道，一个执行进程要多少开销

## 问题

待办“每次执行一个进程”要把 Worker 并进执行进程，执行进程与黑板各自注册为 C-Two 的服务、互为客户端。

要弄清的有三件：

- 两边怎样知道对方没了；
- 心跳与租约还要不要；
- 一个执行进程启动要多久、占多少内存。

为 [ADR-031](../decisions/031-one-process-per-execution.md) 服务。

## 看了什么

- **已安装的 C-Two 0.7.4（本项目的依赖，开发者自己的项目）。** 读了这些：
  - Python 接口的全部公开名字；
  - `config/ipc.py` 与 `config/lifecycle.py`；
  - `transport/registry.py` 里所有者控制与生命周期的部分；
  - `crm/meta.py` 的 `on_shutdown`；
  - `crm/contract.py` 与 `transport/registry.py` 里比对契约的部分。

  原生模块只看了它导出的 108 个名字，没有读实现。
- **自己的实验。** 2026-10-15 在 macOS 上做，不调用模型，只用私有的端点目录。脚本在整合检出被忽略的 `tmp/one-process/` 下。Linux 与 Windows 没有测。

## 看到的事实

C-Two 的自述（读接口与配置所得）：

- 心跳只能在服务端配置（`heartbeat_interval`、`heartbeat_timeout`），客户端没有对应的设置。
- 没有“对端断开”的回调或订阅：Python 接口里没有，原生模块导出的名字里也没有。
- 有一套随所有者存亡的机制：
  - 控制者用 `owner_control_pair()` 拿到一对私有凭证，用 `spawn_owned_child()` 起子进程；
  - 子进程用 `adopt_owner_stdin()` 接过凭证，以 `LifecycleConfig.owner_bound(宽限)` 配置服务；
  - 凭证在起子进程时就用掉了，没有把所有者移交给别的进程的接口。
- `native_lifecycle_snapshot()` 报当前阶段，`native_terminal_outcome()` 报结束的结果。

我们的实测：

- **服务端被 SIGKILL。** 客户端正在等的那次调用，5 毫秒内以 `ClientCallResource`（“IPC client closed”）失败；此后每次调用立刻失败（“Broken pipe”或“local connection aborted”）。
- **客户端被 SIGKILL。** 服务端的生命周期快照没有任何变化。默认心跳与 0.5 秒的心跳都一样，服务端拿不到任何通知。
- **所有者被 SIGKILL，宽限 3 秒。** 子进程约 1 毫秒后进入 `owner_missing`；3.06 秒时结束，结果记为 `owner_bound_grace_expired`，并调用契约上声明的 `@on_shutdown`；3.1 秒时退出。
- **`@cc.on_shutdown` 标错地方不报错。** 标在实现类上既不报错，也不生效，必须标在契约上。
- **契约不一致，连接时被拒。** 服务端注册版本 0.1.0 的契约。客户端用同名而版本为 0.2.0 的契约，或同一版本而某个方法多一个参数的契约，`connect` 都以 `ContractMismatch` 失败，消息里列出双方的命名空间、名字、版本与 ABI、签名两个哈希；同一份契约照常调用。
- **启动开销（各量 3 次）：**

  | 导入 | 用时 | 常驻内存 |
  | --- | --- | --- |
  | 只导入 C-Two | 0.07 秒 | 29 MiB |
  | Worker 的运行时 | 0.23–0.30 秒 | 55–56 MiB |
  | 运行控制 | 0.13–0.14 秒 | 40 MiB |

我们的推断：

- 一方作为另一方的客户端时，在下一次调用就知道对方没了。要两边都及时知道，两边各自要有一个正在进行的调用打到对方，例如等待事件的长调用。
- 随所有者存亡的通道只管“父进程没了”这一个方向。
- 契约的比对只看方法与签名。载荷里的内容（我们传的是事实的 JSON）改了格式，它看不出来。

## 取了什么，没取什么

- **取。** 这些实测结果用作 ADR-031 的依据：执行进程怎样知道黑板没了，黑板怎样知道执行没了，定时续租能不能去掉；契约的比对用于第 10 条，执行与新服务的契约不一致时，接回明确失败。
- **报给开发者。** 以下几处作为 C-Two 的缺口报给开发者，在 hey-my-buddy 里怎样处理由开发者定：
  - 没有断开通知；
  - 所有者不能移交；
  - 导入时就加载 numpy 与 fastdb4py。

  `on_shutdown` 要声明在契约上，开发者说明这是有意的设计：不让 C-Two 的机制进入 Python 的实现类。不算缺口。

## 时效

以下变化会让这份记录过时：

- C-Two 升级，尤其是加了断开通知、所有者移交，或改为按需加载；
- 在 Linux 或 Windows 上重测。
