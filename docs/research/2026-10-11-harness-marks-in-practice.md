# 调研：harness 的标志，通行的做法与最后的决定

日期：2026-10-11。调研人：Claude Code Host。这是同一天[上一份记录](2026-10-11-harness-marks.md)的续篇，只写与它相比变了什么。

## 问题

上一份记录按两家商标规范的字面，把"用真标志"记为用户知情后接受的剩余风险，并建议加一句权利声明、用单色画法。用户随后问：别的开源项目与厂商都在用这些标志，也没有特别的说明，这怎么解释；并表示倾向彩色。

## 看了什么

- 用户给出的三张截图：一个开源的模型网关在它的代理列表里放了各家编码工具的彩色标志；一家模型厂商的官网在"支持的工具"里放了包括竞争对手在内的十来个编码工具的标志；一个 harness 的供应方设置里放了十来家模型厂商的标志。三处都没有权利声明。Host 只看了截图，没有去查这三处各自有没有取得许可。
- 没有新读任何规范原文；上一份记录里关于规范的话仍然只来自检索摘要。

## 看到的事实

- **用标志指明"这是哪个产品"是通行的做法**，开源项目与商业公司都这样做，包括在自己的官网上列出竞争对手的产品。
- **规范的字面比实际被容许的范围严。** 规范是商标权人对合作方提的要求；截图里的用法都不满足"事先批准"这一条的字面，却长期公开存在。
- **没有说明不等于拿到了许可。** 这三处是否各自谈过授权，从截图看不出来。

## 取了什么，没取什么

用户于 2026-10-11 决定按通行的做法来，并说明立场：尊重权利人的一切权利，收到警告就撤掉。

- **取：** 彩色的画法，用图标包里的原样；只有单色画法的那一个（ZCode 所用的标志）用单色。不加专门的权利声明。
- **仍然守住的两条：** 不改动图形；不把别人的标志用作本项目自己的标识。
- **与上一份相比改掉的：** 单色改为彩色；权利声明由"建议加"改为不加。上一份里"没取彩色，因为每种颜色只有一个含义"的理由在这里让位：标志的颜色属于标志本身，不算进界面的颜色词表。

任何一家权利人来信要求撤下：撤掉那一个，并另写一份记录。其余同上一份。
