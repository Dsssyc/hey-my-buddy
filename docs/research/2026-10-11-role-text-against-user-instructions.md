# 调研：黑板加的角色说明压不压得过用户自己的指令；Worker 的会话能不能不留在 harness 的历史里

日期：2026-10-11。调研人：Claude Code Host，应用户的要求。

## 问题

用户想让 Worker 直接用他平日配置好的 harness，不再隔离。这样一来，他为“和自己交互”写的用户级指令也会被 Worker 读到，而 Worker 对接的是 Host，不是用户。用户的设想是由黑板机械地在微任务提示词的最前面加一段按角色写的说明。要弄清两件事：这段说明压不压得过用户级的指令，放在哪一层才有效；Worker 的会话能不能继续不出现在 harness 自己的历史里。为“harness 这一层管哪些事”的决定服务，那份决定还没有起草。

## 看了什么

- 自己的实验，2026-10-11，本机，用户自己的配置原样使用，工作目录是一个空的临时目录，每个 harness 用最便宜的模型：Claude Code 2.1.284 两次调用，Codex 0.162.1 三次调用。每次只问一句话，各一个样本。
- 两个 harness 本机的帮助输出，只读，没有调用模型。
- 三次网络搜索的结果摘要：Claude Code 与 Codex 的官方文档、一个多 agent 框架的参考页、一家厂商讲自己多 agent 研究系统的文章。只读了摘要，没有逐页读原文。

## 看到的事实

实验（实测）：

| harness | 用户一侧的指令 | 角色说明放在哪里 | 回复用的语言 | 结论 |
| --- | --- | --- | --- | --- |
| Claude Code | 用户级记忆文件要求用中文 | 追加的系统提示词，要求法语 | 法语 | 角色说明胜 |
| Claude Code | 同上 | 提示词最前面，要求英语 | 英语 | 角色说明胜 |
| Codex | 项目的 `AGENTS.md` 要求用中文 | `-c developer_instructions=…`，要求法语 | 中文 | 没有起作用 |
| Codex | 同上 | 提示词最前面，要求英语 | 英语 | 角色说明胜 |
| Codex | 同上 | 不加角色说明（对照） | 中文 | `AGENTS.md` 确实生效 |

- 用量：Claude Code 两次各写入约 2.6 万 token 的缓存，输出 651 与 220 个 token；Codex 三次共约 4.6 万 token。
- Codex 那一次没有起作用，分不清是这个键在这种传法下没有被采用，还是它的优先级低于 `AGENTS.md`；没有再查。
- Codex 的用户级 `AGENTS.md` 里没有关于回复语言的要求，所以冲突是用临时目录里的一份项目级 `AGENTS.md` 造出来的。两者属于同一类指令文件，但这是替代，不是原样。

本机帮助输出（实测，未调用模型）：

- Claude Code 有 `--no-session-persistence`：会话不写盘，也不能续接，只在无界面运行时可用。
- Codex 的 `exec` 有 `--ephemeral`：运行时不把会话文件写盘。

搜索摘要里的说法（对方文档的自述，未逐页核对）：

- 一个多 agent 框架自带一段推荐的前缀，告诉 agent 它是多 agent 系统的一员，由框架拼在每个 agent 自己的提示词前面。
- 一家厂商讲自己的多 agent 研究系统：子 agent 的质量主要取决于主 agent 给的任务说明，要写明目标、边界与输出格式；每个子 agent 拿到的是一份自成一体的说明和一个全新的上下文。
- Claude Code 与 Codex 自己的子 agent 都由一段角色提示词定义。

我们的推断：

- 放在提示词最前面这一种做法，在两个 harness 上都压过了用户一侧的指令，而且它不依赖任何一个 harness 的专门机制。放在 harness 自己的指令层，在 Claude Code 上有效，在 Codex 上按我们的传法无效。
- 这只说明一条简单、明确的指令（回复语言）在一个样本上的结果。更强的冲突，例如用户级指令给 agent 指派了另一个角色，没有测。

## 取了什么，没取什么

取：角色说明由黑板机械地放在微任务提示词的最前面，四个 harness 用同一种做法。调研人原先建议优先放在 harness 自己的指令层，实验之后收回：那样各家的做法不同，Codex 上还没有证明有效。

取：隐藏会话用各 harness 自己的开关，没有开关的不藏。ZCode 与 DSH 现在就有单独的存放位置；Claude Code 与 Codex 各有一个“不写盘”的开关。代价是用了这个开关的会话不能原生续接，Codex 的 Worker 现在靠原生续接来接着做同一个微任务，这一点要在决定里权衡。

没取：角色说明当作权限的保证。它只约束行为；Worker 不能充当 Host、Router 不能用工具这些，仍由黑板机械地判定。

## 时效

模型与 harness 的版本一变，指令之间谁压过谁就可能变；这里是 Claude Code 2.1.284 与 Codex 0.162.1 各一个样本。角色说明写出来之后，要用它的真实文字和用户真实的用户级指令再测一次。
