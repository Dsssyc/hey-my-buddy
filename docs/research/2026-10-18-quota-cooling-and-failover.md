# 调研：额度用尽之后怎样不打扰 Host，又怎样知道额度回来了

日期：2026-10-18。调研人：Claude Code Host，应开发者的要求。这是 [2026-10-11 两份记录](2026-10-11-plan-quota-and-paid-usage.md)的续查，与它们相比变了什么写在第四段。

## 问题

开发者的 GLM 套餐额度用完之后，路由在其后七十多个小时里一次次把微任务派给它，每次都失败并停到 Host 面前，由 Host 改派。另外，控制台的额度栏显示的百分比没有任何机制在用：Codex 能随时读到，Claude Code 只在 Worker 回合里顺带看到，常常是几个小时前的，ZCode 与 DSH 没有来源；“已用”与“剩余”的口径也让人读反。开发者还指出：重置卡、临时升级订阅会让额度在重置时刻之前就回来，各家升级时重置哪个窗口也不一样（Codex 两个窗口都重置，升到 Pro 取消五小时窗口；Claude Code 重置周额度而保留五小时窗口）。要回答：被拒之后怎样不打扰 Host；不读用户的凭据、不让黑板自己调模型，怎样知道额度回来了。为 [ADR-019](../decisions/019-worker-accounts-and-usage.md) 第 6 条、[ADR-018](../decisions/018-routing-modes-and-host-workflow.md) 第 23 条与 [ADR-021](../decisions/021-router-buddy-planes-and-routing-evidence.md) 第 22 条服务。

## 看到的事实

对方文档的自述（经摘要）：

- **被拒对调用方不可见。** CLIProxyAPI 遇到额度用完，同一个请求直接用下一个账号重发；OpenRouter、Bifrost 与 LiteLLM 在一个供应方出错或被限流时换下一个候选。调用方只看到最终结果。
- **冷却。** claude-mem 对用完的额度冷却 30 分钟，对限流与故障 90 秒；Bifrost 默认 30 秒，响应头给了重试间隔就照它；LiteLLM 收到 429 就冷却这个部署，时长可配。
- **冷却随连续失败变长。** Envoy 每连续隔离一次，隔离时长就是基础时长乘以连续次数，有上限；恢复正常之后乘数逐步降回去。CLIProxyAPI 对用完额度的账号做指数退避，从一秒到三十分钟。
- **回来的办法。** claude-mem 冷却结束后用一个请求试原来的供应方，答得上来就自动切回；Bifrost 冷却结束后的第一个请求就是试探，又出问题就再断开。都不需要用户操作。
- **读剩余额度。** 9Router 通过订阅账号的登录读这个账号的额度；那篇文章没有说读法。Claude Code 的剩余额度只有它自己的 `/usage` 是准的；按本地日志估算的工具只能说用了多少，不能说还剩多少。
- **同一个账户里换模型没用。** 几篇讲 Claude Code 回退的文章指出，同一个账户下的模型共用额度，回退只在换账户或换供应方时有用。

本项目的事实：

- 读额度百分比的只有控制台的额度栏、Buddy 页的提醒徽标与微任务视图里给 Host 的 `quotaWarnings`，没有一个决定按它做。
- 路由真正用到的是用尽：原生拒绝或某个窗口到 100% 时，这个 harness 的这个提供方在重置时刻之前移出候选；没有重置时刻的，每小时放一次单次重试；`quota-redetect` 可以提前放行。
- 被额度拒绝的回合是微任务的一次失败，停到 Host 面前，这正是开发者那七十多个小时里一次次被打扰的原因。

## 取了什么，没取什么

取：

- 回合在模型开始之前就因额度被拒，不算微任务失败：这个 harness 的这个提供方进入冷却，同一个微任务在同一次路由里改派给下一个候选；所有候选都在冷却时才停到 Host 面前，并给出各自大约何时恢复。与 10-11 的记录相比，这一条从“没取”改为“取”：那时认为换谁由 Host 与路由决定，实际的代价是每次被拒都打扰 Host。
- 冷却随连续被拒的次数加倍：30 分钟、1 小时、2 小时，最长 24 小时；原生给了重置时刻时不超过它；一次成功就清零。
- 冷却结束之后派来的下一个真实回合就是试探，不另开探针。
- 保留 `quota-redetect`，作为买了重置卡、升了订阅之后立即解除冷却的手动入口。

没取：

- 用用户的登录去读剩余额度：本项目不读用户的凭据。
- 黑板自己发请求去探：除 Codex 外，探一次就是一次模型调用，额度回来了就真的消耗，按量计费的还要花钱，而且是没人要求的调用。只给 Codex 加一套就成了第二个机制。
- 固定的短冷却：遇到按周计的用尽，试探会太多。
- 为各家的窗口与升级时的重置方式建模：冷却与试探不需要知道这些。
- 回合进行到一半才被额度打断时也透明改派：模型已经开始，可能已有部分成果，仍交给 Host 决定，只是同样进入冷却。认证失败也不改派：换一个候选修不好凭据。

## 时效

各家的做法随版本变化，这里记的是当天文档的说法。某个 harness 有了不调模型、不读凭据就能读到剩余额度的办法时，重新看“没取”的第二条。
