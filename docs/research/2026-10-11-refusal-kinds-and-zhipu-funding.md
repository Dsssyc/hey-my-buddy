# 调研：供应方的拒绝怎样分类、歇多久；智谱的套餐、资源包与余额各管哪一段

日期：2026-10-11。调研人：Claude Code Host，应用户的要求。这是[同一天上一份记录](2026-10-11-plan-quota-and-paid-usage.md)的续查，与它相比变了什么写在第三段的末尾。

## 问题

一次真实的回合被供应方拒绝时，怎样分清"额度用完了""暂时限流""欠费"，各自移出多久，怎样回来。智谱的订阅套餐、资源包与账户余额之间有没有自动接续，ZCode 在这件事上给得出什么。为 [ADR-021](../decisions/021-router-buddy-planes-and-routing-evidence.md) 第 22 条与它的模块 L9 服务。

## 看了什么

- magpie，一个把多种编码代理接到多家模型供应方的本地网关，许可为 MIT。这一次读了它 2026-10-11 的源码：文件清单是完整的（4,593 项）；判定拒绝种类与休息时长的部分、智谱套餐额度与重置卡的读取、"读到窗口重新开始就提前恢复"的规则、ZCode 自有套餐的余额读取，是逐句读的；按量余额的读取与 ZCode 登录的部分只经一个小模型按问题摘要，没有逐句核对。其余的源码没有读，测试也没有读。读到的内容没有留在本机。
- 智谱的公开文档，2026-10-11 逐句读了这几页：[错误码](https://docs.bigmodel.cn/cn/api/api-code)、[套餐概览](https://docs.bigmodel.cn/cn/coding-plan/overview)、[套餐常见问题](https://docs.bigmodel.cn/cn/coding-plan/faq)、[团队版权益](https://docs.bigmodel.cn/cn/coding-plan/team)、[费用问题](https://docs.bigmodel.cn/cn/faq/fee-issues)。
- 自己的实验，用的是整合分支当天的源码（提交 `27f72e96`）、本机安装的 ZCode 0.16.9 与用户自己的 ZCode 配置，状态目录是私有的：一次不发提示词的原生目录读取，两次无工具的真实回合。两次回合都没有消耗 token：第一次在发出模型请求之前就因配置不在目录里而结束，第二次被供应方拒绝。
- 日常看板上当天早些时候一次被拒绝的 ZCode 回合留下的结果，只读了它的失败事实。

## 看到的事实

对方源码的做法（转述）：

- 它没有按厂商维护错误码表。一次失败按 HTTP 状态和响应正文里出现的词归类。会让账户歇下来的有四种：欠费、套餐额度用完、短暂限流、其他失败；另有一种是厂商要求先验证账户。不让任何人歇的有：安全过滤拒绝、请求的形状不被接受、系统提示词被拒、套餐不允许所要的推理强度、本机代理不通、对话超过模型的长度、首个字迟迟不来、回复陷入循环。
- 判定有先后：对话过长永远不算额度问题；402，或正文说到余额、欠费、充值，归欠费，其中 429 只在正文明说余额已经花完时才算；429 且正文说的是每秒、每分钟一类的频率，又没有说到套餐、额度、每天每周每月，归短暂限流；正文说到额度、用量、套餐、上限，或 429 说到按天按周按月的限额，归额度用完；5xx 只认厂商自己的"额度用尽"代码，不认文字，因为中转站的"负载达到上限"说的是它自己的负载；其余的 429 归短暂限流。
- 休息多久，各取已知的第一项。额度用完：拒绝里写明的恢复时间；最近一次读到已经用满的那个窗口的重置时间；响应头里的重试间隔；都没有时十五分钟；最长八天。短暂限流：厂商给的时间，最多采信一小时；没给就一分钟，刚回来又被限就加倍，最多三十分钟。欠费三十分钟。其他失败从一分钟起逐次加倍，最多十分钟；但订阅账户失败时若已知有窗口用满，就歇到那个窗口重置。
- 怎样提前回来：因额度歇下的账户，失败之后立即重读一次用量，以后每次读到那个窗口不再是满的就马上恢复；五小时窗口重新开始而周窗口仍然用满时不算恢复；用户可以手动解除。
- 拒绝只针对某一个模型（这个套餐不含它、找不到它）而没有提到额度或余额时，只搁置这个账户上的这个模型，账户的其他模型照常。
- 订阅的窗口大约每分钟向厂商读一次。读不到时保留上一次的值；余额为零不当作用完，只有真实的拒绝才算。

对方源码里用到的厂商接口（我们没有调用过，文档目录里也没有找到它们的说明）：

- 智谱套餐的额度：向密钥所属的站点（`open.bigmodel.cn` 或 `api.z.ai`）读 `/api/monitor/usage/quota/limit`，密钥直接放在 `Authorization` 里，不加 `Bearer`。答复里有套餐的级别与一组限额，每项带种类、窗口的单位（3 是小时，6 是周）、已用的百分比与下次重置的时刻（毫秒时间戳）。种类为 `TIME_LIMIT` 的一项是当月 MCP 工具调用的次数，它不会让模型停下。
- 智谱的重置卡：同一站点的 `/api/biz/customer-package-reset/list`，分五小时与每周两类，每张带是否可用与有效期。套餐的起止与续费：`/api/biz/subscription/list`。
- ZCode 自有的套餐（体验套餐等，经 ZCode 的账户登录使用，不经 API 密钥）：向 ZCode 的站点读 `/api/v1/zcode-plan/billing/balance`，凭 ZCode 登录后的会话令牌。答复里是一组套餐与一组余额桶，每个桶带名称、覆盖的模型、总量、已用、剩余与到期时间。请求里不带"用哪个桶"，由服务端挑。
- DeepSeek 的按量余额：`api.deepseek.com` 的 `/user/balance`。

智谱公开文档的说法：

- 错误码都以 429 返回，含义不同：1113 账户欠费；1302 达到速率限制；1305 模型当前访问量过大；1308 达到某个时长的使用上限，消息里写明重置时间；1310 达到每周或每月的使用上限，消息里写明重置时间；1309 套餐已到期；1311 当前套餐不含这个模型；1313 因不符合公平使用策略而被限制频率；1316 至 1321 是团队套餐在额度用完之后因余额或消费上限不足而不能转按量付费的几种情况。
- 个人套餐有每五小时与每周两个上限。五小时的额度在消耗它的请求之后五小时恢复，每周的自下单起七天一轮。**套餐额度用完之后要等下一个周期，系统不会接着消耗资源包或账户余额。** 团队套餐可以由管理员开启"超额按量付费"，开启之后额度用完接着按量计费。
- 套餐只在指定的工具与指定的地址上生效。地址不对或工具不在支持之列时，请求按量计费，买了套餐仍会报 1113 或扣余额就是这个原因。
- 按量计费的扣减顺序：先扣适用于这个模型的资源包，同样适用的先扣最早到期的，再扣现金余额。欠费时有效期内的资源包仍然可用。文档说套餐到期之后要用资源包，得把工具的地址改成通用的按量地址。
- 重置卡是活动期间发放的权益，用掉一张就把对应的额度恢复到满并从那一刻重新计周期；每周的那种同时把五小时的也恢复。

我们的实测：

- ZCode 当前给出的可用模型来自一个供应方条目，访问方式是套餐密钥，模型有 GLM-5.3 与 GLM-5.3-Flash。日常看板目录里的 ZCode 配置指向另一个条目，那个条目已经不在 ZCode 给出的可用清单里，按它发起的回合在发出模型请求之前就以"配置不可用"结束。
- 经现在的条目发起的一次 GLM-5.3-Flash 回合被拒绝：429，代码 1310，消息写明限额在 2026-10-13 16:50:02 重置（消息没有写时区）。用户当天为这个模型买了一个资源包，这次拒绝说明它没有被用上。这与上面文档的说法一致。
- ZCode 给出的结构化失败事实，在今天早些时候那次带工具的回合里是：原因为限流、标明不可重试、供应方代码 1310、状态 429。里面没有恢复时间；恢复时间只出现在供应方的消息文字里，这次是在原生进程的错误输出里看到的。
- ZCode 的用量事件只带各类 token 数与供应方、模型的标识，不带这次请求由什么付费。这一条的依据是本项目的测试样例对 0.16.9 字段的记载，今天没有重新核对。
- **本项目的一处缺陷：** 无工具的回合（Router 的调用走的就是它）失败时，结果里没有供应方的失败事实，也就没有额度用尽的记录；带工具的回合有。今天的真实回合与源码都是这样，核心分支也是这样。

我们的推断：

- 智谱那里，一次请求由什么付费取决于它发到哪个地址、用的是哪种密钥，服务端不会在套餐、资源包与余额之间逐级接续；只有团队套餐开启超额按量付费是例外。用户原先的理解是三者依次接续，就个人套餐而言文档与实测都不支持。
- 1310 被 ZCode 标为不可重试，与文档里"每周或每月上限"的含义相符，所以把"限流而且不可重试"记为额度用尽是对的。1308、1302 与 1305 各被标成什么，没有实测。

与上一份相比变了什么：上一份只读了对方的文档，这一份读了源码，时长与取值顺序的说法与上一份一致，补上了分类的依据。上一份与第 22 条都写着"ZCode 的套餐用完之后是否改走按量，尚未核实"，现在核实了：不会，它给出的只有供应方的拒绝。

## 取了什么，没取什么

取：第 22 条的判断不变并得到印证，黑板不推断 harness 内部怎样转到付费，只听明确的回答。L9 实现"移出多久"时，ZCode 的恢复时间有两个可能的来源，都记在这里供那时取舍：供应方消息里的时间，文档给出了消息的固定写法，但它是文字，而且没有写时区；厂商的额度接口给出的重置时刻，是无歧义的时间戳，但要用套餐的密钥去读，而黑板不持有 ZCode 的密钥。智谱错误码的含义表也留给 L9：哪些是额度用完，哪些是暂时的，哪些与额度无关。

没取：按正文里的词归类。对方面对上百家上游，只能这样做；本项目的四个 harness 各自给出结构化的原因，按词判断会把厂商改一句文案变成误判，这与第 22 条"只听明确的回答"和 ADR-023 第 2 条相反。由黑板直接拿用户的密钥去读厂商的额度接口，现在也不取：按 ADR-023 第 1 条先看 ZCode 自己有没有原生的读法，这一点还没有查。一次请求之内换下一个账户、只剩一个候选时仍然尝试，理由与上一份相同。

缺陷不在这份记录里处理，记在[待办](../design/backlog.md)的"路由与额度"里。

## 时效

智谱的套餐在 2026 年 7 月改成了积分制，错误码与扣减规则随产品调整，这里记的是当天文档的说法；团队套餐与资源包的行为我们没有实测。ZCode 的事实对应 0.16.9。对方的做法随版本变化。第 22 条实现之后（ADR-021 的 L9），以实现与它的验收记录为准。
