# Codex 的睡眠工具与排队唤醒：比 2026-10-14 多了什么

续查 2026-10-14 的三份记录：[会话能不能被叫醒](2026-10-14-waking-an-idle-host-session.md)、[开在 Codex app 里的会话](2026-10-14-waking-a-codex-app-session.md)、[会话正忙时排进的消息](2026-10-14-codex-queue-during-a-turn.md)。与它们相比，新的是官方对排队唤醒的明文说法、0.164.0 里能被插入消息打断的睡眠，以及一个还在开发中的“代理消息唤醒”开关。

**问题。** 开发者的一个 Codex 自动化任务每周查“Codex 能不能在回合结束后被叫醒”，2026-10-26 报告说 Codex 似乎有了睡眠与唤醒的支持；开发者要整合 Host 分析这对 Codex 当 Host（以及 Lead 的唤醒）意味着什么。服务于 [Codex 的 Host 指南](../reference/host-codex.md)的等待方式，以及待办“执行上的问题要让控制台与 Host 都知道；Lead 的唤醒与 `await` 共用一个‘新消息’的定义”。

**看了什么。** 2026-10-26：本机安装的 Codex CLI 0.164.0 的 `codex --version`、`codex queue --help`、`codex features list`（只读，没有模型调用）；[OpenAI 的 Codex 开发者命令文档](https://learn.chatgpt.com/docs/developer-commands)里 `codex queue` 一节（页面后约 4 万字没有读）；Codex CLI 0.149.0 与 0.164.0 的官方发行说明；那个自动化任务这一次的会话记录（开发者交来的，只读了消息部分）。没有读 Codex 的源码，这一次没有做付费实验。

**看到的事实。** 官方发行说明自述：0.149.0 加了 `codex queue`，可以给本机或远程的已有会话发消息，并且“排进的消息现在能可靠地叫醒空闲会话”；0.164.0 有三条与等待有关：代理消息可以叫醒空闲的根会话，但在功能开关之后；待处理的插入消息会打断代理的等待与睡眠；排进的提示会等待尚未确定的权限选择。官方命令文档自述：`codex queue` 按会话的 UUID 或确切名字排进一条文字消息，可以连远程的 app-server，标为 Stable，不支持图片；文档没有写它能不能叫醒空闲会话，也没有写睡眠工具。本机 0.164.0 的功能列表里：`sleep_tool` 为 stable、默认开着，`wake_on_agent_messages` 为 under development、默认关闭；官方文档里没有找到 `sleep_tool` 的说明页（只有第三方的变更摘要提到 0.141.0 起有睡眠工具）。我们 10-14 的实测仍是唯一的一手证据：Codex CLI 0.162.1 与 Codex app 里的 0.162.0-alpha.17.2，空闲会话都被排进的消息在 2 到 6 秒内叫醒；关着的 CLI 会话在下次打开时收到；正忙时排进的消息不打断当前回合，接着按顺序一条一回合。推断（未验证）：有了“插入消息打断睡眠”，Host 可以在回合里用睡眠工具等，等到的不是命令结束，而是一条从外面排进来的消息。

**取了什么，没取什么。** 取：叫醒一个回合已结束的 Codex Host，官方的、不需要开关的办法从 0.149.0 起就有，就是 `codex queue`，而且我们在 CLI 与 app 上都实测过；缺的不是 Codex 的能力，而是我们这边的接法：谁在微任务到了边界时排这条消息、Host 怎样知道自己会话的 UUID、Host 起的等待进程在回合结束后还在不在、它要在 Host 的沙箱之外运行。按 10-14 开发者认同的方向，由 Host 一侧发起、用 harness 自己的输入通道，`await` 留作兜底；同时排队的通知要合并，同一会话最多一条在排队。取：0.164.0 的“插入消息打断睡眠”给了第二种接法，Host 不结束回合、用睡眠工具等，被排进的消息打断后在同一回合里接着做；它省掉现在每个微任务一个监看子代理的开销，但回合要一直开着。没取：`wake_on_agent_messages`，它还在开发中、默认关闭，Host 指南不能要求用户打开实验开关，产品也不替用户开。这两种接法都排在首次发版之后，与上面那条待办一起设计；设计之前要在当前版本上实测（付费，逐次由开发者批准）：Host 怎样拿到自己会话的 UUID，Host 起的后台等待进程在回合结束后是否还活着，0.164.0 上排队唤醒在 CLI 与 app 上是否照旧，睡眠被插入消息打断时消息怎样进入回合、睡眠最长能多久。

**时效。** Codex CLI 与 Codex app 各自的版本一变，就要重查；`wake_on_agent_messages` 转为正式、官方文档写明睡眠工具或排队唤醒的行为、或者 Codex 加上“后台命令结束时叫醒会话”，这份记录就过时了。
