# 第三层导航：不叠页签栏的做法，与 Router 分区的三个原型

2026-11-10，整合 Host。

## 问题

控制台的顶栏是应用一级的页签（任务 / Buddy / 设置），Buddy 页的分区栏是带下划线的分区页签（目录 / Router / 评价）。Router 分区里还有一层：Router 的三个面，界面上只写三项工作的名字，路由、维护、画像，各是一页，有几块设置与几张记录表。这一层换过两种放法：0.67.0 至 0.67.2 是页内左边的三项列表，每项一行状态；0.67.3 起是分区栏下面的一条工具带，里面是带图标的小块，选中的一块填底色。开发者看过三个原型：(a) 第三条整宽的带，带图标、选中填底色，与 0.67.3 起装着的是同一类，开发者嫌页签栏叠得太多、不好看；(b) 摊平成五个分区页签“目录 · 路由 · 维护 · 画像 · 评价”，开发者嫌散、不聚焦，丢了 Router 这层归属；(c) 不要带，三项做成页内的大号标题式切换，当前一项粗体、其余淡色，还在等开发者的看法。问题是：做得好的网页应用怎样放第三层导航而不叠几条页签栏，哪一种适合这里。它为 Router 分区这一层的放法服务，待开发者定；定下之后要改[重做计划](../design/adr029/buddy-router-redo-plan.md)“0.67.2 之后”第 1 条与 [ADR-021](../decisions/021-router-buddy-planes-and-routing-evidence.md) 第 16 条。

## 看到的事实

按做法分组。括号里写来源的性质：自述是厂商或机构在自己的文档里讲的，转述是别人转讲的，推断是我们的；日期与版本见上一节。

### 区内的二级页签

- Material 3（Google 自家文档的转述）：主页签放在内容区顶上、顶栏之下，列出主要的去处，一屏只要一组页签时用它；次页签用在内容区里，把相关的内容再分开、表出层级，一屏要两层页签时才用。一条页签栏里只用一种页签。
- Primer（自述）：UnderlineNav 的每一项是有自己地址的一页，紧贴放在它管的内容上方；页签不超过两层；不要把几条 UnderlineNav 直接上下叠放，再要一层时考虑 NavList；图标只作辅助，标签不能省。
- Carbon（自述）：页签用于相关而不同的内容，例如子页、表单、设置与仪表板；同一内容的切换或筛选用内容切换器，它常放在页签的内容里、低一层；横排页签不换行；竖排页签不当导航用。
- Fluent 2（自述）：Tablist 在不离开页面的情况下切换几类相关的信息，也可以在少数几个紧密相关、常去的页之间导航；更远的导航用链接。
- Atlassian（自述）：不要用页签在不同的页或状态之间导航；对所有页签都适用的信息放在页签线上方；页签尽量少。
- Shopify（自述）：页签只在应用导航不够用时做二级导航，要少用；点一个页签只改它下面的内容；页签不换行。
- Geist（自述）：页签切换同一页上的同级视图，它们共用范围、地址的上级与数据；不相关的页用子菜单；桌面上一排 5 到 7 个；当前页签写进地址。
- NN/g《Tabs, Used Right》（自述）：简单的网站与应用不要在一个页签控件里叠几排，选中的指示会落在几排之间分不清；不要在同一个控件里混用页内页签与导航页签，两种同时出现时要在样子上分开；选中的一项至少用两种指示，例如线、加粗、底色；页签紧贴在它的内容上方；标签一般一两个词。
- 产品（都是各家文档的自述）：GitHub 仓库名下面是一排页签，Settings 是其中一个；Cloudflare 从 Workers & Pages 进到一个 Worker，页里有 Domains 页签；Vercel 在 2026-02-26 把团队与项目两级的横排页签移进了可调宽、可隐藏的侧栏，日志给的理由只有测试期的反馈与按常用流程重排。

### 页内的左侧局部导航

- Primer（自述）：左边的上级侧栏决定右边的详情，用 NavList 实现；NavList 可以分组、带组标题，设置页推荐这样用；子项最多四层，再多就该改设计。
- Apple（自述）：侧栏最多显示两层，更深的用分栏视图，在侧栏与详情之间加一列内容；侧栏占地方，空间紧时紧凑的页签栏可能更好；iPadOS 上先考虑页签栏。
- Fluent 2（自述）：Nav 最多两层，更深的用树。
- Carbon（自述）：左侧面板放二级导航，不支持三层；子菜单下面还有内容时，在页内用页签；二级导航超过五项、或用户常在其间切换时用左侧面板。
- Windows（自述）：NavigationView 的左侧模式用于 5 到 10 个同样重要的类别，顶部模式用于 5 个以内；层级以两层为宜。Navigation basics 一页把左侧导航放在项目多于五个、且不常在其间切换的场合，常切换的子项用列表加详情。Carbon 与 Windows 在切换频繁这一点上说法相反。
- Atlassian（自述，组件已弃用）：侧栏用于在应用的一个子区里移动，例如一个 Confluence 空间或一个 Jira 项目；嵌套尽量少，要有返回。
- NN/g《Local Navigation》（自述）：局部导航列出当前类别里的同级页与子页，告诉用户在哪里；横排放在全局导航正下方，但实际只撑得住两三层，再多就只能少显示几层或叠成几排；竖排在左边，与全局导航成倒 L；局部导航不该比全局导航更显眼，视觉层次应当照着信息层次；更深的页改用面包屑。
- NN/g《Left-Side Vertical Navigation on Desktop》（自述）：竖排适合宽而会长的信息结构，但占掉内容的宽度；文中的例子从竖排改成横排后，内容与外框之比从约 5:1 升到 12:1。
- 产品（都是各家文档的自述）：GitHub 仓库的 Settings 里是一列分组的侧栏，例如 Code, planning, and automation 一组下的 Branches；Vercel 的项目先在侧栏点 Settings，再点里面的菜单项，例如 Build and Deployment；Cloudflare 的侧栏在选定域名之前列账户一级的产品，进了域名之后列域名一级的产品；Stripe 的侧栏分主导航、快捷方式与产品三段，设置分个人、账户与产品三类。

### 分段控件

- Apple（自述）：iOS 与 iPadOS 上用于在密切相关的子视图之间切换，完全分开的几个区用页签栏；macOS 的主窗口区切换视图用页签视图，不用分段控件；可以放在工具栏或检查器里切换面板，例子是 Keynote；宽界面里大约五到七段，各段等宽。macOS 的页签视图把互斥的几块内容放在同一个区域，每块里的控件只管这一块，最多六个页签。
- Carbon（自述）：内容切换器在同一或相关内容的几种视图之间切换，例如网格与表格、全部与已读与未读，不是导航；独立的内容区，例如子页，用页签。
- Primer（自述）：分段控件从少数紧密相关的选项里选一个并立即生效，用于排序、筛选与换一种呈现；选一段不应改变地址；文字段二到五个。导航模式页：点了要改地址的用 UnderlineNav，两种页签组件都不合适时才用分段控件，并让各段是链接。
- Windows（自述）：SelectorBar 是轻量的切换，文字可带图标，在少数几组视图或几页之间选一个，例子是最近、共享、收藏三页；整个应用一级的导航用 NavigationView。

### 页头标题兼切换

- Primer（自述）：PageHeader 是界面最上层的标题区，有标题、动作与导航的位置；UnderlineNav 可以放进导航位，在标题下方，这时页头自己的底线不再画；往上一级在窄屏用上级链接，或在标题上方的上下文区放面包屑。
- Windows（自述）：NavigationView 的页头放所选类别的页标题。
- Apple（自述）：大标题帮人在浏览与滚动时保持方位。
- Windows（自述）：Pivot 用一排文字标题在少数几块内容之间切换，现在不推荐用于 Windows 11 的设计，推荐改用 SelectorBar、NavigationView 或 TabView；页面列出的差别是触摸滑动、溢出的方式与导航的可控程度，没有讲可用性上的问题。
- 产品：GitHub 的仓库页，仓库名下面紧接着那排页签（GitHub Docs 的操作路径，自述）。

### 面包屑与上一级

- Windows（自述）：导航超过两层就给一条面包屑；避免先上一层再下一层的来回（pogo-sticking）。
- Primer（自述）：窄屏的详情页藏起侧栏；只深一层时给一个回上级的链接，更深用面包屑；宽屏有侧栏负责往上，面包屑可有可无。
- Shopify（自述）：不靠浏览器的后退也要能回上一页，用面包屑或页内的返回按钮；页面属于一个流程时才放面包屑。
- NN/g《Breadcrumbs》（自述）：层级深、或用户从外面直接落到深处时有用；只有一两层的扁平结构用不着；它补充、不替代全局与局部导航；显示的是层级，不是浏览历史。NN/g 的局部导航一文补充：面包屑不显示同级页。

### 主从

- Apple（自述）：分栏视图一栏列出上层，下一栏显示所选项的内容，可以再加第三栏；通往详情的每一栏都一直标出当前选中的一项；例子是邮件的两栏与 Keynote 的三栏。
- Windows（自述）：列表加详情用于常在子项之间切换、又要对项目做操作的场合，例如收件箱与联系人。
- Primer：见上面的上级侧栏与详情。

### 合并层级的页头

- Carbon（自述）：顶栏可以放导航链接与下拉菜单，菜单的标签只打开菜单，不能链到一页；更深的导航配左侧面板。
- Windows（自述）：NavigationView 的顶部模式也能显示层级，子项展开在上层项下面。
- Vercel（自述）：2026-02-26 起团队与项目两级用同一套页签，项目当作筛选，一下就能在同一页的团队版与项目版之间切换。
- Primer：见上面 PageHeader 把标题与导航放在同一个页头里。

### 总览加下钻

- Linear（自述，2024-12-18）：设置分成账户、功能、管理（只有管理员看得到）与你的团队四段；一个团队的设置收在一页里，先显示摘要，选一项再打开它的完整设置。
- Stripe（自述）：设置分个人、账户与产品三类，从设置页链到各项。
- Windows（自述）：只链到别的页的集散页适合用层级导航。

### 控制台现状（读本仓库）

- 顶栏与分区栏都是带下划线的页签。目录分区在分区栏下面有一条筛选带；0.67.3 起 Router 的工具带与它同高同位（控制台参考）。
- Router 的设置里，默认模式与探索名额是两段的分段控件，用来选值（原型截图）。
- 时间轴上的步骤也叫“路由”（控制台参考）；术语表在“路由计算”一条下不让单用“路由”指这个计算，因为路由是微任务的一步。
- ADR-021 第 16 条（2026-11-09 改）仍写着 Router 分区左边列出三项工作、每项一行状态；0.67.3 起装的是工具带，小块上不带状态（重做计划“0.67.2 之后”第 1 条）。
- 2026-11-08 已定 Router 不竖排成一页（重做计划）。

## 放到 Router 分区上

先是来源大体一致、对这里适用的几条：

1. 三项、同属一个上级、彼此并列时，横排比竖排合适：Windows 的顶部导航用于五项以内，Carbon 与 Windows 都把五项以上列为用左侧导航的条件，NN/g 说竖排适合宽而会长的结构（推断：由这几条合起来）。
2. 不再叠一条页签栏：Primer 不让几条 UnderlineNav 直接上下叠放；NN/g 建议用面包屑代替叠成几排的局部导航；M3 的次页签也放在内容区里。我们读到的来源里，没有一家把第三条整宽的页签栏当作推荐的做法。
3. 下一层要比上一层轻：NN/g 说局部导航不比全局导航显眼，视觉层次照着信息层次；M3 也把主次页签分开。
4. 三项是各有地址、各有设置与记录的页，不是同一内容的几种视图，所以用导航，写进地址，不用分段控件：Primer、Carbon 与 Apple 的 macOS 部分都这样分。

有一处来源并不一致。Primer 数的是页签的层数：顶栏若算作全局导航、不算一层页签，分区页签与三项工作是两层，在 Primer 的上限之内，只要两层不直接叠放；顶栏若也算一层页签，第三层按 Primer 就该换成 NavList，也就是 0.67.0 至 0.67.2 的左侧列表。M3 与前一种读法一致：顶栏之下是主页签，次页签放在内容区里。Atlassian 则不用页签在页之间导航。

**(a) 第三条整宽的带。**

- 合乎的：Router 这层归属还在；三项都看得见；填底色的小块与上面的下划线分得开，上下两层一眼分得出，这是重做计划当时的理由。
- 代价：顶栏、分区栏与这条带三条横排上下相叠，正是 Primer 不让的直接叠放，也是 NN/g 说的横排局部导航叠成几排。小块带图标、填底色，比上面只有文字的分区页签还重，最低的一层最显眼，与视觉层次照着信息层次相反（推断）。这条带与目录的筛选带同高同位，同一个位置在一个分区是筛选、在另一个分区是导航（推断）。上圆下方的小块是页面结构上的圆角，ADR-029 第 8 条写的是页面结构保持直角、浮层才带小圆角；这一处是开发者 2026-11-10 定的。开发者的评价是页签栏叠得太多、不好看。

**(b) 五个分区页签。**

- 合乎的：只剩两条栏、一套控件；五项在各家给的上限之内（Geist 5 到 7，Windows 顶部 5 以内，Apple 页签视图 6 以内）；路由要处理时的橙点可以直接挂在分区页签上。
- 代价：三项工作没有了共同的上级。Windows 把页面之间有明确的父子关系列为该用层级结构的条件，而三项工作同属 Router（术语表的三个面），摊平之后与目录、评价成了同级，这正是开发者说的散、不聚焦。分区的顺序原本有含义：目录与 Router 是设置，评价是参考；五项之后这层含义淡了（推断）。“路由”单独做分区名，少了 Router 这个限定，又与时间轴上叫“路由”的步骤同名（推断）。

**(c) 页内的大号标题式切换。**

- 合乎的：没有第三条带，归属还在 Router 分区里；切换紧贴在它管的内容上方（Primer、NN/g），相当于 M3 放在内容区里的次页签，也接近 Windows 的 SelectorBar；当前一项同时是页标题，起“你在这里”的作用（Apple 的大标题、Windows NavigationView 的页头、NN/g 说的局部导航的定向作用）；只用字号、字重与墨色，不加框也不加底，合 ADR-029 第 8 条；粗体加亮色是两种选中指示，合 NN/g 的至少两种。
- 代价与风险：
  - 显眼：字号最大的一行成了第三层，比顶栏与分区栏都显眼。读作页标题，这没有问题；读作局部导航，就与 NN/g 的不比全局导航显眼相违。字号是 (c) 最要在像素上看的一点：可以是原型里的标题大小，也可以缩到 SelectorBar 那样的正文大小，后者更像导航、不那么像标题（推断）。
  - 可点：淡色的大字容易被读成标题而不是可点的项；各家都给页签定了指着、聚焦与按下的样子，(c) 也要有，键盘聚焦要画得出。
  - 对比度：暗色下两项淡色字的对比度要达标（ADR-029 第 10 条），截图上没有量。
  - 说明放哪：三项工作的简短说明（ADR-021 第 16 条）现在在工具带的悬停里，(c) 要定是照旧悬停还是放回页里；ADR-029 第 11 条列的三种悬停提示不包括这一种，0.67.3 的悬停是重做计划另定的，两处有出入（推断，由开发者定）。
  - 状态：三项上都不显示各自最近的结果，只有路由的橙点；原来的左侧列表每项有一行状态。
  - 前例：微软那边与 (c) 最像的是 Pivot（推断），它已不推荐用于 Windows 11，但页面列的差别是触摸滑动与溢出的方式，不是可用性；接替它的 SelectorBar 仍是一排文字。
  - 窄屏没有核对，重做计划写明这一轮先不顾窄屏。

**来源提到的其他做法。**

- 合进分区页签的下拉（Carbon 的顶栏菜单、Windows 顶部模式的层级）：没有第三条栏，归属明确。代价是三项藏进菜单，换一项要点两下；按 Carbon 的规矩，Router 只打开菜单、不再是一页，当前在哪一项要另外写出，例如页签写成“Router · 维护”（推断）。
- 页内左侧列表，即主从：0.67.0 至 0.67.2 用过，开发者 2026-11-10 把它移到了上方。来源把它放在项多（五项以上）或常在子项间切换的场合，三项时它占掉一栏宽度（NN/g 的内容与外框之比）。它的长处是每项有地方写一行状态，也是 ADR-021 第 16 条现在写的样子；按 Primer 把顶栏也算作页签的读法，它正是 Primer 给的出路，用 NavList 代替再一层页签。
- 分段控件：三项是各有地址的页，Primer、Carbon 与 Apple 的 macOS 部分都把分段控件留给同一内容的几种视图或选值；Router 的设置里已经用两段的分段控件选值，同一个形状会有两种意思（推断）。
- 总览加下钻（Linear 的团队设置、Stripe 的设置）：Router 分区先是一页总览，每项一行状态，点进去是那一项，页头有回总览的链接。代价是每换一项都要先回总览，正是 Windows 说的来回；面包屑也不显示同级（NN/g）。

**建议（只是建议，由开发者定）：** 取 (c)。读到的来源里没有一家推荐在两条页签栏下再叠一条，Windows 的结构准则又把有明确父子关系的几页放进层级、不摊平；三个原型里只有 (c) 两条都避开，而且只靠字的层次、不加新的容器，合 ADR-029 的口味。要在像素上定的是两件事：字号，是作页标题还是缩到正文大小作导航；以及淡色两项看起来可点。若开发者要在三项上看到各自的状态，(c) 给不了，那时再看左侧列表或总览加下钻。

## 取了什么，没取什么

- **取（建议，待开发者定）：** (c)，并带上四条约束：不叠第三条栏；三项留在 Router 分区下；下一层比上一层轻，选中至少两种指示；三项是带地址的导航链接，当前一项标为当前页，不做成页签控件或分段控件（Primer：点了要改地址的用导航组件）。定下之后写进重做计划，并改 ADR-021 第 16 条里已经过时的左边列出三项工作。
- **不取：** (a)，三条横排相叠，开发者已否；(b)，丢了 Router 的归属，开发者已否；分段控件，它留给选值与同一内容的几种视图；合进下拉，三项藏起来，Router 也不再是一页；总览加下钻，换一项要来回。
- **暂不取：** 左侧列表。按 Primer 的一种读法它最合规矩，又能写状态，但三项时占掉一栏宽度，开发者 2026-11-10 刚把它移走；三项要常驻状态时再看。
- **未验证：** (c) 的字号与可点性、暗色下淡色项的对比度与窄屏，都要在真实浏览器里看像素。

## 时效

以下任何一种变化，都会让这份记录过时：

- 各家改了这几条规矩：Primer 的页签不超过两层、不直接叠放，Apple、Fluent、Carbon 与 Windows 的侧栏两层，NN/g 的局部导航不比全局导航显眼；或者 M3 官网读得到了，而且与 Google 文档的转述有出入；
- 控制台的顶栏不再是页签，例如改成侧栏，或者 Buddy 页的分区多到五个以上；
- Router 多了第四项工作，或者三项上要常驻状态；
- 窄屏进了范围；
- 目录的筛选带改了位置或高度；
- 开发者对层级与留白的口味变了。
