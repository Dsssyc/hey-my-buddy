# 只跑受影响的测试，有没有成熟的工具

## 问题

开发者 2026-10-14 定了：每批验收只跑受影响的测试与共用的下游测试，完整检查在安装之前跑一次。紧接着问：业界有没有成熟的工具能自动选出受影响的测试，免得由 agent 自己梳理该跑哪些，容易漏。为“完整检查提速”那条线和检查运行器服务。

## 看了什么

- pytest-testmon：官方网站首页（2.x，看到“Version 2.0 is out!”），以及 PyPI 上较早版本的说明；没读源码，没试用。
- Pants：社区讨论里关于 `--changed-since` 与 `--changed-dependents` 的问答（2.7 到 2.21 的几次讨论）；没读官方文档全文，没试用。
- Coverage.py：最新版配置文档里 `[run] patch` 一节与动态上下文一节；没读源码，没试用。
- 自己的情况（读了本仓库）：测试用 unittest 写，由我们自己的检查运行器 `hey_my_buddy.cli.checks` 每个测试文件起一个子进程跑；很多关键的测试会起真正的服务、Worker 与控制器子进程（`python -m …`），被测的代码大量运行在这些子进程里。前端用 vitest。

## 看到的事实

- pytest-testmon（对方自述）：用 Coverage.py 记下每个测试执行过哪些代码，与改动比对，只跑受影响的测试；粒度到文件与方法；也跟踪环境变量、Python 版本与第三方包版本；不跟踪静态文件（txt、xml 等）与外部服务；早期说明写着支持起子进程的测试，但要使用者自己让每个 Python 子进程都装上 coverage 的钩子；1.4 起支持 xdist。它是 pytest 的插件，跑的是 pytest。
- Pants（社区问答）：`--changed-since=<ref>` 把 git 里改动的文件映射到所属的目标，`--changed-dependents=transitive` 再沿依赖图扩到所有直接或间接依赖它们的测试；依赖图靠分析 import 自动推出。已知会多选（改了依赖锁文件几乎全跑），也有过改了测试文件自己却没被选中的报告。采用它等于换一套构建系统。
- Coverage.py（对方文档）：7.10 起的 `[run] patch = subprocess` 让 coverage 在经 `subprocess`、`os.system`、`exec*`、`spawn*` 起的 Python 子进程里自动开始测量，并自动打开 `parallel`；用替换过的环境起子进程时，新环境要带上 `COVERAGE_PROCESS_START`。动态上下文能回答“哪一行是哪个测试跑到的”，但文档没说子进程会不会继承父进程的上下文。
- 推断：靠 import 推依赖的做法（Pants）看不见我们按字符串起的子进程（`python -m hey_my_buddy…`）和资源文件；靠覆盖率的做法（testmon、Coverage.py）能看见，前提是子进程里也测了。我们的运行器本来就一个测试文件一个子进程，所以按测试文件分开存覆盖率数据，就能得到“哪个源码文件被哪些测试文件跑到过”，用不着动态上下文是否继承这一点。
- vitest 自带按改动选测试的能力（`vitest related` 与 `--changed`，按模块图选）。这一条是我们已知的，这次没有重新核对它的文档。

## 取了什么，没取什么

- 取（建议，待开发者定）：在我们的检查运行器里用 Coverage.py 做文件级的影响分析。安装前的完整检查顺带采集覆盖率（子进程用 `patch = subprocess`），每个测试文件一份，得出“源码文件 → 跑到它的测试文件”的对照；平时用 `git diff` 找出改动的文件，按对照选出测试文件，再加上改动过的测试文件本身、对照里没有的新测试文件，以及按路径规则处理的非 Python 文件（资源、打包、技能等）。完整检查仍在安装之前跑，兜住漏选。前端用 vitest 自带的选法。
- 没取：Pants，代价是换掉整套构建，而且看不见按字符串起的子进程；pytest-testmon，它要换成 pytest 来跑、子进程的钩子仍要自己配，换来的只是比文件更细的粒度。两者都没有试。
- 未验证：`patch = subprocess` 在我们的测试里能不能测到服务、Worker 与控制器子进程（我们的测试会清掉子进程的环境变量，需要放行 `COVERAGE_PROCESS_START`）；采集覆盖率会让完整检查慢多少。做之前先用三四个测试文件试一次。

## 时效

Coverage.py 的 `patch` 选项或 testmon 对子进程的支持变了；我们的检查运行器不再按测试文件起子进程；或者测试换成 pytest 来跑。
