# ADR-024：控制台的会话视图

## 状态

提议：用户于 2026-10-02 提出并确定了方向（只看不说；用现成的前端组件；不限制会话长度；各 harness 给出多少就展示多少），由 Claude Code Host 起草。用户于同日确认了起草时的三处建议：第 5 条的保留方式改为由用户设置；第 6 条先试用建议的组件库；第 7 条的入口位置照此办理。第 5 条中的默认值与"更改设置对已保留的记录同样生效"是起草时补充的，待用户确认。尚未实现；排在 [ADR-021](021-router-buddy-planes-and-routing-evidence.md) 的逻辑线之后，实现与安装需另行授权。本文遵循 [ADR-023](023-harness-integration-principles.md) 的接入原则，并在 [ADR-019](019-worker-accounts-and-usage.md) 第 11 条的私有目录之上增加一条只读的读取途径，不改变私有目录的归属与回收。

## 背景

微任务在运行时，用户在控制台几乎看不到细节。黑板为每次执行记录的活动是一份封闭的白名单：阶段、最近活动时间、工具名，以及模型回合与工具调用两个计数；提示词、工具参数、输出文字与推理都没有字段，也不收集（见 [Worker 与适配器](../reference/workers.md)的活动观察一节）。想知道一个微任务具体在做什么，只能去问 Host，这既消耗 Host 的额度，也打断它的工作。

2026-10-02 的一个例子：一个微任务执行了 229 分钟，调用工具 378 次，其间三次运行完整检查。运行期间没有人能看到这些，事后靠翻日志才查清原因。

原始材料其实已经存在。每个 harness 都把自己的会话记录写在黑板管理的私有区里（ADR-019 第 11 条的盘点）：DSH 的 JSONL 会话，ZCode 的会话库与原生日志，Codex 微任务私有目录中的线程记录，Claude Code 的流式事件。缺的只是把它们读出来给用户看的途径。

用户同时考虑过在控制台向 Worker 发话，随后决定不做，理由见第 1 条。

## 决定

1. **只看，不说。** 控制台为每次执行提供只读的会话视图。不提供向 Worker 发话、追加指令或回答其提问的入口；`inquire` 仍只由 Host 使用。Worker 只与 Host 交接，用户直接介入会让 Host 手里的任务书与 Worker 实际在做的事不一致。
2. **展示 harness 给出的全部内容，不设长度上限。** 包括消息、推理、工具调用及其输入与输出、文件改动、命令输出与计划。内容不截断。长会话分页读取，可以一直向前翻到开头；运行中的会话持续追加新内容。
3. **各 harness 如实不同。** 每个 harness 能给出哪些内容，作为能力记录下来（ADR-023 第 2 条）。按用户的观察，底层使用开源模型的 DSH 与 ZCode 能给出完整的推理，Codex 与 Claude Code 不能；具体以实现时逐个核实的结果为准。harness 没有给出的内容不显示，也不补造，视图用一行文字说明这个 harness 不提供什么。
4. **统一事件形状，沿用 ADR-023 的词汇。** 适配器把原生会话记录投影成同一套事件：消息、推理、工具调用（类别、标题、状态、输入、输出、涉及的位置）与计划。工具调用的归类与 ADR-021 的 L5 共用同一份代码，不另写一套。
5. **内容留在私有区，按需读取；保留多久由用户设置。** 服务读取这次执行在私有区里的会话记录，投影后只返回给本机的控制台。会话内容不写入黑板数据库，不进入备份与导出，不作为 Router 与维护的输入；响应中不出现文件路径。保留方式是设置中的一项，有三个选择：

    - **随回收删除。** 会话记录随微任务的检出回收而删除。这是默认值。
    - **保留若干天。** 回收之后继续保留，天数由用户设定，到期自动删除。
    - **不删除。** 选择时弹出警告，说明会话记录会随微任务不断累积，可能占用大量磁盘空间，确认后才生效。

    回收之后保留下来的只是会话内容本身，不含私有区里的凭据、配置与原生数据库。更改设置对已经保留的记录同样生效，会因此删除已有记录时先请用户确认。存储检查中列出会话记录占用的空间。记录已被删除的微任务，视图显示"会话记录已删除"；验收记录与结果事实不受影响。
6. **用现成的前端组件。** 不自己编写渲染。建议采用 [AI Elements](https://github.com/vercel/ai-elements)：MIT 许可，组件以源码形式拷入仓库、归本项目所有，并且是由属性驱动的纯展示组件，覆盖对话、消息、推理、工具调用、终端输出、代码块与计划。代价是控制台要为会话视图引入 Tailwind 与 shadcn 的基础样式，并把它们限定在会话视图之内，不改动现有页面；构建产物会变大，代码高亮等较重的部分按需加载。用户同意先试用；试用中发现不合适再另行选择。
7. **入口在微任务详情。** 每个执行回合可以打开自己的会话，时间轴上的执行片段可以直接进入对应的会话。具体布局在展示线里设计。
8. **写明数据边界。** 会话内容可能包含命令输出里的敏感信息，只在本机回环地址的控制台显示（[ADR-020](020-loopback-console-access.md)），启用登录时受登录保护。设置中的数据流向说明相应补充一句。

## 考虑过的方案

- **让用户在控制台向 Worker 发话。** 通道是现成的，但只有部分 harness 能送达，而且会绕过 Host：微任务归 Host 所有并由它验收，用户另行指示之后，Host 仍会按原来的任务书验收。用户决定不做。
- **自己编写渲染。** Host 起初建议只写消息与工具调用两种卡片，前提是内容有上限、不显示推理。用户要求显示全部细节且不设上限之后，Markdown、推理、工具的输入输出、终端输出、差异与长列表都要处理，自己写等于重造一个组件库。
- **assistant-ui、CopilotKit。** 都带一套由页面驱动代理的聊天运行时，本文只需要展示。
- **acp-components。** 数据形状与 ADR-023 的词汇最接近，也不依赖 Tailwind；但组件要求一条活的 ACP 连接，项目也还很新（2026-10-02 时 63 星）。
- **把会话内容写入黑板数据库。** 数据库会无上限增长，敏感内容也会随之进入备份。
- **通过 harness 的钩子收集事件。** 一些观察工具这样做，但需要改用户的 harness 设置；执行进程本来就由 Worker 运行时持有，不需要钩子。

## 影响

- **契约与数据。** 新增一个分页读取会话事件的只读接口、每个 harness 的"会话内容"能力声明，以及会话记录保留方式的设置（三个选择与天数）。回收时按设置删除或留存会话内容，到期的自动删除。活动观察的白名单不变，它仍是黑板记录的全部；会话视图是另一条读取途径。
- **适配器。** 四个 harness 各实现一个从私有区会话记录到统一事件的读取器。是直接读取原生记录，还是由控制器在私有区按统一形状另写一份事件记录，留给实现计划决定。
- **控制台。** 引入组件库及其样式基础；新增会话视图；设置中增加保留方式及"不删除"的警告；存储检查显示会话记录占用的空间。这部分属于展示线。
- **验证边界。** 各 harness 的原生会话格式需要真实样本，优先使用已有的脱敏历史记录做夹具；需要付费的原生检查逐次授权。Windows 未验证。各 harness 实际给出的推理内容尚未核实。
- **实现安排。** 依赖 ADR-021 的 L5（事件分类）与 L3（回收）；从 Worker 事件流得到的工具事件投影与 ADR-021 的 L6 共用。开工前先写执行计划，逻辑与展示分开。
