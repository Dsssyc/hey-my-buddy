# ADR-029：控制台的前端基础

## 状态

已接受：开发者于 2026-10-11 验收控制台返修时提出，实现方一直靠调整像素距离来微调时间轴等部件，很吃力，问有没有成熟的东西可以代替，并要求 Claude Code Host 主持完善前端。Host 读了源码、在浏览器里看了界面、比较了现成的时间轴组件之后给出建议，开发者同日逐项同意：时间轴仍然自己画，但换画法并改用现成的库；整个控制台统一到 Tailwind 与 shadcn；界面用语的改名与中英文 i18n 并入这条线；i18n 用 react-i18next，语言跟随浏览器；几何的检查改在真实的浏览器里做；长等待的画法先出静态稿由开发者挑；首次公开发版等新前端。打底一步与 Buddy 页的重做已合入（[ADR-030 执行计划](../design/adr030-execution-plan.md)的批次 0）并已安装，其余页面的重做尚未开始（待办“顺序”第 4 步）；执行计划见 [console-frontend.md](../design/console-frontend.md)，每一步的核对见 [Host 的记录](../acceptance/console-frontend.md)。本文修改 [ADR-024](024-console-session-view.md) 第 6 条（Tailwind 与 shadcn 不再只限于会话视图），接手 [ADR-021](021-router-buddy-planes-and-routing-evidence.md) 展示线的 U6（界面用语）。开发者同日又放宽了范围：界面不必复刻原样，由 Host 重新设计（第 8 条）。[ADR-016](016-human-console-design.md) 里关于行为与安全的规则保持不变，关于呈现的规则由第 8 条取代。

## 背景

控制台的界面全部是手写的，没有用任何界面库，运行时依赖只有 react 与 react-dom。2026-10-11 的源码里：

- 时间轴约 1,900 行自己写的排布与换算。时间先换成百分比，再换成像素，再换回百分比交给样式；文字放不放得下靠宽度阈值判断；标记靠固定的偏移摆放。
- 浮层的定位与焦点管理也是自己写的，约 250 行。样式表 1,014 行，里面有 1,150 处像素值。
- 958 项前端测试里有 232 项在守着时间轴的几何。这些测试在 jsdom 里运行，jsdom 没有排版：2026-10-10 验收之后才发现的"两段文字叠在一起"，它们一项也看不见。
- 那次返修的修法是再加五个像素常量。每调一处都要改常量、改阈值、改测试。
- 界面文字约 1,700 处，全部是写死的中文；ADR-021 第 23 条已经决定换掉的"工作目标"还有 130 处。

另有一个与画法无关的问题：执行往往只有一两分钟，等 Host 处理却长达几小时。按时间均匀地画，执行只剩几个像素宽，一屏里是一条等待或大片空白。这正是本产品最常见的数据形状。

## 决定

1. **整个控制台用同一套基础：Tailwind 与 shadcn。** 组件以源码拷入仓库，底层是 Radix 的无样式组件。浮层、对话框、页签、提示与滚动区都用它们，不再自己写定位与焦点管理。现有的语义颜色变量迁成这套基础的主题变量，明暗两套照旧。手写的样式表随页面的迁移逐步删除，迁完之后不留。会话视图（ADR-024）建在同一套基础上。
2. **时间轴仍然是自己的组件，换画法。** 它表达的是本产品特有的事实：路由、等待 Host、停止未确认、各种标记。现成的时间轴组件要大量定制才画得出来，而且要按它们的交互与外观来。通用的部分则不再自己写：时间到像素由一个比例尺给出，刻度也由它给出，用 d3-scale 与 d3-time，不再有百分比与像素之间的来回换算；用 SVG 画，层次由书写顺序决定；文字先测量、再决定显示哪一种写法，不靠宽度阈值；浮在上面的部分用第 1 条的组件。
3. **执行很短而等待很长时，执行仍然要看得清。** 怎么画由 Host 先出静态稿，开发者选定之后写进执行计划，再实现，实现之后写进控制台的参考文档。开发者于 2026-10-11 选定：没有任何片段开始或结束的时段压成等宽的断口，其余时段按同一个比例画，规则见执行计划。
4. **界面用语与国际化一起做。** 文字从源码里抽出来，中文与英文各一份，术语取 `CONTEXT.md` 里成对的写法，同时完成 ADR-021 第 23 条对界面的改名。用 react-i18next；语言跟随浏览器，不另设开关。日期、数字与时长用浏览器自带的格式化。
5. **几何在真实的浏览器里检查。** 文字不重叠、不被裁掉、标记不被遮住，这类事实用 Playwright 在合成看板上断言，不做截图比对。守着像素常量的那些测试随旧画法一起删除。读取、筛选、键盘操作与只读约束这些行为，仍由现有的组件测试覆盖。
6. **发行方式不变。** 构建产物仍然随包提交，用户不需要 npm。
7. **首次公开发版等这条线完成。** 不把马上要换掉的界面与用语公开出去。日常的源码安装不受影响。
8. **界面重新设计，不以复刻为目标。** 外观与信息的编排由 Host 设计，先出静态稿，开发者确认后实现。ADR-016 里关于行为与安全的规则保留，关于呈现的规则以新设计为准。设计守本项目的一条约定：界面靠层次、留白与形状传达信息，不靠堆字和提示；不滥用圆角与卡片嵌套；每种颜色只有一个含义，唯一的例外是代码改动里增加的用绿、删去的用红（开发者于 2026-10-11 同意，这是通行的写法）；界面要舒适，信息都在，但不密集，不挤作一团。起因是开发者对原界面的评价：一堆字而没有视觉上的分隔与提示，许多意义不明的提示，圆角用得太滥，一眼看得出是模型生成的样子。
9. **界面由一组自成一体的视图组成。** 每个视图按领域概念划分（宏任务的列表、一个宏任务及其时间轴、一个微任务、buddy、设置），各有一个入口：数据经注入的客户端取得，显示什么由参数给出，导航经回调交给外层，尺寸随容器，不碰文档级的东西（标题、根上的主题属性、网址）；颜色只用主题变量，文字有自己的命名空间。控制台自己的外壳是这些视图的第一个使用者，只经这些入口使用它们。这样组织之后，建立在 hey-my-buddy 之上的其他项目可以把这些视图放进自己的界面；那只是今后可能的用法，不构成对本项目的约束。现在不做：不发布组件包，不在控制台里设注入点，不为嵌进别人的页面做样式隔离。

## 考虑过的方案

- **整块换成现成的时间轴组件。** 查了三个。vis-timeline 仍在发版，支持分行与隐藏时间段，但它是命令式的接口，有自己的交互与外观，本产品特有的那些事实都要靠模板与样式硬做。ECharts 6 的自定义系列能画这类图，也新增了坐标轴断裂，但它画在 canvas 上，键盘操作、读屏与基于 DOM 的测试都要重做；坐标轴断裂能否用于时间轴，没有查到依据。react-calendar-timeline 的维护状况不明，对 React 19 的支持只在测试版里，也没有压缩时间段的能力。
- **保留手写的样式，只引入无样式的基础组件。** 改动小。但会话视图已经定下用 Tailwind 与 shadcn，只在那一页用，控制台里就有两套样式并存。
- **i18n 用 Lingui 或 react-intl。** 前者运行时更小，但要加一道编译步骤；后者写法更重。react-i18next 最常见，开发者与模型都熟悉。
- **用截图比对来守外观。** 基线图片要进仓库，字体与平台的差异会带来误报。断言事实更稳，也说得清失败的是什么。
- **先发版，再换前端。** 发布流程可以早些跑通，但公开出去的是已经决定换掉的界面、用语与只有中文的文字。

## 影响

- **依赖。** 新增 Tailwind 及其 Vite 插件、shadcn 生成的组件所依赖的包、d3-scale、d3-time、i18next 与 react-i18next，开发依赖里新增 Playwright。运行时依赖从两个变成十来个，构建产物会变大（现在脚本 547 KB、样式 72 KB）。每个包的许可与产物大小的前后对比在打底那一步核对并记录。打底之后的实际情况：直接依赖八个，但 Radix 的汇总包把它的全部基础组件带进了锁文件，运行时的包新增 82 个，进产物的只有实际引用的；脚本 682 KB、样式 113 KB。
- **内容安全策略。** 现有策略允许内联样式，预计不需要放宽，打底时核对。
- **测试。** 守几何的约 232 项随旧画法删除，新增浏览器里的断言。改名与文案抽取会改到大量断言文字的测试，测试固定用中文。
- **文档。** `console.md` 与 `objectives.md` 的展示部分随每一步更新；`objectives.md` 里空闲折叠的数字已经过时。`AGENTS.md` 的验证一节加上浏览器检查的命令。
- **待办。** "时间轴与浮层是手写的几何""控制台只有中文""时间轴定时更新时滚动条会闪动"三条并入本文，从待办中删除。
- **验证边界。** 以上是读源码、看界面与查资料之后的判断，没有做原型。Windows 与其他浏览器未验证。
