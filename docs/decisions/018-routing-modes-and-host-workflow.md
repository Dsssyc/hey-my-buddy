# ADR-018：路由双模式与 Host 工作流

## 状态

提议：第一部分（路由双模式）的方向、档位改名与第 5、6、7、10 条的取舍由用户于 2026-09-29 确认；第二部分（Host 工作流）来自以 Claude Code 为 Host 的试用记录，待用户审阅。整篇在审阅后接受，尚未实现。本文修改 [ADR-014](014-router-buddy-and-read-only-routing.md) 中"移除无工具决策助手、只保留一种会查看代码的 Router"的部分；ADR-014 的其余内容（冻结候选、只按路由边界校验、程序计算的偏好检查、Host 边界）不变，并同时适用于两种路由模式。

## 背景

ADR-014 的 Router 在限定预算内只读查看代码仓库再做选择，要求 harness 的原生沙盒能证明读取范围受限、禁止写入、工具不能联网。截至 2026-09-29 只有 macOS 上的 Codex 0.157.0 通过了原生探针（[ADR-017 验收记录](../acceptance/local-harness-discovery-0.19.0.md)）：DSH 的工具不限制读取范围与联网，DeepSeek 系列无论哪个模型都不能担任 Router；验证绑定 harness、版本与平台，Codex 一升级 Router 就不可用；每次委派都要运行一次查看代码的模型回合，较慢也较贵。而 Router 的主要价值是把任务与 Host 维护的评价、用户偏好对上号，其中相当一部分只靠任务描述和评价表就能完成。

2026-09-28 至 29 以 Claude Code 为 Host 的试用（[0.18.0 源码记录](../acceptance/buddy-settings-schema13-0.18.0.md)）还暴露了一批 Host 工作流问题：任务包只能作为一个命令行 JSON 参数传入；没有按方法的参数帮助；Host 已整合 worker 的成果后，要么再让 worker 空跑一轮才能验收，要么只能取消；被额度打断的 worker 没有封存成果，改动只能由 Host 从受管检出里手工提取；显式配置的目标不能换模型续做；失败或取消的目标不能留下 Host 结论，其受管检出也不能清理；整合记录不能写入 Host 在成果之外的补充改动；多轮目标的成果只有逐轮增量补丁。

## 决定

### 第一部分：路由双模式

1. **两种模式，共用一套协议。** Router 分为快速路由与审阅路由，都使用 ADR-014 的冻结候选枚举、答案格式、只按路由边界校验、程序计算的 `policyCheck` 与 Host 边界规则，区别只在 Router 能否查看代码。
2. **快速路由不给工具。** 输入只有任务描述、任务本地的 `routingPreferences`、冻结的合法候选及其评价卡片、生效的用户偏好与家族备注、程序给出的 `policyFacts`，不含仓库内容。执行为一次原生模型调用，由 harness 真正关闭全部工具（读文件、shell、网络与搜索、MCP、子代理），不能只靠提示词；程序检查原生事件流，出现任何工具调用即判本次答案无效。沿用一次格式纠正。答案证据只能引用卡片、偏好与备注。时限 60 秒，没有工具次数预算。
3. **快速路由的资格按 harness 能力判定，不需要付费探针。** adapter 声明并实现"无工具结构化调用"，由模拟测试与一次零工具调用检查确认；满足条件的 harness 下，任何启用且可用的配置都能担任快速 Router。无法可靠关闭工具的 harness 不能担任。
4. **审阅路由即现行 Router。** 仍要求只读结构化能力经原生探针验证，并受 ADR-017 的 harness 健康与版本记录约束。预算三档改名为"简要 / 标准 / 深入"，接口标识由 `quick` / `standard` / `deep` 改为 `brief` / `standard` / `deep`，升级时把已保存的 `quick` 映射为 `brief`；各档时限、工具次数与读取量不变。"快速"一词只用于快速路由。
5. **两个 Router 位置加一个默认模式。** 配置包含快速路由配置、审阅路由配置、默认模式（`fast` 或 `review`）与审阅预算档。新安装的默认模式为快速路由。升级时把现有 Router 放入它符合资格的位置（已验证审阅能力的放入审阅位置，否则在符合快速路由资格时放入快速位置），另一个位置留空并在 Buddy 配置中提示用户选择。
6. **Host 可以按次指定模式。** 提交时可指定 `routingMode: "fast"` 或 `"review"`（例如小任务用快速路由，任务大或需求模糊时用审阅路由），不指定则用默认模式；任务本地偏好在两种模式下都生效。
7. **审阅路由不可用时降级。** 要求审阅路由但审阅 Router 不可用（未配置、未验证、健康检查失败或版本变化导致验证失效）时，默认自动改用快速路由，并在路由记录中写明已降级及原因；Host 可在提交时关闭降级，此时停在 Host 边界。两种都不可用时才停在 Host 边界。
8. **结果可见。** 控制台顶部路由状态分别显示两个 Router 与默认模式；时间轴的路由块用不同纹理区分两种模式并标出降级；"路由依据"显示模式、是否降级及原因。
9. **说明数据流向。** 设置里写明：快速路由会把每个任务的描述发送给快速 Router 所在的模型提供方，包括准备交给其他模型执行的任务；审阅路由另外会让审阅 Router 读取冻结的仓库副本。
10. **ZCode 先接入快速路由。** 依据 GLM-5.3-Flash 的只读调研（run `536df909`，ZCode CLI 0.16.9）：app-server 的 `session/create` 原生支持空的 `toolAllowlist`（buddy 的模型发现已在使用），事件流的 `tool.updated` 带工具调用标识，可以确认零工具调用；没有原生的 JSON 格式参数，按协议用提示词加程序校验与一次格式纠正。ZCode 有 plan 模式、`toolDenylist`、可拒绝操作的 hook，buddy 在非交互时会自动拒绝权限请求，但读取范围、禁止写入与禁止工具联网的系统级限制都未经验证，审阅路由只有在逐次授权的原生探针通过后才开放，证据绑定 ZCode CLI 版本。

### 第二部分：Host 工作流

11. **SKILL.md 只写长期工作流。** 删去版本说明与发布状态（例如"尚未安装"），安装与发布事实只放在 `docs/acceptance/`；SKILL.md 只保留每次委派都需要的核心流程，控制在约 4 KB，细节放在 `references/` 中按需读取，减少 Host 每次激活 skill 的成本。SKILL.md 同时写明：先看 `health` 的路由状态再决定是否依赖路由，后续委派沿用同一工作目标。
12. **任务包可以从文件或标准输入传入。** 每个方法除单个 JSON 参数外，还接受 `--params-file <路径>` 与 `-`（从标准输入读取），语义完全相同，避免长任务文本的 shell 转义与超长命令行。
13. **按方法的帮助。** `buddy help` 列出全部方法与一句说明；`buddy help <方法>` 列出参数、默认值与界限，内容由现有参数校验生成，不另写一份；方法名写错时给出最接近的候选。
14. **后续委派加入同一工作目标。** 提交时可以用 `objectiveOf: "<runId>"` 加入该 run 所属的工作目标，Host 不必从之前的回执里复制 `objectiveId`。
15. **Host 可以在等待 Host 时直接收尾。** worker 最近一轮已封存成果、Host 已完成整合时，Host 可以直接对该成果登记整合与验收并结束目标，不必再让 worker 空跑一轮；"取消"只用于真正放弃的工作，不再被当作收尾手段。
16. **失败与取消的目标也能留下 Host 结论并清理。** 允许对失败或取消的目标记录 Host 结论（例如"未完成的改动已提取为某提交"），不改变目标的执行结果；记录结论后允许清理其受管检出，保留输出、清单与引用。
17. **被打断的工作自动封存为部分成果。** 模型已开始工作后因额度、超时或进程故障失败时，服务把工作区改动封存为一个标明"部分、未验证、非最终"的成果，Host 可以查看、整合或用它续做，不必手工从受管检出中提取。
18. **Host 可以更换自己选的显式配置。** Host 在提交时显式指定的配置，默认视为 Host 的选择而非硬约束：续做时可以附理由换成另一个已启用的配置，记录方式与路由结果被改配相同（`configuration_overridden`）。用户明确要求的配置由提交时的 `configurationLocked: true` 标记为硬约束，此时不能更换。
19. **整合记录可以包含 Host 的补充改动。** `integration-record` 接受 `hostPaths`，单独记录 Host 在成果之外同时修改的文件，不与成果的路径混在一起。
20. **多轮目标提供累计补丁。** 多轮目标的最终成果除每轮的增量补丁外，另附从目标输入提交开始的累计补丁，Host 整合时不必按顺序叠加各轮补丁。

## 考虑过的方案

- **只保留审阅路由。** 路由质量高，但验证绑定版本，harness 一升级就不可用；每次委派都要付出查看代码的成本；DeepSeek 等无法验证的 harness 永远不能参与路由。
- **只保留快速路由。** 简单便宜，但失去查看代码后的判断，对需求模糊或依赖代码结构的任务选择质量下降。
- **把无工具作为预算的第四档。** 把两种资格规则不同的方式压在一个选项上；同时只能有一个 Router，也就无法在审阅 Router 失效时降级到另一个便宜模型。
- **恢复 0.16 的 DSH 专用决策助手。** 只服务一个 harness，并会带回 ADR-014 已经移除的专用代码路径；本文改为 harness 中立的无工具模式。
- **让 Host 用取消来收尾已整合的工作，或继续让 worker 空跑一轮再验收。** 前者让记录显示为"已取消"，与实际不符；后者每次都多花一个模型回合。
- **失败时只保留受管检出，由 Host 自行提取。** 这正是试用中的做法，容易遗漏，也不留记录。

## 影响

- 路由：为各 adapter 增加无工具结构化调用的能力声明、实现与零工具检查（首批为 DSH、ZCode、Codex，Claude 在用户恢复使用后接入）；路由协议增加模式与降级字段；配置增加两个 Router 位置与默认模式，优先用现有的 `meta` 键，若需要改 schema 按现有规则另行确认；契约版本升级。
- Host 工作流：CLI 增加参数文件与标准输入、`help`、`objectiveOf`；工作流增加 Host 直接收尾、失败或取消目标的 Host 结论与清理、部分成果封存、可更换的显式配置与 `configurationLocked`、`hostPaths`、累计补丁；这些都会改变 CLI 与控制台的契约，并需要相应的迁移与测试。
- 文档：SKILL.md 精简并移出版本说明；cli.md、decision.md、evaluation.md、workflow.md、architecture.md 与两份 README 同步更新。
- 快速路由会把任务描述发送给快速 Router 的提供方，需要在设置页与参考文档中写明。
- 实现与安装都需要用户另行授权；验收时两种路由模式和各项工作流改动分别记录证据。
