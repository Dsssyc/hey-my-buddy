# ADR-012: Keep liveness and empty polls out of the durable work ledger

The user approved the ordered runtime-efficiency and reliability repairs on 2026-09-25 after observing high CPU and repeated delegation interruptions. Contract 0.10.0 keeps schema 11 and separates authenticated process liveness (`ping`) from explicit storage/runtime diagnostics (`health`). Routine clients and workers use `ping`; a liveness response makes no integrity claim. Startup and an explicit `health` still validate storage. Caching a full health response was rejected because it would retain unnecessary hot-path work and blur the age of integrity evidence.

An empty worker claim is a transient queue observation, not an allocation. New empty responses do not enter the durable commands ledger, and retrying one may observe work that arrived afterward. The first committed nonempty claim remains an atomic, request/worker/nonce-bound allocation whose replay returns that same attempt and capability, including after restart. A lost empty reply cannot hide a child or an allocation because neither existed. This replaces the earlier promise of retaining every negative poll forever; it does not weaken replay of an actual allocation or completion.

Existing command receipts are retained unchanged, including old negative observations. No runtime migration, deletion, TTL pruning or compatibility facade is introduced. This stops future idle-ledger growth without inventing an expiry for authoritative work. Queue, workspace, family-capacity and shutdown checks still govern each new allocation. More elaborate per-worker sequence/tombstone protocols are unnecessary for this boundary.

The remaining accepted repair order is ZCode recoverable tool-error handling, program-checked routing facts and preference explanations, then bounded Host supervision and Harness-owned evaluation maintenance. User-owned model choices, enabled efforts, annotations and capacity are not changed by these repairs. The [0.10.0 acceptance record](../acceptance/runtime-efficiency-0.10.0.md) separates implemented slices, verification and actual installation.
