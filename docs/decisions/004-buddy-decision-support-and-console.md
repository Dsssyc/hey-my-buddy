## 一、已讨论方向（综合整理，未实现）

### 1. Host 与 Worker 的责任边界

Host 可以亲自实现工作，并按比较优势把部分工作委派出去。Host 保留任务范围、授权和最终验收；减少 Host 参与是选择性移交带来的收益，不把 Host 固定成只负责控制与协调的角色。

Worker 内部 subagent 保持自主：Buddy 不以降本为由施加通用的禁用或数量上限，也不规定每个 Worker 使用相同的内部拓扑。跨 Worker 的新协助以建议形式交给 Host，不在循环中自动转派，也不引入 A2A 或额外的全局 agent 管理器。

### 2. 黑板、C-Two 与停止证据

Python 黑板继续独占权威 SQLite 事实以及事务与事件原子性。Worker 拥有自己的子进程句柄和停止证据；缺失 PID 或租约到期从不证明进程已经停止。C-Two 继续是命名的 agent 侧控制与等待接口，本文不建立第二套状态权威。

任务与尝试身份、幂等键、恢复语义以及“等待不等于重跑”的分离保持不变。新增的决定、接续和评估记录以独立身份累积，不改写原始任务 spec 来冒充同一次幂等提交。

### 3. 跨回合的逻辑任务与接续

一个逻辑任务可以跨多个已经结束的 agent 回合存在。Yield 结束当前回合并上报协助请求、待决问题或接续上下文；它不是无限阻塞的实时调用，也不证明任务完成或工作区已经可以移交。

Host 批准的接续可以消费已经持久化的辅助结果，不需要 Host 手工转述。现有原生 Host 唤醒（唤醒 Codex App 中已经结束的回合）未实现；黑板使一个回合可调度，不等于能够唤醒宿主。

### 4. 显式工作区

顺序的单一写者移交可以继续使用原 checkout；并行写者（包括 Host 自己）需要各自独立的 worktree 和固定的输入快照，并指定唯一的整合者和组合产物的验收方式。

Worktree 隔离文件、暂存区和 HEAD，但不隔离共享的外部资源（服务、测试数据库、分支引用等）。写入占用以实际 checkout/worktree 为单位识别，cwd 只是运行位置，同一 checkout 下的兄弟目录不因路径不重叠就算隔离。

### 5. 有界当前评价与可区分来源

为每个已启用的 Harness/provider/model 组合维护有界的 CURRENT 评价卡，另加一组有界的合法参数 profile。用户偏好、已发现事实、社区声明和 Host 复核结果保持可区分的来源；完整历史可以归档，但日常选择和例行维护不得扫描全量历史。未知保持未知，不填成中性或成功。

model+effort 视为一个合法 profile。卡片保存条件性结论、未解决问题数量和少量代表证据引用，而不是把全部历史内联进去；后续成功更新统计，但不自动清除尚未解决的问题。

### 6. 首选决策路径

当前提议：使用一个已经接入、成本可控的通用 Buddy 模型，在非思考模式下同时承担选择推荐和有证据依据的评价补丁与文字归纳。本次讨论提出的具体组合是 `dsh` / `deepseek-official` / `deepseek-flash` / effort `off`，但实际选择质量和额外开销都还没有测试，不能据此宣称已经更优。

DSH 普通执行的默认配置不变（runner 使用默认 max）。决策配置由固定或引导配置决定，不由同一个自动路由器递归选择。初始配置可以由 Host 根据现有偏好提出；用户不必填写每一个字段，也不必批准每一个任务。

### 7. 已核对的本地事实与限制

本次只做本地源码核对：DSH 的 `off` 映射为关闭思考；目录中 `deepseek-flash` 声明 1M 上下文。Buddy runner 按 run 设置 effort，但 headless 的 finalText 被包在 JSON 里，这不是一个受约束的 JSON 决策接口。

轻量的有界决策调用仍需要 adapter 合同、结果校验、requested/resolved/observed 配置证据和实测开销。上述 DSH 事实来自本机安装版本的源码核对，接入其他版本或 provider 时需要重新确认。

### 8. 决策输入、输出与权限

决策输入固定为固定指令加稳定的当前卡片快照，再加当前任务与变更，以便前缀复用且不引入陈旧风险。输出包含合法 profile 身份、简短理由或证据引用，或 defer-to-host。推荐本身不授予执行许可；普通任务失败与 selector 不可用是两件不同的事。

Jev/Laya 是可选实验后端，不是默认依赖。Laya 的上下文切分管线和强制的 embedding/RRF/ANN/历史检索都不是必需组件。大模型上下文是余量，不是“把全部历史都发过去”的指令；通用模型知识不能覆盖当前卡片证据和 adapter 合法性。

### 9. 评估维护

评估维护复用 Host 的实际验收与执行证据；计数、去重和版本变化是纯代码处理。决策 Buddy 提出有依据的补丁，必要时用自然语言归纳；Python 服务只在被授予的评价字段范围内原子提交变更，并核对期望修订。结构校验不能代替语义质量验证；自动采用范围需要预授权与代表性样例支持，不要求 Host 对每次普通整理重新验收。

它自己的推荐和置信度不算一次成功任务样本。正常 yield、环境故障和已取消的工作不自动计为模型表现不佳；不自动自我晋升，也不自动替换用户偏好。

### 10. 本地控制台

提议的本地控制台包含配置、模型卡片和任务，并显示待处理操作。它显示实际配置来源、证据与变更历史、工作区与辅助依赖、执行与验收的区分，以及当前在等 Host 还是等用户。用户可以修改偏好、更正证据、处理已授权的待决请求。

2026-09-22 补充：用户已确认前端采用 React、前端工程使用 Vite 构建，见 [ADR-005](005-shared-assessments-and-table-exclusion.md) 的控制台技术栈决定；前端工程仍待实现。

浏览器使用本地 HTTP 界面，并委托给与 C-Two 客户端相同的 Python 业务操作；它不是第二个状态权威，也不做浏览器直连 pickle RPC。关闭控制台不停止任务；读取或刷新永不调用模型。现有 dashboard 只是 GET/只读任务查看器，写入权威与 UI 未实现。

### 11. 成本与预算（可选、延期）

成本观测和金额/token 预算保持可选、延期：没有强制的记账，也没有通用的逐任务用户审批门。不因为估算成本自动判定业务任务失败。

### 12. 对 ADR-003 的承接与变化

本节列出本次收敛相对 ADR-003 历史研究的主要变化，避免读者按旧版理解当前提案：

- 默认决策后端从“Jev 作为首个拟验证后端”改为已经接入的通用 Buddy 模型（非思考模式）；Jev 与 Laya 一起降为可选实验后端，不再是默认依赖。
- 延续 ADR-003 的有界当前卡片和按需历史追溯；embedding/RRF/ANN 和 reranker 均不成为日常选择的必需组件。
- 延续模型与 effort 绑定为一个合法 profile 的要求，通用模型通过单次结构化推荐返回该配置；不依赖 Jev 特有的 Choice 接口。
- 决策配置由固定或引导配置决定，不由同一个自动路由器递归选择；selector 的推荐不自动构成执行许可。
- ADR-003 的来源、幂等、版本和合法配置要求作为设计输入；Jev 专有的候选上限、概率与调用形式不成为通用后端的共同约束，旧操作草图仍需重新评审。

## 二、新增边界建议（提案，待 Host 和用户评审）

以下八条是本次讨论新增的内容，不是已经接受的规则。每条按失效场景、建议规则和可检验结果展开，便于逐条评审；测试方式属于实现设计，不在此处展开。

机制边界可以用确定性夹具验证；路由适配和评价归纳的语义质量需要真实模型样例。每条建议必须给出可观察结果，并说明哪些检查仍依赖真实执行。

### 1. 启动与容量

- 失效场景：自动选择或维护任务在需要决策时遇到路由器不可用、被限流，或正好在等待同一个最后的 Worker 名额；如果决策路径本身占用该名额，或必须先完成选择才能继续，配置与恢复会被自己锁死。
- 建议规则：选择与维护任务使用固定配置并绕过自动选择，仍计入实际执行容量；待路由任务不先领取执行槽或工作区写占用。原任务在等待协助前结束当前回合，并以真实停止证据释放执行槽；工作区按 ADR-002 明确移交。后台维护在后续调度中低于用户工作，不能依靠增加等待通道解决执行槽死锁。路由不可用时回到已经授权的固定路线或 Host；重试有上界，配置、取消与接管操作无需模型即可执行。
- 可检验结果：在路由器不可用、被限流和仅剩一个 Worker 名额三种情形下，配置编辑与恢复路径仍能完成；维护任务不会永久占住名额或写占用；回退在声明上界内产生明确结果（固定路线或 Host 待决），没有无限重试链。

### 2. 单一决策所有权与并发 UI

- 失效场景：Host、用户控制台和维护任务对同一个待决请求并发提交决定，变成 last-writer-wins；或者用户刚改的偏好静默替换了正在运行或已经接受任务的模型配置。
- 建议规则：每个待决请求及其版本只有一个有效决定，写入是幂等的 compare-and-set；提供显式的 owner takeover（Host 不在时由谁接管）；冲突可见而不是互相覆盖；用户新偏好的作用域与生效时间可见，且不静默改变运行中或已接受任务的配置；权限撤销与日常偏好编辑是不同命令。
- 可检验结果：并发提交同一请求只产生一个有效决定，其余得到冲突或幂等重放；接管需要显式命令并留下记录；运行中任务在偏好变更后仍报告原配置；撤销权限与修改偏好在事件和权限效果上可区分。

### 3. 学习完整性

- 失效场景：把任务难度、局部任务失败、环境故障和整合失败混为一谈，用原始 accepted 计数形成全局模型排名；别名、provider、harness 或工具 preset 版本变化后沿用旧表现；一次成功抹掉未解决事故，或一次事故永久拉黑模型。
- 建议规则：区分上述失败类别；不从原始计数做全局排名；新别名、provider、harness 或 preset 版本可能使表现不可迁移，实际观测身份未知时保持未知；低样本数是不确定而不是失败；风险解除需要证据和条件（版本、范围、复现）；绝不把自生成的建议计为验证。
- 可检验结果：环境故障和重复验收不增加模型能力失败样本；身份无法确认的样本不写成已确认的精确版本表现；一次成功不删除未解决问题，一次事故不自动产生永久排除；风险更正保留新证据、适用条件与原始记录。很少被选择的配置显示样本不足，不能用历史选择频次证明优劣。

### 4. 数据范围

- 失效场景：项目私有观察进入其他项目的推荐或发给未获准处理该数据的 provider；未筛选日志携带凭据；社区文本被当成指令改写偏好或权限。
- 建议规则：默认共享公开与目录事实，私有观察默认限定项目范围，跨项目复用需要显式提升。项目内路由可以使用获准发送给所选 provider 的任务事实与证据；公开来源 URL 可作引用，未筛选原始日志不整体灌入，配置凭据不进入模型输入。社区文本仅作为带来源的数据。
- 可检验结果：项目 A 的私有观察不会自动进入项目 B 的输入，也不会发往未经授权的 provider；项目内合法请求仍能使用必要证据。提升操作记录范围，请求快照可检查发送字段，凭据值不出现在决策输入中。

> 2026-09-22 状态更新：本条“私有观察默认限定项目范围，跨项目复用需要显式提升”已被 [ADR-005](005-shared-assessments-and-table-exclusion.md) 取代，上面的建议规则与可检验结果保留为历史建议，不再是当前规则。凭据不进入模型输入、社区文本只作数据、未筛选原始日志不整体灌入等安全边界继续有效；共享的是有界归纳与来源引用，不是原始材料。

### 5. 协助生命周期

- 失效场景：父任务取消时连带杀死仍被其他消费者需要的共享辅助工作；辅助 Worker 失败或结果迟到时，父任务永久等待，或把迟到结果接进已经失效的回合。
- 建议规则：首版辅助任务明确归属一个父任务，不自动跨父任务合并。父任务取消后禁止其新增接续，专属辅助任务收到取消意图，资源仍待真实停止证据后释放。若未来允许共享辅助任务，应先记录消费者关系，不能因一个消费者取消就终止其他消费者的工作。结果以带版本产物返回；辅助失败或拒绝协助转回明确待决状态。非 Git 工作使用显式隔离目录或快照；Worker 保留 subagent 自主权，并报告仍在运行的所属工作，不能凭回合结束移交写权限。
- 可检验结果：父任务取消与辅助完成并发时不重启父任务；专属辅助任务的取消与资源释放分别有证据；迟到和重复结果不安排失效接续；未来共享场景保留其他消费者；非 Git 快照可核对，仍有所属工作写入时不复用工作区。

### 6. 评估写入与控制台权限

- 失效场景：合法 JSON 的补丁语义错误仍被采用；把“提出风险”与“改变执行禁令”混为一谈；现有 same-user service token 或 owner 字符串被当作 Host/Worker 授权隔离；只读 URL 与 token 被当成可写接口；对同用户全 shell 攻击者承诺 OS 级隔离。
- 建议规则：限制允许的补丁字段范围；保留证据引用和修订；区分提出风险与修改执行禁令；保留更正历史；新的浏览器写入需要显式授权边界，不能把现有只读 URL 或 token 升级成不受限写权限；不承诺对同用户全 shell 攻击者的 OS 隔离。
- 可检验结果：越界字段的补丁被拒绝且没有部分写入；修改执行禁令需要不同的授权与记录；未经授权的浏览器写请求被拒绝；文档与 capabilities 不宣称 OS 隔离。

### 7. 有界投影与历史保留

- 失效场景：为了让卡片有界而删除仍被待决评审、接续或未解决事故引用的证据或快照；维护积压与容量溢出不可见，或者维护工作依赖页面刷新才能推进。
- 建议规则：当前卡片可以有界，证据、任务和产物继续增长，归档与保留策略单独定义；不删除仍被待决评审、接续或未解决事故引用的证据或快照；待处理维护和溢出保持可见；关闭或刷新控制台不驱动维护。
- 可检验结果：被引用证据受到保留保护；维护积压与溢出可见；打开、刷新、关闭控制台都不额外创建模型任务，既有后台工作仍可独立推进；归档后引用仍可解析。保留期限与删除策略另行配置，不能为控制卡片长度而丢弃依据。

### 8. 验收范围

- 失效场景：只用 schema 合法性和公开模型基准宣称 Buddy 正确，而代表性路由、评估补丁、含噪输出、selector 故障、单 Worker 名额、同时发生的人工与 Host 操作、迟到回执和重启等情形未覆盖。
- 建议规则：验收同时覆盖业务结果与 schema；至少包含代表性路由和评估补丁场景（否定、范围、过期身份、证据冲突）、含噪与重复输出、selector 不可用、仅一个 Worker 名额、同时发生的人工与 Host 操作、迟到回执和重启；聚焦检查，不用公开模型基准证明 Buddy 正确。
- 可检验结果：每个场景都有可复现步骤和观察到的业务结果，而不只是响应 schema 通过；含噪与重复输入不产生重复样本或状态跃迁；单名额与 selector 故障场景下用户任务仍可推进；重启后决定与证据可恢复。

## 三、政策选择与后续决议

> 2026-09-22 状态更新：本部分三项治理选择已由 [ADR-005](005-shared-assessments-and-table-exclusion.md) 裁决，不再是待确认项。第 1 项被取代——当前规则是每个用户/黑板一张共享的有界评估表，按适用性默认跨项目复用，项目仅作来源；下面保留的“默认仅在项目内使用、跨项目复用需要显式提升”只是历史建议。第 2、3 项与 ADR-005 延续的自动维护范围、接管规则一致。

1. 默认跨项目证据复用（已被 ADR-005 取代）：项目私有观察是否默认参与其他项目的选择。建议默认仅在项目内使用，跨项目复用需要显式提升并记录范围。
2. 自动补丁采用范围：建议允许在预授权内追加依据、更新统计及保留原意和条件的归纳，并保留修订供抽查；删除未解决问题、扩大结论范围等变更交给 Host。用户偏好和执行权限保持独立，只有相应用户指令或授权操作才能改变。先以代表性样例验证自动采用质量，不将每次普通整理变成新的 Host 审批。
3. Owner takeover 政策：建议用户可以显式将任务控制权移交给另一个已接入 Host；服务增加 owner generation，使原 Host 的迟到决定失效。自动接管只在已有明确授权时允许，Host 缺席不自动扩大其他 Worker 权限。

以上三项的待确认状态已由 ADR-005 解决。Selector 不可用时采用已有明确授权的固定路线，否则回到 Host 待决；不递归另选 selector。用户通过控制台作出的明确配置、取消或重试指令可直接进入对应业务操作，不因来自 UI 就额外要求 Host 批准；服务仍校验任务版本与操作合法性。偏好修改、撤销权限、取消执行分别显示生效范围，不增设通用的二次确认门。

## 四、可直接实现的工程不变量

- 黑板是权威事实的唯一写入者；事务与事件保持原子性，请求与命令回执保持幂等。
- 缺失 PID、租约到期、final text 和回合结束都不作为停止或工作区移交的证据。
- 决策输入保持有界且前缀可复用；输出经过校验；推荐不等于执行许可；selector 故障不自动使业务任务失败。
- 选择与维护任务绕过自动选择，纳入有限执行容量；等待依赖不持有该依赖所需的最后执行槽或写占用，后台维护低优先；回退有明确上界。
- 有界卡片与全量归档并存；未解决问题不被后续成功覆盖；未知保持未知。
- 控制台读取或刷新不调用模型，关闭不停止任务，浏览器委托同一套 Python 业务操作。
- 现有 dashboard 保持只读，直到写入授权边界被显式实现并验收。
- 成本数据缺失不阻止正常工作，估算超限不触发自动失败。
