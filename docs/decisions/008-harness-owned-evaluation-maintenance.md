# ADR-008：由 Harness 发起的共享评价维护

## 状态

用户于 2026-09-24 确认本方案并要求记录。状态为已接受、待实现。本次只保存设计决定；运行中的 0.6.1、已发布配置和既有记录均未因此改变。现有行为仍以 [评价与控制台参考](../reference/evaluation.md) 为准。

本决定调整 [ADR-004](004-buddy-decision-support-and-console.md) 中评价维护的发起方式和职责划分，保留 [ADR-005](005-shared-assessments-and-table-exclusion.md) 的共享评价与来源追溯原则，以及 [ADR-007](007-neutral-core-and-single-current-contract.md) 的单一黑板权威、Host 控制和当前契约原则。

## 维护任务的归属

评价更新由能够使用 hey-my-buddy skill 的 Harness 承担。用户可以在会话中明确要求执行一次维护，也可以通过该 Harness 已有的定时任务能力安排维护。Skill 负责提供读取事实、整理证据、更新卡片和验证结果的工作流程。

指定某个 Harness 每日维护，表示把维护任务交给它执行。例如“每天让 DSH 更新 Buddy 黑板的模型评价”中，DSH 是维护任务的执行主体。评价范围由维护任务指令确定；没有额外限定时，可以处理共享黑板中所有需要更新的已接入模型配置。

共享证据可以来自不同 Host 和不同项目。维护执行者的身份不构成证据来源过滤条件，也不把可更新的卡片限制为其自身作为 Host 时使用过的 Worker。各个 Harness、提供方、模型和 thinking effort 的事实归属仍分别保存，适用条件随证据保留。

## 黑板与 Harness 的职责

黑板保存任务、验收、证据、卡片及维护历史，并通过正式接口承担权限、结构、引用、版本和发布校验。现有业务委派、智能路由和 Worker 运行机制继续保留。评价维护的任务发起、定时安排和执行决策放在外部 Harness 一侧，控制台不再发起评价模型调用，也不在黑板内另建一套评价维护调度机制。

任务执行和交付验收照常留下原始事实。每次验收不触发一次模型能力归纳；维护任务集中读取已有记录，再形成有来源的证据和卡片更新。维护结果通过黑板接口提交，保持 Python 服务对 SQLite 的唯一写入权威。

正式任务验收仍由拥有该任务控制权的 Host 负责。维护执行者可以比较不同来源、指出覆盖不足或结合后续反馈提出新的评价，但应保留原始验收作为历史记录，不通过维护模型卡片去改写其他任务的控制权或正式验收状态。

## 证据界面

模型卡片中的证据区始终只读，不受控制台编辑模式开关影响。移除“补充观察”输入框、“记录待整理观察”按钮以及证据区内直接修改关联的控件。用户仍可通过与维护 Harness 的对话提供反馈，由维护任务保留来源并纳入整理；其他已允许的配置与偏好编辑入口保留。

证据为空时显示可读的浅灰色提示：

> 暂无评价证据。你可以让已配置 hey-my-buddy skill 的 Harness 执行一次模型评价更新，或在该 Harness 中设置定时更新任务。

移除控制台中调用模型进行评价更新的“请求整理”等操作。已有维护记录可以作为只读历史保留，查看历史不触发模型调用。

## 更新范围与成本

维护任务按相关配置和未处理事实读取有界输入，并以固定任务、执行尝试、产物和证据身份去重。重复请求不应重复计数；已有待审核结果应可继续处理，无需每次重新生成。没有新事实时可以跳过卡片重新生成，用户明确要求重新评估时再执行相应工作。

上述安排不宣称唤醒一个 Harness 完全不消耗 token。定时任务的启动成本由所选 Harness 及其配置决定；本方案避免把每次业务验收都变成一次独立的评价模型调用。

用户偏好与可核验事实分别保存。路由推荐理由本身不构成执行能力证据；基础设施错误、取消、未验收结果和通过验收的产物也不能混为相同的质量样本。

## 当前实现的差异与后续实施

0.6.1 仍包含控制台证据手工录入、内置评价整理请求，以及 `configuration.autoMaintain`。该字段控制内置维护任务生成的卡片建议是否可在校验后自动发布；它不负责定时触发、证据采集或每次验收后的模型调用。

实施本决定时，需要统一收敛上述入口、Skill 工作流及维护专用运行路径。当前“固定决策模型负责比较候选与整理经验”的说明和“自动采纳常规整理结果”开关也需要随职责调整重新处理，避免留在路由配置中产生错误含义；本 ADR 尚未修改这些运行时设置。

实施不得清空现有委派、证据或卡片，也不得为了生成评价而重新执行历史业务任务。其他已讨论的编辑模式和并发改进继续作为独立工作推进，具体调度参数不由本 ADR 决定。
