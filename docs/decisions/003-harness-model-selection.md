# ADR-003 草案：有界动态评价表与 Jev 模型选择

## 状态与修订

状态：修订提案，供讨论；没有实现运行时，也没有调用 Jev 验证效果。日期：2026-09-21。

> 后续状态说明（2026-09-21）：本文正文保留为历史研究，其中的接口、存储布局与默认后端描述不代表当前提案。当前综合提案见 [ADR-004：决策支持、评估维护与本地控制台](004-buddy-decision-support-and-console.md)；ADR-004 收敛本文方向并加入新的边界建议，同样属于讨论、未被接受也未实现。

本版采用用户提出的方向：黑板维护所有已接入组合的有限当前评价，普通分派将合法候选的评价快照交给一个类型化决策后端。Jev 是首个拟验证的后端。此前的 embedding、RRF、ANN 和 reranker 不再作为日常分派的必需组件；完整历史保留用于显式追溯，不先检索历史再叠加 Jev。

保持 [ADR-002](002-host-directed-assistance-and-workspaces.md) 的边界：Host 可以亲自执行并决定跨 Worker 分派，Worker 保留内部 subagent 自主权，Python 黑板与 C-Two 继续承载权威状态和操作。精确成本核算、金额预算和自动全局排行榜不是前置条件。

## 1. 数据与责任

Skill 只说明发现、选择、委派和验收流程。Python 黑板在现有 `board.sqlite3` 内保存动态事实和当前评价，adapter 提供实际模型与合法参数。Jev 只根据本次输入返回候选判断，不直接更新评价、修改偏好或启动 Worker。

采用五类事实记录，另维护一份有界的当前评价投影：

| 记录 | 用途 | 更新来源 |
| --- | --- | --- |
| `model_catalog_entries` | Harness 实例、provider、模型 ID、别名、合法参数与默认值、发现修订和可用性证据 | Adapter 在事务外发现，服务验证后写入 |
| `execution_profiles` | 不可变的 Harness/model/参数组合、工具及 preset 指纹、已知版本与目录修订 | 服务解析具体候选时建立 |
| `selection_preferences` | 用户或项目的 prefer/pin/exclude、适用范围、指令来源和修订 | Host 依据明确用户指令记录 |
| `model_observations` | 本地验收、用户经验和社区观察，含条件、来源、证据与修正关系 | Host 验收或已授权的有限资料任务 |
| `model_research_requests` | 新模型资料需求、去重键、状态、关联维护任务和重查条件 | 目录 diff 与显式维护请求 |
| `model_assessment_cards`（派生） | 当前启用候选的有限综合评价、风险状态、版本及少量代表依据 | 程序增量更新；必要文字归纳由受限维护任务提出 |

偏好以黑板内的规范化记录为准，导入导出只是编辑入口。Harness 自身默认值属于发现事实，不自动成为用户偏好。观察是可追溯事实；评价卡是截至某个证据修订的综合状态，不等同于最后一次任务点评。

## 2. 动态但有界的评价卡

每个已启用的 Harness/provider/model 保留当前卡片及有限的已配置参数变体。目录可以完整记录支持的型号，但不会自动展开所有参数的笛卡尔积；具体 variant 来自 adapter 默认、用户偏好、已有执行或明确配置。每个可交给决策器的选项绑定一个合法 profile。

卡片采用固定字段和有界集合：

| 字段 | 内容与边界 |
| --- | --- |
| 身份与修订 | Harness、模型、可识别版本、合法 profile IDs、cardRevision、evidenceRevision |
| 实际能力 | 模态、工具与调用限制等 adapter 事实；未知明确保留 |
| 适用工作 | 少量当前有效的条件性优点，标出本地验证、用户经验或社区报告 |
| 局限与警示 | 当前适用的限制、未解决严重问题、待整理新观察；超出展开容量保留数量和引用 |
| 用户偏好 | 独立的明确偏好与作用域，后台归纳不可覆盖 |
| 依据与新鲜度 | 不同任务数、有效版本、更新时间、少量代表证据 ID，不内联全部历史 |

卡片条目必须保留条件。例如“在要求保留配置文件的清理任务中发生过一次越范围删除”，不能压缩为“DSH 不可靠”。后续成功更新统计，不自动清除尚未解决的问题；反证或修复版本通过新修订改变当前判断，原始观察保留。

建议将单卡、每个字段及证据引用数设置为配置项，并对整次请求设置总字节和 token 边界。仅限制每卡大小并不能保证所有候选合计可放入一次请求。设候选组合数为 M、每卡最大长度为 B，普通决策输入随 M×B 增长，与累计历史任务数无关。

有限卡片不能同时完整保存任意数量的罕见历史条件。无法在卡片中展开的未解决问题应保留待核对数量和引用，必要时交回 Host 查看。评价更新积压时仍显示新观察状态，不将旧卡片当作最新、完整的事实。

## 3. 评价更新流程

用户偏好由 Host 按明确指令写入一次，支持作用域和修订比较。prefer 是软偏好，pin/exclude 来自明确限制。模型输出或社区资料不能把推断改写为用户命令。

Host 在原有验收中向 `task_acknowledge` 附加可选 assessment，包含任务情境、是否符合预期、现象、归因和证据。它复用已有审查，不另开每任务一次评价模型。当前 accepted/rejected 的验收语义保留，不将对失败结果的审查误统计为任务成功。

初次 assessment 与验收同事务写入；重复的 `(attemptId, assessmentId)` 不增加样本。后续修正通过 supersedes/refutes 关系追加。正常 yield 或请求协助没有自动负分，判断依据是其实际行为及当时任务合同。尚未最终完成的任务可以单独记录已结束回合的复核，不能提前做最终验收。

程序即时更新计数、修订与未解决问题状态。需要合并自然语言观察时，只给维护 Worker 当前卡片与新增证据，提交有来源的增量修改；服务验证字段、长度、证据身份及期望修订后发布。新严重观察及待整理标志即时可见，不等待文字整理完成。Jev 不承担自由文本摘要生成。

资料维护按新增模型、参数或已知版本变化去重；一次未找到资料保留 no-evidence，按明确重查条件更新。先补用户默认、已选组合及相关新候选，不因接入数百模型就立即研究全部型号。维护使用已配置且获授权的普通 Worker，用户任务优先获得后续空闲容量。

社区记录保留 URL、内容 hash、日期、作者或项目及适用范围。转载去重；没有 Harness 或 effort 证据时保持较宽范围，不伪装成本地精确组合的验证。公开搜索不携带私有任务、代码或日志。原始网页不能作为修改偏好和权限的指令。

## 4. 日常选择流程

正常流程为：读取有界评价快照 → 程序确定合法选项 → 一次有界决策请求 → 程序校验 → 向 Host 返回推荐或待决原因。

1. Host 提供已经形成的任务描述、必要能力、明确禁止操作及本次选择要求。复用已有信息，不再让 Host 阅读全量评价或重新写一份模型研究报告。
2. 程序处理可确定条件：账户与配置可用性、参数是否合法、明确能力要求、用户 pin/exclude、版本状态。日期比较、计数和硬约束不交给 Jev。
3. 对所有符合条件的已启用候选组装当前评价表。选择空间中每个 profile 都包括确定的模型和原生 effort；默认给决策器完整的合法集合，不先按语义 top-k 删除候选。
4. 用 Jev 的 Choice 在这些 profile IDs 与 `defer_to_host` 中作出推荐。发送任务事实、当前评价、软偏好及清楚的适配准则。候选不足、存在无法判断的条件或资料矛盾时，允许交回 Host，不强迫选出一个 Worker。
5. 程序验证返回 ID、候选身份、输入快照及当前目录/风险修订；返回配置、概率分布、confidence、资料覆盖与依据引用。程序提供的是被选卡片的来源，不伪造 Jev 生成的自然语言解释。
6. Host 保留正常选择与最终验收权。若已有明确且适用的授权策略，可以按校准后的条件自动采用推荐；低置信度、超时、网络错误或输入超限都不自动使业务任务失败。

Host 已经明确固定合法配置、仅有一个合法选项且无未决选择，或同一请求的决策缓存仍然有效时，可以跳过 Jev；仍读取最新风险和参数状态。软 prefer 不自动转换成 pin。

初版只用一个闭合候选选择问题，不分别独立询问 model 和 effort。TypeSafe 的多个问题独立读取同一 state，不能假定它们按顺序相互依赖。以后如引入适配评分或风险判断，问题保持单一、清晰，并由程序处理结果一致性和权重，不依赖跨问题算术恒等关系。

## 5. Jev 的已核实能力与限制

本次检查的 [官方 API](https://docs.typesafe.ai/api) 接受 state 和 typed questions，支持 Choice、Score、Noul。Choice 从预定义选项返回选择、分布和 confidence，最多 255 个选项；保留 defer_to_host 时，实际 profile 数还需扣除这个选项。

[官方模型页](https://docs.typesafe.ai/models) 当前列出 `jev-1.13.0`，请求总上下文 64k tokens，state 加最长问题 32k。它也说明英语表现最好，其他语言需要用实际内容验证。这些是截至本次查阅的接口事实，adapter 应校验实际配置版本，不能永久硬编码成不变产品保证。

[官方限制说明](https://docs.typesafe.ai/model-jaggedness/jev-1.13) 提到字面解读、数字比较、间接推理、无关长上下文及对抗内容的局限。因此需要有限且条件明确的卡片，不能把整个档案传进去，也不能把 schema 正确当作决策正确。

[confidence 文档](https://docs.typesafe.ai/confidence) 将其定义为答案分布的统计量。它不等于被选 Worker 完成任务的真实成功率；采用阈值必须根据 Buddy 的实际任务集校准。不能仅凭某次高 confidence 将推测升级为能力事实。

Jev 在当前拟用接入中是外部 API。启用此路线意味着普通候选比较可能有一次远端决策调用，取代旧方案的“零网络调用”约束。调用需要已配置的访问凭据和数据范围；发送的任务及评价应限于该决策所需内容。本文只完成资料核实，没有安装 SDK、读取凭据或发出模型调用。

## 6. 有界输入、失败回退与缓存

程序在发送前同时检查候选数、每卡长度、总请求大小和后端上下文限制。Jev 文档允许的最大上下文不等于质量目标，应使用更小、经实际中文样例验证的输入配置。所有已启用模型都有卡片，不代表任意多的候选必然能装进同一次 API 调用。

超过单次上限时，首版返回 `candidate-set-too-large`、合法集合的分页入口和具体超限原因，由 Host 缩小范围或使用明确授权默认。不能静默取前 255，也不能将不同批次归一化后的概率直接比较。如果未来需要两阶段选择，应作为独立策略验证，且明确报告额外调用与覆盖范围。

普通决策限制为一次逻辑模型请求，缓存命中为零。HTTP/SDK 的重试、超时和并发另设有限策略并记录实际调用次数，不能通过默认重试把“一次决策”变成无限等待。维护积压、索引构建和全历史分析不进入该路径。

无候选、选择不确定或 Jev 不可用时返回 `defer_to_host` 或结构化不可用原因，并附合法候选和当前风险。存在适用的已授权固定选择时可以继续使用；否则 Host 作出正常分派决定。Host 介入不等于每次都找用户确认。

缓存键包含规范化任务与约束、候选 profile IDs、卡片与偏好修订、风险修订、selector 版本和问题模板版本。新严重观察使相关缓存失效。决策返回后目录或风险发生变化时重新验证，不自动启动无界重评链。

历史可以继续存档，但不能随着使用增长自动附加进卡片或模型请求。有界整理有信息损失，卡片要表明资料范围及未解决问题数量；Host 可显式查询原始证据。全文、向量或其他历史检索可作为后续诊断工具，不属于首版日常选择完成条件。

## 7. 代码与操作合同

建议在 `python/buddy/model_selection/` 内按 `catalog.py`、`preferences.py`、`evidence.py`、`cards.py` 和 `selector.py` 实现，避免再建立一个全局 agent 管理器。`DecisionBackend` 接受已准备的决策输入并返回结构化结果；Jev 是一个实现，服务不依赖其 SDK 对象表示任务状态。

以下为待实现操作，不是当前可调用命令：

| 操作 | 职责 | 边界 |
| --- | --- | --- |
| `model_catalog_refresh` | adapter 读取目录，服务提交 diff、修订和资料需求 | I/O 在事务外，失败保留旧快照 |
| `selection_preference_put` | 记录带指令来源和期望修订的用户偏好 | 后台模型不能覆盖 |
| `model_evidence_record/get` | 写入有来源观察、按 ID 或分页读取原始依据 | 去重、更正与来源范围明确 |
| `model_assessment_publish` | 发布某组合新的有限综合评价 | 比较修订，校验依据、字段上限及未解决问题覆盖 |
| `selection_candidates` | 读取当前卡片、合法配置和资料状态 | 纯本地操作，有明确分页和范围 |
| `selection_decide` | 组装快照、调用配置的决策后端并校验结果 | 至多一次逻辑调用或命中缓存，不自动启动 Worker |
| `selection_resolve` | 将确定选择解析为合法 profile 与配置 | 提交前复核配置，不做付费试执行 |
| `task_acknowledge` 扩展 | 原验收附可选 assessment | 初次验收、观察与最新风险状态同事务，旧客户端兼容 |

决策记录保存 `decisionId/tableRevision/profileIds/selectorModel/templateRevision/inputHash/result/status`，包含实际返回的 selector 版本。任务 spec 中保存接受的完整配置和选择来源，attempt 结果区分 requested/resolved/observed。普通重复提交按原 requestId 恢复已经接受的选择，不重新调用 Jev。

所有外部推理在 SQLite 事务外进行。提交推荐或任务时核对版本，源记录与事件保持原子性。选择的 provider/model/effort 与旧参数同时提供时必须一致。实际配置无法确认的验收不能硬归给一个未被证实使用的精确模型。

[现有 Adapter](../../deepseek-delegate/python/buddy/adapters/base.py) 需要目录发现和参数解析；[store.py](../../deepseek-delegate/python/buddy/store.py) 扩展评价与决策记录，[run.mjs](../../deepseek-delegate/scripts/run.mjs) 当前 requested 字段不能直接冒充实际配置。新增命名操作同时修改 [contracts.py](../../deepseek-delegate/python/buddy/contracts.py)、[service.py](../../deepseek-delegate/python/buddy/service.py)、[schemas.py](../../deepseek-delegate/python/buddy/schemas.py)、client、CLI 和 transport。

[db.py](../../deepseek-delegate/python/buddy/db.py) 当前 schema 为 5。新增事实及投影需要在私有旧库副本上验证显式升级和恢复，取得维护所有权、确认旧进程不再写入、备份数据库与恢复状态后再事务升级。原有 same-user token 也不能被宣称提供了独立 Host/Worker 授权；按 ADR-002 设计写入边界，不能用 actor 字符串代替身份校验。

## 8. 相关已有探索

[TypeSafe 的 skill suggestion cookbook](https://docs.typesafe.ai/cookbooks/skill_suggestion) 是直接相关的实例：读取有限目录作选择，并保留不采用任何候选的路径。其示例对较大技能目录使用先排名、再核对短名单的两阶段调用。Buddy 首版拟验证更小的完整配置表和一次调用，不能将示例的效果或时延视为本机保证。

[Agent-as-a-Router](https://github.com/LanceZPF/agent-as-a-router) 的执行后反馈、[models.dev](https://github.com/anomalyco/models.dev/blob/dev/sync.md) 的目录增量同步，以及 [LangMem](https://github.com/langchain-ai/langmem/blob/main/docs/docs/guides/delayed_processing.md) 的延迟合并处理，仍可作为资料维护的参考。不引入它们的完整运行框架，现有黑板与普通 Worker 足以承载相应职责。

## 9. 实施路线与验收

1. 先完成卡片与本地闭环：目录、合法 profiles、偏好、验收观察和有界综合评价。证明重复反馈不增样本，新事故即时可见，后续成功不会抹去未解决问题。
2. 加入可替换决策后端和 Jev adapter，使用录制或构造响应验证合法 ID、模型与 effort 联合选择、输入上限、版本冲突、超时及回退。开发测试不需要真实凭据。
3. 在具备授权接入后，用冻结的真实卡片和代表性任务对照 Host 判断或既定策略，验证实际路由效果、中文表现、实际调用次数及延迟。验收阈值依据样例校准，不引用宣传数字作为目标。
4. 接入目录增量变化和有限社区维护，验证资料不可用时正常分派仍能继续，以及动态更新不会改写正在执行或已接受的选择。

| 验收场景 | 要求 |
| --- | --- |
| 固定候选，历史从几十条增加至十万条 | 日常读取量与发送输入不随历史线性增长，卡片和引用保持上限 |
| 模型及参数变化 | 返回组合必须来自 adapter 确认的合法集合，不出现模型与 effort 不兼容 |
| 新事故、成功、反证与重复回执 | 未解决问题不被最后一次成功覆盖，修正可追溯，重放不增计数 |
| 所有候选都不适合或证据不足 | 可以交回 Host，不因 Choice 必须选一项就强迫委派 |
| 候选数或输入超过 Jev 限制 | 明确报告范围和原因，不静默截断或比较不同批次概率 |
| 中文、改写、否定与条件相反 | 用人工标注场景评价任务适配、已知风险识别和应当交回 Host 的情形 |
| 网络失败、低置信度、selector 更新 | Host 可继续正常决定；版本和阈值可追溯；业务任务不被自动判失败 |
