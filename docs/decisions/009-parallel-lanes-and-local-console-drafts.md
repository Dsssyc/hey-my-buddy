# ADR-009：并行执行、独立路由容量与本地编辑草稿

## 状态

已接受，并在 0.6.2 的并行运行时和 0.7.0 的控制台源码中实现。用户于 2026-09-25 要求优先完成并行派发，并明确要求完整版本完成验证后等待通知再安装。源码状态和运行中版本分别核实。

## 执行与路由

黑板默认同时容纳两个业务 attempt 和一个独立的路由 decision attempt。`BUDDY_MAX_CONCURRENT` 控制业务上限，`BUDDY_MAX_DECISIONS` 控制路由上限；自动启动的通用 worker 池大小为二者之和，每个 worker 仍只执行一个 attempt。排队候选先按有空余容量的类别筛选，再施加有界查询限制，避免一个类别积压时遮蔽另一类别。

并行执行仍遵守工作区与独占资源约束，独立写入者使用不同 worktree。未确认停止的 attempt 继续占用容量和资源；过期租约、缺失进程或已返回的 RPC 都不能代替停止证据。

worker 池用持久清单记录精确成员身份，不凭相似名称接管手动 worker。缩容通过执行间隙的退出请求完成，保留活动子进程并补交已有结果；只有数据库中的不确定记录、没有可恢复本地证据时，保留待恢复状态，不反复启动空进程。显式 `worker-stop` 仅作用于指定 worker，在当前 daemon 生命周期内不自动撤销该请求。

## 编辑与发布

“编辑模式”控制浏览器内存中的草稿。开启和输入均不申请黑板写入资格，也不调用模型；两个页面可以同时拥有草稿。保存时才根据草稿版本申请短时发布资格，沿用单一 writer、代际、租约和幂等命令约束。此决定保留 ADR-005 的权威发布排他性，并把人类输入时间移出独占区间。

版本冲突保留草稿并提供明确的重载与放弃操作。结果未确认时保留原请求和命令身份进行恢复；无法确认的释放不能被显示为已成功释放。关闭有修改的编辑模式提供保存并退出、放弃修改和继续编辑三个选项。

证据始终只读，评价维护按 ADR-008 交给外部 Harness。已启用档位、当前查看档位和未保存状态分别展示。主题选择只保存显示偏好；任务控制、凭证、验收事实和模型配置均不因主题或本地草稿发生变化。
