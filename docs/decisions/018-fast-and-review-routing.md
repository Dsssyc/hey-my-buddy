# ADR-018：快速路由与审阅路由

## 状态

提议：用户于 2026-09-29 确认了双模式方向与档位改名，待审阅本文后接受。尚未实现。本文修改 [ADR-014](014-router-buddy-and-read-only-routing.md) 中"移除无工具决策助手、只保留一种会查看代码的 Router"的部分；ADR-014 的其余内容（冻结候选、只按路由边界校验、程序计算的偏好检查、Host 边界）不变，并同时适用于两种模式。

## 背景

ADR-014 的 Router 在限定预算内只读查看代码仓库再做选择。这要求 harness 的原生沙盒能证明读取范围受限、禁止写入、工具不能联网。截至 2026-09-29，只有 macOS 上的 Codex 0.157.0 通过了原生探针（[ADR-017 验收记录](../acceptance/local-harness-discovery-0.19.0.md)）：

- DSH 的工具不限制读取范围与联网，无法验证，因此 DeepSeek 系列无论哪个模型都不能担任 Router。
- 验证绑定 harness、版本与平台。Codex 一升级，验证就会失效，Router 随之不可用，默认路由的委派会停在 Host 边界。
- 每次委派都要运行一次查看代码的模型回合，较慢，费用也较高。

另一方面，Router 的主要价值是把任务与 Host 维护的模型评价、用户偏好对上号，其中相当一部分判断只靠任务描述和评价表就能完成。

## 决定

1. **两种模式，共用一套协议。** Router 分为快速路由与审阅路由。两者都使用 ADR-014 的冻结候选枚举、答案格式、只按路由边界校验、程序计算的 `policyCheck` 与 Host 边界规则，区别只在 Router 能否查看代码。
2. **快速路由不给工具。** 输入只有任务描述、任务本地的 `routingPreferences`、冻结的合法候选及其评价卡片、生效的用户偏好与家族备注、程序给出的 `policyFacts`，不含仓库内容。执行为一次原生模型调用，由 harness 真正关闭全部工具（读文件、shell、网络与搜索、MCP、子代理），不能只靠提示词；程序检查原生事件流，出现任何工具调用即判本次答案无效。沿用 ADR-014 的一次格式纠正。答案的证据只能引用卡片、偏好与备注，不能引用文件。时限固定（初值 60 秒），没有工具次数预算。
3. **快速路由的资格按 harness 能力判定，不需要付费探针。** adapter 声明并实现"无工具结构化调用"，由模拟测试与一次零工具调用检查确认；满足条件的 harness 下，任何启用且可用的配置都能担任快速 Router。无法可靠关闭工具的 harness 不能担任。
4. **审阅路由即现行 Router。** 仍要求 harness 的只读结构化能力经原生探针验证，并受 ADR-017 的 harness 健康与版本记录约束。预算三档改名为"简要 / 标准 / 深入"，接口标识相应由 `quick` / `standard` / `deep` 改为 `brief` / `standard` / `deep`，升级时把已保存的 `quick` 映射为 `brief`；各档的时限、工具次数与读取量不变。"快速"一词只用于快速路由。
5. **两个 Router 位置加一个默认模式。** 配置包含快速路由配置、审阅路由配置、默认模式（`fast` 或 `review`）和审阅预算档。升级时把现有的 Router 配置放入它符合资格的位置：harness 已验证审阅能力的放入审阅位置，否则在符合快速路由资格时放入快速位置，都不符合则保留为待处理并给出提示。新安装的默认模式为快速路由。
6. **Host 可以按次指定。** 提交时可以指定 `routingMode: "review"` 要求审阅路由（例如任务大或需求模糊），不指定则用默认模式；任务本地偏好在两种模式下都生效。
7. **审阅路由不可用时降级。** 要求审阅路由但审阅 Router 不可用（未配置、未验证、健康检查失败或版本变化导致验证失效）时，自动改用快速路由，并在路由记录中写明已降级及原因；Host 可以在提交时关闭降级，此时停在 Host 边界。两种都不可用时才停在 Host 边界。
8. **结果可见。** 控制台顶部路由状态分别显示两个 Router 与默认模式；时间轴的路由块用不同纹理区分两种模式，并标出降级；"路由依据"显示模式、是否降级及原因。
9. **说明数据流向。** 设置里写明：快速路由会把每个任务的描述发送给快速 Router 所在的模型提供方，包括准备交给其他模型执行的任务；审阅路由另外会让审阅 Router 读取冻结的仓库副本。
10. **ZCode 适配。** 依据 GLM-5.3-Flash 的只读调研（run `536df909`，ZCode CLI 0.16.9）：
    - 快速路由可以适配。app-server 的 `session/create` 原生支持空的 `toolAllowlist`（buddy 的模型发现已在使用，见 `zcode_runner.py`），事件流的 `tool.updated` 带工具调用标识，可以确认零工具调用；没有原生的 JSON 格式参数，按协议用提示词加程序校验与一次格式纠正。需要为 ZCode adapter 增加无工具结构化调用的实现。
    - 审阅路由有条件。ZCode 有 plan 模式、`toolDenylist`、可拒绝操作的 PreToolUse 与 PermissionRequest hook，buddy 在非交互时会自动拒绝权限请求；但官方文档没有沙盒与无头模式说明，读取范围、禁止写入与禁止工具联网的系统级限制都未经验证。只有逐次授权的原生探针通过后才能标为已验证，证据绑定 ZCode CLI 版本。

## 考虑过的方案

- **只保留审阅路由。** 路由质量高，但验证绑定版本，harness 一升级就不可用；每次委派都要付出查看代码的成本；DeepSeek 等无法验证的 harness 永远不能参与路由。
- **只保留快速路由。** 简单便宜，但失去查看代码后的判断，对需求模糊或依赖代码结构的任务选择质量下降。
- **把无工具作为预算的第四档。** 把两种资格规则不同的方式压在一个选项上；同时只能有一个 Router，也就无法在审阅 Router 失效时降级到另一个便宜模型。
- **恢复 0.16 的 DSH 专用决策助手。** 只服务一个 harness，并会带回 ADR-014 已经移除的专用代码路径；本文改为 harness 中立的无工具模式。

## 影响

- 需要为各 adapter 增加无工具结构化调用的能力声明、实现与零工具检查，并补测试；路由协议增加模式、降级字段；配置增加两个 Router 位置与默认模式，优先用现有的 `meta` 键实现，若需要改 schema 按现有规则另行确认。
- 契约版本需要升级；CLI、控制台的 Buddy 配置与时间轴、路由依据、SKILL.md 与参考文档（decision.md、evaluation.md、cli.md、architecture.md）同步更新。
- 快速路由会把任务描述发送给快速 Router 的提供方，这一点需要在设置页与参考文档中写明。
- 实现与安装都需要用户另行授权；验收时两种模式分别记录证据。
