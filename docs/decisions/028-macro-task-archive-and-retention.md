# ADR-028：宏任务的归档与保留期

## 状态

方向已接受：用户于 2026-10-10 讨论 [ADR-024](024-console-session-view.md) 第 5 条的默认值时提出，保留与删除应当以宏任务为单位：给宏任务增加归档，归档之后保留多久由用户在设置中选择，到期删除宏任务及其全部微任务的记录，归档期间可以恢复。由 Claude Code Host 起草。用户同日同意了 Host 提出的四处调整：归档只是收起、默认永久保留；期限里不设"立即删除"，改为单独的删除；恢复的入口在宏任务列表里；删除时留下不含内容的结果事实。下列内容是起草时补充的，待用户确认：第 1 条中不属于宏任务的执行；第 4 条的自动恢复；第 5 条；第 6 条中"没有强制删除的途径"；第 8 条。尚未实现：归档排在 [ADR-021](021-router-buddy-planes-and-routing-evidence.md) 的 L15，删除排在 L7 之后，实现与安装需另行授权。本文取代 ADR-024 第 5 条中会话记录单独的保留设置。

## 背景

黑板上的记录只增不减。没有任何操作会删除宏任务或微任务的记录：存储结构里的 36 处外键全部禁止删除，27 张表带着任务的编号。2026-10-10 的日常黑板运行了三周，有 49 个宏任务、866 个任务与约 17.4 万条事件，数据库 375 MB，用户的仓库里留着 2,872 个由黑板保留的 Git 引用。升级时的迁移与存储清理对残留引用的核对，耗时都随黑板的大小增长。

ADR-024 第 5 条原先只为会话记录设了保留方式，并把它挂在微任务的检出回收上。回收是黑板内部的事件，用户不会按它来想自己的数据；它也只管会话记录这一类。用户想的单位是宏任务，术语表里宏任务的定义本来就包括用于浏览与归档，只是一直没有做。

## 决定

1. **归档以宏任务为单位，只是收起。** 用户在控制台把一个宏任务归档：它离开默认的列表，记录、结果与会话内容都不变，随时可以恢复。归档时黑板顺带回收它名下按已有规则可以回收的检出，回收不了的留着并列出原因。不属于任何宏任务的执行按同样的规则单独归档。
2. **归档之后保留多久由用户在设置中选择，默认永久保留。** 选择有四个：永久保留、三个月、一个月、7 天，从归档的时刻算起。用户选了期限，到期的宏任务才会被删除；默认永久保留，所以归档本身不会让任何东西消失。
3. **删除是另一个动作。** 已归档的宏任务上有单独的"删除"，带确认。期限里不设"立即删除"，否则归档按钮就成了没有提示的删除。确认框写明会删除什么，以及滚动备份里的副本要等备份轮换之后才消失。删除不可恢复。
4. **归档不妨碍工作。** 宏任务不调度工作，也不授予控制权，归档同样如此。名下还有正在排队、路由或运行的微任务时不能归档，黑板拒绝并列出是哪些；停在 Host 那里的微任务不妨碍归档。已归档的宏任务有了新的活动（新的微任务，或对原有微任务的继续）时自动恢复，黑板不因为归档而拒绝提交。
5. **只有用户能归档、恢复与删除。** 入口在控制台里。Host 与 Worker 不能归档或删除，也不能更改期限。
6. **删除的是这个宏任务的全部内容。** 包括它名下所有微任务与协助任务的记录、消息、结果、路由与验收记录，私有区里的会话内容，检出留下的记录目录，以及黑板保留在用户仓库里的 Git 引用。删除只走已有的回收保护：还有检出没有回收的宏任务不删除。手动删除时列出受阻的原因；到期时它留在已归档里并标明原因。没有强制删除的途径，未验收的改动要由 Host 先给出结论。删除不触及用户自己的 harness 登录与原生会话库。
7. **留下 Router 学习用的事实。** 不含内容的结果事实（哪个 buddy、哪个领域与任务类型、结果、用时与用量）在删除之后保留，评价与路由的证据不因用户的清理而变少。它们不再指回已删除的微任务。
8. **删除留下一条记录，期限的更改对已归档的同样生效。** 黑板记下删除的时刻、宏任务的编号、删除了多少个微任务，以及是用户手动删除还是到期删除，不保留标题与任何内容；此后指名这个宏任务的提交被拒绝并说明它已删除，不会悄悄重新建出一个同名的空宏任务。更改期限会让一些已归档的宏任务立即到期时，设置先告诉用户数量并请用户确认。
9. **恢复与删除的入口在宏任务列表里。** 列表的筛选增加"已归档"，已归档的宏任务在那里显示还剩多久，并可以恢复或删除。设置中只有期限这一项。存储检查列出已归档的宏任务占用的空间。
10. **会话记录不单设保留方式。** 微任务的检出回收之后，私有区里的凭据、配置与原生数据库照旧清除，会话内容留下，随宏任务一起删除。ADR-024 第 5 条已相应改写。

## 考虑过的方案

- **按微任务保留会话记录，挂在检出回收上。** ADR-024 第 5 条原先的写法。单位是内部事件，只管一类数据，其余的记录仍然只增不减。
- **不设归档，按时间自动删除旧记录。** 没有用户的动作就删除数据，仍在进行的长期宏任务还会被从中间截断。
- **归档默认带期限，或把"立即删除"作为期限的一种。** 多数工具里归档的意思是收起来但还在。点了归档之后东西在几天后或当场消失，用户不会预料到。
- **在设置里恢复已归档的宏任务。** 要在设置里另做一个列表。找宏任务的地方只应当有一个。
- **删除时连同统计一起删除。** 路由的证据会随着清理变少，逼着用户在磁盘与路由质量之间取舍。
- **允许 Host 归档。** 加上期限就等于让代理触发删除。整理宏任务是用户的事。
- **手动删除可以连同未验收的改动一起强制删除。** 用户不必再找 Host 给结论，但这等于在控制台里放弃别人交付的工作，并且要在回收保护之外另开一条途径。先不做；实际使用中受阻的情况多了再议。

## 影响

- **契约与数据。** 宏任务增加归档时刻；设置增加期限；新增归档、恢复与删除三个只供控制台调用的操作，以及删除记录。这是黑板的第一条删除途径：全部外键现在都禁止删除，删除要按依赖顺序在一个事务里完成，并与存储清理共用写入围栏。
- **存储结构。** 归档的字段与删除记录随 ADR-021 的 schema 16 一起加入（L15），不另做一次升级。
- **顺序。** 归档与恢复可以随 L15 与展示线先做。删除要等 L7 把结果事实从微任务的记录里分出来之后才能做，否则第 7 条做不到。会话内容的保留随 ADR-024 实现。
- **控制台。** 列表的筛选与已归档条目上的操作、设置里的期限、存储检查中的占用。属于展示线。
- **验证边界。** 删除要在日常规模的私有副本上演练并量出耗时；到期删除在用户不在场时进行，它的拒绝与受阻都要有测试。Windows 未验证。
